# 实施计划：书籍趣味性提升

## P1 基线与试点准备

- [x] 记录 6 个试点章当前工作树状态，识别与其他任务重叠的未提交修改。
- [x] 为每章写一行“核心问题、主误判、证据、回扣”，先审结构后改正文。
- [x] 记录受保护区与事实 token 基线。

## P2 六章试点

- [x] C 指针：加入可运行的预测题与内存现场回扣。
- [x] 构建系统：用一次构建事故工单串起工具选择与依赖关系。
- [x] STM32 DAC：用“有数字、没波形”的症状链推进排查。
- [x] FreeRTOS 调度：用时间线竞猜解释就绪态与调度点。
- [x] ESP32 GPIO Matrix：用“引脚没坏，路由错了”的翻案结构。
- [x] GD32 RCU：用“STM32 经验为何在这里误导你”的迁移陷阱推进。

## P3 试点守卫与报告

- [x] 逐章运行事实/受保护区守卫，修复所有非预期差异。
- [x] 运行元数据、阅读时间、链接与站点构建检查。
- [x] 生成试点前后报告，列出五槽位、净增字数与已知限制。
- [ ] 用户抽评至少 2 章；未通过则只迭代试点，不扩展。

## P4 分批扩展

- [x] 按章节类型建立优先级清单，先处理长且叙事标记稀少的章节。
- [x] 每批不超过 10 章，沿用试点守卫与报告。
- [x] 已有强叙事章只补互动或回扣缺口，不重复改写。

## P5 全书验收

- [ ] 全量站点构建与书稿测试通过。
- [ ] 抽检各分部至少 1 章，确认风格有变化但不模板化。
- [ ] 更新必要的 Trellis 规范与任务记录，提交时与其他在途改动分离。
