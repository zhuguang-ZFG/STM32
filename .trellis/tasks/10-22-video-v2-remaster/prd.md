# 视频 v2 重制：实验室仪器风 + 全量旁白重写 + 全平台换新

## Goal

把现有 18 集视频重制为 v2：实验室仪器风画面、云扬配音、节拍驱动的动效与音效、逐集重写的旁白与竖版短剪；全部 v2 母版与发布包产完并验收后，再按平台节奏替换线上作品。

## 现状基线（2026-10-22 实测）

- 18 集编号正片 + 1 集 c3b A/B 测试。横版 534 场、59,274 字旁白；竖版 197 场、4,925 字旁白。
- 只有 `s5-systick` 有 `platforms.bilibili.sections`（6 节）与竖版 5 节；其余 17 集无分节。
- 17/18 集有可引用的 `code/**/probe.sh`；`c3-volatile` 只有 `blink-variants.sh` + `opt_probe.c`，没有 `probe.sh`。
- 31 个被引用的动画 SVG 全部存在；18 集横竖母版全部存在，时长均在 `targetSec` 内。
- 四条投放线都没有「删除已发布作品」的自动化；B站也没有换源实现。B站只有编辑标题/简介/封面的 API，知乎有真草稿，抖音/小红书只有表单态，小红书发布不写幂等台账。
- 已记录的平台节奏：抖音 1 天 1 条、最多 2 条；知乎账号级滚动频控；B站投稿队列间隔约 30 分钟；小红书实测 27 分钟 17 条但无正式上限口径。

## 已确认的决定（2026-10-22 对话）

1. 四个方向都做：画面与动效、声音与配音、内容与选题、发布包装与运营。
2. 18 集全部重制；不是只改下一集。
3. 线上处理口径：全平台换新（删稿重发）；B站若实测到换源入口，优先换源并单独拍板。
4. 内容深度：18 集全量重写旁白；不是只改钩子或只做视听升级。
5. 视觉基调：实验室仪器风。
6. 旁白音色：`zh-CN-YunyangNeural`（云扬）。
7. 投放节奏：先把 18 集 v2 母版全部产完并验收，再排平台投放。
8. 推进方式：样板先行——先用 `s5-systick` 做一集端到端样板，验收后再分 wave 重制其余 17 集。

## Requirements

### R1 内容重写（18 集）

- 每集先产出 fact sheet：源文档、取证脚本、现有场景、每个上屏数字对应的本机实跑输出。
- 旁白按 v2 结构重写：0–15 秒冷开场、15–30 秒成本与路线、3–6 节正文、20–30 秒回收、10 秒下集钩子。
- 竖版短剪重写为 60–75 秒、10–12 场；钩子前置、每场一个点、金句收尾。
- 所有技术断言与数字必须能回到 fact sheet 或本机实跑输出；不新增未取证结论。
- 每集必须有 `sections`（横版与竖版各自一份），节名 ≤12 字。

### R2 v2 视听引擎

- 新增 `formatVersion: 2`；旧集未迁移时保持现有渲染路径与产物逐字节不变。
- 实验室仪器风：石墨蓝黑底、细网格、四角测量框、通道/时基读数、游标与测量标注；不牺牲代码与字幕可读性。
- 节拍驱动：由字幕起止时间生成场景内节拍；code 行组逐步揭示并高亮当前行；card 逐条揭示；关键数字有一次锁定动效；钩子标题有通电/扫描入场。
- 节拍只在离散状态截图，保住逐帧去重；每场至少 2 个节拍，code/card 场最长静止段 ≤6 秒。
- 转场使用离散的仪器扫描/淡入，不做连续动画。
- 音频：云扬配音（先试 `+2%`）；新增程序化音效层与更贴仪器感的 BGM；统一 -14 LUFS；音画漂移 ≤0.15 秒。
- 对 hex、`offsetof`、`BSRR`、`PendSV` 等词建立发音替代表，逐集抽听。

### R3 封面与文案

- 封面沿用「一句钩子 + 一张物证 + 一个数字」，改为仪器面板构图；生成 B站 16:10、抖音 3:4、知乎 16:9、小红书 4:3 四尺寸，336px 缩略图逐张可读。
- 标题与简介逐集重写，保留平台限制：抖音标题 ≤30 字、简介不提站外；B站简介纯文本；小红书标题 ≤20 字、正文 ≤1000 字、话题走 chip。
- 每集发布包包含四尺寸封面、平台文案、合集/分区信息。

### R4 平台替换工具

- Phase 0 先做只读能力探针：B站换源入口、抖音删除入口、知乎删除入口、小红书笔记删除入口。
- 新建归档、准备、核对、删除、发布、回读、台账工具；删除与发布都是默认只读、`--go` + 逐集闸门才执行。
- 小红书补幂等：发布写 `<ep>-published.txt`、消费闸门、回读必须区分新旧笔记。
- 替换顺序：归档旧 ID/元数据/母版 → 准备新稿 → 核对 → 删除旧稿（逐集授权）→ 发布新稿（逐集授权）→ 回读新 ID/时长/封面/合集 → 更新台账。
- 绝不在一次批处理中删除多集；每集单独授权、单独回读。

## Non-goals

- 不做 backlog 新集（C1/S9/S1/F1）；等 18 集 v2 收口后再立项。
- 不重制 c3b A/B 测试集。
- 不改站点正文，除非某集取证脚本本身有错。
- 不在没有逐集授权的情况下删除任何线上作品。
- 不改平台账号、凭证或既有投放红线。

## Acceptance Criteria

### 每集（18 × 横竖）

- [ ] `npm run video:lint` 通过；`npm run video:check` 横竖两版全绿。
- [ ] 钩子 ≤15 秒；每集有 `sections`；code/card 场最长静止段 ≤6 秒。
- [ ] 所有上屏数字通过 fact sheet 审计；新增/改写的数字有本机实跑依据。
- [ ] 云扬音色；音频 -14 LUFS；音画漂移 ≤0.15 秒；关键术语抽听无错读。
- [ ] 四尺寸封面通过 336px 缩略图检查；标题/简介符合平台限制。
- [ ] v2 母版与旧母版并排抽帧留档。

### 全局

- [ ] 18 集 × 2 平台母版、封面、发布包全部齐全，且 `series.json` 的 `masters` 与实际时长一致。
- [ ] `video/out/` 旧产物在迁移前有归档或校验记录；没有未记录的覆盖。
- [ ] 新审计项都有一次故意的失败样例与报错原文。

### 投放

- [ ] 每集旧/新 ID、标题、时长、封面、合集与删除时间写入 `.temp/repost/<date>/<ep>/`。
- [ ] 删除与发布各有一张逐集闸门；闸门内容来自对话里的明确授权。
- [ ] 新稿回读使用新 ID，不按标题匹配；小红书能区分旧笔记与新笔记。
- [ ] 投放节奏遵守平台频控；抖音默认 1 天 1 条，知乎按滚动窗口。

## Constraints

- 证据优先：任何旁白/画面上的数字必须能回到 `probe.sh` 或本机实跑输出；做不到就删掉或标「待上板实测」。
- 逐集放行：删除与发布都是不可逆动作，必须逐集授权，不允许用「上次同意过批量」推断。
- 先产后排：18 集母版全部验收前，不启动任何平台删除/发布。
- 兼容：`formatVersion` 缺省时，旧集渲染路径、DOM、审计输出保持不变。
- 凭证不进 stdout、不进仓库；沿用现有投放红线。

## Open Decisions（Phase 0/1 收口）

- B站是否实测到换源入口；若有，是否以换源替代删稿重发。
- 小红书网页端是否有删除入口；若没有，是否 App 手动删或该平台不换视频。
- 云扬语速最终取 `+0% / +2% / +4%` 哪一档（按实测字/秒与抽听定）。
- 封面是否保留现有「撞色对切」结构，还是完全改为仪器面板构图（Phase 1 出两版对比）。
