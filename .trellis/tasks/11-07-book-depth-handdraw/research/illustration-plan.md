# 手绘机制图设计与验收

## 已证风险

本轮真实Chromium打开现有线上C2、S11、F3，在390×844视口测得SVG宽310px、viewBox320×88；源字号7–8映射成约6.78–7.75 CSS px。截图已观察。只有这三张被实测，不能推断全站图均有同一问题，也不能把暗色抽样当浅色/印刷通过。数据见visual-baseline.json。

已有art_guard的font>=7是印刷结构地板，不是手机可读证明。保持原门禁不变，新增图的设计验收要求实际手机主要标签至少约13 CSS px（本批设计目标，不改测试/策略）；在现有310px图宽下选14用户单位即可约13.56px。长标签放图注，不挤进小画布。

## 分工

- 题花保留章节辨识，不背机制；已有动画保留时间展开；架构图保留连接全景。
- 手绘机制图解释一个具体问题，如“指针变量存什么、箭头指到谁”“为什么就绪而非存在决定能否参选”。
- 优先复用正确且清楚的图。图有用但太小：改成若干连续小图或精简标签；不要同一关系换三个画法堆叠。每张图一条结论。

## 沿用现有管线

生产资产仍入docs/public/figures，正文相对现有机制图引用规则；config.mts构建期内联，hand-figure/CSS墨色令牌适配主题，整书装配复用同源。保留viewBox320×88、纯矢量、<=6000bytes/图、LF、无filter/id/url()/外链/script/style/image，至少两档笔压。手绘感靠曲线、少量不完全对称和主次线宽，不靠滤镜或假纸底。

单张容不下就分成2–3张有逻辑顺序的独立小图，不扩大图形门禁预算或把标签缩到不可读。不同小图只共享必要对象，旁边用自然语言讲状态变化。正文图要有alt/图注并说明读图顺序。

## 每图交付卡

正文文件/原锚点、读者问题、图的一句结论、对象与箭头映射、事实来源及芯片/版本、已有资产处置(reuse/upgrade/new/none)、允许新链接、深浅主题/手机/印前证据。图中新增数字与事实同正文审查，不从模型自信或旧图推断正确。

## 双重验收

1. 内容：每个图内符号、关系、状态与有版本的一手来源/当前工程对账；类比不能额外引入“原子/无限/一定”等保证。
2. 几何：art_guard原门、原anim-audit布局检查；再真实截图查压字、连线穿对象/文字、箭头方向、裁切、留白与对齐。
3. 读者：390px与1440px实际阅读，不依赖浏览器缩放；浅/深主题同样清楚，不能只验ink变量存在。主要标签约13px以上，不把这个目标硬塞进共享测试。
4. 印刷：完整HTML及A4/16开链各自生成，检查图在正确段落、细线/最小字号可辨、无滤镜栅格化；最终印前13项原合同通过。单图SVG通过不能替代完整PDF。
5. 页面：新图实际出现在对应正文与离线书，不拿章首题图计数证明机制图已入书；目录/折叠/代码滚动不退化。

## 六个样章图示方向

| 样章 | 目标 | 现有资产 | 规划动作 |
|---|---|---|---|
| C2 指针 | 变量存地址、目标是另一个对象；宽度/步长和指针自身大小分开 | pointer-arrows动画、c-02-pointer手绘 | 保留动画；改进步长图字号；新增“变量→地址→目标”分镜，不重复数组格子画满 |
| B7 构建 | 同一源改动沿哪些依赖边影响哪些目标 | build-dep-graph动画 | 复用动画；配“改源→需重建目标→无关目标不动”三镜，证据前提先核实，不能把dry-run当全图 |
| S11 I2C | 线电平由谁拉低/释放，采样和控制信号怎么区分 | i2c-timing动画、i2c-bus架构、两张机制图 | 升级可读性；分开电气角色、单字节、事件等待，不能用一张细波形包办全部 |
| F3 调度 | 任务存在、延时、就绪和实际运行不是一件事 | scheduler-structs架构、list-insert动画、位图图 | 图文并排追踪同一任务三次状态，位图图去掉小号密集标签；不混IDF SMP |
| P2 GPIO Matrix | 信号路由与焊盘条件各管一件事 | gpio-matrix-routing动画、pad-attrs手绘 | 复用动画；画“新路线接上≠旧路线拆掉”的前后对照，避开PSRAM/strapping危险实验 |
| AI2 手册对账 | 候选代码、手册位定义、板卡接线、实测是不同证据 | ai-reconcile-loop动画 | 新增证据层级手绘，代码绿灯不能跨越硬件/接线；不复制寄存器位表 |

这些是待审设计，不是已制作的生产图；全书其余图在对应批次逐点审查后确定，不能只为每章凑一张。
