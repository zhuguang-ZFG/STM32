# 创作与分镜

新主题先产出 `design.json`，至少包含：

- `narrative_route`：模型判断默认生活问题路线是否适用，写出 decision、reason、director_review；非默认路线增加 director_plan。
- `topic`、`audience`、`explanation_goal`：观众看完能理解或做出的具体事情。
- `source_scope`：原创主题、用户文章、外部文章改编；来源链接和事实依据。
- `opening_hook`：按[黄金5秒开场](opening-design.md)记录主策略、首句、首帧、关键绘制动作、正文衔接与兑现位置；配音后补实测时间。
- `visual_direction`：人物设定、用色理由、线条/材质、场景与镜头密度。
- `beats`：每段口播、画面中的具体对象、动作、文字、强调位置以及与口播的对应关系。
- `cover`：准确短标题、主视觉和与正文的一致性。
- `asset_prompts`：生成要求、角色参考职责、是否包含文字、图像来源记录。
- `presentation`：**导演密度模式**（不是用户选项）。模型根据受众与内容结构推断，写入 mode + reason：

| mode | 密度 | 适用 | 页策略 |
|---|---|---|---|
| `picture_book` | sparse | 儿童绘本/故事 | 单页少内容，1 个 hero，画完长停 |
| `focus_diagram` | medium | 单概念深挖（默认） | 一主图+关键标注 |
| `dense_infographic` | dense | 知识科普/信息图 | 单页多模块 |
| `accumulating_board` | dense | 黑板报/课堂讲解 | 底板累积，随讲随写 |
| `step_sequence` | medium | 步骤教程 | 一步一焦点 |
| `narrative_comic` | medium | 情绪/品牌叙事 | 分镜格推进 |

```json
"presentation": {
  "mode": "accumulating_board",
  "density": "dense",
  "reason": "成人知识科普，概念需连续板书",
  "page_content_policy": {
    "max_heroes_per_page": 6,
    "max_labels_per_page": 16,
    "board_reuse": true,
    "text_role": "board_labels",
    "hold_after_draw_s": 0.8
  }
}
```

`storyboard.json` 同步写 `presentation`（至少 mode+reason）。`storyboard_lint` 按 mode 调整 `max_hold`、所需视觉数、每镜图片上限、画完停留与笔忙占比。出图 brief 必须带上本 mode 的笔预算与模块/hero 上限。

### 画面丰富度：先确定关系，再分配空间

成人知识内容先判断是否需要对比、分类、因果或步骤；需要时选 `dense_infographic` 或 `accumulating_board`，不要沿用儿童绘本的单物体留白。没有这种结构时仍可用单主体，主体要在播放尺寸下清楚可见。

密集模式每个镜头必须写 `composition`。`focus` 引用主视觉 id；`context` 至少两项，分别说明画面中的具体元素和它帮助讲清的事情。辅助元素可以位于同一幅完整场景图中，不强制拆成更多图片；底纹、花边、重复标题不能充数。模式与 `design.json` 必须一致。

```json
"composition": {
  "layout": "scene",
  "focus": "v01",
  "context": [
    {"visual": "v01", "element": "左侧满篮的果实", "explains": "显示已经投入的采摘劳动"},
    {"visual": "v01", "element": "右侧尚未采摘的果串", "explains": "显示接下来仍可选择的行动"}
  ]
}
```

`layout` 可取 `hero_with_context`、`scene`、`comparison`、`sequence`、`modules`、`accumulating_board`。每项 `visual` 必须引用本镜头计划中的插画/图解，`element` 与 `explains` 不可为空或重复。文字不承担主视觉。输出图片后要实际查看这些关系，字段齐全不代表画对。

空间按整页设计：先留平台界面和字幕区，再摆主体和关系。默认画布是 2:3（1280×1920）；全屏竖屏（9:16）手机信息流顶部约7%是状态栏和标签，底部约20%是账号、描述和音乐，右侧约12.5%是点赞/评论按钮；字幕默认紧贴底部界面之上。`layout_plan.py zones` 给出头部标题区、主图区、辅助区、字幕区的像素范围；`layout_plan.py fit --template hero|hero_with_labels|pair_rows|pair_cols|trio_rows|grid4|list|compare --aspect 宽高比` 按图片比例给出落位，主图通常占安全区宽度的70%以上。draw-v3 的绘制时长跟随图幅而非屏幕（720px 宽的单人场景约10秒），图放大后用 `layout_plan.py probe` 实测最少秒数，不要再靠小图加1.3倍镜头凑尺寸。需要在一页里讲多个对象时，可用大画板：素材按屏幕像素铺满整页，镜头以1.6—2倍逐个推近讲解，最后拉远看全图。单主体用清楚的大图和少量标注；对比共用基线和尺度；步骤用固定方向；板书保持同一页逐项累积。先画出解释当前句子的部分，最后完成背景，避免听完半段才出现关键结果。丰富度服从原有笔数和时间预算，不能通过加速旁白、取消阅读停留或切成揭示模式实现。

构建读取 `work/assets` 的实际像素及摆放坐标，记录 `storyboard.composition.pages`：

- `content_extent_ratio`：排除字幕与底纹后，内容包围范围占字幕上方区域的比例。
- `picture_extent_ratio`：仅插画/图解的包围范围比例；近白或透明留白不算主体。
- `visible_ink_ratio`：可见墨迹比例，仅供诊断；线稿天然较低，不拿它作为审美分数。

图片范围小于 8% 时生产构建失败，先放大主体或补充有讲解作用的场景，再检查绘制与字幕避让。内容范围的模式提醒阈值为绘本22%、单概念32%、密集信息图/板书50%、步骤28%、漫画35%；这些是找出过小布局的启发式提醒，不是画面合格率。刻意表现远景、孤独等留白时，该页所有镜头在 `composition.negative_space_reason` 写明理由，仍需实际看片；声明不会移除报告中的提醒。

测量针对一页完成时的素材坐标，不含镜头运动后的构图，不能代替连续观看；已有的分镜节奏、画完停留、字幕避让和真实逐笔绘制检查继续执行。

### 老师板书：整页先规划，随讲逐项补齐

`accumulating_board` 必须在生图前写 `boards`，每块板至少两个区域，每个区域说明位置、解释作用和承载的 visual。矩形坐标按整页宽高归一化；底部另留字幕带。区域按从上到下、同一行从左到右排列，实际起笔顺序也要相同。

```json
"boards": [{
  "id": "web-tools",
  "purpose": "在同一屏比较网页交互与立体场景",
  "regions": [
    {"id": "interaction", "purpose": "网页按钮如何响应", "box": [0.06, 0.08, 0.94, 0.45], "visuals": ["v-js", "t-js"]},
    {"id": "dimension", "purpose": "网页如何表现立体场景", "box": [0.06, 0.50, 0.94, 0.88], "visuals": ["v-3d", "t-3d"]}
  ]
}]
```

相关镜头写同一 `"board": "web-tools"`，它们的 beat 和 visual_group 必须落在同一张 `job.json.pages[]`。用 `from_beat` 对齐讲解进度；已经画完的区域持续保留，下一句补入下一区域，一组关系讲完整才换页。构建会拦截“名义上同一块板、实际每句话换页”、素材越出已规划区域、绘制顺序跳区等情况。持续增加计划内内容时，同一幅底图可跨越多个 beat 保留，无需重复描画。

图片背景的大片纸边也占分配的宽高。放大框但主体仍很小时，可先规划更紧的 source `crop`；同图的部位多边形、区域图与美术批准裁切必须一起核对，不能在渲染阶段自动裁掉背景或改动语义分区。

绘制顺序以“板书区域 → 语义部位 → 外轮廓/结构/细节 → 同类笔画的上下左右”为层级。它不要求圆形轮廓或每一个像素只能向右下运动；强行让坐标单调会破坏整笔和真实图形。

这些字段记录设计判断，不是要求所有主题使用相同叙事。生活观点可以用具体困境引入；解释机制可以用对照或操作过程；故事保留人物行动与因果；文章改编不能任意删掉条件以换取戏剧性。

**用户给了稿子，就改错不改意。** 只修事实错误、读不顺的句子和口播里听不清的书面语；作者的观点、取舍、举例和有意的简化（科普里“粗略地说”不是错误）都保留。篇幅增长不超过约20%，用户要求扩写时除外。每处实质改动写进 `design.json` 的 `script_changes`（原句、新句、理由），交付时告诉用户改了哪里。

## 分镜：先算预算，再生图

先完成开场判断，再锁定整篇旁白。开头0–5秒按成片计时，包含1秒封面；第一镜的 `purpose` 要说明观众为什么继续看，`visuals` 要让这个理由可见。承载钩子的简单主体或关键关系先画，装饰、长标题和复杂背景后置；镜头可以跨过第5秒继续完成，不必为卡点强制换页。数字承诺、结果或悬念必须映射到后文实际的 beat，不能只写“结尾揭晓”。

长片里模型容易偷懒：素材变少、关键画面被跳过、同一张图连用、每镜都是“口播配一幅慢慢画的图”。分镜因此写成 `storyboard.json`，数量和时间全部由脚本按真实旁白计算，不由模型估算。

1. 主题 → 完整口播稿 → 锁定整篇旁白与时间戳（[连续旁白约定](continuous-narration.md)）。语义可先规划，镜头时间必须在声音锁定后定。
2. 导演设计镜头：每个镜头覆盖连续的 beat，为每句先想几种画法，只留最有表现力的一种；`purpose` 写清这一镜比直接念出这句话多解释了什么。
3. 拆出每个镜头需要的视觉元素 `visuals`。
4. 运行 `python3 scripts/storyboard_lint.py JOB --budget`。脚本给出需要的视觉数 `ceil(旁白秒数 / max_hold × 当前模式 cadence_factor)`、每个视觉可用的绘制秒数和复杂度档位；数量不够时报错并列出最稀疏的镜头，从那里补视觉。
5. 把每个视觉的秒数和档位写进本图美术简报，再写 drawing-plan（含 `identity_cues`）并生图。图按可用时间设计，而不是画完再压缩时间。
6. 写 `job.json`：动作带 `"visual"`；一个镜头通常对应一个跨句的 `visual_group`，`from_beat` 让后一个元素在它那句开始时起笔。
7. 用 `storyboard_lint.py JOB` 和 `plan_status.py JOB` 查剩余工作；`build` 按实际时间线重算并硬性拦截。

```json
{
  "version": 1,
  "presentation": {"mode": "focus_diagram", "reason": "单机制讲解，一主图带标注"},
  "max_hold_seconds": 8,
  "characters": [{"id": "fox", "reference": "inputs/characters/fox.png", "sha256": "参考图实际哈希"}],
  "shots": [
    {"id": "s01", "beats": ["opening", "why"], "type": "scene_with_background",
     "purpose": "雨夜街口让观众先看到困境，再听解释",
     "visuals": [
       {"id": "v01", "kind": "illustration", "subject": "雨夜街口躲雨的小狐狸", "background": "路灯、湿地面", "characters": ["fox"], "weight": 3},
       {"id": "v02", "kind": "text_group", "subject": "两个关键词"}
     ]},
    {"id": "s02", "beats": ["back"], "type": "overview_recap", "callback": "回到开场画面收束",
     "visuals": [{"id": "v09", "kind": "illustration", "subject": "开场狐狸"}, {"id": "v10", "kind": "diagram", "subject": "前后对照箭头"}]}
  ]
}
```

- `shots` 按顺序覆盖全部 beat，每个只出现一次。`kind`：`illustration`、`diagram`（马克笔框线/箭头加文字）、`text_group`。`weight` 同动作权重，只影响预算分配。可选 `source` 记录计划的图片路径，供 `plan_status` 判断是否已生成。
- `type` 及其最低结构：`scene_with_background`（插画声明 background）、`comparison`（≥2 幅插画/图解）、`process_sequence`（≥2 个视觉）、`closeup`（插画）、`key_points`（text_group）、`overview_recap`（≥2 个视觉）、`character_action`（插画中出现已声明角色）。脚本只核对结构，镜头是否真的成立由导演判断。
- `max_hold_seconds` 默认8，可设5–12。`text_only_reason`、`callback` 只在确有理由时填写。

## 脚本计算的预算与门槛

| 检查 | 规则（脚本计算） |
|---|---|
| 视觉节奏 | 每 max_hold 秒内必须有新元素开始绘制；声明 background 的场景图，每个语义部位开始描线也算新元素；报告最长静止段 |
| 复用 | 同一张图（source+crop）连续作为主视觉不超过2个 beat，除非该镜头写 `callback` 理由 |
| 数量 | 视觉数 ≥ ceil(旁白秒数/max_hold × 当前模式 cadence_factor)，其中插画/图解 ≥ 80% |
| 构图多样 | 旁白超过45秒：至少3种镜头类型，任一类型 ≤ 60% 时长 |
| 计划即承诺 | storyboard 中每个视觉都必须被 job.json 绘制；job 中每幅插画都必须在 storyboard 中 |
| 纯文字 | 无插画/图解的镜头 ≤ 20% 时长，否则须写 `text_only_reason` |
| 角色一致 | 声明的角色有锁定哈希的参考图；出现该角色的插画，其 drawing-plan 的 `references` 引用该图 |
| 绘制时间 | build 读取引擎 drawability：窗口 < minimum_seconds 报错；短于视频节奏（插画 max(minimum, required/3)）记录警告 |
| 画完要停 | 插画按约3倍人速画完就停，文字按自然速度的1/1.8写完就停，窗口余下的时间留给观看，不放慢去填满窗口；全片笔在画的时间不超过旁白的70%，超过即报错 |
| 真正的阅读时间 | 单独实测“至少一幅插画/图解画完且没有元素继续绘制”的停留，占旁白至少30%；片头空白和结尾静音不算。任意一幅画完成后到下一元素的停留不足1秒均警告，不用中位数掩盖 |
| 不超预算 | 生产构建拒绝引擎时间压缩、描线超速和上色超速；留不出时间就简化、调整跨句分组，不切换揭示 |

复杂度档位按可用秒数的70%（其余留给观看）、实测约每秒5笔（draw-v3，含抬笔与上色，图幅放大不再按面积变慢）计算：<3秒 只放标签或极小图标（≤14笔）；3–6秒 简单图标/剪影（≤29笔）、平涂；6秒到 max_hold 单一主体（≤40笔）、平涂无纹理线；超过 max_hold 做带背景的场景（声明 background，用部位推进画面）或拆成两个视觉，笔数仍按每秒5笔封顶。参考：《天涯》的桌前人物在 360px 宽最短约7.6秒、放大到 720px 宽约10.7秒（draw-v2 分别为11和20秒）。窗口不够时，简化图，或用 visual_group 跨句延长窗口；不能截短呼吸、拉慢旁白。

宿主无法生成图片时停止并告诉用户，不能静默降级成只有文字的视频。

## 画面如何服务讲解

每幅图必须回答“它比直接显示这句话多解释了什么”。涉及成本，可以画已经消耗的东西与接下来的选择；涉及时间，可以表现同一人物的先后动作。不要仅靠人物站在纸张、灯泡、箭头旁边代表所有抽象概念。部分镜头应带场景和背景，不要每镜都是白底单物体。

标题和短标签承担导航，口播承担完整论述。避免正文把整段字幕再抄一次。页面可以累积多个相关元素，待一个完整意思讲完再转场；图文位置、数量和比例应随内容变化。

**列举、分类、对比用一块板累积。** 讲“几类工具”“三个步骤”“前后对照”时，先画框架（分栏、流程线、坐标），每句在固定位置补一个小图或标签，讲完一整组才转场；回顾时回到这块板圈出重点，而不是重画。每句换一页、重画一幅满版大图，笔几乎一直在画，观众刚看清就被翻走，也会触发上面的70%门槛。

**一眼认得出。** 主体按观众认识它的方式画：葡萄靠一串果和藤叶被认出，一颗放大的烂葡萄会被看成无花果或李子。drawing-plan 的每个 subject 写 `identity_cues`；出图后运行 `python3 scripts/drawing_contract.py JOB --thumbnails`，看编号缩略图（160px、无字幕），1秒内叫不出名字就重画，结论写进 drawing-review 的 `recognizability`。同时看有没有两格读起来是同一幅画（同一图集里换了裁切的相似小图也算）：脚本只能拦同图同裁切的连用，这种重复要模型自己发现，换图或给后一个镜头写 `callback` 理由。

## 生成素材

先完成[画风选择与可绘制约定](style-and-drawing.md)，任何历史案例的画风都不作为新片默认值。

每张图都先读取随包 sweety-image-art-direction 并写本图美术简报，库内模式保留手绘风格的完整配方；独立推理、自定义模式使用已记录的独立风格说明。简报、最终提示词、清理后哈希和实际查看结论一一对应。

人物和道具在出图前就要考虑能否分部位独立描线。设计阶段列出部位顺序和预计笔划复杂度，不能等画完才发现无法分解。模型查看成图后标注实际部位多边形；通常上到下、左到右，例外须在设计里解释。全部轮廓完成后才填色。

先确定一张本片的身份与画风参考，锁定为 storyboard 的 `characters`，再按场景变化动作和道具。人物服装、脸型与线条保持可辨认的一致性。颜色可以围绕主题重新选，不默认复用梨黄叶绿或任何历史人物。

插画适合干净白底或透明背景、可分辨的轮廓与局部色块。密集照片纹理、极细碎线条会放大路径数量和绘制速度问题；需要这种画风时先做代表段，不先批量生成整套。

正文可控文字由运行工具书写；封面AI只生成主视觉和留白，准确标题必须用可核对、可编辑文字图层合成。生成图片中的无用伪文字、相邻图集残片、异常肢体不能靠“渲染成功”跳过。

## 有效的短段验证

先预览成片0–5秒及其后正文，通常看至约15秒；短片看至结尾。分别检查开场是否成立、第一句正文是否承接、承诺是否有实际兑现位置，方法见[黄金5秒开场](opening-design.md)。这段若未覆盖完整插画的描线和上色，另选代表段完成下面的绘制检查，不能只凭开场通过就批量出图。

选择包含完整小意思的一段，而不是仅能证明编码成功的几秒静帧。应看到标题底纹逐渐出现、文字写入、插画轮廓、至少一处颜色跟笔尖变化，以及绘制完成后的阅读停留。若固定笔手的袖子裁切边进入画面，重新设计手臂素材或镜头，不能把裁切边当正常效果。

长片按章节推进：每完成一组镜头运行 `plan_status.py`，按 `next_shot` 继续，不要一次生成全部再回头补。
