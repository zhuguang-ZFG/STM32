## 1. 结构性坑（和油管那轮同类，已踩过一次）

| 坑 | 实测 | 对策 |
|---|---|---|
| 整个应用挂在 `<wujie-app class="wujie_iframe">` 的 shadow root 里 | `shadow 宿主 1`；`document.querySelectorAll('button')` 找「发表」→ 0 个；递归走 `shadowRoot` → 107 个控件 | 任何自写 DOM 查询一律递归穿 `el.shadowRoot` |
| Playwright `locator('button:has-text("发表视频")')` 命中 **0** | 同一时刻能量到该按钮 @1269,485 | 别信"选择器写不出来=元素不存在"；量坐标按中心点投 |

## 6. 封面：为什么另做一版，以及量出来的结论

「编辑封面」对话框里两个真实展示位都是 **204 宽**（个人主页卡片 204x513、分享卡片 204x513）。
1080 缩到 204 是 5.3 倍。现版 `douyin-cover.png` 在这个尺度下只剩 LED 对撞和主标题读得出来，
汇编卡 / 「1 次」那句注释 / kicker / 底部小字全部糊掉——**画面下方约 40% 信息量为零**。
所以那张封面不是不好看，是信息层级只在 1080 大图上成立，一进微信的小卡片就塌。

三张候选（`.temp/wx-run/cand-{A,B,C}.png`）人检后又暴露两个新问题：

1. **B/C 的主标题左半边被裁掉了**。根因是 flex 居中 + 内容比容器宽 = 两侧对称溢出，`body{overflow:hidden}` 吃掉左边。
   1080 大图上肉眼看不出来（字还在，只是少了半笔），缩略图对照表里才现形。
2. A 干净但下方 45% 空着。

终版（`.temp/wx-cover-final.mjs` → `.temp/wx-run/final.png`）不靠肉眼，改成两步：

- 每行文字先用 100px 探针量真实宽度，单行 `nowrap` 下宽度与字号成正比，直接线性反算目标字号 → 结构上不可能溢出；
- 量完再 assert 左右边界（`x < pad-1 || x+w > W-pad+1` 就非零退出）。
  实测落点：`一行代码没改` 162px @64..1016、`灯自己灭了` 178px @103..977、`你的 volatile 白加了` 101.5px @84..996，
  左右安全边距 59px，全部在框内。

三档层级铺满整屏，且这三档在 204 宽都还读得出来：LED 对撞（一眼）→「一行代码没改 / 灯自己灭了」（一句话）→「你的 volatile 白加了」（结论）。
kicker 和底部「本机实跑」在缩略图里读不出来，但它们不再承担信息，所以留着不亏。

换完回读：服务器留下的 `cover-img-vertical` 是 810x1080（3:4），单独截出来看就是新图（`.temp/wx-run/cover-preview.png`）。
**换封面不需要重渲任何成片**——`package.mjs` 的 `ep.cover?.sizes?.[platform]` 那个钩子本来就支持按平台出不同尺寸的封面。

## 7. 读数启发式踩的两个坑（同一条规则的两面）

`.temp/wx-fix.mjs` 为了修「标注」的假绿，改成只读"自有文本叶子节点"（`childNodes` 里 nodeType==3 的部分）。
这条规则在换封面那一轮反过来造了个**假红**：`.input-editor` 的第一个有自有文本的子节点是话题 chip，
于是把完好的三行描述读成了 `"#STM32"`，看着像被清空了。

教训：**"读哪个节点"必须由该节点的结构实测决定，不能有一条通用启发式**。
描述这种"文本 + 内联 chip 混排"的 contenteditable，要读 `innerText`（47 字，三行，逐字对得上发布文档），
而 `.mark-tag-select` 那种"容器包住全部选项"的下拉，恰恰不能用 `textContent`。
两处都再拿截图兜一次底——这一轮就是截图把假红否掉的。

## 10. 发布这一步踩的三处（都是"点了之后怎么知道成没成"）

1. **`[class*=dialog]__title` 不是合法 CSS 选择器**——属性选择器后面直接跟 `__title` 缺组合符。
   脚本已经点完「发表」才崩，等于"动作做了、判据没拿到"。这种半截状态只能靠**只读回查**收敛，
   不能重跑点击。回查结论：页面自己跳到了 `post/list`，列表里那条是 审核中。
   合法写法是 `[class*="dialog__title"]`。
2. **列表卡片不能拿整页 `textContent` 找关键词**——拼进去的先是 `<style>` 里的 CSS 注释，
   信号被噪声淹掉，一度看起来像"发出去但内容不对"。改成按卡片节点逐条量才对。
3. **`复制视频ID` / `复制视频链接` 在未展开时是 0x0 @(0,0)**，入口是行尾那个 20x20 的
   `div.weui-desktop-popover__wrp.more-action`。而且第一版 `grab()` 把第一次量到的坐标数组锁进闭包，
   第二次点的是旧坐标 → 拿回来的"链接"和视频ID一模一样。**同一个函数里每次点击前都要重新量**。
   重量之后真链接才是 `weixin.qq.com/sph/...`。

另外：取 ID 走的是剪贴板（平台只给"复制到剪贴板"）。剪贴板是用户的东西，
脚本先 `Get-Clipboard -Raw` 存盘、跑完用 here-string 写回 `.temp/wx-run/clip-restore.ps1` 还原，
两次运行都还原成功（原内容是 dash.cloudflare.com 那条）。
