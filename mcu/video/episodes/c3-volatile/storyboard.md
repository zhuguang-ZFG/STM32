## 第一幕（0:40–2:30）—— 优化器的世界观

**画面**：`volatile-as-if.svg` 动画第一阶段——"优化器的世界观"。

**旁白**：
"C 标准给编译器发了一张授权书，叫 **as-if rule**——只要程序的可观察行为不变，中间的机器指令随它怎么排。"

**画面**：动画里出现三个小恶魔，分别举着牌子：**缓存**、**删除**、**合并**。

**旁白**：
"于是优化器做三件事：
- **缓存**：你读了三次同一个变量，它只读一次，剩下两次用寄存器里的值；
- **删除**：你写了个值但后面没人读，它直接不写了；
- **合并**：你连续三次 `|=`，它合成一次写进去。"

**画面**：三个小恶魔对"普通内存"竖大拇指，对"硬件寄存器"做 X 手势。

**旁白**：
"对普通内存，这三件事完全正确。但对外设寄存器——你不读它，它也在变；你不写，那次写本身就是目的。优化器不知道这件事。"

**画面**：动画切到第二阶段——"不加 volatile 的下场"。

**旁白**：
"`volatile` 就是把这三项授权收回的合同条款：**每次使用，都必须真实访存**。"

**画面**：字幕卡：**"管三件事：不许缓存、不许删除、不许合并。"**

## 第二幕（2:30–6:00）—— 四个犯罪现场

**旁白**：
"口说无凭，我们看四个犯罪现场。每个现场都摆两份汇编：x86 的，方便你本机 30 秒复现；Cortex-M4 的，才是你板子上真正跑出来的东西。"

### 现场 1：轮询死等（2:50–3:40）

**画面**：左侧源码 `poll_plain`，右侧 `-O2` 汇编。

**旁白**：
"第一段代码，轮询一个状态位等它置位。`-O0` 下，每圈都真的去内存读——这才是 `-O0` 能跑的真相。"

**画面**：高亮汇编里的 `movl g_status(%rip), %eax`。

**旁白**：
"换成 `-O2`——"

**画面**：汇编变成：

```asm
testb  $1, g_status(%rip)   ; 只读这一次
je     .L3
...
.L3: jmp .L3                ; 死转
```

**旁白**：
"它只读了一次。判断依据被缓存了。后来硬件把 bit0 置成 1，代码永远不会知道。`jmp .L3` 是一条指令的紧死循环——板子看起来还活着，SWD 还能连，但这段代码永远不会往下走了。"

**画面**：切到 Cortex-M4 版本，高亮 `b .L3`。

**旁白**：
"M4 上更残酷：`b .L3` 一条指令死转，连内存都不再碰。"

**画面**：切到 `poll_volatile` 的 `-O2` 汇编，高亮每圈一次的 `testb`。

**旁白**：
"加上 volatile，每圈都真的读了。合同生效。"

### 现场 2：延时消失（3:40–4:20）

**画面**：源码 `delay_plain`：`while (n--) {}`。

**旁白**：
"第二段，你写的 500ms 延时。`-O2` 下，整个函数的产物是——"

**画面**：汇编只有一行 `ret`（x86）/ `bx lr`（M4）。

**旁白**：
"一条返回。你的 500ms 变成了 0ms。不是延时不准，是延时**根本没存在过**。"

**画面**：字幕卡：**"C11 标准：没有副作用的空循环，编译器可以假定它不会无限跑。"**

**旁白**：
"标准给了编译器这个权利。没有 volatile，没有 asm，循环体里什么可见的事情都没发生——优化器就当它没跑过。"

### 现场 3：三次写并一次（4:20–4:55）

**画面**：源码三个连续 `reg |= 1; reg |= 2; reg |= 4;`。

**旁白**：
"第三段，你想依次置位三个使能位。普通变量下，x86 直接 `orl $7`，三次读-改-写合成一次；M4 也差不多，整段只访存两次。"

**画面**：切到 volatile 版本，三条独立的 `orl` / 三组 `ldr/orr/str`。

**旁白**：
"加了 volatile，三次就是三次。对外设来说，有的寄存器每写一次就触发一个动作——压 FIFO、启动转换、打脉冲。折叠写入 = 少发了两个动作。"

### 现场 4：volatile 不是锁（4:55–6:00）

**画面**：源码 `isr_toggle`：`shared_flag ^= 1;`。

**旁白**：
"第四段，最危险的一段。中断里翻转一个 volatile 标志。x86 上看起来是一条指令 `xorl`——"

**画面**：高亮 `xorl $1, shared_flag(%rip)`。

**旁白**：
"但一条指令也是读-改-写三步。M4 上更明显——"

**画面**：M4 汇编：`ldr` / `eor` / `str`，三条指令。

**旁白**：
"三条指令，两个间隙。主循环读到旧值，被中断抢占，中断改了值，主循环回来把带旧值的结果写回去——中断的动作就地蒸发。volatile 一个字都没帮你。"

**画面**：字幕卡：**"volatile 保证访存，不保证原子。"**

**旁白**：
"这是本章最容易出事故的一点，待会讲怎么补。"

## 第三幕（6:00–8:30）—— 六变体实验：流行说法是错的

**旁白**：
"网上讲 volatile 的视频，几乎都会说同一句话——"

**画面**：模拟弹幕飘过："去掉 delay 的 volatile，-O2 灯就不闪了"。

**旁白**：
"**这句话是错的。** 至少在我们这份 `00-blink` 代码里是错的。"

**画面**：切到 `00-blink/main.c`，高亮三处 volatile：① 寄存器宏 ② `delay` 参数 ③ `__asm__ volatile ("nop")`。

**旁白**：
"这份代码有三道防线。我们做六个变体，每次去掉一道或几道，看 `-O2` 下 main 函数变成什么样。"

**画面**：六变体表逐行亮起，配合反汇编片段。

| 行 | 旁白要点 |
|---|---|
| **A 现状** | "三道都在，灯闪。" |
| **B 去参数 volatile** | "只去第二道——灯**照闪**。因为 `asm volatile ("nop")` 独立兜底，循环删不掉。这就是网上那个说法翻车的地方。" |
| **C 去参数 + 去 nop** | "连第三道一起去——延时消失，两条 BSRR 写紧挨着，灯不闪。**要复现翻车，得走到这一步。**" |
| **D 只去 nop** | "参数 volatile 还在，计数留在寄存器 r3 里——volatile 保的是'每次使用都可见'，不是'必须占一块内存'。" |
| **F 去宏 volatile** | "最阴的一种：顺序倒了。读 GPIOF_MODER 排到了写 RCC_AHB1ENR 之前——GPIOF 时钟还没开，代码就去读它的寄存器。现象不是'不闪'，是'偶尔配不上 / 换颗芯片就不好使'。" |
| **E 全去** | "main 只剩一条 `b.n 0`——所有外设写被当死 store 删光。全黑。" |

**旁白**（B 行亮起时，语气加重）：
"所以请记住：**本站第一版也照抄了那个流行说法，实测才发现不成立。** 结论要自己跑一遍才敢写——包括本站写的结论。"

**画面**：底部浮现命令：`sh code/c/03-volatile/blink-variants.sh`。

**旁白**：
"这条脚本跑出全部六个变体，你自己试。"

## 第四幕（8:30–10:30）—— 怎么补

**旁白**：
"volatile 不管的那两件事——原子性和顺序性——靠什么补？"

**画面**：三栏卡片逐张翻出：

**卡片 1：原子性 → 临界区 / 原子入口**

**旁白**：
"读-改-写要做对，要么进临界区——关中断、挂起调度；要么用外设侧天生原子的入口。STM32 的 BSRR 写 1 有效、写 0 无影响，压根不需要读-改-写。"

**画面**：BSRR 寄存器示意图，高亮"写 1 置位 / 写 0 无影响"。

**卡片 2：顺序性 → 屏障**

**旁白**：
"两次 volatile 访存之间，编译器仍可能在中间重排其他计算。Cortex-M 用 `DMB/DSB/ISB`，CMSIS 封成了 `__DMB()/__DSB()/__ISB()`。"

**卡片 3：cache → 清理 / 无效化**

**旁白**：
"F407 没有数据 cache，volatile + 屏障基本够用。ESP32-S3 有数据 cache，DMA 共享缓冲还要 cache 清理——光 volatile 会读到旧数据。"

**画面**：切到 CMSIS `GPIO_TypeDef` 源码，高亮每个字段前的 `__IO`。

**旁白**：
"最后，看 CMSIS 怎么把 volatile 写进架构里——`GPIO_TypeDef` 每个字段都带 `__IO`，就是 volatile 的封装。声明一次，整组寄存器都管住。你写 `GPIOF->BSRR = ...` 的时候，根本不用操心限定符。"

**画面**：SPL `I2C_GetFlagStatus` 里两个 `__IO` 局部变量。

**旁白**：
"但 SPL 里这种——两个局部变量也加 `__IO`——它们的值由本函数算出，硬件改不到。**这是'可加而不必加'的 volatile，是性能税。** 看到一个 volatile，先问：'谁会绕过编译器改这块内存？'答得出来是必需，答不出来是税。"

### 旁白语气

- 不要用"让我们来看一下"这种 B 站教程腔
- 用短句，用反问，用停顿
- "流行说法是错的" 这句要**加重语气**，是全片情绪高点
- 汇编不要念指令名，念**含义**（"它只读了一次"而不是"testb 美元符号一"）

### 字幕 / 花字

- 每个"现场"开头用红色大字：**现场 1 / 现场 2 / ...**
- "管登门，不管排队" 做成金句卡，可截图传播
- 六变体表用红/绿两色标注"灯闪 / 灯不闪"

### 配乐建议

- 片头钩子：悬疑感（低频 pad + 心跳）
- 四现场：冷静电子（lo-fi beats 风格）
- "流行说法是错的"：短暂静音 + 一声"叮"
- 收尾：轻快上行

### 封面文案候选

1. **"你的 volatile 白加了"** —— 悬念型
2. **"编译器：你的延时我没收"** —— 拟人型
3. **"-O2 一开，灯就不闪了？"** —— 反转型（配 LED 灭的图）

推荐 1，点击率最高的句式。
