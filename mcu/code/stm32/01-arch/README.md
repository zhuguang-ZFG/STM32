# 01-arch —— S1 位带别名取证

配套章节：[S1 F407 架构总览](../../../docs/stm32/01-arch.md)（位带机制那一小节）。
**不需要开发板，也不需要 make**，只要交叉工具链在 PATH 里。

```bash
sh probe.sh            # 别名地址 + 编译期断言 + 三种写法的反汇编
sh probe.sh bitband    # 同上（就一项）
sh probe.sh clean      # 删掉 build/
```

## 证的是三件事

1. **别名地址是算出来的**：`GPIOF->ODR` 在 `0x4002_1414`（`GPIOF_BASE 0x40021400` + ODR 偏移 `0x14`，两个数都出自 CMSIS `stm32f407xx.h`），PF6 的别名字 = `0x4200_0000 + 0x21414×32 + 6×4 = 0x4242_8298`。同一个字节的 8 个位摊成 `0x4242_8280..0x4242_829C` 共 32 字节。`bb_probe.c` 里三条 `_Static_assert` 替我们验算——算错了连 `.o` 都编不出来。
2. **读-改-写有窗口**：`-O2` 下 `GPIOF->ODR |= 1u<<6` 编成 `ldr r3,[r2,#20]` / `orr.w r3,r3,#64` / `str r3,[r2,#20]`（`&=`、`^=` 换成 `bic`、`eor`，条数一样）。`orr` 用的是 `ldr` 读回来的那份，中间被谁改过它就不知道。
3. **位带与 BSRR 都是单写**：`*0x4242_8298 = 1u` 只剩 `movs r2,#1` + `str.w r2,[r3,#664]`——`664 = 0x298`，加在字面量 `0x4242_8000` 上正是算出来的别名地址；`GPIOF->BSRR = 1u<<6` 是 `movs #64` + `str [r3,#24]`，连"读回来"这一步都没有。

## 工具链口径

xPack GNU Arm Embedded GCC **15.2.1**，`-mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard -O2`。
换版本或换 `-O` 档位，字面量池的装载方式会变（`ldr [pc]` 那条就是取地址常量，不是读寄存器），但"读-改-写三条 vs 单写一条 `str`"这件事不会变。
