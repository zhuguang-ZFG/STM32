## 三、实测流程

### 单次会话模板（3 小时）

```
1. 准备（15min）
   - 检查装备清单
   - 安装驱动（ST-Link、USB-UART）
   - 确认工具链版本（arm-none-eabi-gcc、idf.py）

2. 编译烧录（30min）
   - cd code/<platform>/<project>
   - make / idf.py build
   - make flash / idf.py flash

3. 实测与数据采集（90min）
   - 按实验目标逐项验证
   - 截图/拍照：接线、波形、串口日志
   - 记录实测数据：电流值、频率、占空比、时序图

4. 回填文档（45min）
   - 更新实验 markdown：填入实测数据、截图
   - 修正操作步骤（如有偏差）
   - 补充排错提示（常见坑）

5. 提交 PR（15min）
   - git add <experiment>.md
   - git commit -m "test(<id>): 实测验证，回填数据与截图"
   - frontmatter 改 hardware_status: verified
```

### 优先级排序

**第一批（基础）**：E01 → E02 → E03  
- 目标：验证 GPIO/UART/TIM 三大基础外设  
- 装备门槛最低，30-45min/项

**第二批（通信）**：E04 → E05  
- 目标：验证 I2C/FreeRTOS 同步机制  
- 需要逻辑分析仪，60min/项

**第三批（高级）**：E06 → E07 → E08  
- 目标：验证低功耗/传感器/音频  
- 需要专用模块，60-90min/项

**第四批（综合）**：J1 → J2  
- 目标：验证系统级项目  
- 依赖前序实验经验，120min/项

### 排错提示补充

在"常见坑"后追加：

```markdown
## 实测排错（来自 2026-10-XX 实测）

- **问题**：UART 乱码  
  **原因**：USB-UART 转接器输出 5V，F407 GPIO 容忍但噪声大  
  **解决**：换 3.3V 转接器或加分压电阻

- **问题**：逻辑分析仪抓不到起始位  
  **原因**：采样率太低（1MHz），115200 波特率需 ≥8MHz  
  **解决**：升级采样率或降低波特率到 9600 先验证
```

## 六、风险与缓解

| 风险 | 缓解 |
|---|---|
| 板卡损坏 / 缺货 | 先用仿真器验证代码逻辑，实测延后 |
| 工具链版本不一致 | 锁定版本（arm-none-eabi-gcc 15.2.1、IDF 5.5.2） |
| 实测数据与理论偏差大 | 记录偏差原因（时钟误差、温度、负载），不强行凑数 |
| 时间不足 | 优先完成 E01-E03（基础三件套），其余分批推进 |
