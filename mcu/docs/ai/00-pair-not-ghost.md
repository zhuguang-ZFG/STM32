# A0 为什么把大模型当结对工程师

> 🎯 AI 都能写出能跑的代码了，我为什么还要学寄存器和 RTOS？这个问题值得当面问出来，也值得一个有证据的回答：模型交出的是假设，你手里的手册、原理图与示波器交出的才是判据；它出草稿，你出终审，这是结对工程师与代笔的全部区别。本章立这个工作观，发你一张「能替你做与不能替你做」的清单，画一张只引官方定位的 2026 工具地图，再划清学习阶段与工作阶段两种用法的边界。界面会变，方法论不变。

## 本章精髓

1. **模型给假设，人给判据，终审权在人**。工具官方文档把分工写得比任何警告都直白：你描述结果、评审改动、验证产物；红线句更直白：输出可能不正确甚至含安全漏洞，评审与测试是你的活。结对工程师的意思是它当快手草稿员，你拿手册与原理图当终审法官，审不过的稿子不许进代码库。
2. **能与不能的分界线是你的板子**。写样板代码、解释报错、写测试、起草寄存器代码，它能做，因为这些事的正确性定义在公共知识里；知道你的原理图、替你上板、为你的事故负责、替你做工程取舍，它永远不能，因为这些事的正确性定义在你的硬件与你的责任里。这张清单背下来，比记任何快捷键都值钱。
3. **学习阶段要它解释，工作阶段它出稿你审计**。学习阶段让它代写，等于给「CubeMX 也能点灯，但你学会了什么」这道老答辩题换一个更贵的替身：灯亮了，你没学会。工作阶段反过来用，它量产草稿，你按对账三问终审；审计动作在 A2，工单写法在 A1。

- **能理解**：为什么「AI 会写代码」不构成「你可以不学寄存器」的理由；「模型输出是分布不是事实」的经验含义；四种工具官方定位的分工差异。
- **能用**：背出能/不能清单并在下次提问前自查；按学习、工作两阶段切换用法；各用一条官方定位向同伴说清 Copilot、Claude Code、Cursor、MCP 分别是什么。

## 先跑起来（一致性实验，10 分钟）

打开你手边任意一个代码模型，网页对话框就够用。开三个互不可见的会话（隐身窗口、退出重登、换一台设备都行），把同一句原样各问一遍：

发问之前先押个一致性：同一个问题问三个互不可见的会话，三份答案会全对、全错，还是有对有错？光看语气，你分得出哪份是幻觉吗？押完再动手，这一把量的是你手边这个模型的分布。

> STM32F407 的 GPIOF 挂在哪条总线上？它的时钟使能位在哪个寄存器的哪一位？

标准答案你在 [S2](../stm32/02-rcc-clock.md) 已经学过：GPIOF 挂 AHB1，使能位是 `RCC_AHB1ENR` 的 bit5（GPIOFEN）。判据不用背，查就行：RM0090 §2.3 表 1 的存储器映射写着 GPIOF 基地址 0x40021400 落在 AHB1 外设区段，§7.3 的 RCC 寄存器定义写着 AHB1ENR 的 bit5 是 GPIOFEN。

把三份回答并排，填这张表：

| 会话 | 总线归属 | 寄存器名 | 位号 | 语气 |
|---|---|---|---|---|
| 第 1 次 | | | | |
| 第 2 次 | | | | |
| 第 3 次 | | | | |

两个实验纪律先说清。其一，三个会话必须互不可见：在同一个会话里追问三次，模型会参考自己上一轮的答案，你测到的就不是分布，而是它维护一致性的能力。其二，选题有讲究：好的实验题要满足手册里有唯一正确答案（否则你无法判对错）、语料密度适中（太热的题测不出分布，太冷的题超出能力没有教学价值）。GPIOF 恰好卡在中间：它在全网的点灯教程里出现频率高，但「挂哪条总线」这个问题，错法有足够的想象空间。

实验报告按这个格式存档（进版本控制或实验笔记，下次直接调用）：

| 字段 | 内容 |
|---|---|
| 日期与模型 | 哪天问的、用的哪个模型与版本 |
| 问题原文 | 原样记录，一个字不改 |
| 三份答案 | 总线归属、寄存器名、位号，逐条摘录 |
| 一致性判定 | 全对 / 全错 / 有对有错 |
| 手册判据 | RM0090 §2.3 表 1 + §7.3，标准答案的出处 |
| 结论 | 这次观察到的分布形态 |

三种结果，三种解读：

- **三次全对**：别急着宣布模型可靠。GPIOF 是全书反复使用的例子，语料密度高；换一个你不熟的型号再问三次，比如 F103 的 GPIOA，或者 ESP32-S3 的某个信号该走 GPIO 矩阵还是 IO_MUX 直通（背景在 [P2](../esp32/02-gpio-matrix.md)），再看它的一致性。
- **三次全错**：恭喜，你用手里的一道题抓到了幻觉现场。先别纠正它，把三份答案存档，去 [A2](02-manual-reconciliation.md) 看怎么把这种现场变成对账练习。
- **有对有错**：这是信息量最大的结果。同一个模型、同一个问题、同样自信的语气，答案却不同——你观察到的这个东西叫分布。

为了让你认得出长相，错的那份答案通常是这样的（编造示例，语气还原）：

> GPIOF 挂在 APB1 总线上，时钟使能位是 RCC_APB1ENR 的第 5 位。

工整、笃定、带寄存器名带位号，与标准答案的差别只有 A 和 H 一个字母。这不是它不用心，是它真的分不清：语气从来不由正确性供电，这个结论在 [A4](04-hallucination-defense.md) 还会再收一次利息。

这个实验的产出不是「模型不行」四个字，是本章工作观的经验底座：**模型输出是分布，不是事实**。分布收敛成事实的动作叫对账，全流程在 [A2](02-manual-reconciliation.md)；本章只负责让你在接受这个工作观之前，先亲手摸一次分布。

为什么把实验放在全章最前面？因为工作观靠说服立不住，靠观察立得住。读十篇「AI 会幻觉」的文章，不如亲手抓到一次「同问不同答」。你填的那张表，就是你与结对工程师共事的第一份档案。

## 一、结对工程师，不是代笔

这一章排在整部最前，是因为工作观决定后面所有章节的姿势：提示词怎么写（A1）、对账怎么做（A2）、工具怎么接（A3）、幻觉怎么防（A4），全是同一个工作观在不同工序上的投影。观不正，后面每章的技巧都会用歪成代笔的辅助工具。

先把两个比喻坐实，因为它们决定你接下来用 AI 的全部姿势。

**代笔**的关系是：你出题，它交稿，你照抄。这个关系里没有验证工位，稿子的正确性由交稿者的语气担保。嵌入式世界里语气一文不值：编译器只查语法，不认识你的板子；烧录器只管搬运，不认识你的原理图；能让灯亮的只有「位写对了地方」这一件事——而这件事只有手册、原理图与上板现象说了算。

**结对工程师**的关系是：它出草稿，你出判据；它给假设，你给验证。这个分工不是本书的发明，是工具官方文档自己写的。VS Code 的 agents 文档给了一句可以贴在工位上的分工句：

> For a task that spans files and tools, an agent can find relevant code, make changes, and run checks without you directing each search, edit, and test run. You describe the outcome, review the changes, and verify the result.

前半句是它的活：跨文件找代码、做修改、跑检查，不用你逐步指挥。后半句三个动词，describe、review、verify，主语全是你。

把这三个动词逐个翻译成嵌入式动作。**describe 是下工单**：芯片型号、手册章节号、板卡事实、约束条件写清楚，工单质量决定草稿质量，三段式写法在 A1 展开。**review 是对账**：寄存器名与总线归属对不对、每个位域的值对不对、初始化顺序对不对，三问清单全流程在 [A2](02-manual-reconciliation.md)。**verify 是上板**：烧录、按复位、看灯、量波形，工具链与调试器用法在 [B6](../build/06-flash-debug.md)。

三个动词有一个共同点：它们都要求你手里先有判据。describe 要求你知道自己要什么；review 要求你能查出它错在哪；verify 要求你认得物理世界的证据。没有判据的人用 agent，三个动词全部退化成同一个动作：点头。

同一份文档还给这个工作机制起了名字：

> An agent uses a language model to reason about your request and tools to act on your development environment…This repeated reasoning, action, and validation is the **agent loop**.

推理、行动、验证，循环往复。注意 loop 里的「验证」是机器侧的：跑测试、看编译输出、读 lint 报错。机器侧验证只能证明代码在它触达的环境里表现如何，证明不了位定义与你的板子一致。GPIOF 挂 AHB1 还是 APB1，编译器不报警，测试框架也不知道，这道终审只能在你手里。

把机器侧验证的边界再划细一点。编译器检查的是语法与类型；测试检查的是你写下的断言；lint 检查的是风格与常见坏味道。三样都不认识 RM0090，不认识你的原理图，不认识共阳与共阴的区别。嵌入式代码的错误有一大半活在这三样的盲区里：总线归属错了，编译通过；上下拉配反了，编译通过；把 BSRR 的高 16 位当置位用，编译还是通过。机器侧验证是 agent loop 的内环，你的手册与示波器是外环，外环缺席的内环转得再快也只是在原地空转。

官方对这道终审的表述，一条比一条硬。GitHub 的 Copilot 文档写得一字未曲：

> Both chat and agentic experiences on GitHub.com can produce incorrect or suboptimal code, including code that contains security vulnerabilities. Review and test the output before using it in production.

> Logs do not replace your own review and testing.

VS Code 的 agents 文档把责任主体点得更明：

> You remain responsible for deciding which changes reach your codebase.

三句连起来读：输出可能有错，包括安全漏洞；日志代替不了你的评审与测试；哪些改动进你的代码库，由你负责。这是厂商白纸黑字的文档口径，不是本书的危言。把这些表态当免责套话翻过去，是 AI 时代嵌入式开发者最常踩的认知坑：厂商比你更清楚模型的边界在哪，并且已经告诉你了。

为什么厂商要写这种「自拆台」的红线？因为责任划分必须清晰：工具提供生成能力，你提供正确性担保。这跟示波器厂商在手册里写「测量结果的正确解读由使用者负责」是同一种条款。区别在于，示波器的波形不会自己辩解，模型的输出会：它用流畅的注释与自信的口吻包装每一个假设，包括对的部分与错的部分。语气越自信，红线越重要。

所以「结对工程师」四个字要拆开读：「工程师」描述它的产出能力（读代码、改文件、跑命令），「结对」描述责任形态（终审与责任都在你）。两种关系的对照：

| 维度 | 代笔 | 结对工程师 |
|---|---|---|
| 初稿 | 模型写 | 模型写 |
| 正确性判据 | 模型语气 | 手册 + 原理图 + 上板现象 |
| 验证环节 | 缺失 | 机器侧 agent loop + 人的终审 |
| 出错时排查起点 | 从头怀疑人生 | 对账三问（[A2](02-manual-reconciliation.md)） |
| 事故责任 | 你（盲签） | 你（审过，留了证据） |

代笔关系的结局只有三种，按发生频率排：

1. **运气好**：代码恰好对，灯亮了。你什么都没学到，还强化了「照抄就行」的肌肉记忆，下次赌得更大。
2. **坏得明显**：灯不亮。你没有判据，只能从头怀疑人生：板子坏了？线松了？型号错了？排查没有起点。
3. **坏得隐蔽**：灯亮了，时序错了；功能对了，边界炸了。这种雷不在实验室爆，在凌晨的生产现场爆，排查成本是实验室里的十倍。

结对关系不改变模型出错的概率，改变的是错误的落点：雷在对账台上爆，不在现场爆。

盯住对照表最后一行：无论哪一列，责任都是你。这就是把终审工位建起来的理由：责任逃不掉，能选的只是盲签还是有证据地签。两种签法的差异不在出不出事，在出事之后：盲签的人从零开始怀疑人生，有证据地签的人从对账记录往回倒一层就找到断点。

最后把「结对」的信任结构说准：结对不是不信任模型，是把信任放对地方。信任它的速度、语料广度与不知疲倦；不信任它对任何具体事实的断言，凡是具体事实都回到手册与原理图。也信任官方红线：厂商说输出可能有错，这句话本身是可用的元信息。信任放对地方之后，它犯的每个错都只是流程里的一次普通迭代，不是事故。

还要给比喻划个边界：结对工程师不是人。它不会愧疚，不记得昨天的对话（跨会话记忆要靠机制与文件，A3），更不会为你的 deadline 焦虑。所以与它协作靠流程纪律，不靠人际关系技巧：工单写清楚、判据摆上桌、证据留档案。把对人的期待投射到它身上（「它应该会改」「它应该知道」），是代笔心态的另一种形态。

## 二、能替你做，与不能替你做

这张清单不是凭感觉拍的，它的每一项都来自两类出处：官方文档写明的能力与边界（附录 E 来源卡），以及前面章节里被反复验证的嵌入式事实（总线归属、共阳接法、中断纪律）。清单会随工具进化微调，分界线的逻辑不变。

**能做的四件事**，按可靠度从高到低排：

1. **写样板代码**。工程骨架、Makefile、CMakeLists、CI 配置、.gitignore。这类内容的正确性定义在公共知识里，全网语料密度最高，幻觉率最低。它几十秒交出的骨架，你手敲要半小时，这是结对关系里最划算的一笔交易。
2. **解释报错**。编译错误、链接脚本报错、HardFault 的寄存器现场，它读得比你快，给出的排查方向常常靠谱。两个纪律：报错要贴原文，贴「跑不起来」它只能陪你猜；它的解释仍是假设，成立与否靠你复现。
3. **写测试**。测试用例、边界值枚举、参数化测试骨架，它量产极快且不知疲倦。测试代码本身也有幻觉（编出来的库函数名能以假乱真，类型学在 A4），但测试跑不过这件事会自己报警，自带纠错回路。
4. **起草寄存器代码**。注意「起草」二字。给它芯片型号、手册章节号、板卡事实、明确约束，它能交出结构像样的初始化框架；然后每一个位都要过对账（[A2](02-manual-reconciliation.md)），因为总线归属、位语义、共阳共阴这些「你这块板子」的事实，它一概不知。

能侧四件的共同特征：正确性都可以在「你的板子」之外定义清楚。Makefile 对不对，构建系统说了算；报错解释对不对，复现说了算；测试对不对，跑一遍说了算；寄存器草稿对不对，RM0090 说了算。判据全部外在于你本人的记忆与偏好，所以可以放心让它起草，再由判据收口。

**不能做的四件事**，按危险度从高到低排：

1. **为你的事故负责**。烧错的板子、炸掉的驱动管、误期的交付，责任主体只有你。第一节三句官方红线已经把这件事写得很白，不再重复。
2. **知道你的原理图**。霸道者 F407 的 RGB 灯 PF6/7/8 共阳接 3.3V、低电平点亮，这个事实只活在你的原理图和 [S3](../stm32/03-gpio.md) 的板卡事实表里。模型没见过你的板子，它有的是全网最常见接法的统计印象，而最常见接法未必是你的接法。
3. **替你上板**。烧录、按复位、看灯、量波形、摸芯片温度，物理世界的终审工具在你手里：示波器、逻辑分析仪、万用表。它能读你贴回来的波形描述与日志（怎么让它读得顺，在 A3），但探头只能你去夹。
4. **替你做工程取舍**。功耗与响应速度的权衡、引脚分配与 PCB 布局的妥协、交期与严谨度的平衡。这些决策的输入是你的产品约束与现场条件，它不知道你的约束，给出的「最佳实践」只是统计意义上的常见答案。

不能侧四件的共同特征：正确性定义在物理世界与法律关系里，不在软件能力里。原理图是物理事实，上板是物理动作，责任是法律关系，取舍是你的约束函数。这四样都不随模型升级而改变：下一版模型代码写得更好，它仍然没见过你的板子、夹不了探头、签不了字。不能清单是这张表里最稳定的部分。

四加四的分界线只有一条：**这件事的正确性定义在公共知识里，还是在你的板子与你的责任里**。前者放心让它起草，后者它连入场券都没有。

拿一张真实工单演示拆分。需求：「给霸道者 F407 加一个 UART 命令行，能命令点亮、熄灭 PF6 红灯」。拆给模型的部分：命令行解析的骨架代码、环形缓冲区的测试用例、链接报错的解释。必须自己扛的部分：PF6 共阳低电平点亮这个写进提示词的板卡事实；UART 波特率分频值的复算（手册公式加计算器，模型算术错不罕见）；中断回调里只设标志不办事这条纪律的执行（中断里为什么不调阻塞函数，[F0](../rtos/freertos/00-why-rtos.md) 有完整推导）；最后烧上板看现象。一张工单拆完，模型拿到的是速度与广度，你留下的是判据与责任，这就是分工。

有一个容易误判的中间地带要说透：RM0090 是公共的，谁都能读；但「你的板子怎么用这些位」是你的，全网语料里没有你的原理图。所以寄存器代码落在能侧，却永远带对账条件。RTOS 同理：队列与信号量的语义有官方文档定义，属公共知识；但你的任务优先级怎么排、栈开多大、看门狗超时怎么定，输入是你的产品，它只能给起点，不能给答案。

速查表贴在工位上：

| 任务 | 能不能甩给它 | 附带条件 |
|---|---|---|
| 工程骨架、构建脚本 | 能 | 跑一遍构建再信 |
| 报错解释 | 能 | 贴原文；解释当假设，靠复现确认 |
| 测试用例 | 能 | 测试代码也要审，编的库函数名在 A4 有案底 |
| 寄存器初始化草稿 | 能 | 每一位过对账三问（A2） |
| 原理图相关决策 | 不能 | 它没见过你的板子 |
| 上板烧录与量测 | 不能 | 探头在你手里 |
| 事故责任 | 不能 | 官方红线三句，第一节 |
| 工程取舍 | 不能 | 约束输入在你这里 |

用法很简单：提问之前先看这张表。落在「能」侧的任务，放心甩，甩完按附带条件验收；落在「不能」侧的任务，问它之前先问自己：我是不是在把本该自己扛的判据外包出去？外包判据的瞬间，你就从审计员降级成了盖章员。

自查再简化成三问，提问前过一遍：这件事的正确性谁定义？定义物（手册、原理图、测试、规范）在我手里吗？验收动作我做得起吗？三问都答得上来，甩给它；任何一问卡壳，先补判据再提问。这张三问卡与 A2 的对账三问是同一套方法论的两个侧面：一个管提问前，一个管收货后。

## 三、学习阶段与工作阶段：两种用法

同一个工具，两个阶段，用法相反。混用是新人最容易犯的错：学习阶段用了工作阶段的代写法，工作阶段又用学习阶段的逐字手敲硬扛交付压力。

**学习阶段：要它解释，不要它代写。**

全书 FAQ 里有一条针对 CubeMX 的答辩口径：工作中能用图形化配置工具，学习阶段先手写一遍；理由是工具把引脚复用、时钟分频这些「会出错的决策」藏起来了，你只有先自己错过一次，之后才看得懂它替你做了什么选择。

AI 代写把这个坑放大了两级。CubeMX 生成的代码至少是确定性的：同样的勾选永远生成同样的代码，你可以对着生成结果反推配置逻辑。AI 代写连确定性都没有：同一句提示词三次给三个版本，每个版本配着一本正经的注释。用它代写作业，「你学会了什么」这道答辩题照样答不出，还多一层自欺：我好像看懂了。看懂别人的代码与写出自己的代码之间，隔着的就是亲手错那一次。

学习阶段的正确用法有四种，每一种的产出物都留在你脑子里：

| 角色 | 你怎么用 | 示例提示词 |
|---|---|---|
| 讲解员 | 让它解释概念，再追要不同角度的例子 | 「解释 BSRR 高 16 位为什么是复位，给三个不同角度的例子」 |
| 出题官 | 让它出题考你，你答它批改 | 「出十道 GPIO 位定义填空题，我答完你逐题批改」 |
| 答辩对手 | 让它扮演面试官追问你 | 「追问我：中断里为什么不能调阻塞函数，直到我答不上来」 |
| 错题分析员 | 把你写错的代码给它，只许指疑点不许给答案 | 「指出这段初始化里可疑的三处，不要给正确写法」 |

注意第四种：不给答案是关键。它给了答案，你的排查肌肉就萎缩一次。检验标准朴素：合上聊天窗口，你能把刚学的东西重写一遍、再讲给别人一遍。做不到，说明刚才是它学了一遍，不是你。

「讲解员」用法的一次完整示范，照这个节奏来：

> 你：解释 BSRR 高 16 位为什么是复位，给三个不同角度的例子。
>
> 它：（给出解释与三个例子。）
>
> 你：我用自己的话复述一遍：高 16 位写 1 把对应引脚拉低，因为共阳 LED 低电平点亮，所以「写高 16 位」等于点灯。我复述得对吗？
>
> 它：（确认或纠正你的复述。）
>
> 你：出一道变式题考我：如果 LED 改成共阴接法，BSRR 该怎么写？

同一节奏搬到 RTOS 一样成立：

> 你：解释中断里为什么不能调带超时的队列接收，从调度器的视角讲。
>
> 它：（给出解释。）
>
> 你：我复述：中断上下文没有任务控制块，调度器不知道中断阻塞了该切给谁。对吗？
>
> 你：出题考我：中断里要通知任务处理数据，正确做法有哪些，各适合什么场景？

注意这个节奏里代码一行都没让它写，但每一步都在用你的话重建概念。它输出的是解释，你输出的是理解；理解到位了，代码你自己写得出来，写的过程再卡壳，回 [S3](../stm32/03-gpio.md) 查。

学习阶段还有三种自欺要提防，全是「它学了不是你学了」的变种：

1. **看懂了等于会了**：读它的解释频频点头，合上书一个寄存器名都写不出。检验：能不能默写。
2. **改对了等于懂了**：它指出错误你照改，灯亮了。你学会的是「听它的」，不是「为什么」。检验：换个引脚、换个外设，能不能独立再来一遍。
3. **问过了等于学过**：聊天记录越来越长，脑子里的越来越少。检验：这道题的判据，你能不能讲给没用过 AI 的同伴听。

为什么不能跳级？因为嵌入式知识是层层咬合的：总线归属咬合存储器映射，位语义咬合数据手册，RTOS 纪律咬合中断模型。代写跳过的每一层，都会在后一层的排查现场连本带利讨回来：灯不亮时你连「先查时钟还是先查模式」的顺序都没有，AI 给的五个猜测你只能挨个试。学习阶段的手写不是为了怀旧，是为了让排查时有顺序。

**工作阶段：审计员模式。**

交付压力下分工反过来：它当快手草稿员，你当审计员。草稿员的价值在速度，审计员的价值在判据。你的审计工位上摆三件工具：手册在位（RM0090，位定义可查）、原理图在位（板卡事实可查）、上板现象在位（终审判决可查）。审计动作就是对账三问：名对不对、位对不对、序对不对，全流程在 [A2](02-manual-reconciliation.md)。

审计员模式有两条配套纪律。其一，工单质量决定草稿质量：上下文（芯片型号、手册章节、板卡事实）、约束（资源、时序、风格）、验收（可编译、上板现象、对账动作）三段式写法在 A1 展开；这里只立原则，不给上下文的工单等于让它猜你的板子。其二，审计员必须懂行：不懂总线归属的审计员，看不出 `RCC->APB1ENR |= (1<<5)` 错在哪；不懂 RTOS 的审计员，看不出中断服务函数里那句阻塞调用是死锁配方。这条纪律直接把本章开头那个问题的答案顶了出来，第五节收拢。

一张最小工单长这样（三段式的骨架，完整写法在 A1）：

> 上下文：STM32F407 霸道者板，PF6 红灯共阳接 3.3V，低电平点亮；手册 RM0090 §7.3、§8.4。
>
> 约束：只用裸寄存器，不用 HAL；时钟使能必须第一行；给出每一行的位定义出处。
>
> 验收：我会逐位对账并上板，灯亮且引脚读回低电平才算过。

对照这张工单，回看 [A2](02-manual-reconciliation.md) 里那段自信满满的点灯代码，你会发现雷全是工单没写清的地方爆的：没给板卡事实，它就按最常见接法猜；没要求出处，它的注释就敢写得像查过手册。工单是草稿质量的上限。

审计员模式的标准动作序列，五步成环：

1. **下工单**：三段式提示词交底（A1），上下文给足，约束写死，验收标准列清；
2. **收草稿**：拿到输出先别读注释，注释是它的语气，不是它的证据；
3. **对账**：名、位、序三问逐位过（A2），手册与原理图是唯二判据；
4. **上板**：烧录取证，现象与寄存器读回值留档；
5. **回喂**：把证据句写回对话（实测 + 手册出处 + 板卡事实），让草稿基于证据修正，迭代到闭环。

五步里模型参与第一步与第五步的接收端，中间三步全是你的主场。这个环转熟了，单次迭代从小时级压到分钟级，这就是结对工程师的产出形态：它不替你会，它让你的会转得更快。

两阶段之间有个过渡带，判定标准也给你：当你对某个外设能做到「不看生成结果，自己手写也能点亮」，这个外设就从学习阶段毕业，进入工作阶段的代写区。毕业一门甩一门，永远只在已毕业的领域用审计员模式，在未毕业的领域保持手写生涩但扎实的节奏。全领域的毕业进度，就是你的能力地图。

同一个人的两个下午，对照一下两阶段的差别。学习阶段的下午：目标是搞懂 DMA 循环模式，你让它讲原理、出变式题、批改你的默写，代码你亲手写，写错它只指疑点。工作阶段的下午：目标是交付一个已毕业外设的驱动，你下三段式工单，它出草稿，你按三问对账、上板取证、证据回喂，五步环转到绿。两个下午都用 AI，产出物完全不同：一个产出你脑子里的判据，一个产出仓库里审过的代码。混淆两个下午的用法，是最常见也最隐蔽的浪费。

工作阶段也有三样不甩：架构决策（模块边界与数据流，错一层代价放大十倍）、安全相关代码（官方红线明写输出可能含安全漏洞，这类代码的每一行都要能追溯到你的评审）、量产固件的最终签发（签字的是你）。审计员模式管的是效率，这三样管的是命脉。

## 四、2026 工具地图：三种工位，一条总线

口径先行：本节每条只引官方文档与官方规范的能力描述、规范定义（来源卡与访问日期 2026-10-27 见附录 E），营销话术不引，产品优劣不评。四家文档都在高频改版：VS Code 文档 2026-10-21 刚把 chat 与 agent mode 重组为 Agents 章节，GitHub 的旧 coding-agent 文档页已 301 跳转到新地址。任何写到按钮位置的教程都在倒计时过期，所以这一节只写分工与边界：界面会变，方法论不变。

**Copilot：编辑器里的 agents 体系。** 分工句在第一节引过了：你描述结果、评审改动、验证产物；agent 在 VS Code 内跨文件找代码、做修改、跑检查，工作机制叫 agent loop，推理、行动、验证循环往复。这个机制的雏形早在 2025-02-24 的 agent mode 预览公告里就写明了：它响应编译与 lint 错误、监视终端与测试输出、自动修正并循环直到任务完成。嵌入式可用性有两条官方事实打底：C/C++ 是 VS Code 的一等支持语言，Microsoft 官方 C/C++ 扩展提供 IntelliSense 与调试，Copilot 在 C/C++ 工作流内提供编码建议；Copilot code review 自 2025-04-23 起支持 C/C++，官方 changelog 称覆盖 PR 中逾 90% 的常见文件类型。另有云端形态：Copilot cloud agent 在临时云开发环境里改代码、跑测试与 linter，官方硬限制是单仓库、单分支、每任务一个 PR、每次会话上限 59 分钟。云端跑得了测试跑不了你的板子，59 分钟的会话上限也装不下一次完整的上板排查，这两条限制本身就是「不能替你上板」的官方注脚。

**Claude Code：终端里的 agentic coding 工具。** 官方仓库 README 的定位句（截取能力部分）："an agentic coding tool that lives in your terminal, understands your codebase, edits files, runs commands"。一个引擎四种表面：terminal、IDE 扩展（VS Code、JetBrains）、desktop、web，官方口径是你的 CLAUDE.md、设置与 MCP servers 在四种表面间通用。CLAUDE.md 是放在项目根的 markdown 文件，每个会话启动时读取；官方同时明示它把这类文件当上下文而非强制配置，想硬拦某个动作要用 hooks 这类机制。软约束不是硬门禁，这条分界线 A3、A4 会反复用到。另有一个对嵌入式极顺手的性质：遵循 Unix 哲学、可管道化，`tail -200 app.log | claude -p "分析这段日志"` 是官方文档给出的合法用法；把 app.log 换成串口抓回来的日志，就是 A3 工具流的入口。

**Cursor：整款产品定位成 coding agent。** 官方文档的能力分句：理解你的代码库、规划并构建特性、修 bug、评审改动。Agent 由三构件组成：Instructions（系统提示与规则）、Tools（编辑文件、跑终端命令、浏览器等）、Model；官方明示一个任务内工具调用次数无上限，运行中可以反问澄清、可以排队追加指令。产物管理有一条官方口径值得照抄：Checkpoints 是会话期间的本地代码快照，只用于撤销 Agent 的改动，官方明说永久版本控制请用 Git。agent 产物必须进你自己的版本控制，这条纪律与工具无关。安全口径必须引原文：运行模式分 Auto-review、Allowlist、Run Everything 三档，Auto-review 下白名单内的命令直跑、其余尽量进沙箱、剩下的交后端分类器判断，而 "Auto-review is not a security boundary"，官方明说分类器会犯错。权限闸门不能外包给一个会犯错的分类器，A3 的权限边界一节由此展开。

**MCP：不是工具，是协议。** 最短定义来自 Claude Code 官方文档："The Model Context Protocol (MCP) is an open standard for connecting AI tools to external data sources." 规范侧的事实清单（协议版本 2026-07-28）：消息格式 JSON-RPC 2.0；架构分三方，Hosts 是发起连接的 LLM 应用，Clients 是 host 内的连接器，Servers 是提供上下文与能力的服务；server 向 client 暴露三类原语：Resources（数据）、Prompts（提示模板）、Tools（可执行能力）。安全原则写在规范里：调用任何工具前 host 须获得用户明示同意；工具代表任意代码执行，须谨慎对待。生态口径：官方在册 reference servers 仅 7 个（Everything、Fetch、Filesystem、Git、Memory、Sequential Thinking、Time），官方明示其定位是教学示例而非生产方案，更多服务器走 MCP Registry。治理口径：2025-12，MCP 由 Anthropic 捐赠给 Linux Foundation 下设的 Agentic AI Foundation（2025-12-09 成立），与 Block 的 goose、OpenAI 的 AGENTS.md 同为创始项目。一个协议有了中立治理与官方注册中心，它就更像 USB 口而不是私有排线，这是它进地图的理由。

三类原语用嵌入式的手翻译一遍：Resources 是数据，你的手册 PDF、原理图导出文本、仓库文件都可以作为 Resource 进模型的上下文；Prompts 是提示模板，A1 的三段式工单可以固化成一个 Prompt 原语全组复用；Tools 是可执行能力，跑构建、读串口日志、查寄存器头文件都能包成 Tool。连接拓扑也写在官方架构页里：host 为每个 server 建一个 client，本地 STDIO server 通常只服务一个 client，远程 Streamable HTTP server 通常服务多个。这套拓扑决定了工具权限的颗粒度：每个 server 的能力清单独立授权，A3 讲权限边界时会用到。

四格速览：

| 工具 | 官方定位（一条） | 工位形态 | 核心边界 |
|---|---|---|---|
| Copilot | VS Code agents 体系，agent loop = 推理 → 行动 → 验证 | 编辑器内 + 云端 agent | 输出可能有错，评审与测试是你的活 |
| Claude Code | 住在终端的 agentic coding 工具，一个引擎四种表面 | 终端为主，IDE/desktop/web 同引擎 | CLAUDE.md 是软约束，不是硬门禁 |
| Cursor | 整款产品即 coding agent，Agent = Instructions + Tools + Model | 编辑器即 agent | Auto-review is not a security boundary |
| MCP | 连接 AI 工具与外部数据源的开放协议 | 协议，不是产品 | 7 个 reference servers 是教学示例；工具调用须用户明示同意 |

工位选择按工作形态对号：

| 你的主战场 | 先看哪格 |
|---|---|
| 日常在 VS Code 里写代码，偶尔甩后台任务 | Copilot |
| 日常在终端，日志与脚本要能管道化 | Claude Code |
| 想让编辑器本身就是 agent | Cursor |
| 要让模型读到手册、仓库、串口日志 | MCP（搭配任一工位） |

连起来读：前三格是结对工程师的三种工位，选哪个看你的编辑器与终端习惯；MCP 是它们接外部世界的共用插座标准，手册 PDF、串口日志、构建系统都能经这只插座进模型的手。消费侧怎么用这只插座，在 A3。

地图的用法两条。其一，选型按工作形态不按热度：热度是别人项目的答案，工作形态才是你的问题，每天坐在哪就先看哪格，工位换了再换格，地图跟人走。其二，查证按来源卡不按记忆：本节每个断言都对应附录 E 里的一张来源卡（官方文档 URL + 访问日期 2026-10-27），界面与条款改版时以官方当前文档为准。这一节的时效口径与全书一致：界面会变，方法论不变。

三份互不隶属的官方文档（VS Code agents 文档、GitHub Copilot 文档、Claude Code 仓库 README）措辞指向同一个分工：模型出方案，工具作用于环境，人负责验收。三个来源互相印证，这本身就是本章工作观的外部证据：结对而非代笔，不是本书的口味，是工具提供者自己写下的边界。

这一节刻意不教安装与配置，原因有二。其一，四家界面都在高频改版，安装步骤的保质期按月计，官方文档永远比任何二手教程新。其二，装哪个工具不是本章的决策，怎么用才是：工位可以换，终审工位不能撤。装好之后的第一件事也不是跑起来，是把这个工具的红线条款找出来读一遍，每家的文档里都写着，位置不同，意思相同。

云端与本地也值得分一眼。Copilot cloud agent 这类形态把「改代码、跑测试」搬进了临时云环境，适合边界清晰、验收可自动化的任务；嵌入了上板环节的活留在本地，因为终审工具（烧录器、示波器）接在你的机器上。云的干云的，桌上的干桌上的，分工界限与「能/不能清单」同一条线。

## 五、为什么还要学寄存器和 RTOS

回到本章开头的问题：AI 都能写出能跑的代码了，我为什么还要学寄存器和 RTOS？

现在可以给出完整答案了。**终审需要判据，判据就是寄存器与 RTOS 本身。** 模型交出 `RCC->APB1ENR |= (1<<5)`，编译过、注释工整、语气自信。学过 [S2](../stm32/02-rcc-clock.md) 的人一眼看到 GPIOF 在 AHB1 不在 APB1；学过 [S3](../stm32/03-gpio.md) 的人知道共阳 LED 要低电平点亮，BSRR 该写高 16 位；学过 [F0](../rtos/freertos/00-why-rtos.md) 与调度器原理的人知道中断上下文没有任务控制块，调阻塞函数是死锁配方。这些「一眼」不是天赋，是前面章节一篇一篇攒下的判据。没有判据的审计员，审什么都不成立。

**AI 把「写」的成本打到接近零，反而把「审」的价值抬到最高。** 它生成越快，单位时间堆到你终审工位上的代码越多。软件世界的终审工具是测试与类型系统，嵌入式还要再加三样：手册、原理图、示波器。判据的厚度，就是你在 AI 时代的不可替代性。

看个具体场景。模型给你写了一段 UART 中断服务函数，里面调了一个带超时等待的队列接收，注释写着「等待数据到达后处理」。代码能编译，逻辑读起来通顺，注释甚至很贴心。学过 [F0](../rtos/freertos/00-why-rtos.md) 的人看到这里警报已经响了：中断上下文没有任务控制块，阻塞调用会让调度器不知道该切给谁，结果是死锁或内存损坏。没学过的人看到的是一个贴心的助手帮你处理了等待逻辑。同一段代码，两种读者，两种结局：一个在对账时拦下，一个在凌晨的生产现场追查偶发死机。终审权不是抽象的权力，是这种具体场景里的拦截能力。

判据的库存长什么样，给你一张审计员检查单。寄存器侧：总线归属（§2.3 表 1）、使能位（§7.3）、位定义与偏移（§8.4）、时钟先行。RTOS 侧：中断上下文没有 TCB，不能调阻塞函数；队列传数据副本、信号量传事件通知，选型不同结局不同；任务栈要留水位余量；看门狗超时按最坏执行时间定，不按愿望定。这些条目没有一条是 AI 时代的新知识，全部是前面章节的老功夫。新的是使用场景：它们从「你写代码时的规范」变成了「你审代码时的拦截网」。

还有个更实际的角度：工具换代淘汰的是打字员，留下的是懂行的人。会查手册、会对账、会上板取证的人，模型越强他的产出越大，因为草稿便宜了，终审的吞吐量成了瓶颈。这一部剩下的章节，就是把这套工作观拆成可操作的动作：A1 提示词模式，教你怎么把芯片型号、手册章节、板卡事实写进工单；[A2 手册对账](02-manual-reconciliation.md)，给你终审的三问清单；A3 工具流，教模型自己读手册、跑构建、看串口；A4 幻觉防御，给你幻觉的类型学与决策树；A5 用这本书自己的生产线自证，这套方法是产线不是口号。

判据还有复利。每学透一个外设，你对同类外设的审计速度翻几倍；每排过一次现场，你的提示词里就多一条写给模型的约束。模型每几个月换一版，你的判据只增不减。寄存器与 RTOS 不是 AI 时代的过期知识，是你与模型分工里不可替代的那一半。

## 常见坑

- **把能编译当能烧**：编译器只查语法，不认识你的板子、总线与共阳接法。AI 代码过编译只是拿到对账的入场券，终审在手册与上板，动作见 [A2](02-manual-reconciliation.md)。
- **学习阶段让模型代写**：作业交了，脑子空转，还多一层「我好像会了」的幻觉。FAQ 里 CubeMX 的答辩口径对 AI 同样成立：工作可用，学习先手写。
- **把官方定位句当能力担保**：定位是定位，担保是担保。GitHub 红线写着输出可能有错、含安全漏洞；Cursor 写着 Auto-review is not a security boundary。把定位读成承诺，是新型迷信。
- **不给上下文就信输出**：你的原理图、共阳接法、时序预算，模型一概不知。不给上下文，等于让它猜你的板子，猜错的代价你付。上下文三段式怎么写，在 A1。
- **追着界面记按钮位置**：四家官方文档都在高频改版，2026-10 的界面截图到明年就是考古资料。记分工与边界不过期：界面会变，方法论不变。
- **让模型自己验证自己**：agent loop 里的机器侧验证是内环，只能证明代码在它触达的环境里表现如何。内环全绿不等于外环过关，外环是手册、原理图与上板。
- **实验与对账不留档**：三次一致性实验的答案、对账发现的问题、上板的现象，都是可复用的证据。进版本控制或实验笔记，下次同型号直接调用；不存档等于每次都从零开始认识同一个模型。

## 短自测

五题全答得出，本章才算闭环；答不出的回到对应节复读。

1. 「模型给假设，人给判据」。嵌入式开发里的「判据」具体是哪三样东西？终审权在人的官方出处是哪几句？
<details><summary>看答案</summary>判据三样：手册（RM0090 的位定义，如 §7.3 的 RCC 使能位、§8.4 的 GPIO 位定义）、板卡原理图（共阳共阴、接线）、上板现象（灯亮不亮、波形对不对）。官方出处三句：VS Code agents 文档「You describe the outcome, review the changes, and verify the result.」；GitHub 文档「Review and test the output before using it in production.」与「You remain responsible for deciding which changes reach your codebase」。分工的落点一致：评审与验证是人的活。</details>

2. 能/不能清单各四条是什么？它们的共同分界线是哪一条？
<details><summary>看答案</summary>能：写样板代码、解释报错、写测试、起草寄存器代码（草稿必须过对账）。不能：为你的事故负责、知道你的原理图、替你上板、替你做工程取舍。分界线：这件事的正确性定义在公共知识里，还是在你的板子与你的责任里。中间地带只有一类：手册是公共的，但你的板子怎么用这些位是你的，所以寄存器代码永远落在能侧、永远带对账条件。</details>

3. 学习阶段为什么「要它解释，不要它代写」？用 FAQ 里 CubeMX 的问答说明。
<details><summary>看答案</summary>FAQ 口径：工作中能用 CubeMX 这类图形化工具，学习阶段先手写一遍；工具把会出错的决策藏起来，你先自己错过一次，之后才看得懂它替你做了什么选择。AI 代写把这个坑放大两级：生成结果没有确定性，还配一本正经的注释，让你误以为看懂了。学习阶段四种正确用法：讲解员、出题官、答辩对手、错题分析员，共同点是把产出物留在你的脑子里，检验标准是合上聊天窗能重写、能讲给别人。</details>

4. 各用一条官方定位说清 Copilot、Claude Code、Cursor、MCP 的区别。
<details><summary>看答案</summary>Copilot：VS Code agents 体系内的结对者，机制是 agent loop（推理 → 行动 → 验证循环）。Claude Code：官方 README 定位「住在终端的 agentic coding 工具，理解代码库、编辑文件、运行命令」，一个引擎覆盖 terminal / IDE / desktop / web 四种表面，CLAUDE.md 启动读取。Cursor：整款产品定位 coding agent，Agent = Instructions + Tools + Model，官方明示 Auto-review is not a security boundary。MCP：不是工具是协议，连接 AI 工具与外部数据源的开放标准，JSON-RPC 2.0，Hosts/Clients/Servers 三方，Resources/Prompts/Tools 三类原语，协议版本 2026-07-28。</details>

5. 「GPIOF 挂哪条总线」三次实验的结论是什么？为什么说结论不是「模型不行」？
<details><summary>看答案</summary>结论：模型输出是分布，不是事实。同一模型、同一问题、不同会话，答案可能不一致，而每份答案的语气一样自信。这不是「模型不行」：它对最常见写法的拟合近乎完美，但 GPIOF 这类事实恰好落在幻觉高发区，全网示例里 APB 总线出现频率高，总线归属张冠李戴的概率不低（A2 第一节有实锤案例）。分布是这类工具的性质而非缺陷；把分布收敛成事实的动作叫对账，在 A2。</details>
