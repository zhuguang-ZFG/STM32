# A2 手册对账：模型写的寄存器代码，逐位验证给它看

> 🎯 模型三十秒生成的 GPIO 初始化，过编译、长得像教科书、注释写得比你工整——烧进板子，灯不亮。它错在哪一位？你手里有一样它永远没有的东西：RM0090。这一章教你把「AI 生成的代码」从结论降级为假设，再用手册逐位对账，最后上板终审。对账不是不信任模型，是给模型装上游标卡尺。

## 本章精髓

1. **模型输出是假设，不是事实**。它对「最常见写法」的拟合近乎完美，对「你这块板子的具体接法」一无所知：总线归属、上下拉语境、共阳共阴，全是它可以一本正经编错的地方。验证的对象不是模型，是手册的位定义表。
2. **对账三问：名对不对、位对不对、序对不对**。寄存器名与总线归属查 §7.3 时钟树与存储器映射；位域值查 §8.4 寄存器位定义表；初始化顺序查「时钟先行」这条铁律。三问全过，代码才配烧上板。
3. **闭环的最后一环是回喂**。上板现象（灯亮不亮、示波器有没有波形）要回到提示词里，让模型基于证据修正，而不是基于你的吐槽修正。「实测：BSRR 高 16 位是复位」比「你写错了」对模型的校正效率高一个数量级。

- **能理解**：为什么过编译是最弱的一种「正确」；模型幻觉在寄存器层面的四种常见形态；对账的依据永远是手册章节号而不是模型自信程度。
- **能用**：拿到任意一段 AI 生成的寄存器初始化代码，按三问清单逐位对账，把发现的问题改写成可回喂的证据句。

## 一、一个真实的幻觉

模型对这道点灯题的回答，十次里有八次长这样（注释是它自己加的，雷也是它自己埋的）：

```c
/* 点亮 PF6 上的 LED */
void led_init(void)
{
    /* 1. 使能 GPIOF 时钟（GPIOF 挂在 APB1 总线上） */
    RCC->APB1ENR |= (1UL << 5);          /* 雷 1：总线归属 */

    /* 2. PF6 推挽输出 */
    GPIOF->MODER   |= (1UL << 12);       /* 模式：输出 */
    GPIOF->OTYPER  |= (1UL << 6);        /* 雷 2：开漏 */
    GPIOF->OSPEEDR |= (3UL << 12);       /* 100MHz */

    /* 3. 拉高 PF6 点亮 LED */
    GPIOF->BSRR = (1UL << 6);            /* 雷 3：位语义 */
}
```

编译一把过。逐行读，每一行都像教科书。问题在哪？四个，一个比一个隐蔽：

| 雷 | 模型写的内容 | 实际正确口径 | 幻觉类别 |
|---|---|---|---|
| 1 | `RCC->APB1ENR \|= (1<<5)`，注释「GPIOF 挂在 APB1」 | GPIOF 挂在 **AHB1**，`RCC->AHB1ENR` bit5（GPIOFEN） | **总线归属幻觉**：编造一条似是而非的总线分配 |
| 2 | `OTYPER \|= (1<<6)`，输出类型开漏 | 共阳 LED 需要低电平拉电流点亮，必须是**推挽输出**（OTYPER=0） | **硬件语境幻觉**：无视「共阳接 3.3V」这一接线事实 |
| 3 | `BSRR = (1<<6)` 置位 | 共阳 LED **低电平点亮**：要拉低该置 BSRR 高 16 位的复位位（`(1UL << (6+16))`），或者写 ODR；置位反而熄灭 | **位语义幻觉**：BSRR 高 16 位复位 / 低 16 位置位的规则张冠李戴 |
| 4 | （前面三颗之外）三行寄存器操作的隐含顺序 | 模型这段恰好顺序没错，但它有相当概率把「配 MODER」写在「开时钟」前面 | **顺序幻觉**：违反「时钟永远先于一切」铁律（[S3](../stm32/03-gpio.md) 原话） |

注意一个共同点：这四颗雷**没有一颗能被编译器抓到**。编译器不认识你的板子，不认识共阳共阴，不认识 AHB1 和 APB1 哪条总线上挂着 GPIOF。过编译只证明语法合法，不证明任何一个位写对了地方。这就是为什么对账的对象是手册，不是编译器，也不是模型的语气。

那模型为什么错得这么「像」？因为它学的是全网的代码与文本，而全网关于点灯的示例里，APB1 出现得极其频繁（USART/SPI/I2C 都在 APB 上），OTYPER=1 的开漏写法在 I2C 场景里天天见，BSRR 低 16 位置位是 90% 教程的写法。模型给你的是「最常见写法」，不是「你的板子的正确写法」。这个区别，就是对章存在的全部理由。

## 二、对账工具箱

对账只需要三样东西：手册、板卡事实、一张表。

**手册怎么查**。RM0090 的 §2.3 管「哪个外设挂哪条总线」，§7.3 管「时钟使能位是哪个」，§8.4 管「每个寄存器每一位是什么」。查总线归属看 §2.3 的存储器映射（表 1）；查使能位看 §7.3 的 RCC 寄存器定义；查位定义看 §8.4 的寄存器位表：MODER 偏移 0x00、OTYPER 0x04、OSPEEDR 0x08、PUPDR 0x0C、IDR 0x10、ODR 0x14、BSRR 0x18、LCKR 0x1C、AFRL 0x20、AFRH 0x24。这张偏移表在 [S3](../stm32/03-gpio.md) 已经抄过一遍，对账时直接搬。

**板卡事实从哪来**。原理图。霸道者的 PF6 红灯共阳接 3.3V。这个事实模型不知道，手册也不知道，它只活在你的原理图和 [S3](../stm32/03-gpio.md) 的板卡事实表里。对账永远发生在「手册」与「板卡事实」的交叉点上：手册说 BSRR 高 16 位写 1 会把引脚拉低，板卡事实说拉低才亮，两个一拼，模型那句 `BSRR = (1<<6)` 的死刑判决书就写好了。

**表怎么填**。三问清单，一行一行来，不许跳：

| # | 对账项 | 查哪里 | 判据 |
|---|---|---|---|
| 1 | 寄存器名与总线归属 | RM0090 §2.3 + §7.3 | 基地址落在哪条总线（§2.3 表 1），使能位就在哪条总线的 ENR（§7.3） |
| 2 | 位域值 | RM0090 §8.4 位定义表 | 每个写进去的数值能对回某几位的定义，无一位悬空 |
| 3 | 初始化顺序 | 手册时序图 + 「时钟先行」铁律 | 先使能时钟，再碰外设寄存器 |
| 4 | 硬件语境 | 板卡原理图 | 电平极性、上下拉、开漏推挽，与接线一致 |

## 三、逐位对账实操

拿第一节那段代码，把表填完：

**对账项 1：总线归属**。查 §2.3 存储器映射：GPIOF 基地址 0x40021400，落在 AHB1 区段（AHB1 外设从 0x40020000 起）。结论：使能位在 `RCC->AHB1ENR`，§7.3 的 RCC 寄存器定义里 bit5 是 GPIOFEN。模型写的 `APB1ENR |= (1<<5)` 双重错误：总线错了，而且 APB1ENR bit5 是 TIM7EN，等于顺手打开了定时器 7 的时钟：一颗雷炸出两处伤。改法：`RCC->AHB1ENR |= (1UL << 5);`。

**对账项 2：位域值**。逐寄存器过：

| 寄存器 | 模型写的 | §8.4 定义 | 判定 |
|---|---|---|---|
| MODER | `(1<<12)` | MODER6 = bits 13:12，01 = 通用输出 | ✓ 值对（输出模式） |
| OTYPER | `(1<<6)` | bit6=1 开漏；共阳 LED 需推挽（=0） | ✗ 雷 2，删掉这行 |
| OSPEEDR | `(3<<12)` | OSPEEDR6 = bits 13:12，11 = 100MHz | ✓ 值合法（点灯其实 2MHz 足够，但不算错） |
| BSRR | `(1<<6)` | 低 16 位置位输出高；高 16 位（bit22）复位输出低 | ✗ 雷 3，共阳要低电平，改 `(1UL << 22)` |

**对账项 3：顺序**。这段代码恰好先开时钟再配 MODER，顺序这颗雷没爆。但对账不能赌运气。把顺序显式写进你的检查习惯：任何外设初始化，第一行使能时钟，这是 [S3](../stm32/03-gpio.md) 说的「新手第一大坑，没有之一」，模型踩中的概率不低。

**对账项 4：硬件语境**。原理图：PF6 红灯共阳。推导链：共阳 → LED 另一端接 3.3V → 引脚输出低电平才有电流 → 推挽 + 拉低。模型不知道这条链，你必须替它知道。

四问全过，修正版才三行：

```c
RCC->AHB1ENR   |= (1UL << 5);    /* GPIOFEN：AHB1，bit5 */
GPIOF->MODER   |= (1UL << 12);   /* PF6 通用输出 */
GPIOF->BSRR     = (1UL << 22);   /* 高 16 位：PF6 输出低，共阳 LED 点亮 */
```

从模型自信满满的七行注释，到对账后的三行。中间消失的部分，就是幻觉的体积。

## 四、上板终审与证据回喂

对账全过，才配烧上板。烧。灯亮，闭环完成一半；灯不亮，回到第三节，必有一问你填得太快。

终审的意义不只是「亮没亮」。拿示波器或者最简单的串口打印，确认你看到的亮是推挽拉低的亮（引脚电平 0V 附近），而不是某个悬空引脚被恰好接通的假象。一次上板，三个产出：现象（亮/不亮）、证据（波形/寄存器读回值）、修正后的代码。

然后是最值钱的一步：**回喂**。把证据句写进下一轮提示词，不是写情绪句：

| 回喂句 | 模型能学到什么 |
|---|---|
| 「你写错了，灯不亮」 | 几乎什么都学不到，只会道歉 |
| 「实测：GPIOF 挂在 AHB1 不是 APB1，RM0090 §7.3 存储器映射 0x40021400 属 AHB1 区段；APB1ENR bit5 是 TIM7EN」 | 总线归属这条，本轮记住 |
| 「实测：BSRR 高 16 位写 1 复位引脚输出低，低 16 位写 1 置位输出高；本板 LED 共阳需低电平」 | 位语义 + 硬件语境，本轮记住 |

补一个现场细节：喂进证据句之后，它的下一轮多半以「您说得对」开头。这四个字出现得再诚恳，也担保不了下一轮的正确率：道歉是它的文体，不是它的修正动作。账对没对，仍然只认 §7.3 与 §8.4。

回喂的格式就是证据三元组：**实测 + 手册出处 + 板卡事实**。这跟你在 [S3](../stm32/03-gpio.md) 学寄存器时的取证习惯是同一套——对账不是 AI 时代的新发明，是这本书从头到尾的方法论，只是现在多了一个会犯错的结对对象。

## 五、对账的边界：哪些逐位、哪些抽样

逐位对账很费人。全部代码逐位对，你很快就弃坑。按风险分级：

| 代码层 | 对账强度 | 理由 |
|---|---|---|
| 时钟使能（RCC 各 ENR） | **永远逐位** | 总线归属是模型幻觉第一名，错了编译不报错、上板没反应，排查成本最高 |
| 模式/类型/上下拉寄存器（MODER/OTYPER/PUPDR） | **永远逐位** | 与板卡接线强相关，模型永远不知道你的原理图 |
| 数据路径寄存器（ODR/BSRR/DR） | 逐位 + 上板现象 | 位语义幻觉高发（高 16 位/低 16 位、MSB/LSB） |
| 时序参数（波特率分频、定时器 PSC/ARR） | 逐位 + 计算复算 | 模型算术错不罕见，拿计算器重算一遍 |
| 应用层逻辑（状态机、协议解析） | 抽样 + 单测 | 幻觉密度低，测试比手册快 |
| 纯软件算法（滤波、CRC） | 单测对拍 | 有现成数学定义，不需要手册 |

分界线只有一条：**这段代码的「正确性」定义在手册里，就逐位；定义在数学或测试里，就用计算和单测**。前者是嵌入式独有的对账，后者是普通软件工程的老本行。

## 记忆锚点

::: tip 一句话记住
**模型输出是假设：名对没对查 §7.3，位对没对查 §8.4，序对没对时钟先行；板卡接线是你的领地；上板拿证据，回喂写三元组。**
:::

**延伸**：弱提示与强提示的对照实录在 A1 提示词模式；让模型自己读手册跑构建的工具流在 A3 工具流；幻觉的完整类型学与防御决策树在 A4 幻觉防御。

## 常见坑

- **拿编译通过当对账通过**：编译器不认识你的板子，也不认识 AHB1 和 APB1 的区别。过编译是最弱的一种正确。
- **对账对到一半信了你自己的记忆**：使能位是 bit5 还是 bit6，OTYPER 偏移 0x04 还是 0x0C？手边没手册就别对账，凭记忆的对账只是两个人一起幻觉。
- **回喂只喂情绪不喂证据**：「不对」「错了」「再试试」对模型是零信息。证据三元组：实测现象、手册章节号、板卡接线。
- **对账粒度一把梭**：应用层代码逐位对到地老天荒。按第五节的分级表分配力气，RCC 和模式寄存器才是逐位区。
- **忘了顺序也是审计项**：模型把 MODER 写在使能时钟前面，对账清单如果只查「位」不查「序」，这颗雷就漏了。

## 短自测

1. 模型的点灯代码 `RCC->APB1ENR |= (1<<5)` 错在哪两处？查 RM0090 §2.3 与 §7.3 说明你的判据。
<details><summary>看答案</summary>两处错。其一，GPIOF 挂在 AHB1 总线，使能位在 RCC->AHB1ENR 的 bit5（GPIOFEN），不在 APB1ENR；其二，APB1ENR 的 bit5 是 TIM7EN，这句代码顺手打开了定时器 7 的时钟。判据：§2.3 存储器映射（表 1），GPIOF 基地址 0x40021400 落在 AHB1 外设区段（0x40020000 起）；§7.3 RCC 寄存器定义，AHB1ENR bit5 标注 GPIOFEN、APB1ENR bit5 标注 TIM7EN。总线归属错了编译器不报错，这是必须逐位对账的原因。</details>

2. 共阳 LED 接 PF6，为什么 `GPIOF->BSRR = (1<<6)` 点不亮？正确的写法是什么？
<details><summary>看答案</summary>BSRR 低 16 位写 1 把对应引脚置为输出高，高 16 位写 1 置为输出低（BSRR 偏移 0x18，§8.4）。共阳 LED 的阳极接 3.3V，引脚输出低电平才有电流流过，输出高反而两端等电位熄灭。所以正确写法是写高 16 位：`GPIOF->BSRR = (1UL << (6 + 16))`，即 bit22；或者写 ODR 对应位为 0。模型 90% 的教程学来的是「置位点亮」，那对共阴或低电平有效的电路成立，对你的板子不成立：这就是硬件语境幻觉。</details>

3. 对账三问是哪三问？各自查手册的哪个位置？
<details><summary>看答案</summary>名对不对：寄存器名与总线归属，查 §2.3 的存储器映射（基地址落哪条总线）与 §7.3 的 RCC 寄存器定义（使能位在哪条 ENR）。位对不对：每个写进代码的数值对回位定义表，查 §8.4（以及各外设章节的寄存器说明），不许有一位悬空。序对不对：初始化顺序，查手册时序要求加「时钟永远先于一切」铁律：先使能时钟，再配置外设寄存器。</details>

4. 为什么「你写错了」对模型的校正价值几乎为零？合格回喂句的三元组是什么？
<details><summary>看答案</summary>模型从「你写错了」里只能得到一个布尔值：错。它不知道是总线错、位错还是顺序错，更不知道正确口径，下一轮只能换一个猜法。合格回喂句的三元组：实测现象（灯不亮/引脚读回高/波形无翻转）、手册出处（RM0090 §2.3 存储器映射：0x40021400 属 AHB1 区段）、板卡接线（PF6 红灯共阳）。三元组给了模型一条可验证的更正链，本轮对话内它就能收敛。</details>

5. 按第五节分级表，HAL 库的 GPIO 时钟使能函数 `__HAL_RCC_GPIOF_CLK_ENABLE()` 内部那一行，要不要逐位对账？
<details><summary>看答案</summary>要。凡是你代码路径上经过的时钟使能，无论裸寄存器还是库函数，都属「永远逐位」级：总线归属错了，库函数也救不了你（虽然 HAL 的总线归属是对的，但读一遍它的实现，就是对 RCC->AHB1ENR bit5 的封装，把「名对不对」这问闭环，成本一行）。分级表按代码层不按写法层：库函数只是封装，不降低时钟使能的风险等级。</details>
