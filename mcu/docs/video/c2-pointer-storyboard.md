## 第一幕（0:40–3:00）—— 指针的值是地址

**画面**：`pointer-address.svg` 动画——内存格子，每个格子 1 字节，地址从 0x40021400 开始编号。

**旁白**：
"指针的值，就是地址。0x40021418 是一个门牌号，指向 GPIOF 的 BSRR 寄存器。"

**画面**：动画里一个小人拿着门牌号，走到对应的内存格子前。

**旁白**：
"但问题来了——这个门牌号后面，是 1 字节、2 字节、还是 4 字节？"

**画面**：三个小人分别拿着 uint8_t*、uint16_t*、uint32_t*，站在同一个地址前。

**旁白**：
"指针的类型，决定每次读写的字节宽度。uint8_t* 读 1 字节，uint16_t* 读 2 字节，uint32_t* 读 4 字节。"

**画面**：三个小人分别用不同大小的勺子，从同一个格子里舀出不同大小的数据。

**旁白**：
"这就是为什么寄存器必须用 uint32_t*——硬件要求 32 位访问，你用 8 位，硬件不理你。"

**[取证环节]**

**画面**：切到终端，`gcc -O0 -S` 编译三段代码，分别用 uint8_t*、uint16_t*、uint32_t* 写同一个地址。

**旁白**：
"我们用 gcc -S 看汇编——uint8_t* 生成 STRB（Store Byte），uint16_t* 生成 STRH（Store Half-word），uint32_t* 生成 STR（Store Register）。"

**画面**：三段汇编并排显示，STRB/STRH/STR 用不同颜色高亮。

**旁白**：
"宽度错了，指令就错了。这就是'指针类型决定宽度'的铁律。"

## 第二幕（3:00–5:30）—— 指针运算的步长

**画面**：`pointer-arithmetic.svg` 动画——数组格子，p 指向第 0 个元素。

**旁白**：
"指针运算的步长，由类型决定。p+1 对 uint32_t* 是 +4 字节，对 uint8_t* 是 +1 字节。"

**画面**：动画里 p+1 的箭头，uint32_t* 跳过 4 个格子，uint8_t* 跳过 1 个格子。

**旁白**：
"这就是为什么'寄存器数组'能用结构体或数组索引访问——GPIOF 的寄存器从 0x40021400 开始，MODER 在 +0x00，OTYPER 在 +0x04，BSRR 在 +0x18。"

**画面**：动画展示 GPIOF 寄存器地图，每个寄存器占 4 字节，地址依次递增。

**旁白**：
"所以 `((uint32_t*)0x40021400)[6]` 就是 BSRR——基址 + 6×4 = 0x40021418。"

**[取证环节]**

**画面**：切到终端，`gcc -O0 -S` 编译两段代码：一段用指针偏移，一段用数组索引。

**旁白**：
"我们看汇编——两段代码生成的指令一模一样。数组索引只是指针偏移的语法糖。"

**画面**：两段汇编并排显示，完全相同。

**旁白**：
"这就是 C 语言的设计哲学——数组和指针，本质上是同一件事。"

## 第三幕（5:30–8:00）—— const 和 volatile 的纪律

**画面**：`pointer-qualifiers.svg` 动画——两个锁，一个锁目标（const 在 * 左边），一个锁指针（const 在 * 右边）。

**旁白**：
"const 在 * 左边，锁目标——`const uint32_t *p` 表示 p 指向的内容不能改。"

**画面**：动画里 p 可以移动，但 p 指向的格子被锁住，写操作被拒绝。

**旁白**：
"const 在 * 右边，锁指针——`uint32_t * const p` 表示 p 本身不能改，但 p 指向的内容可以改。"

**画面**：动画里 p 被锁住，不能移动，但 p 指向的格子可以写。

**旁白**：
"驱动里满街都是 `volatile uint32_t * const`——指针本身不能改（const），但每次使用都必须真实访存（volatile）。"

**画面**：代码示例：`#define GPIOF_BSRR (*(volatile uint32_t * const)0x40021418)`

**旁白**：
"volatile 告诉编译器：别替我偷懒，每次都去读硬件。const 告诉编译器：这个指针不能改，别让我到处找。"

**[取证环节]**

**画面**：切到终端，`gcc -O2 -S` 编译两段代码：一段不加 volatile，一段加 volatile。

**旁白**：
"我们看汇编——不加 volatile，编译器把三次读优化成一次；加了 volatile，三次读就是三次 LDR。"

**画面**：两段汇编并排显示，左边 1 个 LDR，右边 3 个 LDR。

**旁白**：
"这就是 volatile 的作用——收回编译器优化的授权。"

## 第四幕（8:00–10:00）—— 点灯公式全拆解

**画面**：回到片头的点灯公式，逐 token 拆解。

**旁白**：
"现在我们把点灯公式拆一遍——`*(volatile uint32_t *)0x40021418 = 1UL << 22`。"

**画面**：代码逐 token 高亮，每个 token 飞到对应的盒子里。

**旁白**：
"0x40021418：门牌号，GPIOF_BSRR 的地址。"

**画面**：门牌号盒子。

**旁白**：
"(volatile uint32_t *)：把门牌号转换成'32 位宽度、每次都真实访存'的钥匙。"

**画面**：钥匙盒子，上面写着"32 位"和"volatile"。

**旁白**：
"*：用这把钥匙，打开门牌号对应的格子。"

**画面**：开门动作。

**旁白**：
"1UL << 22：把第 22 位置 1，对应 BSRR 的 BR6（复位 PF6）。"

**画面**：数据盒子，二进制 0000...0100...0000，第 22 位是 1。

**旁白**：
"=：把数据写进格子。"

**画面**：数据飞进格子。

**旁白**：
"这就是点灯公式的全部秘密——一个门牌号、一把钥匙、一个数据、一次写入。"
