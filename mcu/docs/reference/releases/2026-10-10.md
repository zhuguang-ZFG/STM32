## 内容与事实

- **三批次收尾**：STM32 外设（S6–S11）、FreeRTOS 内核（F4–F7）、ESP32-S3 驱动（P 篇）三批任务验收关闭；ESP32-S3 矩阵在 CI 共 11 个构建（含 faults 变体）全绿。
- **HAL 逐行对照**：[S2](../../stm32/02-rcc-clock) / [S6](../../stm32/06-tim) / [S7](../../stm32/07-usart) / [S8](../../stm32/08-dma) 四章末尾沿用初稿的"上游 SPL/HAL：待补"清账——基于 ST 官方仓库 `STMicroelectronics/stm32f4xx_hal_driver @ 1f6451c` 的对照表，每条结论带源文件行号锚点。**SPL 诚实标缺**：StdPeriph 未随 ST 官方 GitHub 分发，位定义落点保持 RM0090。
- **一处事实修复**：[S7](../../stm32/07-usart) 正文把接收流写成 `dma1_stream5_rx_init / DMA1 Stream5`，与工程源码和 [S8](../../stm32/08-dma) 的总线分工（USART1 在 APB2 → DMA2）矛盾——已按源码改为 `dma2_stream5_rx_init / DMA2 Stream5 Channel4` 并回链 S8。
- **工程卫生**：三个 ESP32 教学工程入库的 `sdkconfig` 是本机陈旧生成物（target=esp32，与 `sdkconfig.defaults` 的 esp32s3 冲突，克隆后直接构建会报 target 不一致），解除跟踪并更新忽略规则，从此一律由构建再生。
