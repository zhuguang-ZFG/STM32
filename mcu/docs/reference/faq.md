# 常见问题 FAQ

> 🎯 这些问题在评论区、私信里被问了几十遍，答案都一样。集中写在这里，省得每个人重新走一遍弯路。

## 起步

### 我该买哪块板子？

只有一块预算：**野火 STM32F407 霸天虎**，站点 S 篇与 RTOS 移植全部按它写，资料最多、引脚全引出、调试接口标准。做语音/AIoT 才选 **立创·实战派 ESP32-S3**。两块都想买的话，先 STM32 后 ESP32：裸机地基打在前者更牢。清单与别花冤枉钱的配件见 [实物装备清单](/guide/hardware.md)。

### 没有数电/模电基础，能学吗？

能，但别硬撑。你需要的是"看得懂原理图、知道上下拉和上电顺序"这一档，不是会设计滤波器。缺的这部分在本站靠两处补：[手册地图](/guide/manuals.md) 教你查资料，[实验中心](/lab/index.md) 让你在板子上看到现象。

### SPL、HAL、寄存器，到底学哪个？

顺序是**寄存器 → 库**。先在寄存器层把一个外设的"配置寄存器 + 数据寄存器 + 状态寄存器"三件套走通，再回头看库把它封成了什么；本站每章的"库源码解析"就是这个对照。反过来先学 HAL，你会卡在"CubeMX 生成的代码为什么这样写"，而那是没有答案的问题。详见 [S15 SPL 库解剖](/stm32/15-spl-anatomy.md)。

### 能用 CubeMX / 图形化配置工具吗？

工作中能用，学习阶段先手写一遍。理由很实际：工具把引脚复用、时钟分频这些"会出错的决策"藏起来了，你只有先自己错过一次，之后才看得懂它替你做了什么选择。

## 环境

### Windows 够用吗？

够。本站全部工程在 Windows 上构建验证（工具链 + VSCode/命令行）。ESP-IDF 走官方安装器，注意路径不要带中文与空格。步骤在 [S0 环境搭建](/stm32/00-env.md) 与 [P0 环境搭建](/esp32/00-env.md)。

### 没有示波器/逻辑分析仪能做实验吗？

E01/E02/E05 用串口打印或 LED 就能验；E03/E06/E07/E08 需要仪器（示波器、毫安级电流测量）。不必一次买齐：先做不需要仪器的实验，等需要看波形时再补；预算顺序在 [实物装备清单](/guide/hardware.md) 里标了。

### 板子到手第一件事做什么？

点灯，而且要**知道自己在往哪个地址写什么**。（[实验 E01](/lab/e01-blink.md)）

## 学习路线

### 学到什么程度算入门？

三条检验：① 换一个没玩过的芯片，只看手册能在两小时内把 USART 收发跑起来；② 程序跑飞时，你有排查顺序而不只是重烧一遍；③ 能向别人讲清"中断里为什么不能调用阻塞函数"。这三条分别对应 S 篇、B4/S16、F 篇。

### FreeRTOS 和 RT-Thread 先学哪个？

先 FreeRTOS——内核小、能一行行读完，读完你就懂"RTOS 到底做了什么"。之后 RT-Thread 的重点变成设备框架与组件生态，那是另一套问题。对照结论在 [双实现对照](/rtos/compare/00-side-by-side.md) 与 [选型决策树](/rtos/compare/01-choose.md)。

### 为什么 C 篇要放在最前面？

因为指针、`volatile`、栈帧这三样不补上，后面每一章的"库源码解析"都会变成玄学。见 [C0 为什么嵌入式 C 是另一种 C](/c/00-c-in-mcu.md)。

### 章节显示"建设中"，还值得读吗？

骨架页的**结构、学习目标、先修关系、常见坑**已经写完，可以当提纲用；正文、动画与工程还没补齐。首页地图实心=成稿、虚线=建设中，数字由脚本全站统计，不会骗你。

## 内容与协作

### 数字和事实怎么保证不出错？

寄存器地址、引脚号必须有出处，写不出就标"以某手册某节为准"，禁止编数值；核对过的数值要有第二来源（CMSIS 头文件/官方手册）。这条纪律写在 [贡献指南](https://github.com/zhuguang-ZFG/mcu/blob/main/CONTRIBUTING.md)，未回填的坑也都在页面上明说。

### 发现错误怎么办？

开 Issue 或直接在每页右下角"在 GitHub 上编辑此页"提 PR。勘误是本项目的正式贡献类型，不是打扰。

### 可以转载/商用吗？

内容是 [Apache-2.0](https://github.com/zhuguang-ZFG/mcu/blob/main/LICENSE)，引用的上游源码遵守各自许可证且已注明出处；实物照片与图表请勿单独摘走。

### 为什么这个项目参考"通往AGI之路"？

学它的**开源、体系化、面向初学者**，但不学它把深度让渡给广度：这里每一个知识点都要追到寄存器、追到源码、追到示波器上的波形。说明见 [关于我们与致谢](/reference/about.md)。

## 技术细节

### 为什么寄存器地址都是 0x4002xxxx 这种？

ARM Cortex-M 把外设编进内存地址空间（MMIO），0x4002xxxx 是 AHB/APB 总线外设的区域。读一个地址就是读一个寄存器，不是访问内存。详见 [C1 内存模型](/c/01-memory-model.md)。

### volatile 到底保什么？

只保"每次读写都真实访存"，不保原子性、不保顺序。多个 volatile 变量之间的操作顺序，编译器仍可能重排。需要顺序用 `__DSB()`/`__DMB()`，需要原子用中断保护或 RTOS 互斥量。详见 [C3 volatile](/c/03-volatile.md)。

### 为什么中断里不能调用阻塞函数？

阻塞函数（如 vTaskDelay、xQueueReceive 带超时）会让出 CPU 等事件。中断上下文没有任务控制块（TCB），调度器不知道"中断阻塞了该切到谁"，结果要么是死锁、要么是内存损坏。中断里只做"记账"（设标志、发通知），办事交给任务。详见 [F0 为什么需要 RTOS](/rtos/freertos/00-why-rtos.md)。

### FreeRTOS 的队列和信号量有什么区别？

队列传数据副本（你塞进去 4 字节，接收端拿到的是拷贝），信号量传事件通知（二值信号量=1 个令牌，计数信号量=N 个令牌）。队列适合"生产者-消费者"数据流，信号量适合"事件发生"同步。详见 [F4 队列](/rtos/freertos/04-queue.md) 和 [F5 信号量与互斥量](/rtos/freertos/05-sem-mutex.md)。

### 为什么看门狗不能无限加长？

看门狗超时时间应该覆盖"最坏情况下的任务执行时间"，而不是"我希望它多久复位一次"。无限加长等于放弃了故障检测能力。正确做法是分析任务期限预算，让看门狗超时略大于最坏执行时间。详见 [S17 看门狗](/stm32/17-watchdog-reset.md) 和 [P13 健康监督](/esp32/13-watchdog-health.md)。

### I2C 上拉电阻怎么选？

标准模式（100kHz）通常 4.7kΩ，快速模式（400kHz）用 2.2kΩ。电阻太小功耗大、电平低；太大上升沿慢、通信失败。具体值要看总线电容和器件手册。详见 [S11 I2C](/stm32/11-i2c.md)。

### SPI 模式 0/1/2/3 怎么记？

CPOL=0 表示空闲时 SCK 低电平，CPOL=1 表示空闲时高电平；CPHA=0 表示第一边沿采样，CPHA=1 表示第二边沿采样。模式 0（CPOL=0, CPHA=0）最常用，但传感器可能用模式 3。**以传感器手册为准，不要假设**。详见 [S12 SPI](/stm32/12-spi.md)。

### 为什么 DMA 配置错了"看起来正常"？

DMA 搬的是字节数，不是"语义"。如果你配错了方向（外设到内存 vs 内存到外设）或数据宽度（8 位 vs 16 位），DMA 仍会默默搬完，只是搬错了内容。肉眼看不出区别，必须用示波器或逻辑分析仪验证。详见 [S8 DMA](/stm32/08-dma.md)。

### RTOS 任务栈多大合适？

太小会溢出（HardFault 或数据损坏），太大会浪费 RAM。经验值：简单任务 256 字节，带 printf 的任务 512 字节，复杂任务 1024 字节。用 FreeRTOS 的 `uxTaskGetStackHighWaterMark()` 查剩余量，留 20% 余量。详见 [F1 任务与 TCB](/rtos/freertos/01-task-tcb.md)。

### 为什么 ESP32 的 ISR 要放 IRAM？

ESP32 的代码默认从 Flash 执行，靠 Cache 加速。但某些操作（如 Flash 写入）会关闭 Cache，此时如果 ISR 在 Flash 里就会取指失败。把 ISR 放进 IRAM（指令 RAM）保证 Cache 关闭时仍能执行。详见 [P4 中断与双核](/esp32/04-irq-dualcore.md)。
