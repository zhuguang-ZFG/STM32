# 01 · 项目总览与架构

## 1.1 项目定位

《通往单片机之路》是一个**内容型开源仓库**：以"把一颗芯片讲透"为目标，产出三类交付物——

1. **在线教学站点**（VitePress，`docs/` → GitHub Pages，base 为 `/mcu/`）
2. **整书离线版**（`mcu-book/` → 单文件 HTML + A4 PDF，随站点发布在 `/mcu/book/`）
3. **机制动画与视频**（`docs/public/anim/` 110 张 SMIL 动画；`video/` 产线产出 B站/抖音/知乎/小红书成片）

围绕这三类交付物，仓库内置了一套**脚本化质量闸门**（`scripts/`）和**与章节同构的示例工程**（`code/`，47 个），保证"页面上的每个数字都可复跑、每行代码都有出处"。

## 1.3 五大子系统

| 子系统 | 目录 | 技术栈 | 交付物 |
|---|---|---|---|
| 教学站点 | `docs/` + `docs/.vitepress/` | VitePress 1.6 / Vue 3 / markdown-it 定制管线 | GitHub Pages 静态站 |
| 示例工程 | `code/` | ARM GCC / ESP-IDF / 宿主 GCC + Makefile/probe.sh | 可编译固件与取证输出 |
| 质量闸门 | `scripts/` + `tests/` | Node ESM + node:test + Playwright | 构建期/CI 检查报告 |
| 整书离线版 | `mcu-book/` | Python 3 + Playwright + paged.js | 单文件 HTML、A4 PDF |
| 视频产线 | `video/` | Node ESM + puppeteer + ffmpeg + TTS | mp4 成片、封面、发布包 |

## 1.4 内容生产的三条数据流

**站点流**：`docs/**/*.md`（章节 frontmatter 含 `status/difficulty/minutes`）+ `docs/public/anim/*.svg` → `gen-progress.mjs` 预扫描生成 `progress.json/updates.json` → VitePress 构建期把 `![…](/anim/x.svg)` 内联为 `<AnimFigure>` 组件 → `docs/.vitepress/dist`。

**整书流**：`mcu-book/manifest.json`（11 分部 / 94 章罗盘）+ 章节 md + 动画 SVG + `mcu-book/book/` 附录 → `build_html.py` 把站点方言（`<AnimFigure>`、`<QuizBank>`、Mermaid 等）转换为静态 HTML → `build_print.py` 用 Playwright + paged.js 分页输出 A4 PDF。

**视频流**：`video/research/<id>-factsheet.md + <id>-numbers.json`（事实底稿）→ `video/episodes/<id>/episode.json`（分集 spec）→ 六阶段产线 → `video/out/<id>/<platform>/` 成片 → `video/publish/` 投稿四平台。

## 1.5 质量哲学（理解本仓库的关键）

1. **数字不手写**：章节数 / 动画数 / 工程数 / 阅读时长全部由脚本扫描产出，README 进度块、首页学习地图、贡献指南同源；`readme:check` 在漂移时报错。
2. **闸门即契约**：`npm run quality` 串起 15+ 道检查（死链、动画规范、元数据、导航、SEO、性能预算、无障碍、搜索、页面完整性），任何一道失败都阻止构建发布。
3. **事实纪律**：寄存器地址/引脚号必须有出处（RM0090/datasheet），未实测现象一律标「待上板实测」；`docs/` 下禁止出现 `TODO/待补充/placeholder`。
4. **禁占位**：骨架章节可以「建设中」，但 frontmatter 元数据必须完整合法（`docs:gen` 校验）。
5. **规范可执行**：`.trellis/spec/docs-site/` 的写作/动画规范尽量落成可执行检查（如 `anim-lint` 检查 SMIL 槽位、色板映射、dur 整除、指示点出界）。

## 1.6 Trellis 管理体系

仓库由 Trellis 管理 AI 协作开发（`AGENTS.md` 入口）：

- `.trellis/workflow.md` — 三阶段工作流（Plan → Execute → Finish），任务创建需用户同意；
- `.trellis/spec/` — 四层编码规范：`docs-site/`（站点内容）、`firmware-stm32/`、`firmware-esp32/`、`video/`（产线）+ `guides/`（跨包指南）；
- `.trellis/tasks/` — 任务档案（`prd.md` / `design.md` / `implement.md` + jsonl 上下文清单）；
- `.trellis/workspace/` — 开发者会话日志（journal）。

关键脚本：`python3 .trellis/scripts/task.py`（任务生命周期）、`get_context.py`（上下文查询）。
