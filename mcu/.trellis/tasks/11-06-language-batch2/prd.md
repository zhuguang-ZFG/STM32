# 第二批语言通俗化：B1 与 B2 阅读入口

## 目标

延续用户接受的B0试点方法，改善“会运行命令但看不懂产物”的阅读障碍。B1串起四步构建，B2明确ELF阅读问题与术语；本批限定两篇中已诊断的散文段落，不全章重写，不扩展全书。

## 背景与当前证据

- 用户接受B0并同意创建第二批任务进入规划；本轮尚未批准具体实施范围。
- 当前原文指标：B1共75句，长句2.7%、均长30.5；B2共143句，长句8.4%、均长32.2。数字来自本轮调用既有metrics，不以长句少证明通俗易懂。
- B1 `docs/build/01-four-steps.md:27-40,58,74-79,140,159-171` 在命令输出、工具分工、目标文件与链接术语之间切换，需要明确“在看哪一步、哪个文件、哪列信息”。
- B2 `docs/build/02-elf.md:16-17,31-48,131-136` 在抽屉/装车/住址/货架等比喻间切换，初学者易把运行地址、文件位置和用途混在一起。
- C0已抽查，不纳本批：越界/硬件保护与C语义存在事实审查风险，不能借语言改写改变适用范围。
- 当前B0未提交稿及11-02用户改动保留，不归档或重写旧任务；GitNexus无mcu索引，不能运行本项目context/impact或据此断言无影响。

## 需求

- R1（B1）：按输入/输出文件解释四步及gcc调度，把名词放在可观察对象之后；现有命令、错误文本与数据不变。
- R2（B2）：说明读ELF要回答什么问题，再解释原有术语；对Addr/Off/Size/Type/Flg的散文明确每列要看什么，不改表格、地址和技术含义。
- R3：保留frontmatter、标题锚点、围栏代码、源码include、行内代码序列、表格行、链接/图片/组件目标、数字事实。保护工具使用严格双文件模式，不改为additions规避失败。
- R4：仅编辑design.md界定的段落；事实疑点原样冻结并登记。若解释改善必须修事实，停止该段，不强行改写或扩大范围。
- R5：不改B0、C0、其他章节、固件、印前程序、测试、runner、策略、阈值或`.prose-baseline.json`。不自动提交、发布或下载依赖。
- R6：同类动作两次失败后记录已否证假设并换证据；认证权限问题只用授权解决。纯措辞工作无需新增永久测试。

## 验收标准

- AC1/R1：B1候选给出至少两组有原句证据的改写；读者能定位四步各自的输出、gcc与内部工具的区别、链接阶段为什么需要定义，不新增未经核实结论。
- AC2/R2：B2候选给出至少两组改写；原有阅读问题与列名的解释可定位，不再只依赖另一套比喻理解术语。
- AC3/R3：两章逐一通过原文与候选、原文与落盘正文的严格prose_guard；源码include、Vue组件/HTML块显式保留。既有prose与reading检查通过，无基线更新。
- AC4/R4-R5：正文改动仅两章的允许段落，疑点未被强化；B0及保护输入哈希不变。`book:check`与`docs:build`按最终版本执行，结果和未验证项分列。
- AC5：实际预览检查两页桌面/手机正文、图、动画、代码和折叠答案；目标页面HTTP可达不能冒充鼠标导航通过。任务保持待文字验收，不自动扩展。
- AC6：具体规划经用户审阅后才task.py start。涉及代码时必须task_verify；即使本批仅正文也调用并如实报告operator检查覆盖，缺检查不算成功。
