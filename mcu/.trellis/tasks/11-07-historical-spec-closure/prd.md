# 全部历史 spec 统筹收口

## 目标与授权

用户要求继续完成所有spec计划，明确选择“统筹全部历史spec任务”，并同意创建总任务进入规划。范围为创建前22个未归档task.json，不把本总任务算作第23个原需求。目标是让每项原承诺有可执行下一动作、唯一责任、真实完成检查和授权边界，避免重复实施已存在产物或用旧勾选伪造完成。

本轮仅规划与只读核验，不启动生产实施，不重挂原父子关系，不归档、提交或发布原任务。新总任务保持planning；原22项状态作为历史字段，不等于验收结论。

## 已确认事实

- 创建时原任务9项planning、13项in_progress，其中5项缺design/implement、9项context为seed、社媒任务引用不存在的video/research/wx-plan.md；本轮复核时22项均已有prd/design/implement与真实context，wx-plan已指向video/publish/wx-plan.md，仅10-28仍余两处旧skill路径失效（随本任务规划补齐）。
- 全书当前manifest为94章、11部、7附录；历史88章/6附录、11或12门口径不能直接作为当前验收范围或降低原13项印前合同。
- 四个B0/B1/B2/B7候选与当前正文逐字节一致；其文字接受、发布/PDF等不同任务的条件仍须分别核实。
- 印前任务原承诺PDF和EPUB3；当前EPUB构建器/检查器/npm入口均不存在。不能静默删掉EPUB需求，亦不在纯规划回合假装补完。
- E04当前四臂实测表为空；没有目标板证据，禁止用模型时间填表。18集正片配置均formatVersion=2，另有c3b变体，但配置/旧台账不证明母版、听感或线上替换已验收。
- 三个受托只读审计被watchdog报stale，proc核对后已取消并保存read历史；未交付有效综合，不计为审阅通过。

## 需求

- R1 无漏项：22项原任务逐一记录原需求锚点、静态产物、历史宣称、当前窄验、未满足AC、下一动作/完成检查、依赖、权限和规划缺口。
- R2 不缩水：EPUB、OSS新增工程、四平台、四臂实测、全书逐点知识等原承诺不以“已存在部分资产”代替。历史口径与当前合同冲突单列决策，不静默重写原PRD。
- R3 单一实施归属：正文只按获批批次实施一次，精修/趣味/深度各保留自己的验收维度；PDF/下载物、硬件和平台操作分别有唯一执行者。总任务只做跨项追踪，不覆写原父子结构。
- R4 计划可执行：补齐5项缺失design/implement和9项seed上下文，修复实证失效路径；其余原计划保留并有逐项收口卡，注明不能照跑的旧步骤。
- R5 证据分级：文件存在、哈希一致、历史记录、本回合运行、读者/视觉接受、硬件和线上结果分别记录；缺检查不算通过，不将status或checkbox当完成证明。
- R6 保全与权限：固定本轮214验证输入、42用户文件、101书稿源和原任务既有修改；新测试/runner/policy仍需review与新用户回合基线。无认证/平台权限、无识别设备或无可写授权只走合法解决，不旁路。
- R7 明确后续门：规划完成后交审执行顺序；外部发布/删除、逐条合集写入、烧录、测试策略、提交分组保持具体授权，不能从“统筹所有”推导全部放行。

## 验收

- AC1→R1：原22项与台账集合完全相等；每项至少一条原PRD验收锚点及可观察完成检查，未核实项明确标识。
- AC2→R2/R3：覆盖PDF+EPUB、OSS P1–P4、18正片横竖/平台替换、AI工具四平台、E04四臂、全书101源等承诺；依赖无环，重叠文件有唯一执行路由，原责任关系不变。
- AC3→R4：22项均有prd/design/implement及真实存在的implement/check上下文；task.py validate全部通过，不改原需求和状态来制造完成。
- AC4→R5：本轮窄运行原样记录passed/failed/unverified；候选对正文哈希、已有保护门和renderer回归按实际输出，不复用checkpoint测试记忆。
- AC5→R6：生产源/214输入/42用户成员及内容与本轮起点相同；原任务只允许获授权规划文件新增或上下文修订，原PRD/task状态不变。
- AC6→R7：总任务三文档、22项收口卡、依赖/授权计划和验证报告齐备，明确本轮规划完成与全部历史交付尚未完成的区别。

## 非目标

本轮不改生产正文/图/代码，不补造测试或operator基线，不动用户素材，不联系平台发布或删除，不操作串口与板卡，不构建覆盖既有视频或发布PDF下载包，不替用户做审美/文字接受决定。
