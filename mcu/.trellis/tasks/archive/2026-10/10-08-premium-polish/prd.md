# 精品化四维打磨：看得懂·找得到·学得下去·有兴趣

## 目标与授权

用户要求把 D:\Users\mcu（「通往单片机之路」VitePress 教程站）做成**精品项目**，并给出四个验收维度：**看得懂、找得到、学得下去、有兴趣钻研**。用户选择「全量四维打磨」范围，要求分批交付、每批可独立验收（2026-10-08）。

本任务负责**站点层面的阅读体验与可发现性**；内容深度补全（事实纠错、前置章节、双板可靠性、综合项目实体工程）已由既有父任务 `.trellis/tasks/10-07-knowledge-closure` 及其四个子任务规划，本任务**不重复其范围**，仅在交叉处对接（见「与既有任务的关系」）。

## 已确认事实（本轮评估，基线 76b619b）

- 站点结构成熟：78 章成稿、55 动画、34 工程、CI 三道闸门、严格元数据、数字由脚本产出。
- **找得到有硬伤**：`docs/.vitepress/config.mts` 的 GD32 侧边栏只列了 10 章中的 1 章（导览 + G1）；`G0/G2/G3/G4/V0-V4` 共 **9 章不在任何 nav/sidebar 链接中**。用脚本对照全站 93 条 nav/sidebar 链接与 103 个页面文件，**唯一缺口就是这 9 个**，其它板块齐全。这违反本项目自己的规范「sidebar 按板块分组全量列出」（`.trellis/spec/docs-site/structure.md`）。
- **无自动化导航可达性检查**：`scripts/` 与 `tests/` 中没有任何 sidebar/nav 校验，此类漏洞会静默复发。
- **学得下去有断头路**：README 路线图（mermaid）终点为 `H[综合项目]`，`docs/esp32/12-audio-path.md` 也承诺「综合项目（小智类终端）」，但**全站不存在「综合项目」页面**。
- **有兴趣最大缺口（本任务不可解）**：8 个实验全部 `hardware_status=pending`，「上板验证 0 项」；需要真实板卡与仪器，AI 无法代替。
- 既有规划：`knowledge-closure` 父任务（planning）含 fact-corrections / prerequisites / reliability / capstone 四子任务，其中 capstone 即综合项目实体工程。

## 与既有任务的关系

- **不重叠**：本任务只做导航、可达性闸门、结构一致性、落地页；不改写章节技术结论、不新增前置章、不实现双板固件。
- **对接点**：R5 的综合项目落地页引用 `knowledge-capstone` 的规划范围；实体工程由该任务交付，本任务只保证「导航与承诺一致」。

## 验收标准

- **A1 / R1+R2**：导航可达性脚本零缺口；`npm run quality` 全绿；反例测试（人为移除一条 sidebar 链接）能让闸门失败。
- **A2 / R3**：各板块 index 路线表与 sidebar 逐条一致，无「有页面无入口」或「有入口无页面」。
- **A3 / R4**：一致性审计报告落盘（`research/` 或任务目录），缺项已修正或登记为已知项。
- **A4 / R5**：综合项目页可访问、`docs:build` 死链零错误、roadmap 不再指向不存在页面。
- **A5 / R6**：各导览页钩子/下一步齐全。
- **A6**：最终 `npm run quality` 通过后按 Trellis 3.4 分批提交。

- 不伪造上板实测；不把 CI 通过当作硬件验证。
