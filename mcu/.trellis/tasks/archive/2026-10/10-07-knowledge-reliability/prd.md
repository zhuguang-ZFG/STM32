# 看门狗与串口协议工程

## 目标与已确认范围

让学习者在 STM32F407 与 ESP32-S3 上用同一主机工具收发可靠串口帧，区分通信错误、传感器失联与任务卡死，为后续双板记录器提供经过边界验证的公共机制。

2026-10-07 用户同意“接续已有任务并完善规划”。复用本任务，保留父任务确定的双板完整范围；本轮交付需求、设计、执行计划及研究依据，审阅后再实施。父任务为 knowledge-closure。

## 背景与依赖

- knowledge-fact-corrections 与 knowledge-prerequisites 均已完成，提供 DMA/时间/同步修复和 16 篇前置教材。
- 基线提交为 314fe33；本轮实际通过 27 项单元测试、28 个工程清单检查。新增可靠性工程尚未实现，这些结果不代表其编译或上板结果。
- F407 使用寄存器级外设、FreeRTOS-Kernel V11.1.0；S3 使用立创实战派 N16R8、ESP-IDF v5.5.2，两套内核配置独立。
- 原 UART 教材仍有帧边界冲突：docs/stm32/07-usart.md:143 与 :209、docs/esp32/05-uart-driver.md:168、code/stm32/03-uart-dma/README.md:11。本批须在原位置修正，不能只在新章补说明。

## 验收标准

- **W-A1 / 三端一致**：CRC/COBS 固定向量，C 与独立 Python 实现双向交叉验证；不以同一实现自编自解代替。两平台 INFO/STATUS 都由同一 CLI 解析。
- **W-A2 / 输入边界**：负载 0/1/64/65 字节、全部单切分点、连续帧、空分隔符、噪声、截断/非法编码、坏 CRC/version/length、丢字节、超长帧均有断言。超时前/等于/超过阈值、uint32 时间回绕、16 位序号回绕可复现。说明何时需要额外同步分隔符，不承诺噪声后的第一帧必然保留。Linux sanitizer 检查生产 C 逻辑。
- **W-A3 / 背压**：DMA 积压、UART 已报告错误、自有 RX/响应队列满、消费者延迟均有计数与恢复；发帧有序，不混文本、不无限阻塞。事件丢失后能周期查询继续取数据；不宣称能精确计数每次物理丢字节。模型与真实驱动验证分开记录。
- **W-A4 / 健康**：全员进展、从未启动、宽限边界、单任务超时、时间回绕、非法配置/ID、传感器失败但循环继续、STOP/通信空闲、任务恢复、监督任务停止都有测试。首次确认超时后停止喂狗，迟到进展不得撤销重启决定。S3 显式配置超时 panic/reset，不能以默认警告当作复位。
- **W-A5 / 工程教材**：公共宿主、两板协议、两板健康监测共五个工程登记真实入口。F407 IWDG/WWDG 与默认/故障构建、S3 正常/故障构建实际编译；C8/S17/P13 进入课程规划、导航、导览和生成统计；旧文冲突清除，站点与浏览器检查通过。实验放在三篇教程中，本批不新增 E 编号、不改变旧实验完成状态。
- **W-A6 / 可复现工具**：CLI 支持显式端口、查询/命令、日志保存、离线异常帧回归、有限响应等待和序号匹配；离线 codec 测试不依赖设备或串口库。正常构建拒绝故障指令，测试构建也需显式故障命令。README 提供干净环境命令、接线和故障排查。

## 完成证据

实施阶段在 research/validation.md 对 W-A1–W-A6 逐项记录命令、实际结果、提交和剩余项。软件构建、宿主行为与真实上板观测分栏；无板/仪器时，卡死→复位→原因日志、LSI 计时、WWDG 窗口和服务延迟保持“待上板实测”，不能编造耗时。远端 CI 绑定交付提交，沿用父任务集成流程。
