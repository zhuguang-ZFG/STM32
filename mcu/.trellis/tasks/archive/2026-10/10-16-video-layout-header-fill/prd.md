# 下一集起：视频版式补常驻页头与纵向填充

## Goal

对照 `D:/Users/STM32/final-videos`（同物种：1080p30、配音 + SRT、深色幻灯片、11–14 分钟）逐帧比过，
我们这边有两处实打实的差距。本任务只改这两处，不改叙事骨架。

## 实测到的差距（抽帧证据，非印象）

1. **常驻页头不答「这是第几章的哪一节」**。
   他们每帧顶部：系列徽标 + 「STM32 零基础自学 / 第03章 · GPIO 与 LED」+ 右上角当前小节 chip「01 八种模式」+ 一条分段进度。
   我们每帧只有左上 `F5` 和右上灰字「通往单片机之路 · F5」（`layout.mjs:317` 的 badge/kicker 两个槽），
   小节信息全在标题里，划进来的一帧看不出位置。
2. **横版内容没有铺满可用带**。
   内容块实测卡在 y≈300–700（1080 高），上 1/3 与下 1/3 全空；他们的表格/卡片从 y≈150 铺到 780。
   手机小窗看，等于把画面压成中间一条横幅。

## Phase 1 修订（2026-10-17，实测见 `research/baseline-20261017.md`）

立项时这两条差距是从对照参考逐帧看出来的方向，落地前用 `research/fill-probe.mjs` 在同一入口
（Playwright + `video/src/layout.mjs` 的舞台 DOM）量了一遍，三处按实测改写、两处补记：

- **差距 2 的成因不是 `.frame` padding**。横版 `.body` = y 64.8…918，扣自身 padding 后可用内带
  y 97…879 本来就有 782px；内容中心 y=488 与内带中心 **完全重合**——不是被挤偏，是按自然高度居中摆着
  （`.lay-code{justify-content:center}` `:236`、`.cols{flex:0 1 auto}` `:210`）。
  所以改造点是**带内分布**，不是外框 padding。`:208` 那条「8 行代码配 800px 的框，下半屏全是空的」
  的护栏必须保留，不能靠拉伸面板填。
- **差距 2 主要是横版的事**。竖版 card 已 85%、hook 75%，只有 code 52%。同一套上下界目标不能两平台共用。
- **`anim` 场已 92%、`outro` 是 23% 且是刻意的**（标题 + 一枚 URL 药丸）。这两类不在改造范围，
  AC 按 kind 分档，否则要么把 URL 药丸吹成一屏，要么每轮检查都红着。
- **页头的小节信息没有数据源**。`scenes[].kicker` 实测覆盖率 2–6 场 / 33–35 场 ≈ 6%，
  值是「先说结论 / 重叠 / 编译期 / 一句话记住」——那是卡片内小标题，不是小节名，而且已被审计选择器
  收进去（`cli.mjs:226`、`:239`）。原 Requirements 里「把 `scenes[].kicker` 带到页头」证伪，
  改成新增显式分段契约（见 `design.md`）。
- **分段进度条已存在**：`.ticks`（`:274`–`:278` + `drawTicks` `:410`）横版可见、竖版 `:291` 藏掉。
  不新建第二套进度载体。

## Requirements

- 页头补当前小节 chip：新增显式分段契约 `ep.platforms[p].sections = [{at: sceneId, title}]`，
  由 `sceneSections()` 展开成每场所属小节；`.topbar` 右侧那一格放它（实测集号已被 `badge` 与
  `cover.kicker` 里的 `· F5` 印了两遍，右格本就该空出来放小节信息）。
  横版复用已存在的 `.ticks` 作分段进度，不新造。
- 纵向填充：改带内分布，让 `code`/`hook`/`card` 三类的上下界逼近内带；
  `.step` 页码带（`:189`–`:191` 的注释解释了为什么单独留带）不能被压掉；
  `anim`/`outro` 豁免。
- **只对未发布的新集生效**：已投出去的 18 条不回炉（抖音合集里画风是连续的，混两种版式更糟）。
  契约缺省即旧行为：episode.json 没有 `sections` 时，`.topbar` 文本要与今天逐字节相同。
- 竖版 9:16 的抖音短版只补 `code`（52%）；`.ticks` 保持 `display:none`，右下角 `03 / 09` 仍是竖版唯一进度。
  横版页头不许缩放过去当竖版页头用。

## 明确不抄

- 他们的码率：单条约 **1 GB / 10 Mbps**；我们 539 kbps 的纯色底 + 文字根本吃不下更高码率，白占上传与配额。
- 「猜一猜」三选一卡片 + 吉祥物：那是另一套教学法。我们这条线的卖点是屏上每个数都能 `probe.sh` 复现，
  要塞互动也该是「先猜这条 `#define` 展开成什么」这种有唯一答案的形式。

## Acceptance Criteria

分档目标以 `research/fill-probe.mjs` 的**逐场**读数为判据（不是目测、不是单帧代表值）。
F5 现状：横版 code 每场填充 `0.35…0.61`、card/hook 0.55、anim 0.92、outro 0.23；竖版 code 0.52。

- [x] 任意一帧单看页头，能答出「哪一集 · 哪一节 · 全集走到第几段」。
      实测：横版 = badge+系列名+`.secchip`「第 i/n 节 · title」+底部 `.ticks`；
      竖版 = 同一 chip + 页头下 `.secbar`（`.ticks` 仍 `display:none`）。47 场全部有值。
- [x] ~~横版 `code`/`hook`/`card` 每一场 ≥ 0.70~~ → **按实测分档改写**（`research/baseline-20261017.md` §六）：
      - `card`：横版 8 场全部 **0.82**（改前 0.55/0.45），面板是有底/描边/投影的可见盒子，达标且无空洞；
      - `code`/`hook`：**0.70 这条 CSS 达不到**。唯一能到的是 `space-between` 把内容拆到带的两端，
        实测读数 0.74 而截图中间空 250px（`lever-spacebetween-bilibili-code.png`）——那是挖洞不是填充。
        落地走法改成"保持居中、只加大 gap"，横版 code 0.64（最差 0.38）、hook 0.59（最差 0.51）；
        剩下的差距归**每场内容量**（写稿层面），不归版式。
      - 硬约束（取代阈值）：**不许用拆开内容的方式换填充**，判据是截图，不是数字。
- [x] ~~竖版 `code` 每场 ≥ 0.70~~ → 同一回写：竖版 code 实测 0.54（改前 0.38…0.52），
      竖版 `hook` 0.75、`card` 0.85/0.67 **均无回退**（竖版 card 不参与"面板长满"那条，理由见 design §4）。
- [x] `anim` 不回退（实测两平台均 92%/90%，一个字没动）、`outro` 维持单行居中（23%/未设下限，未动）。
- [x] 改版前后同帧并排留档：`baseline-{platform}-{kind}.png` ↔ `after-{platform}-{kind}.png`（双平台各一张）
      + `baseline-f5-sem-mutex.json` ↔ `after-f5-sem-mutex.json` / `after-sec-f5-sem-mutex.json`。
- [x] `npm run video:check` 对 18 条既有集**两平台 694 场全绿**（exit 0）。
      「输出逐字节相同」的实测：旧集没有 `sections` ⇒ 页头 DOM 一字不变 ⇒ 35 + 12 场逐场读数 `diff` 为空；
      唯一差异是通过行文案按惯例补了「进度杠重复」这一项（`research/baseline-20261017.md` §八）。
- [x] `md5sum -c research/out-md5-before.txt --quiet` → exit 0，`video/out/` 全部 1220 个文件一字节未变；
      全程未对任何既有 id 跑 `video:build`。
- [x] 竖版页头/字幕无溢出、无压字：chip 最宽 505px（画布 46.8%）、47 场 `scrollWidth−clientWidth = 0`；
      横版任一时刻只有一条按场进度（新判据实测 0 命中，故意反例逐场报出）。
