# P1 复核材料：分页引擎原型与全量试排（2026-10-25 实测）

本文件是 P1（引擎原型 + 选型定案）的交付证据。所有数字都来自真实产物，不来自估计。

## 1. 引擎定案：**paged.js 0.4.3（钉版）**，不换 vivliostyle

判据逐条实测（全量 88 章 + 6 附录，1119 页）：

| 判据 | 结果 |
|---|---|
| MediaBox 精确 185×260 mm（±0.5） | **185.0×260.0 ✓** |
| `target-counter()` 解析目录页码 | **✓ 且经独立核对完全正确**：目录写 01→9 / 02→17 / 03→33，正文里这三章首次出现页正是 9 / 17 / 33 |
| `@page` 页眉页脚 margin box | 页脚 `N / 1119` **✓**（1102 页有页脚）；页眉**奇数页 ✓ / 偶数页 ✗**（见缺陷 2，已定位并修） |
| 字体不是 Type3 | 文字主体 ✓（4 支随书字体嵌入）；**emoji 一处 Type3**（缺陷 1，已定位并修） |
| 2 章样本 < 30 s 且可外推 | 全量分页 **142 s**（远超预期地快），整轮构建 **~3 min**，在 CI 10 min 预算内 ✓ |

结论：**paged.js 落地，不再评估 vivliostyle**（同 CSS 思路可随时替换，但当前无需）。

## 3. 缺陷清单（P1 的价值就在这份清单）

### 已修的

1. **emoji 印成 Type3 位图**——根因：正文里的 `💡️`/`⚠️` 带 **U+FE0F 变体选择符**，Chromium 因此改用系统彩色 emoji 字体。
   最小用例可复现：不带 VS16 → 走我们自己的 Noto Emoji；带 VS16 → 立刻出现两条**无名 Type3**。
   修法：印前冻结去掉 VS16（纸面单色，VS16 无意义），emoji 回到随书字体。见 `build_print.py::strip_variation_selectors`。
2. **偶数页页眉整片空白**（奇 551 / 偶 0）——根因：书名用 `string-set` 从页脚元素取，而那个元素是 `display:none`，取值不生效。
   修法：书名由构建器注入字面量（`BOOK_TITLE_MARKER`）。
3. **目录页码一开始一个都不出现**——根因：`content: … leader(".") … target-counter(...)` 里 `leader()` 不被 paged.js 支持，**整条 content 失效**。
   修法：点线改为 flex + 虚线底边，页码单独用 `target-counter`。
4. **书籍构建器解析跨渲染锚点**——已在本轮之前的提交里修（`fragment_key`）。
5. **体检模块自己的判据错误**：中文禁则两组字符写反（把"行尾是 ）"这种合法排版判成 5000+ 处违规），字体判定把"系统字体的子集"误算成随书字体，版心统计把标题/代码行算进中位。已全部改正——**判据写错比没有判据更糟**，它会让人去修不存在的问题。

### 未修，P2 的第一批工作

6. **图（SVG）内的文字仍用系统字体**：书里的图是 `data:image/svg+xml;base64,…` 的 **`<img>`**（162 处），父文档 CSS 进不到 `<img>` 里的 SVG，所以图内标签一直是 Segoe UI / 微软雅黑 / Consolas / SimSun / CambriaMath（实测 10 个外来族）。
   影响：CI 上没有这些系统字体 → 同一本书在两台机器上不是同一本；且这些字体的子集被嵌进 PDF（可印但不便携）。
   修法（P2 定案候选）：把图**内联成 `<svg>` 标记**（而不是 `<img>` data URI），让印刷样式里的 `svg text { font-family: … }` 生效；代价是 HTML/PDF 体积与 SMIL 动画需冻结首帧。
7. **目录点线与页码的视觉对齐**：抽取文本参差（`01．C0 … 9`、长标题换行后页码独占一行、`03．…33` 粘连），需渲染成图逐页目检后再定字号/缩进。
8. **体检模块的目录解析器**：目前只能核对到 1 条（文本参差导致正则漏读），要按"目录页 → 行 → 尾随数字"重写，并把"抽检 ≥10 章"做成断言。

## 4. 待你定的（G2 复核门）

- **满行 43 字 vs 惯例 39–40**：收窄版心到 ~128 mm（内 24 / 外 33）会更贴惯例但版心偏窄；或保持现状并在设计文档里写明"按 16 开上限排"。默认建议：**保持**（119 mm 行长仍在 120 mm 建议线内，且行数/版心都合规）。
- **图内联的代价**：单文件 HTML 会失去"图片全部内嵌 data URI"的紧凑性（162 个 SVG 内联后体积可控，但打印 HTML 会变大）。默认建议：**内联**（排版一致性优先，印刷产物不追求体积）。
- **emoji 的印刷处理**：默认保留（单色 Noto Emoji）；若你觉得纸书里不该有 emoji，可改为纯文字标签（`💡 提示` → `提示`），这属于改动正文以外的"工艺替换"，需你点头。
