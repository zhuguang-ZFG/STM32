# C5 函数指针与状态机：中断驱动代码的基本功

> 🎯 中断来了，硬件只负责跳到一个固定地址——"接下来干什么"全靠向量表里那个**函数指针**。而你要写的所有"中断驱动"代码，归根结底都是这三件套的排列组合：函数指针 + 状态机 + 环形缓冲。

## 本章精髓

1. 函数指针=可变的跳转目标：向量表、回调注册、命令分发表，本质都是"存起来的地址"。交叉编译后它长成一条指令：`blx r3`。
2. 状态机是中断代码的"记账本"：中断里只做记账（改状态+搬数据），不做业务，业务留给主循环。
3. 环形缓冲是生产者-消费者的最小解：中断生产、主循环消费；单生产单消费只是前提，还需索引访问原子、正确的发布/获取顺序和明确的满空规则。

- **能理解**：看 `fsm_feed` 的反汇编：`ldr.w r3, [r2, r3, lsl #2]` 查表、`blx r3` 跳过去。源码里那个 `t(f, ch)` 在机器码层面就是这么两条指令。
- **能用**：拿到"串口收到一帧命令"这类需求，直接落成"状态×事件→动作表"，不再写一坨 `if/else`。

## 一、声明阅读法：右左法则与 typedef

`probe.c` 里三种声明，指向的是同一个东西：

```c
typedef void (*cb_t)(void);        /* cb_t = "指向 void(void) 函数的指针"这个类型 */

static cb_t key_table[8];                          /* 8 个函数指针 */
static void (*pick_raw(int id))(void);             /* 函数返回函数指针：裸写法 */
```

右左法则读 `void (*table[8])(void)`：从名字 `table` 出发，**先右**看到 `[8]`，说明 `table` 是数组；**再左**看到 `*`，说明元素是指针；**再右**看到 `(void)`，说明指针指向函数；**再左**看到 `void`，说明函数返回 `void`。合起来：`table` 是"8 个元素的数组，元素是返回 void 的无参函数的指针"。

`typedef` 只是给这个类型起名，不改语义。`probe.c` 用一条断言把"两种写法等价"钉死：

```c
cb_t via_typedef = on_press;
void (*via_raw)(void) = on_press;   /* 两种写法指向同一对象 */
CHECK(via_typedef == via_raw);
```

**编译期还钉死了尺寸**：`_Static_assert(sizeof(key_table) == 8 * sizeof(cb_t), ...)`：`nm` 显示 `key_table` 占 0x20 = 32 字节，正好 8 × 4。

## 二、向量表 = Flash 里的函数指针数组

回看 [B1 四步构建](../build/01-four-steps.md) 里 `.isr_vector` 那 392 字节：它就是**一个 `const` 函数指针数组**，存在 Flash 起始处。启动文件里的每一行

```asm
.word EXTI0_IRQHandler
```

都是在表里填一个地址。`Reset_Handler` 是 `W`（弱符号），就是"表里那个槽默认指向这里，你可以覆盖"的机制：**弱符号 = 可被覆盖的函数指针槽位**。

所以"注册中断服务函数"这件事，在 C 层面根本不需要 API：你写出同名函数，链接器就把表里那格重定位到你函数的地址。

## 三、查表法状态机：`fsm_feed` 的机器码只有两条指令

![查表法状态机：状态×事件查表取出函数指针](/figures/c-05-fsm-table.svg)

`probe.c` 实现的是一个"串口命令解析"状态机：单行命令 `<字母><数字>\n`，字母 ∈ {R,G,B}，数字 ∈ 0..9。核心是一张 **状态 × 事件 → 动作** 的 `const` 表：

```c
typedef state_t (*trans_t)(fsm_t *f, char ch);   /* 动作 = 返回下一状态的函数 */

static trans_t const FSM[3][4] = {
    /*              EV_LETTER     EV_DIGIT      EV_LF       EV_OTHER  */
    /* S_IDLE */ { act_save_cmd, act_ignore,  act_ignore, act_ignore },
    /* S_ARG  */ { act_save_cmd, act_save_arg, act_error, act_error  },
    /* S_END  */ { act_error,    act_error,    act_exec,  act_error  },
};
```

整个"状态机"就是这一行：

```c
__attribute__((noinline))
static void fsm_feed(fsm_t *f, char ch)
{
    trans_t t = FSM[f->state][classify(ch)];
    f->state = t(f, ch);            /* ← 查表 + 间接调用：中断里只做这点事 */
}
```

交叉编译（`-O2`）后 `fsm_feed` 的机器码，查表和跳转一目了然：

```asm
00000070 <fsm_feed>:
  70:	b510		push	{r4, lr}
  ...
  92:	eb03 0382	add.w	r3, r3, r2, lsl #2			@ r3 ← state*4 + ev
  96:	4a05		ldr	r2, [pc, #20]	; (ac <fsm_feed+0x3c>)	@ r2 ← FSM 基址
  98:	4620		mov	r0, r4
  9a:	f852 3023	ldr.w	r3, [r2, r3, lsl #2]	@ 查表：取出函数地址
  9e:	4798		blx	r3				@ 间接调用
  a0:	7020		strb	r0, [r4, #0]		@ 返回值写回 f->state
  a2:	bd10		pop	{r4, pc}
```

三点值得注意：

1. **`blx r3` 就是"函数指针"在机器码层面的全部含义**：跳到寄存器里的地址。你在源码里看到的每一次"回调"，交叉编译后都是这条指令。
2. `f->state = t(f, ch)` 被翻译成 `strb r0, [r4, #0]`：**动作函数的返回值直接就是下一状态**。这个设计让整张表不需要任何"转移逻辑"代码，表驱动。
3. **`classify(ch)` 被完全内联掉了**（没有 `bl` 调用），只剩下 `cmp`/`beq`/`bls`/`ite` 一串比较。`-O2` 会把短小的分类函数摊平。

`const` 的价值在这里是硬的：`nm` 显示 `FSM` 是 `r` 类型（只读），落在 `.rodata`，**48 字节（3×4×4）一个字节都不占 RAM**。对比 `key_table`（运行时要注册，非 const）：`b` 类型，老老实实占 `.bss` 的 32 字节。**这就是 C1 讲的"const 经济学"**。

行为断言（`probe.c` 实测全绿）：

- `"R5\n"` → `n_exec==1`，`cmd=='R'`，`arg==5`，回到 `S_IDLE`；
- 逐字节喂 `'R'`、`'4'` 跨调用续命：喂完 `'4'` 时 `state==S_END`，再喂 `'\n'` 才 `n_exec` 加一：**状态活在结构体里，不在调用栈上**，这正是中断分片处理的必要条件；
- `"R\n"`（缺参数）、`"R5X\n"`（参数后混垃圾）→ `n_err` 加一、状态复位，**不崩溃不死等**。

## 四、环形缓冲两派：满/空判定的两条路

先看这张图：指针相等的歧义，和两条判定路线。

![环形缓冲两派动画](/anim/ring-buffer.svg)

单生产单消费环形缓冲的经典难题：**读写指针相等时，是空还是满？** 两派各有一个答案，`probe.c` 两派都实现了，用同一组测试对照。

**A 派（牺牲一格）**：留一个空位当哨兵：

```c
if ((uint8_t)((w + 1) % RB_CAP) == q->r) return false;   /* 满 */
...
if (r == q->w) return false;                             /* 空 */
```

8 格物理容量，**只能用 7 格**（实测输出 `A 派可用 7 格`）。代价是浪费一格，好处是判定逻辑直白。

**B 派（单调索引）**：指针永不取模，交给 `uint8_t` 自然溢出，用"在飞元素数"判满：

```c
uint8_t w = q->w;
if ((uint8_t)(w - q->r) >= RB_CAP) return false;         /* 满：无符号减法天然抗回绕 */
q->data[w % RB_CAP] = v;                                 /* 只在寻址时才取模 */
```

**8 格全部可用**（实测输出 `B 派可用 8 格`）。妙处在于 `(uint8_t)(w - q->r)`：即使 `w` 从 255 回绕到 0，无符号减法的模 256 语义让"在飞数量"依旧正确：**不用写任何回绕判断**。

两派共用的发布/获取顺序（这是"中断生产、主循环消费"的正确性关键）：

```c
q->data[w % RB_CAP] = v;                          /* 先写数据 */
atomic_signal_fence(memory_order_release);        /* 屏障：数据先于写指针发布 */
q->w = (uint8_t)(w + 1);                          /* 再发布写指针 */
```

消费者对称：先读 `r`，再 `atomic_signal_fence(memory_order_acquire)`，最后取数据。**顺序反了就是"读到空槽"的经典 bug**（对应 C3 的屏障一节）。

长跑验证（两派各 600 步、塞取交错）：序号对 256 取模后与读出值逐一比对，`n_put == n_get`（一个不多一个不少）。B 派额外断言 `n_put > 256`：**确实跨过了 255→0 回绕**，且 `q.w == n_put mod 256`、`q.r == n_get mod 256`。A 派额外断言"满写被拒"路径真的触发过（`n_refused > 0`）。

## 五、中断礼仪：记账不做事

回到开篇那句"中断里只做快递分拣，不下厨房"。三件套的分工是这样的：

| 组件 | 中断里做什么 | 主循环做什么 |
|---|---|---|
| 函数指针（向量表/分发表） | 一跳到位，不做判断 | 注册/替换处理函数 |
| 状态机 | 只改 `f->state`、搬一字节 | 读 `state`/`n_exec` 决定业务 |
| 环形缓冲 | 只 `put` 一个字节 | 循环 `get` 出来慢慢处理 |

**为什么不能恋战**：`fsm_feed` 的全部工作量是"一次查表 + 一次间接调用 + 一次 `strb`"：机器码 4 条有效指令。这就是中断预算的基准线：几十个时钟周期。一旦你在里面加 `printf`、`delay`、浮点运算，预算立刻爆掉（`-O0` 下 `printf` 要几百微秒，见 [C3](03-volatile.md)）。

**重入与临界区预告**：单生产单消费的成立前提是"生产者只有一个、消费者只有一个"。一旦中断和主循环都要**改同一个索引**（例如双向队列、或多优先级中断都往里塞），就必须上临界区，S7 与 F4 展开。

## 常见坑

- **函数指针类型不匹配**：签名差一个参数，调用就是 UB，编译器未必报警（老代码里 `void(*)()` 与 `void(*)(void)` 不一样）。
- **环形缓冲读写指针写反**：读指针只能消费者动、写指针只能生产者动，交叉修改即翻车。
- **状态机里做长延时**：中断/主循环统统被拖死，延时本身就该是一个状态（等超时事件）。
- **查表数组忘加 const**：白白吃掉 RAM（回 [C1](01-memory-model.md) 的 const 经济学）。`nm` 一眼可辨：`r` = Flash，`b`/`d` = RAM。
- **分派前不判空**：`key_table[i]` 可能是 `NULL`（未注册的槽），直接调用就是跳进地址 0，`probe.c` 里 `if (key_table[i] != NULL)` 是纪律，不是装饰。这条纪律在反汇编里看得见：`main+0x20` 是一条 `cbz r3, 24 <main+0x24>`，紧接 `main+0x22` 才是 `blx r3`——空槽直接跳过。

## 短自测

**1. 用右左法则读 `void (*table[8])(void)`。**

<details><summary>答案</summary>

从 `table` 出发：右看 `[8]` → 是数组；左看 `*` → 元素是指针；右看 `(void)` → 指向函数；左看 `void` → 函数返回 void。合起来：**8 个元素的数组，元素是指向"无参、返回 void 的函数"的指针**。`sizeof(table)` = 8 × 4 = 32 字节（`_Static_assert` 与 `nm` 双向验证）。

</details>

**2. `blx r3` 是什么？为什么说"函数指针"在机器码层面就是它？**

<details><summary>答案</summary>

`blx` = Branch with Link and Exchange：**跳到寄存器里的地址**，同时把返回地址放进 `lr`。函数指针变量存的就是一个地址，调用它 = 把地址装进寄存器 + `blx`。`probe.c` 交叉编译后在 `.text+0x9e`（`fsm_feed` 的查表分派）和 `.text.startup+0x22`（`main` 里内联的回调循环）各出现一条。

</details>

**3. 环形缓冲 A 派和 B 派各能装多少格（物理 8 格）？为什么？**

<details><summary>答案</summary>

A 派 7 格（牺牲一格当哨兵：`w+1 == r` 判满，所以永远留一格空）；B 派 8 格（用 `(uint8_t)(w - r) >= RB_CAP` 判满，"在飞数量"用无符号减法算，天然抗 255→0 回绕）。实测输出 `A 派可用 7 格，B 派可用 8 格`。

</details>

**4. `FSM` 表和 `key_table` 分别落在哪个段？说明了什么？**

<details><summary>答案</summary>

`FSM` 是 `const` → `nm` 类型 `r`（只读），落在 `.rodata`，链接后进 Flash，48 字节不占 RAM。`key_table` 运行时才注册（非 const）→ 类型 `b`，落在 `.bss`，占 RAM 32 字节。同一份代码里，"能不能改"直接决定它住 Flash 还是住 RAM。

</details>

**5. 为什么消费者要先读指针、再屏障、最后取数据？**

<details><summary>答案</summary>

生产者是"先写数据、再发布写指针"；消费者必须对称地"先看到写指针、再读数据"。`atomic_signal_fence(memory_order_acquire)` 阻止编译器把"取数据"提前到"读指针"之前，否则可能读到还没写进去的空槽。顺序反了就是经典的单生产单消费 bug。

</details>
