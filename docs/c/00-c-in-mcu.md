# C0 为什么嵌入式 C 是另一种 C

> 🎯 在电脑上，数组越界=段错误弹窗；在单片机上，数组越界=隔壁外设的寄存器被改写，电机突然转了一下——没有弹窗，只有事故。

## 本章精髓

1. 裸机没有"运行时爸爸"：没有 MMU、没有段错误、没有 GC，越界/野指针的后果直接落在硬件上。
2. C 在嵌入式里是"高级汇编"：每一行都能对应到确定的机器行为，这正是我们选它写驱动的原因。
3. 资源观不同：RAM 按 KB 计、Flash 按 MB 计，`malloc` 不是想用就能用。

- **能记住**：裸机 C 与应用 C 的四条差异：无 OS、内存按 KB、直接碰硬件、从复位向量起跑（即精髓三条）
- **能理解**：为什么"数组越界"在单片机上不是弹窗而是事故：没有 MMU 替你拦，写谁就是谁；为什么全局变量的初值要从 Flash 搬到 RAM
- **能用**：用"地址 + 宽度"的语言描述一次寄存器写（如"向 `0x40021418` 写 32 位值"），并在 `code/stm32/00-blink` 的三个文件里各指出一处对应

## 一、没有 OS 的世界

<AnimFigure src="/anim/embedded-c-diff.svg" />

电脑上运行一个 C 程序，`main` 之前站着一整座运行时大厦：装载器把 ELF 映射进虚拟地址空间，动态链接器解析符号，CRT 初始化堆，最后才 `__libc_start_main → main`。程序崩溃时，内核送来段错误弹窗，进程尸体被收走，世界照旧。

单片机上没有这座大厦。上电那一刻，Cortex-M4 内核只做两件硬件规定的事（RM0090 §12.2，具体值以你手上芯片的参考手册为准）：

1. 从 Flash 起始的**向量表第 0 项**取出初始栈顶地址，装进 MSP；
2. 从**第 1 项**取出复位处理函数 `Reset_Handler` 的入口地址，跳过去。

没有装载器、没有堆初始化、没有任何人替你准备 C 语言的运行前提。`Reset_Handler` 必须亲手做完三件事，`main` 里的第一行 C 才合法（本工程 `startup_stm32f407xx.s:35-80`，逐行走读在 [B4 启动过程](../build/04-startup.md)）：

- 使能 FPU（复位后 CP10/CP11 默认关闭，浮点指令一碰就 UsageFault）；
- 把 `.data` 段（有初值的全局变量）从 Flash 搬到 RAM；
- 把 `.bss` 段（无初值的全局变量）清零。

崩溃的形态也完全不同。越界写在 PC 上：内核通过 MMU 拦截，进程死给你看。越界写在裸机上：没有 MMU，写谁就是谁：写到隔壁外设的寄存器，电机可能真的转一下；写到向量表映射区，下一次中断就跳进荒野。内核唯一的兜底是 HardFault：一张没有弹窗、没有日志、只有调试器才看得到的"死亡通知"。

**取证**（xPack arm-none-eabi-gcc 15.2.1，`-mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard`，完整命令见工程 Makefile）：

```text
$ mingw32-make            # 在 code/stm32/00-blink 下，零警告
   text	   data	    bss	    dec	    hex	filename
    660	      0	   1536	   2196	    894	build/blink.elf
```

660 字节代码 + 1536 字节 `.bss`（其中 1024 字节是链接脚本预留的最小栈、512 字节最小堆），这就是"点灯"在最裸的世界里的全部开销。没有 OS 的世界，从 2196 字节开始。

## 二、内存按 KB 计

PC 上"内存不够"是个遥远概念；F407ZGT6 上它是链接脚本里两行硬数字（`stm32f407xx.ld:22-29`）：

| 区域 | 起始 | 容量 | 住什么 |
|---|---|---|---|
| FLASH | `0x08000000` | 1024 KB | `.text` 代码、`.rodata` 常量、`.data` 的初值仓库 |
| RAM | `0x20000000` | 128 KB | `.data`、`.bss`、栈（从尾部向下长）、堆 |

（F407 另有 64KB CCM @ `0x10000000`，CPU 直连、DMA 够不着，本章不展开。）

128 KB 是什么概念：一张未压缩的 320×240 灰度图就要 76.8 KB。于是三条应用层的"常识"全部作废：

- **`malloc` 不是想用就能用**。堆没有操作系统替你扩，碎片化了没有交换分区兜底；本工程给堆的"最小预算"只有 512 字节（`_Min_Heap_Size = 0x200`），链接时 RAM 摆不下就直接报错，把"运行时踩内存"提前成"链接期拒签"。
- **栈是奢侈品**。默认 1 KB 起步，递归深一点、局部数组大一点就撞进 `.bss`，而且撞得无声无息。
- **全局变量的初值要付两份钱**。`int x = 42;` 运行时在 RAM，但 `42` 这个初值还占 4 字节 Flash，启动时由 `Reset_Handler` 搬过去（[C1](01-memory-model.md) 逐字节追踪这三段旅程）。

上面的 size 输出就是证据：`data 0` 表示本工程没有带初值的全局变量，`bss 1536` 几乎全是链接脚本强制预留的栈/堆，点灯程序本身一个全局变量都没用。

## 三、C 与硬件的直线

裸机编程的全部秘密就一句：**寄存器就是有名字的地址**。GPIOF 的 BSRR 寄存器住在 `0x40021418`（本工程 `main.c:29,34` 用 `GPIOF_BASE + 0x18` 拼出来，地址经 ST 官方 CMSIS 头文件核对），对它写 32 位值，红灯亮灭：

```c
#define GPIOF_BSRR  (*(volatile uint32_t *)(GPIOF_BASE + 0x18UL))
/* ... */
GPIOF_BSRR = (1UL << (LED_R_PIN + 16));  /* BR6：PF6 拉低 → 红灯亮 */
```

这行赋值编译出来就是一条 `str` 指令——高级语言到硬件之间**没有中间商**。这正是嵌入式选 C 的原因：每一行都能对应到确定的机器行为，性能与副作用都可预测。

注意那个 `volatile`，它不是装饰：硬件寄存器会被"程序之外的力量"改变（状态位被外设置位、输入数据寄存器随引脚变化），编译器的常规假设"没人动的内存不会变"在这里不成立。`volatile` 是告诉编译器"每次都真去访存，不许缓存、不许合并、不许删"的合同条款。为什么是三条、边界在哪，[C3](03-volatile.md) 用两套工具链的反汇编逐条取证。本章先立下这条：**凡指向硬件寄存器的指针，必须戴 volatile**。

## 四、工具链即世界观

你在 PC 上敲 `gcc hello.c`，编译器默认目标是"本机"。嵌入式里这句默认不再成立：你在 x86_64 的电脑上，为一颗 Cortex-M4 的芯片产代码，这叫**交叉编译**，工具链也从此变成四件套（以本工程 Makefile 为实例）：

| 角色 | 本工程里的身份 | 干什么 |
|---|---|---|
| 编译器 | `arm-none-eabi-gcc` 15.2.1 | C→汇编→目标文件，`-mcpu=cortex-m4` 指明目标内核 |
| 链接器 | 同上驱动 `-T stm32f407xx.ld` | 按链接脚本把 `.o` 拼成落在 `0x08000000` 的固件 |
| 二进制工具 | `arm-none-eabi-objcopy / objdump / size` | ELF↔bin/hex 转换、反汇编取证、体量统计 |
| 烧录/调试 | OpenOCD + ST-Link + `arm-none-eabi-gdb` | 把 ELF 写进 Flash，从复位向量单步 |

"即世界观"的意思是：工具链的每一项配置都在替你回答一个世界观问题：目标是谁（`-mcpu`）、代码放哪（链接脚本）、初值谁来搬（启动文件）、错了怎么看（GDB）。把这些串起来的完整走读在 [B0 交叉工具链](../build/00-toolchain.md) 与 [B1 四步构建](../build/01-four-steps.md)，本章只需建立直觉：**同一份 C 源码，换一组 `-mcpu` 和链接脚本，就是另一颗芯片的世界**。

## 短自测

1. 上电后、进入 `main` 之前，`Reset_Handler` 必须完成哪三件事，缺了哪一件会让哪类 C 代码出错？

<details><summary>答案</summary>

① 使能 FPU：缺了它，任何浮点指令触发 UsageFault；② 把 `.data` 初值从 Flash 搬到 RAM：缺了它，有初值的全局变量读到的是 RAM 里的随机值；③ 清零 `.bss`：缺了它，无初值全局变量不为 0，违反 C 标准对静态存储期的承诺。（对应 `startup_stm32f407xx.s:35-72`。）

</details>

2. 用"地址+宽度"的语言描述这条语句的硬件行为：`GPIOF_BSRR = (1UL << (6 + 16));`

<details><summary>答案</summary>

向地址 `0x40021418`（GPIOF 的 BSRR 寄存器）做一次 32 位写，写入值 `0x00400000`：bit22（BR6）为 1，表示把 PF6 输出拉低，共阳接法的红灯点亮；写 0 的位无影响，所以不需要读-改-写。

</details>

3. 本工程链接结果 `text 660 / data 0 / bss 1536`。为什么 `data` 是 0？`bss` 里那 1536 字节主要是谁？

<details><summary>答案</summary>

`data = 0` 因为工程没有"带初值的全局变量"（所有常量要么是宏、要么是局部量）。`bss 1536` 几乎全是链接脚本强制预留的最小堆（`_Min_Heap_Size = 0x200`，512 字节）+ 最小栈（`_Min_Stack_Size = 0x400`，1024 字节），这是"链接期拒签"机制占的位子，不是真正的全局变量。

</details>

4. 同事说："寄存器指针不加 `volatile` 也能编译过，先不管。" 用本章与 C3 的取证逻辑反驳他，一句就够。

<details><summary>答案</summary>

"能编译过"与"能对"是两回事：不加 `volatile`，编译器有权把多次访存合并/缓存/删除：`-O2` 下轮询状态位的循环会被优化成只读一次甚至整个消失（C3 的反汇编实测），程序在真硬件上死等，而源码看起来毫无问题。

</details>
