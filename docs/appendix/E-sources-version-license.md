# 附录 E · 来源、版本与许可

## 本章罗盘

- **问题**：本书把来源分成哪几层、彼此为什么不能替代？一条「手册说」要怎样才能算钉住？两本姊妹书的来源注册表怎么合并，`[D2]` 这类标签对应哪条条目？许可边界按什么分域？
- **交付**：能用四格（订货号/文档号/寄存器/算式）钉住一笔数字；能按快照规则引用手册与代码；能沿正文标签找到注册表条目；能说清两域许可的边界。
- **边界**：本附录只登记事实与规则，不转载任何第三方手册、规范或源码；商标归各自权利人。注册表的机器源是两份 manifest（根书 94 条 + mcu 75 条），统一渲染在站点收口批次接线；本附录收录两域的纪律、标签对照与许可文字。
- **依据锚点**：根书附录 E（`stm32-book/book/E-参考资料.md`）、mcu 附录 E（`mcu/mcu-book/book/E-参考资料.md`）；`stm32-book/manifest.json`（94 条 sources）、`mcu/mcu-book/manifest.json`（75 条 sources，其中 ai-* 15 条 accessed 2026-10-27）。

## 一、来源四层与快照规则

本书把来源分成四层，使用时不能互相替代：

1. **规范与芯片手册**：数据手册回答引脚/电气，参考手册回答寄存器/外设，编程手册回答内核，协议规范回答线上语义。
2. **官方代码与应用笔记**：展示一个版本上的实现方法；仍有具体芯片、固件包和例程配置边界。
3. **官方社区与开源实现**：用于发现坑、比较写法和构造验证；社区结论不是规范，必须回查目标版本源码或手册。
4. **本项目原创内容**：章节、例程、图和构建器。事实性参数尽量指向前三层；教学组织和实验步骤由本项目负责。

**快照规则**：手册引用至少写文档号；对引脚、典型电流等修订敏感事实再写 Rev、Figure、Table 或章节。GitHub 参考实现冻结 tag 或完整 commit，不用「main 现在看起来一样」作证据。社区文章记录访问日期和用途，只作经验线索。例程复现记录同时冻结芯片订货号、板卡丝印、固件包、编译器和时钟配置。

**证据纪律四条**（mcu 域并入）：**版本号是结论的一部分**——寄存器位看手册 Rev，行号看代码 tag/commit，API 看文档版本，三样对不上先怀疑口径。**代码基准冻结点**：FreeRTOS-Kernel V11.1.0、ESP-IDF v5.5.2、CMSIS device_f4 v2.6.11、SPL V1.8.0、GD32 固件库 V3.3.3；RT-Thread 未固定 tag（master 稀疏检出）——这是已知的可复现性缺口，注册表如实标注。**「待上板实测」制度**：没量过的现象一律标注，空白记录表不表示验证通过。**社区内容只作线索**：会改变产品行为的结论必须回到一手资料与实测。

## 二、正文标签对照

两域的正文引用标签与注册表 ID 的对应规则：

- **根书域**：正文「来源锚点」链接到 `#source-*` 锚点（`#source-rm0008`、`#source-ds5319-swd` 等），与 `stm32-book/manifest.json` 的 94 条 sources 一一对应。
- **mcu 域**：正文沿用 `[D2]` 这类标签，与 mcu 注册表 ID **字母区相同、编号相同**——正文 `[A1]` = 注册表 `a1`（RM0090）、`[D2]` = `d2`（优先级继承论文）、`[F1]` = `f1`（FreeRTOS V11.1.0）；`mcu-*` 三个小写条目是本仓库自有的工程/实验/动画资产；`ai-*` 15 条是 AI 章的工具事实卡（accessed 2026-10-27）。

**两套 ID 禁止重号**：合并后注册表保留双命名空间（根书条目保留原名，mcu 条目保留 `a1–f8`/`mcu-*`/`ai-*` 前缀口径）；机器源是两份 manifest，统一渲染在站点收口批次接线。

## 三、一笔数字怎样才算钉住

[附录 D](./D-glossary.md) 文末的前两张账用同一套四格：订货号、文档号或章节、寄存器或公式、算式结果。**缺一格，就还只是线索**。第二张账把订货号换成 G0、L4 或 H7 时，时钟和寄存器整行重写；第三张账钉 DMA 通道、USB 描述符长度和 `CFSR`/`HFSR` 地址，换请求表或换描述符时同样整行重写。

115200 这一格可以当样子：订货号 STM32F103C8T6，USART1 时钟走 APB2（不是 APB1）；文档号 [RM0008] 的 USART 波特率寄存器；公式 `fPCLK / (16 × 波特率)`；72 MHz 代入得 39.0625，BRR 低 4 位是 1，结果 `0x271`，分频误差是 0。记录里如果只有「误差 0.16%」而没有 USART 编号和 BRR，这一格还没钉住——0.16% 是 36 MHz 那一行，或是把 72 MHz 的小数位丢掉之后的数。mcu 域的「版本号是结论的一部分」并入同一段。

![手绘板：把一格填满——料号、时钟、寄存器、算术、证伪（原理示意，非实拍）](/images/app-e-fill-cell.png)

换一个数之前，先按这张空表抄一行（500 kbit/s 已填作样子，对应 [附录 D](./D-glossary.md) 第二张账）：

| 格子 | 填什么 | 500 kbit/s 这一格 |
| --- | --- | --- |
| 订货号 | 丝印上的完整订货号，H7 还要有 revision | STM32F103C8T6 的 bxCAN；FDCAN 另开一格 |
| 时钟 | 写进公式的那一路，带数值 | APB1 = 36 MHz；72 MHz 是 APB2 和定时器那一路 |
| 寄存器 | 名字和将要写入的字段 | 预分频 9，BS1=5，BS2=2，SJW=1 Tq |
| 算式 | 一行除法，除不尽写出小数 | `36e6 / (9 × 8) = 500000`；采样点 `(1+5)/8 = 75%` |
| 证伪 | 哪个仪器读数会推翻这一格 | 位速率若是 450 kbit/s → 10 Tq 与预分频 8：`36e6/80 = 450000`，那一格的预分频本来是 7.2 |
| 不写进设计的数 | 这一格证明不了什么 | 回环收到自己的帧，只证明控制器接受了这组位时间；两端 120 Ω、ACK 和错误计数另记 |

> [!WARNING]
> 7.2 写不进预分频字段。写成相邻的整数 8 之后，总线速率是 450 kbit/s，回环仍然可能是绿的。

## 四、许可与再分发边界（按域分节）

**根域（根书侧）：**

- `docs/`、除 `assets/photos/` 外的原创图形资产与原创正文/版式：**CC BY 4.0**；转载或改编须署名、链接来源并说明修改。
- `assets/photos/` 中五张第三方实拍保持原许可：两张 Nucleo-64 为 CC0 1.0，两张 Blue Pill（Avandalen、Popolon）为 CC BY-SA 4.0，一张 Blue Pill（Paul Gallagher / tardate）为 MIT；作者、原图页、处理尺寸和 SHA-256 见照片目录 README。
- `examples/`、`tools/` 与代码片段：MIT。完整条款以仓库根 `LICENSE` 为准。

**mcu 域（姊妹书侧）：**

- 书稿正文、版式与机制动画：**Apache-2.0**（与仓库 `mcu/LICENSE` 一致），可自由转载与二次创作，需保留署名与许可声明。

**共同边界：**

- 被逐行引用的上游代码（FreeRTOS、ESP-IDF、CMSIS、HAL、SPL、GD32 固件库、RT-Thread）：本书仅链接、引用行号并独立表述，不随书再分发其源码；各归其上游许可。
- 外部手册、规范、论文与书籍：只作链接与事实引用（文档号/DOI/ISBN 与版本），权利归原权利人；注册表每张卡片都标了许可边界。
- 商标：STM32、STM32Cube、Nucleo、ESP32、GD32、Keil、IAR、FreeRTOS 等名称与标识归各自权利人；本书作为独立教学材料使用这些名称仅出于指称目的，与这些公司没有隶属关系。
