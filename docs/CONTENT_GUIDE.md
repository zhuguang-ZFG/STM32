# 内容风格指南（贡献者必读）

> English: [Writing guide](en/CONTENT_GUIDE.md)

本仓库定位：**面向中文学习者的 STM32 知识库**，参考 [通往AGI之路](https://github.com/waytoagi/WaytoAGI) 的组织方式——
门户首页 + 分章知识库 + 可视化（动画/图示/实物图）+ 可运行代码 + 速查表。

为了让 20+ 篇文章风格统一，请所有贡献者遵守下面的约定。

## 写给读者，不写给审稿人

正文——尤其是原理、插图说明、时序与状态、常见坑与出处——写给正在学的人，不写给审稿人或作者备忘。

不要把编写过程里的说法写进读者正文。禁词与 `tools/slop_lint.py` 的「审稿用语」规则组同源，例如：

- 「主图」「正常路径」「旁注」「只钉在」「整格照抄」「不编」
- 「作废」（Cache 术语「清洁或作废」除外）
- 表头「该来源允许支持的主张」（改成「出处里能查到什么」）

直接写事实和条件，例如：「换到 F4 时，这个地址要改成 0x…」。

硬门：`python tools/slop_lint.py`（仓库根目录）。贡献者文档里讨论教学合同与功能块可以，章正文不要写审稿过程。


## 节奏、分层与自测（从 handraw 抽取，Port B）

机械禁词仍由 `tools/slop_lint.py` 管；下面三条管人眼与 Sepia 流程，不能被 lint 替代。细则与合流合同见 [`../stm32-book/BOOK_CLASSIC_CONVERGE_SPECS.md`](../stm32-book/BOOK_CLASSIC_CONVERGE_SPECS.md) §5、§6。

### 节奏

- 句子与段落长短要跟着内容变，不要整章同一拍长。
- 禁止连续多章旁白/回忆卡共用同一套 8–10 拍填词模板；短片与长课也不要同构拉伸。允许的节拍池与硬禁见 Overlay §5.4。
- 改写整段或整章时：**先**用 Sepia `review` 列出缺陷，**再** `refactor` 逐项改；禁止边读边改导致越改越长。技能树在 [`.claude/skills/sepia/`](../.claude/skills/sepia/SKILL.md)，操作入口见 `sepia-review` / `sepia-refactor`。日常短句与禁词见 [`.claude/skills/plain-voice/SKILL.md`](../.claude/skills/plain-voice/SKILL.md)。

### 分层

阅读顺序固定为三层，后一层可以后读，不要颠倒：

1. **最小胜利**：读者能在板子或仿真上立刻验证的一小步结果（现象可观察）。
2. **机制**：电流 / 字节 / 状态 / 寄存器为何如此。
3. **手册密度**：订货号、revision、表号、地址与边界条件后置；第一次读可以先跳过，做完实验再回来钉死。

写作时把「先结论后原理」落实为：**先给出可验证的最小胜利结论，再展开机制；手册密度后置。**

### 自测（编辑完成前强制）

1. **离开检查**：读者合上这一节，仍能复述最小胜利与一个失败信号。
2. **删除检查**：删掉新增词句后意思不变 → 删掉新增（Sepia deletion test）。
3. **回退检查**：原句更短更准且语气合适 → 保留原句，不为润色而改（Sepia reversion test）。

代码、URL、ID、表数据、`<!-- video: -->` / `<!-- links: -->`、`#source-` 链接是保护区，文风技能不得改写事实。

### Handraw 与真证（指针）

技术图与概念图走 Handraw 知识轨（Layout / 风格 / 配色登记，见 Overlay §6 与 `.claude/skills/handraw-style`）；真板照片与仪器截图走真证轨，永不 AI 冒充、永不把自绘图写成实拍。规划字段写在 Overlay，不在本指南重复枚举。

## 1. 文件与命名

- 文档放 `docs/`，文件名：`NN-中文标题.md`（NN 两位数字，如 `05-定时器与PWM.md`）。
- 示例代码放 `examples/<模块名>/`，每个示例目录包含 `README.md` + `main.c`（可选 `Makefile`）。
- 速查表放 `cheatsheets/`。
- 图片一律使用**相对路径**，例如 `../assets/animations/gpio-blink.svg`。

## 2. 每章教学合同与功能块（可选）

不再强制「每篇文章同一套固定标题顺序」。合入门禁看：**教学合同字段是否已登记**、**选用功能块是否完成认知任务且无空标题**。完整合同见 [`../stm32-book/BOOK_CLASSIC_CONVERGE_SPECS.md`](../stm32-book/BOOK_CLASSIC_CONVERGE_SPECS.md) §4；本指南只落地写作细则。分部重映射表与视频成片参数不放在本文件。

### 2.1 教学合同字段（必填登记）

每章在 `manifest` 的 `chapter_guides`（或等价机器可读表）登记下列字段（七项核心 + 先备知识）；中英文事实对齐、表达分写：

| 字段 | 合同含义 | 可检查标准 |
| --- | --- | --- |
| 进入问题 | 读者已遇到的可观察现象或具体任务 | 开头 120 字内出现；禁止主题式预告 |
| 先备知识 | 只引用前文已讲概念；后用概念先给最小定义 | 审计不得发现未定义关键术语依赖后文 |
| 最小胜利 | 可运行、可测量或可查表复算的一个结果 | 出现在手册密度长表之前；步骤可独立复现 |
| 核心机制 | 一个主要认知难点 | 全章只保留一个主比喻/主关系图争夺注意力 |
| 失败分支 | 至少一个能区分原因的证据与下一检查动作 | 禁止以「可能坏了」收尾 |
| 迁移边界 | 换芯片/库/时钟/封装/软件栈时必须重查的条件 | 写成条目，不写「注意移植」空话 |
| 记忆锚点 | 准确比喻 **或** 核心关系图 **或** 可复述口诀（可组合，但必须指向同一机制） | 比喻后必须有「相似点 / 失效点」对照 |
| 离开检查 | 不翻书能答的问题 + 能独立完成的动作 | 与 L0–L5 本部交付对齐；可被测验或实验覆盖 |

- **讲透彻** = 核心机制 + 失败分支 + 迁移边界三项同时成立。
- **一点就懂** = 进入问题 + 最小胜利在手册墙之前完成，且记忆锚点可单页复述。
- **从入门到精通** = 读者能指出自己停在 L0–L5 哪一级，并知道下一级缺哪份证据——不是读完 33 章标题。

### 2.2 阅读顺序原则（标题名可变）

1. 进入问题 / 反差现象
2. 最小胜利（短步骤 + 预期证据）
3. 核心机制（一个难点）
4. 按需展开：时序、公式、寄存器、全表、系列差异
5. 失败分支与排查
6. 迁移边界
7. 离开检查

允许把完整寄存器表、电气极限表、长 API 列表放在机制之后或附录式小节。禁止在最小胜利之前堆「原理与适用范围」式手册墙。

### 2.3 功能块可选清单

章内从下列功能块**按需选取**，不要求全出现，不固定顺序；选用的块必须完成其认知任务，禁止空标题：

| 功能块 | 何时选用 | 完成标准 |
| --- | --- | --- |
| 现场问题 / 失败现象 | 几乎每章 | 可观察、可复述 |
| 一句话直觉 | 概念易混时 | ≤40 字，随后必须被机制校正 |
| 最小可运行步骤 | 每章必有等价物 | 含预期现象或测量 |
| 硬件数据流 / 状态机 / 时序 | L1–L5 机制章 | 能算回去或能逐步对账 |
| 可复算公式与参数条件 | 涉及分频、波特率、采样等 | 变量、单位、适用订货号齐全 |
| 测量方法与证据 | 配置是否作用在硬件上 | 写清探头/窗口/读回位置 |
| 常见误判与最短排查 | 有两种以上易混原因时 | 每行：现象 / 区分证据 / 下一动作 / 出处 |
| 跨系列迁移边界 | 数字会随系列变时 | 列出「什么不变 / 什么必须重查」 |
| 由易到难实验 | 需要动手巩固时 | 1–3 个，难度递进，预期可区分 |
| 离开前检查题 | 每章必有等价物 | 不翻书可答 + 可动作验收 |
| 代码实现（HAL 为主，LL/寄存器/SPL 有边界） | 需要可编译片段时 | 真实可编译边界写清；完整工程链到 `examples/` |
| 硬件与接线表 | 涉及具体引脚时 | 板型 / 外设 / 引脚 / 备注 |
| 相关资源 | 需要手册定位时 | 指向具体手册章节与来源 id，不堆链接墙 |

章首仍可用一句话导语（不超过 40 字）与居中主视觉（相对路径，例如 `../assets/animations/xxx.svg`）。

### 2.4 视频注释区、出处与旧标题

- 若章内有 `<!-- video: -->` … `<!-- /video: -->`，注释结束之后的正文仍写给读者、不写给审稿人（见上文「写给读者」）；与第 00、03、04、06 章相同。本指南不改正文章，也不在此收录旁白稿或 `<!-- video: -->` 写法细则。
- 旧「常见坑与排查 / Pitfalls and troubleshooting」不再作为标题。原先写在那一节的坑迁入「常见坑与出处 / Pitfalls and sources」（或等价功能块「常见误判与最短排查」），不保留两套说法，不留空标题。尚未加厚的章可暂时留着旧标题，直到后面的加厚批次；**新改章与 ch03 样章**必须按 §2.1–2.3 组织。
- 每一行只有一个主张。出处列写成指向 `#source-{id}` 的链接。`{id}` 是两份 manifest 的 `sources` 里已有的 id。构建后的目标是附录 E 卡片上的 `id="source-{id}"`。
- 不另建出处表。需要新出处时，把 id 追加进两份 manifest 的 `sources`。
- 禁词由 `tools/slop_lint.py` 硬拦。

## 3. 写作要求

1. **先最小胜利，再机制；手册密度后置**：每节第一句给出可验证的最小结论，再讲机制；订货号与表号等手册密度放后面。
2. **表格化**：参数、寄存器位、坑位排查尽量用表格，不要长段落堆砌。
3. **图文对应**：正文提到的动画/图示必须在文中出现一次，并用 `<sub>` 标注。
4. **代码可编译**：示例代码必须是真实可用的 HAL 代码（`HAL_` 前缀），或明确锁定 STM32F10x SPL 版本的代码，包含头文件、`main()`、必要注释；不要写伪代码。参数用宏定义，避免魔法数字。SPL 内容必须写明系列、版本和迁移边界。
5. **诚实标注（双轨）**：Handraw 知识轨覆盖技术图与概念图（登记见 Overlay §6）；真证轨才是板照与仪器截图。本仓库大量插图仍是**作者自绘矢量图（SVG）/程序生成的 GIF**，不是厂商实拍；需要实拍请引用官方产品页（「实物与资料」）。禁止把自绘图说成实拍，禁止 AI 冒充测量证据。
6. 术语统一：`GPIO`、`定时器(TIM)`、`中断(IRQ)`、`DMA 通道`、`HAL 库 / LL 库 / SPL 标准外设库 / 寄存器`。
7. 行宽不限制，但**不要**使用 HTML `<script>`、外链图片（GitHub 会代理失败）。

## 4. 可视化资产清单（由 `tools/` 脚本生成，勿手改）

见 `assets/README.md`。文档只能引用清单里已存在的文件名；如果确实需要新图，
先在 issue/PR 里说明，或用 `tools/svgkit.py` 自行生成后再引用。

## 5. 提交规范

涉及改章时，提交说明宜勾选：教学合同已登记、功能块清单、旁白节拍指纹、Sepia 删除/回退（详见 Overlay）。

```text
docs(05): 补充 PWM 占空比计算公式与呼吸灯动画
fix(gif): 修正 led-blink.gif 时序与 1Hz 说明不一致
```

一次提交只做一件事；图片（尤其是 GIF）请确认体积 < 500 KB。
