# 内容风格指南（贡献者必读）

> English: [Writing guide](en/CONTENT_GUIDE.md)

本仓库定位：**面向中文学习者的 STM32 知识库**，参考 [通往AGI之路](https://github.com/waytoagi/WaytoAGI) 的组织方式——
门户首页 + 分章知识库 + 可视化（动画/图示/实物图）+ 可运行代码 + 速查表。

为了让 20+ 篇文章风格统一，请所有贡献者遵守下面的约定。

## 1. 文件与命名

- 文档放 `docs/`，文件名：`NN-中文标题.md`（NN 两位数字，如 `05-定时器与PWM.md`）。
- 示例代码放 `examples/<模块名>/`，每个示例目录包含 `README.md` + `main.c`（可选 `Makefile`）。
- 速查表放 `cheatsheets/`。
- 图片一律使用**相对路径**，例如 `../assets/animations/gpio-blink.svg`。

## 2. 每篇文章的固定骨架

```markdown
# NN 标题

> 一句话说明这个外设/主题解决什么问题（不超过 40 字）。

<p align="center">
  <img src="../assets/animations/xxx.svg" width="760" alt="xxx 动画演示">
  <br><sub>▲ 动画：xxx（GIF/SVG 均可在 GitHub 页面直接播放）</sub>
</p>

## 原理与边界
结论钉在哪颗订货号、哪路时钟、哪一版手册；换系列时哪一句作废

## 关键插图
这一节放关键插图

## 时序或状态
一张能算回去的时序表或状态表。没有电气时序就写状态迁移，不留空标题

## 坑与出处卡
| 现象 | 原因 | 处理 | 出处 | 该来源允许支持的主张 |
| --- | --- | --- | --- | --- |

## 📌 学习目标
- [ ] 目标 1
- [ ] 目标 2

## 🧠 核心原理
（用表格/图示讲清楚硬件在做什么，配一张 assets/diagrams 或 animations 里的图）

## 🛠️ 硬件与接线
| 开发板 | 外设 | 引脚 | 备注 |
| --- | --- | --- | --- |

## 💻 代码实现
关键代码片段（HAL 库为主，附寄存器/LL 对照；F1 遗留工程可附锁定版本的 SPL 映射），完整工程见 `examples/...`。

## 🧪 动手实验
1~3 个由易到难的实验，写清预期现象。

## 🔗 相关资源
- 官方参考手册章节、数据手册章节、相关章节链接
```

章内若有 `<!-- video: -->` … `<!-- /video: -->`，四块仍写在该注释结束之后、学习目标之前，与第 00、03、04、06 章相同。这四章是范例。这一版不改正文章。上面的代码块不收录旁白稿，也不写入 `<!-- video: -->`。

- 旧「常见坑与排查 / Pitfalls and troubleshooting」不再作为骨架标题。原先写在那一节的坑迁入「坑与出处卡 / Pitfalls and source cards」，不保留两套说法，不留空标题。尚未加厚的章继续留着旧标题，直到后面的加厚批次。
- 每一行只有一个主张。出处列写成指向 `#source-{id}` 的链接。`{id}` 是两份 manifest 的 `sources` 里已有的 id。构建后的目标是附录 E 卡片上的 `id="source-{id}"`。
- 指南不新开第二份出处表。新 id 仍按既有加厚设计追加进 `sources`；这一版不追加 id。

## 3. 写作要求

1. **先结论后原理**：每节第一句给出可直接使用的结论。
2. **表格化**：参数、寄存器位、坑位排查尽量用表格，不要长段落堆砌。
3. **图文对应**：正文提到的动画/图示必须在文中出现一次，并用 `<sub>` 标注。
4. **代码可编译**：示例代码必须是真实可用的 HAL 代码（`HAL_` 前缀），或明确锁定 STM32F10x SPL 版本的代码，包含头文件、`main()`、
   必要注释；不要写伪代码。参数用宏定义，避免魔法数字。SPL 内容必须写明系列、版本和迁移边界。
5. **诚实标注**：本仓库所有插图为**作者自绘的矢量图（SVG）/程序生成的 GIF**，不是厂商实拍照片；
   需要看实拍图请引用官方产品页链接（放在「实物与资料」小节）。禁止把自绘图说成实拍。
6. 术语统一：`GPIO`、`定时器(TIM)`、`中断(IRQ)`、`DMA 通道`、`HAL 库 / LL 库 / SPL 标准外设库 / 寄存器`。
7. 行宽不限制，但**不要**使用 HTML `<script>`、外链图片（GitHub 会代理失败）。

## 4. 可视化资产清单（由 `tools/` 脚本生成，勿手改）

见 `assets/README.md`。文档只能引用清单里已存在的文件名；如果确实需要新图，
先在 issue/PR 里说明，或用 `tools/svgkit.py` 自行生成后再引用。

