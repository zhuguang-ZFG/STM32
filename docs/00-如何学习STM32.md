## 零基础预备

这一节写给从没接触过电路或 C 语言的读者，读完大约要一个下午。下面三句如果都看得懂，可以直接跳到「核心原理」：

- 3.3 V 加在 330 Ω 电阻两端，电流是 10 mA。
- `0x2C` 是二进制 `0010 1100`，也就是十进制 44。
- `GPIOC->BSRR = (1U << 13);` 只把 PC13 这一只脚置高，同一端口的其他脚不受影响。

### 1. 电压、电流、电阻

先打个比方：把电路想成水管。电压像水位差，水塔比地面高得越多，水压越大；电流像每秒流过的水量；电阻像管子上一段变窄的地方，越窄，流过的水越少。

比方到这里为止。水管破了水会洒出来，电流却只在一个闭合的圈里流：从电源正极出发，经过电阻、LED 这些器件，回到电源负极（GND）。这个圈叫回路，断开任何一处，电流就停了。

三个量的意思和单位：

- **电压**，单位伏特（V）。电压永远是两点之间的差。电路里约定一个点为 0 V，叫「地」，写作 GND。说「PA0 是 3.3 V」，意思是 PA0 和 GND 之间差 3.3 V。
- **电流**，单位安培（A）。单片机电路里的电流很小，常用毫安（mA），1 mA = 0.001 A。
- **电阻**，单位欧姆（Ω）。常用千欧（kΩ），1 kΩ = 1000 Ω。

三者的关系叫欧姆定律：

```text
电压 = 电流 × 电阻        V = I × R
电流 = 电压 ÷ 电阻        I = V ÷ R
```

算两个例子：

- 3.3 V 加在 330 Ω 电阻两端：I = 3.3 ÷ 330 = 0.01 A = 10 mA。
- 按键电路里的 10 kΩ 上拉电阻，按下时 3.3 V 全落在它上面：I = 3.3 ÷ 10000 = 0.00033 A = 0.33 mA。电流很小，所以上拉电阻几乎不耗电。

电阻上的电流会变成热，功率 P = V × I。上面第一个例子是 3.3 V × 0.01 A = 0.033 W，也就是 33 mW。常见的 1/4 W 电阻能承受 250 mW，绰绰有余。

还有两个词每章都会用到：

- **短路**：两点之间的电阻接近 0，按欧姆定律电流会非常大，轻则电源保护，重则烧坏器件。把 3.3 V 直接连到 GND 就是短路。
- **共地**：两块板子之间传信号，GND 必须连在一起。电压是两点之间的差，不共地，一块板说的「3.3 V」在另一块板上就没有参照。

单位前缀在整本书里反复出现，下表一次列全，遇到不认识的回来查：

| 写法 | 读法 | 等于 |
| --- | --- | --- |
| mA | 毫安 | 0.001 A |
| µA | 微安 | 0.000001 A |
| kΩ | 千欧 | 1000 Ω |
| MΩ | 兆欧 | 1000000 Ω |
| kHz | 千赫 | 每秒 1000 次 |
| MHz | 兆赫 | 每秒 1000000 次 |
| ms | 毫秒 | 0.001 s |
| µs | 微秒 | 0.000001 s |
| ns | 纳秒 | 0.000000001 s |

### 2. 高电平、低电平和时钟

数字电路只认两种状态：电压接近电源电压，叫高电平，记作 1；电压接近 0 V，叫低电平，记作 0。STM32F103 用 3.3 V 供电，多高算 1、多低算 0，第 03 章给出数据手册里的数字。

电平从 0 变成 1 的那一刻叫**上升沿**，从 1 变成 0 叫**下降沿**。很多外设说「在上升沿动作」，指的就是这一刻。

```text
 1        +-----+     +-----+     +-----+
          |     |     |     |     |     |
 0   -----+     +-----+     +-----+     +-----
          A     B     C
```

图里 A 是上升沿，B 是下降沿，从 A 到 C 是一个**周期**，记作 T。一秒钟里重复多少个周期叫**频率**，单位赫兹（Hz）。两者互为倒数：

```text
频率 f = 1 ÷ 周期 T
1 Hz    → 周期 1 s
1 kHz   → 周期 1 ms
72 MHz  → 周期约 13.9 ns
```

一个周期里高电平占的比例叫**占空比**。上图高低各占一半，占空比是 50%。第 05 章的 PWM 就是靠改占空比调亮度和转速。

芯片里有一个一直在 0 和 1 之间翻转的信号，叫**时钟**。CPU 和外设每来一个时钟边沿就往前走一步，时钟越快，同样的活干得越快，也越费电。STM32 为了省电，外设上电后默认没有时钟，所以「先开时钟」几乎是每一章代码的第一步。

### 3. 二进制和十六进制

一个 0 或 1 叫一**位**（bit）。8 位是一个**字节**（byte），能表示 0 到 255。STM32 的寄存器是 32 位，也就是 4 个字节。

二进制从右往左，每一位的分量依次是 1、2、4、8、16、32、64、128……哪一位是 1，就把那一位的分量加起来。`0010 1100` 从右数第 2、3、5 位是 1（最右边算第 0 位），所以等于 4 + 8 + 32 = 44。

二进制写起来太长，于是每 4 位合成一个**十六进制**数字。十六进制用 0–9 再加 A–F，A 表示 10，F 表示 15。C 语言里在前面写 `0x` 表示十六进制。`0010 1100` 分成 `0010` 和 `1100` 两组，分别是 2 和 C，合起来就是 `0x2C`。

下表是最常用的几个对照，十六进制和二进制之间每 4 位一一对应：

| 十进制 | 二进制 | 十六进制 |
| --- | --- | --- |
| 0 | 0000 | 0x0 |
| 1 | 0001 | 0x1 |
| 5 | 0101 | 0x5 |
| 9 | 1001 | 0x9 |
| 10 | 1010 | 0xA |
| 12 | 1100 | 0xC |
| 15 | 1111 | 0xF |
| 16 | 0001 0000 | 0x10 |
| 44 | 0010 1100 | 0x2C |
| 255 | 1111 1111 | 0xFF |

换算时，十六进制转二进制，就把每一个十六进制数字单独展开成 4 位；二进制转十六进制，从右往左每 4 位一组。Windows 自带计算器的「程序员」模式可以直接换算，拿来对答案很方便。

内存地址也用十六进制写。在 STM32F103 上，`0x08000000` 是 Flash 的起点，`0x20000000` 是 SRAM 的起点，从 `0x40000000` 开始是外设的寄存器（[RM0008](#source-rm0008) 第 3.3 节）。

### 4. 位运算：只动一个位

寄存器里的每一位常常单独管一件事。比如 RCC_APB2ENR 这个寄存器的第 4 位叫 IOPCEN，写 1 就打开 GPIOC 的时钟（RM0008 第 7.3.7 节）。改这一位时，同一个寄存器里别的位不能被碰到，这就要用位运算。

下表用一个 8 位的数 `x = 0000 1111`（`0x0F`）做例子，位号从最右边的第 0 位数起：

| 想做的事 | 写法 | 结果 | 说明 |
| --- | --- | --- | --- |
| 造一个只有第 5 位是 1 的数 | `1U << 5` | `0010 0000` | 把 1 往左移 5 位 |
| 把第 5 位置 1 | `x \| (1U << 5)` | `0010 1111` | 或：有 1 就是 1 |
| 把第 2 位清 0 | `x & ~(1U << 2)` | `0000 1011` | `~` 把每一位取反，再「与」 |
| 把第 0 位翻转 | `x ^ (1U << 0)` | `0000 1110` | 异或：相同得 0，不同得 1 |
| 看第 3 位是不是 1 | `x & (1U << 3)` | `0000 1000` | 结果不是 0，说明那一位是 1 |

实际代码里常写成复合赋值：`x |= (1U << 5);` 就是 `x = x | (1U << 5);` 的简写。

`1U` 里的 `U` 表示无符号数。写成 `1 << 31` 时，1 是有符号的 `int`，左移到最高位在 C 语言里属于未定义行为，编译器怎么处理都不算错。养成写 `1U` 的习惯，就不会掉进这个坑。

### 5. C 语言里和硬件打交道的几样东西

C 语言的基础语法（变量、`if`、`for`、函数）这里不重复，找一本 C 语言入门书学到指针那一章就够开始了。下面只讲单片机程序里天天见、入门书里讲得少的几样。

**固定宽度的整数。** `<stdint.h>` 里的 `uint8_t`、`uint16_t`、`uint32_t` 分别是 8 位、16 位、32 位的无符号整数。寄存器是 32 位，所以用 `uint32_t`。`int` 有多宽由编译器决定，不拿它表示寄存器。

**指针。** 指针是一个存放地址的变量。`uint32_t *p` 读作「p 指向一个 32 位的数」，`*p` 就是那个地址上存的数。

**volatile。** 它告诉编译器：这个地址上的值随时可能被硬件或中断改掉，每次读写都必须真的去访问，不许省略，也不许合并。寄存器和中断里会改的全局变量都要加。不加的话，打开优化后，编译器可能把「反复读一个状态位，等它变成 1」的循环优化成只读一次，程序就卡在那里。

把这三样放在一起，就能直接写寄存器：

```c
#include <stdint.h>

/* RCC_APB2ENR 的地址：RCC 基地址 0x40021000 + 偏移 0x18 */
#define RCC_APB2ENR  (*(volatile uint32_t *)0x40021018UL)

RCC_APB2ENR |= (1U << 4);   /* 第 4 位 IOPCEN：打开 GPIOC 的时钟 */
```

从里往外读：`0x40021018UL` 只是一个数；`(volatile uint32_t *)` 把它当成「指向一个 32 位寄存器的地址」；最外层的 `*` 取出那个地址上的寄存器本身；`|=` 只把第 4 位置 1。地址和偏移来自 [RM0008](#source-rm0008) 第 3.3 节表 3 和第 7.3.7 节。

**结构体和 `->`。** 一个外设有一组寄存器，厂商的头文件把它们写成结构体。`GPIOC` 是一个指向地址 `0x40011000` 的结构体指针，ODR 在这组寄存器里的偏移是 `0x0C`，所以 `GPIOC->ODR` 就是地址 `0x4001100C` 上的那个寄存器。写 `GPIOC->ODR` 和自己算地址是同一件事，只是不容易写错。

**宏 `#define`。** 宏是编译之前的文本替换，常用来给数字起名字，比如 `#define LED_PIN GPIO_PIN_13`。代码里出现的是名字而不是光秃秃的数字，别人一看就懂。

### 6. 单片机里面有什么

单片机就是装进一颗芯片里的小电脑。下表以本书用的 STM32F103C8T6 为例，数字来自 [DS5319](#source-ds5319) 的特性列表和 [RM0008](#source-rm0008) 第 3.3 节的存储器映射：

| 部件 | 作用 | 在 STM32F103C8T6 上 |
| --- | --- | --- |
| CPU 内核 | 一条一条执行指令 | Arm Cortex-M3，最高 72 MHz |
| Flash | 存程序，断电不丢 | 64 KB，从 `0x08000000` 开始 |
| SRAM | 存运行时的变量，断电就丢 | 20 KB，从 `0x20000000` 开始 |
| 外设 | GPIO、定时器、串口、ADC 等 | 寄存器从 `0x40000000` 开始 |
| 时钟系统 | 给 CPU 和外设提供节拍 | 第 02 章细讲 |

型号本身也是一张说明书。按 DS5319 Rev 20 第 7 节「Ordering information scheme」拆开：

| 片段 | 含义 |
| --- | --- |
| STM32 | Arm 内核的 32 位单片机家族 |
| F | 通用型 |
| 103 | 增强型（Performance line）子系列 |
| C | 48 只引脚 |
| 8 | 64 KB Flash |
| T | LQFP 封装 |
| 6 | 工业级温度范围，−40 到 85 °C |

上电或复位以后，事情按这个顺序发生：

1. CPU 从地址 `0x00000000` 读出栈顶地址，从 `0x00000004` 读出复位后第一条要执行的代码在哪里。BOOT0 接低电平时，这两个地址指向 Flash 里你烧进去的程序（细节在本章「原理与适用范围」）。
2. 启动代码开始运行：把有初值的全局变量从 Flash 复制到 SRAM，把没有初值的清零，调用 `SystemInit`，最后进入 `main`。
3. `main` 里打开外设时钟、配置外设，然后进入 `while (1)` 循环一直跑下去。

所谓**寄存器**，就是外设里一个个有固定地址的 32 位格子。往格子里写数等于给硬件下命令，从格子里读数等于看硬件的状态。

### 7. 怎么读数据手册

每颗 STM32 都配几份手册，各管一摊。下表是 STM32F103C8 用到的几份：

| 手册 | 编号 | 查什么 |
| --- | --- | --- |
| 数据手册（Datasheet） | DS5319 | 这颗芯片有哪些外设、引脚表、电气参数、封装尺寸 |
| 参考手册（Reference manual） | RM0008 | 每个外设怎么工作，每个寄存器每一位的含义，整个 F1 系列共用一本 |
| 编程手册（Programming manual） | PM0056 | Cortex-M3 内核本身：中断控制器 NVIC、SysTick、异常、指令 |
| 勘误手册（Errata sheet） | 在 ST 官网同一芯片页面下载 | 芯片已知的问题和绕过办法 |

数据手册里最常查的是两类表。

**引脚表**（DS5319 表 5）：每一行是一只脚，写着它在各种封装上的脚号、名字、类型、是否标 FT（能承受 5 V）、复位后的默认功能和可选的复用功能。接线之前先查这张表。

**电气参数表**：每一行有 Min、Typ、Max、Unit 和测试条件几列。按 DS5319 Rev 20 第 5.1.1 和 5.1.2 节的定义，Min 和 Max 是保证值，除非注脚说明是「基于表征」，否则都经过量产测试；Typ 是 25 °C、3.3 V 下的典型值，只作设计参考，不保证。所以算余量时用 Min 或 Max，不用 Typ。还要分清「绝对最大额定值」（表 6、表 7）和「工作条件」（表 9）：前者是超过就可能损坏的红线，后者才是正常工作的范围，比如 VDD 的工作范围是 2 V 到 3.6 V。

参考手册里每个寄存器都写着偏移（Address offset）和复位值（Reset value），每一位下面标着访问方式。最常见的几种，按 RM0008 Rev 21 第 2.2 节：

| 标记 | 意思 |
| --- | --- |
| rw | 可读可写 |
| r | 只读 |
| w | 只写，读出来是复位值 |
| rc_w1 | 可读，写 1 把它清零，写 0 没有作用 |
| rc_w0 | 可读，写 0 把它清零，写 1 没有作用 |
| rc_r | 可读，读一次就自动清零 |

寄存器的实际地址 = 外设基地址 + 偏移。基地址在 RM0008 第 3.3 节表 3，偏移在各外设章节的寄存器说明里。

### 8. 工具和安全

- **万用表量电压**：表笔并在两点上，红笔接电压高的一端，黑笔接 GND。
- **万用表量电流**：表要串进回路里，红笔还要换到电流插孔。量完立刻把红笔插回电压插孔；忘了换回去就去量电压，等于用电流档把两点短路。
- **通断档**：蜂鸣器响，说明两点之间是通的。查虚焊、查线有没有接上都用它。
- **先断电再改线**：通电时插拔杜邦线，很容易碰到相邻的脚造成短路。
- **3.3 V 和 5 V 分清楚**：STM32F103 的 VDD 工作范围是 2 V 到 3.6 V（DS5319 表 9）。BluePill 板上标 5V 的脚直接连着 USB 的 5 V，标 3.3 的脚是稳压后的 3.3 V，不要接反。5 V 模块的信号不要随便接到 STM32 的脚上，只有标 FT 的脚能承受，第 03 章细讲。
- **发烫或有焦味**：立刻拔电，再查哪里短路了。

## 核心原理

**一句话结论：STM32 入门不需要学完整个电子工程，只需要「够用」的前置知识，加上一条不跳步的路线。**

### 先打个比方

学 STM32 像学开车。不用先学会修发动机，但交通规则（基础电路和 C 语言）和仪表盘（数据手册、寄存器）得认识。先在空场地练起步（点一颗灯），再上路（串口、I2C、SPI），最后才跑长途（一个完整项目）。

比方到这里为止。开车可以凭感觉，单片机不行：频率、电流、地址，每一个数字都要能算出来，也能在手册里查到出处。

### 1. 前置知识「够用」标准

下表左列是必须会的，中间是了解即可，右列是需要回头补课的信号。右列中了哪一条，就回到上面的「零基础预备」对应小节。

| 知识块 | 最低要求（必须会） | 够用即可（了解） | 需要补课的信号 |
| --- | --- | --- | --- |
| C 语言 | 指针、数组、结构体、`typedef`、`enum`、位运算 `& \| ^ ~ << >>`、函数指针 | 宏与条件编译、`volatile`/`static`/`const` 语义 | 看到 `*(volatile uint32_t*)0x40021018` 完全懵 |
| 数字电路 | 高低电平、与或非、上升/下降沿、推挽/开漏概念 | 时序图、建立/保持时间、总线仲裁 | 看不懂「上升沿触发」是什么意思 |
| 模拟电路 | 欧姆定律、分压、LED 限流电阻、上拉电阻作用 | 三极管/MOS 开关、运放基础、RC 滤波 | 不会算 LED 限流电阻 R=(Vcc−Vf)/I |
| 计算机组成 | 二进制/十六进制、字节与地址、寄存器是什么 | 中断、DMA、总线、Cache | 不理解「寄存器」和「内存」的关系 |
| 英语 | 能读数据手册里的引脚表、参数表 | 能读参考手册整章 | 连 Pin Name 都查不下去 |

一句话标准：**能用指针操作一个 `uint32_t` 变量，能算 LED 限流电阻，能读懂引脚表**，就可以开始了。推挽、开漏、限流电阻这几样第 03 章还会从头讲一遍。

### 2. 三种开发方式对比

写 STM32 程序有三种常见方式，区别在于离寄存器有多远：

| 维度 | 寄存器（裸寄存器） | 标准库 SPL | HAL + LL + CubeMX |
| --- | --- | --- | --- |
| 抽象层级 | 最低，直接写 `GPIOA->ODR` | 中，`GPIO_SetBits()` | 最高，`HAL_GPIO_WritePin()` |
| 上手难度 | 高（要一直翻手册） | 中 | 低（图形化生成初始化代码） |
| 代码量 | 少但晦涩 | 中 | 多但清晰 |
| 可移植性 | 差（F1 换 F4 要改） | 差（F1、F4 各有一套 SPL） | 好（HAL 跨系列统一 API） |
| 资源占用 | 最小 | 小 | 略大（可裁剪，LL 更小） |
| 官方维护 | 不依赖任何库，一直能用 | **已停止维护** | 持续更新 |
| 适用场景 | 学原理、抠时序、资源极紧 | 老工程维护 | 新产品、快速原型、求职主流 |

HAL 是 Hardware Abstraction Layer（硬件抽象层）的缩写，LL 是 Low Layer，CubeMX 是 ST 的图形化配置工具，能把时钟和引脚配置生成成代码。

**建议路线：先用 HAL 和 CubeMX 入门，再对照寄存器理解底层，关键的地方用 LL 优化。**

如果你接手的是 F103 标准库旧工程，不要把函数名零散混进 HAL 工程；先读[第 26 章 · STM32F10x 标准外设库（SPL）](26-STM32F10x标准外设库SPL.md)，锁定 V3.5.0、密度宏、启动文件和外设所有权，再决定维护或迁移。

## 代码实现

「第一个程序」：让板载 LED（PC13，低电平点亮）每秒闪一次。这是验证环境是否搭好的标准动作。

```c
/* main.c —— BluePill 板载 LED(PC13) 1Hz 闪烁
 * 依赖：STM32F1 HAL 库，系统时钟 72MHz
 */
#include "stm32f1xx_hal.h"

#define LED_PIN   GPIO_PIN_13
#define LED_PORT  GPIOC

static void SystemClock_Config(void);   /* 由 CubeMX 生成或手写 */

int main(void)
{
    HAL_Init();                 /* 初始化 HAL、SysTick、中断优先级分组 */
    SystemClock_Config();       /* 配置 HSE 8MHz -> PLL x9 -> 72MHz */

    __HAL_RCC_GPIOC_CLK_ENABLE();   /* 关键：先开 GPIO 时钟，否则寄存器写不进 */

    GPIO_InitTypeDef gpio = {0};
    gpio.Pin   = LED_PIN;
    gpio.Mode  = GPIO_MODE_OUTPUT_PP;   /* 推挽输出 */
    gpio.Pull  = GPIO_NOPULL;
    gpio.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(LED_PORT, &gpio);

    while (1)
    {
        HAL_GPIO_TogglePin(LED_PORT, LED_PIN);  /* 翻转电平 */
        HAL_Delay(500);                         /* 500ms，半周期 */
    }
}

/* 时钟配置（也可用 CubeMX 生成的版本） */
static void SystemClock_Config(void)
{
    RCC_OscInitTypeDef osc = {0};
    RCC_ClkInitTypeDef clk = {0};

    osc.OscillatorType = RCC_OSCILLATORTYPE_HSE;
    osc.HSEState       = RCC_HSE_ON;
    osc.HSEPredivValue = RCC_HSE_PREDIV_DIV1;
    osc.PLL.PLLState   = RCC_PLL_ON;
    osc.PLL.PLLSource  = RCC_PLLSOURCE_HSE;
    osc.PLL.PLLMUL     = RCC_PLL_MUL9;        /* 8MHz x 9 = 72MHz */
    HAL_RCC_OscConfig(&osc);

    clk.ClockType      = RCC_CLOCKTYPE_HCLK | RCC_CLOCKTYPE_SYSCLK |
                         RCC_CLOCKTYPE_PCLK1 | RCC_CLOCKTYPE_PCLK2;
    clk.SYSCLKSource   = RCC_SYSCLKSOURCE_PLLCLK;
    clk.AHBCLKDivider  = RCC_SYSCLK_DIV1;   /* AHB = 72MHz */
    clk.APB1CLKDivider = RCC_HCLK_DIV2;     /* APB1 = 36MHz（上限 36MHz） */
    clk.APB2CLKDivider = RCC_HCLK_DIV1;     /* APB2 = 72MHz（上限 72MHz） */
    HAL_RCC_ClockConfig(&clk, FLASH_LATENCY_2);  /* 72MHz 需 2 个等待周期 */
}
```

逐段看：

- `HAL_Init()` 先把 HAL 库自己准备好，其中包括让 SysTick 每 1 ms 产生一次中断，`HAL_Delay()` 就靠它计时。
- `SystemClock_Config()` 把系统时钟从上电默认的 8 MHz 内部时钟切到 72 MHz：外部 8 MHz 晶振（HSE）经 PLL 乘 9。时钟树第 02 章细讲，这里先照抄。
- `__HAL_RCC_GPIOC_CLK_ENABLE()` 打开 GPIOC 的时钟，就是上面「零基础预备」第 5 小节那行 `RCC_APB2ENR |= (1U << 4);`。
- `GPIO_InitTypeDef` 那几行把 PC13 配成推挽输出，各项含义第 03 章逐一讲。
- `while (1)` 里每 500 ms 翻转一次电平：亮 500 ms、灭 500 ms，一个周期 1 s，也就是 1 Hz。

寄存器等价写法（理解底层）：

```c
/* 不用 HAL 时，点灯的四行核心操作 */
RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;        /* 使能 GPIOC 时钟 */
GPIOC->CRH &= ~(0xF << 20);                 /* 清 PC13 配置位 */
GPIOC->CRH |=  (0x2 << 20);                 /* PC13 通用推挽输出 2MHz */
GPIOC->ODR ^= GPIO_ODR_ODR13;               /* 翻转 PC13 */
```

PC13 的配置在 CRH 寄存器里：CRH 管第 8 到 15 脚，每只脚占 4 位，PC13 是 (13 − 8) × 4 = 20，所以占第 20 到 23 位。`0x2` 是二进制 `0010`：低两位 MODE = 10 表示 2 MHz 输出，高两位 CNF = 00 表示通用推挽（[RM0008](#source-rm0008) 第 9.2.2 节）。

完整工程见 [`examples/gpio-blink/`](../examples/gpio-blink/)。

## 动手实验

1. **实验一：环境验证。** 按上面的代码让 PC13 以 1 Hz 闪烁。
   - 预期现象：板载 LED 每秒亮灭一次。BluePill 上这颗灯多数是绿色，也有红色的，以手上的板子为准；另一颗常亮的是电源灯。
   - 怎么确认：用手机秒表数 10 次闪烁，应在 10 s 左右。
   - 没成功先查：BOOT0 跳线是不是接在 0；ST-Link 的四根线有没有接错；工程里写的是不是 PC13。
2. **实验二：改动参数。** 把 `HAL_Delay(500)` 改成 100。
   - 预期现象：闪烁明显变快。
   - 怎么确认：用逻辑分析仪量 PC13，高、低电平各约 100 ms，周期约 200 ms，频率约 5 Hz。
   - 没成功先查：改完有没有重新编译、重新下载。
3. **实验三：寄存器对照。** 用上面的寄存器写法实现同样的闪烁，对比 HAL 版本。
   - 预期现象：灯的节奏和 HAL 版本一样。
   - 怎么确认：在调试器里单步，看 `GPIOC->CRH` 第 20 到 23 位是不是 `0010`，`ODR` 第 13 位是不是每次翻转。
   - 没成功先查：时钟开了没有；移位的位数是不是 20。

## 自测

1. 3.3 V 加在 330 Ω 电阻两端，电流是多少？这个电阻发热多少毫瓦？
2. `0x2C` 换成二进制和十进制各是多少？
3. 只把变量 `x` 的第 5 位置 1、不动其他位，C 语言怎么写？只把第 2 位清 0 呢？
4. 为什么指向寄存器的指针要加 `volatile`？
5. BOOT0 接低电平时，复位后 CPU 从哪里取程序？

参考答案：

1. I = 3.3 ÷ 330 = 0.01 A = 10 mA；P = 3.3 V × 0.01 A = 0.033 W = 33 mW。
2. `0x2C` 的两位分别是 2 和 C，展开成 `0010` 和 `1100`，合起来是 `0010 1100`；十进制是 32 + 8 + 4 = 44。
3. `x |= (1U << 5);` 置 1；`x &= ~(1U << 2);` 清 0。
4. 寄存器的值会被硬件随时改变。不加 `volatile`，编译器优化时可能只读一次就把结果留在 CPU 里，之后硬件改了也看不到，程序就卡在等待里。
5. 从主 Flash 取。BOOT0 = 0 时，地址 `0x00000000` 映射到从 `0x08000000` 开始的 Flash，CPU 从 `0x00000000` 读栈顶、从 `0x00000004` 读复位向量，取到的就是你烧进去的程序。

## 原理与适用范围

> [!NOTE]
> 从这一节到「常见坑与出处」是深入部分，把前面的结论落到具体订货号、手册章节和能复算的数字上。第一次读可以先跳过，做完动手实验再回来对照。

这一节只讲一件事：复位之后，CPU 为什么会去跑 Flash 里的程序。结论按订货号 STM32F103C8T6 来记，出自 [RM0008 Rev 21 第 3.4 节表 9](#source-rm0008-boot)。G0、H7 的启动表不一样，不要拿来填这一行。

**BOOT 脚什么时候算数。**BOOT 脚的电平在复位之后 SYSCLK 的第 4 个上升沿被锁存，退出 Standby 时还会再采样一次。锁存完成之前程序还没开始跑，所以在 `main` 里再改 BOOT 脚已经晚了。锁存之后，CPU 从 `0x00000000` 取栈顶，从 `0x00000004` 取复位向量。

**BOOT0 = 0：从 Flash 启动。**不管 BOOT1 是什么，主闪存都被映射到 `0x00000000`，闪存本体仍在 `0x08000000`。刚烧进去的程序要被执行，走的就是这一行。

**BOOT0 = 1、BOOT1 = 0：进系统存储器。**系统存储器被映射到 `0x00000000`，里面是 ST 出厂写好的串口下载程序。STM32F103C8T6 不是互联型，系统存储器在 `0x1FFFF000`；互联型的 `0x1FFFB000` 在这颗芯片上不适用。

**BOOT0 = 1、BOOT1 = 1：从 SRAM 启动。**SRAM 本体在 `0x20000000`，跑的不是 `0x08000000` 里的那份程序。XL 密度 Bank2 的 `0x08080000` 对这颗 64 KB 的 C8 也不适用。

## 时序与状态

下表把三种启动状态放在一起，按 BOOT1、BOOT0 两列对照你板子上的跳线：

| 状态 | BOOT1 | BOOT0 | CPU 从 0x00000000 取到什么 | 在 STM32F103C8T6 上 |
| --- | --- | --- | --- | --- |
| 正常：刚烧入的程序会跑 | x | 0 | 主闪存的别名；本体仍在 0x08000000 | 成立。下一字地址是 0x00000004 |
| 失败：烧了仍停在系统存储器 | 0 | 1 | 系统存储器的别名 | 本体地址是 0x1FFFF000；0x1FFFB000 不适用 |
| 失败：从 SRAM 启动 | 1 | 1 | 不是闪存里的程序 | SRAM 在 0x20000000；0x08080000 不适用 |

表里的 x 表示 0 和 1 都一样。锁存点是复位后第 4 个 SYSCLK 上升沿，出处是 [RM0008 Rev 21 表 9](#source-rm0008-boot)。

## 常见坑与出处

| 现象 | 原因 | 处理 | 出处 | 出处能证明的部分 |
| --- | --- | --- | --- | --- |
| 程序已经写进 0x08000000，复位后跑的却不是它 | BOOT1=0 且 BOOT0=1，启动区别名到系统存储器 | 把 BOOT0 拉到 0，再复位 | [RM0008 表 9](#source-rm0008-boot) | 闪存本体仍在 0x08000000；这颗料的系统存储器是 0x1FFFF000 |
| 在 main 里才改 BOOT 脚，这一次复位已经走错 | 脚电平在第 4 个 SYSCLK 上升沿已经锁存 | 在复位之前摆好 BOOT0 与 BOOT1 | [RM0008 第 3.4 节](#source-rm0008-boot) | 锁存点是 SYSCLK 的第 4 个上升沿；退出 Standby 会再采样 |
| 把互联型或 XL 密度的启动地址抄进 C8 工程 | 0x1FFFB000 与 0x08080000 不是这颗料的行 | 系统存储器用 0x1FFFF000，闪存用 0x08000000 | [RM0008 第 3.4 节](#source-rm0008-boot) | 这两行在 STM32F103C8T6 上不适用 |
