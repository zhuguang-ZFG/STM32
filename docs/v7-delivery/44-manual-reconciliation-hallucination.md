# 手册对账与幻觉防御

AI 的输出里混着三类话：手册里有的、手册里没有但它编得很像的、以及它自己都不知道是哪类的。对账（把输出逐条按回手册）与幻觉防御（按类型分流、按成本处置）是本章的两件武器；最后用本书自己的生产管线自证——这套方法不是口号，本书每一章都是它产出的，门禁会自己报警。

证据先说清：本章的事实断言全部可复现——AI05 的数字断言逐条重测（13 道门与 27 条声明成立；`check_pdf.py` 的 main 已从 619 漂到 **631**；测试函数 73 个（收集数待核）；题花 101（旧稿写 100）；动画 111（旧稿写 109）；章数 94（「91」是过程数））；工具红线三句按快照（2026-10-27）转写；「假勘误四件套」是**编造示例，请勿当真**——它在书里就是教你看穿编造的样本。板名口径：霸天虎（旧稿「霸道者」错名已统一）。

> 版本口径：AI02《手册对账》（`mcu/docs/ai/02-manual-reconciliation.md`）、AI04《幻觉防御》（`.../04-hallucination-defense.md`）、AI05《本书生产管线》（`.../05-this-book-pipeline.md`）；mcu 子树门禁（`mcu/mcu-book/check_pdf.py`、`tools/prose_guard.py`、`tools/art_guard.py`、`mcu/scripts/docs-check.mjs`、`anim-lint.mjs`）与根书门禁（`tools/slop_lint.py`、`book/checks.py`）是**两套独立的门禁**（后者 SKIP mcu 目录），本章按域分开列，禁混写成一套。RM0090 口径与 [v1 第 9 章](../v1-drivers/09-gpio.md) 一致。

## 本章罗盘

- **问题**：对账三问（名/位/序）怎么查，「雷 1 炸出两处伤」的案例说明什么？证据回喂三元组是什么，为什么「道歉是文体不是修正动作」？八类幻觉（手册层 4 + 话语层 4）各长什么样、判据是什么、最低成本动作是什么？验证决策树的分流入口在哪，两条入口纪律是什么？软约束/硬门禁的分界与「不经过模型意志、失败会自己报警」的门禁定义是什么？本书生产管线的八道工序与三起事故各证明了什么？

## 先做出来

### 1. 对账三问：名、位、序

AI 说「开 GPIOF 时钟要置 `RCC_APB1ENR` bit5」。三问：

1. **名**：寄存器叫对了吗？RM0090 §7.3：`RCC_APB1ENR` bit5 是 **TIM7EN**——不是 GPIOF。位名张冠李戴。
2. **位**：位号对了吗？GPIOFEN 在 `RCC_AHB1ENR` bit5——寄存器名错了，位号倒是延续的。
3. **序**：顺序对了吗？先开 GPIO 时钟再写 GPIO 寄存器——这个序它说对了。

一条输出三问全过才算过；「雷 1 炸出两处伤」的案例就是位号对、寄存器错——单看位号会漏判。**道歉是文体不是修正动作**：模型说「抱歉我错了」不改变任何事实，回喂三元组（实测现象 + 手册出处 + 板卡事实）才算修正。

### 2. 证据回喂

发现错误后的标准动作：把**实测现象**（比如「引脚没翻转」）+ **手册出处**（RM0090 §7.3 的原句）+ **板卡事实**（原理图网络名）三条一起写回对话或文档。只写「你错了」不给证据，下一轮回答的采样分布不会移动——**模型的每次回答是独立采样**，「下次会更正」不是结论。

## 机制

### 一、八类幻觉：手册层四类 + 话语层四类

| 类 | 长相 | 判据 | 最低成本动作 |
| --- | --- | --- | --- |
| 手册·位名张冠李戴 | bit5 说是 GPIOFEN 实为 TIM7EN | 手册位表 | 30 秒 grep 头文件/手册 |
| 手册·地址错位 | 基址/偏移差 0x400 | 存储器映射表 | 章节检索 |
| 手册·修订版差异 | Rev V 才有的特性写成全系列 | errata/ES 文档 | 分钟级勘误检索 |
| 手册·特性编造 | 「硬件 CRC 单元」其实没有 | 特性表 | 特性表核对 |
| 话语·引用幻觉 | 引「§7.3 存储器映射」实际在 §2.3 | 章节检索 | 30 秒 |
| 话语·行号漂移 | `main:619` 实为 631 | 重测 | grep -n |
| 话语·数字陈旧 | 「100 枚题花」实为 101 | 重数 | 重数 |
| 话语·编造示例当真 | 假勘误四件套（**编造示例，请勿当真**） | 原文自带标注 | 看标注 |

八类的成本序（教学口径，不是测量）：30 秒 grep → 1 分钟章节检索 → 分钟级勘误/逐位 → 分钟级跑现象。总原则：**先存在性，后语义**——先查「这东西存在吗」，再查「它是我说的意思吗」。ESP32 侧的能力宏（`soc_caps.h`）是终裁（[第 30 章](../v4-platforms/30-esp32s3-architecture-boot.md) 口径）。

### 二、验证决策树与两条入口纪律

决策树的根是 [第 43 章](./43-ai-pair-programming.md) 的分界线问题：**正确性定义在公共知识，还是在你的板子与责任里？** 公共知识（手册可查）→ 三问对账；板卡事实（原理图/丝印）→ 实测读回；你的责任（安全边界/阈值）→ 不进 AI。两条入口纪律：**30 秒分诊**——任何 AI 断言先花 30 秒分类（手册层/话语层/板卡层）；**贴不出证据默认升级**——拿不出出处与判据的断言，按最高成本路径处理。

对账分级表（AI02 口径）：RCC 与模式寄存器**永远逐位**；应用层抽样；纯算法单测。个人幻觉案例库四栏：类型/长相/判据/出处——被坑一次就记一行，你的案例库是你个人的分布地图。

### 四、本书生产线自证

本书自己就是这套方法的产品：**八道工序十几道门**（选题→研究→计划→写作→门禁→评审→修复→证据归档），三起真实事故——滤镜题图被光栅化（art_guard 抓出）、U+2011 幽灵连字符（印前门抓出）、手写数字漂移（docs-check 的 CLAIMS 抓出：任何命中的数字必须等于当前真相）。AI 在管线里的四个角色：研究代理（只读对账）、写作协作者、评审代理、门禁执行者——file-first 纪律：一切结论落文件，不留在对话里。四条不许碰边界：**终审裁决、上板实测、出版决策、阈值只紧不松**——全部留给人。

度量表：每条论断配一条可复现命令。本章的三条复现命令按合并仓库路径写：

```bash
python mcu/mcu-book/check_pdf.py <PDF>            # 13 道印前门
python mcu/mcu-book/tools/prose_guard.py --single <章节文件>
npm run docs:check --prefix mcu                   # 27 条 CLAIMS
```

（`mcu/docs/ai/02-…` 这类旧路径在合并后已不存在，--single 参数改指本章文件；命令实跑输出在批次证据里登记。）

## 失败分支

| 症状 | 第一条假设 | 区分实验 |
| --- | --- | --- |
| AI 断言与手册冲突 | 位名/地址/修订版三类之一 | 三问对账；30 秒 grep 先行 |
| 引用章节号查无此文 | 引用幻觉（话语层） | 章节检索真实位置 |
| 数字对不上 | 行号漂移或计数陈旧 | 重测重数；写「截至日期」 |
| 模型道歉但下轮还错 | 独立采样，道歉不是修正 | 回喂三元组；换证据不改语气 |
| 门禁报错但「内容没错」 | 门禁查的是形式（符号/路径/计数） | 修形式；门禁不解语义 |
| 两套门禁结论冲突 | 域不同（根书 vs mcu 子树） | 按域分别处理，禁混写 |
| 度量表命令跑不通 | 合并仓库路径已变 | 按本章改写后的路径实跑 |

## 离开检查

- 三问（名/位/序）能把一条 AI 输出对完账；雷 1 案例能复述。
- 回喂三元组能落地；「道歉是文体」的立场没有被稀释。
- 八类幻觉能分型并给出最低成本动作；「先存在性后语义」是总原则。
- 决策树能走；30 秒分诊与「贴不出证据默认升级」两条纪律记得住。
- 两套门禁按域分列不混写；「失败会自己报警」的门禁定义说得清。
- 三起事故与四条不许碰边界能复述；本章的数字全部是重测后的值。
