## 背景

《STM32 实战》是一本由 29 章教程构建的独立整书。正文在 `docs/00`–`docs/28` 与 `docs/en/` 的对应章；`stm32-book/` 在构建时加上分部、章首罗盘（问题 / 交付 / 边界 / 来源锚点）、文前版本与修订、书末主题索引，以及附录 A–F。文件名继续用两位章号 `00`–`28`。对外说「00–28，共 29 章」。

v1.0.7 是教程加厚后的第一版：原理写到能上手，深读、写实插图和可逐条核对的出处还没有铺进各章。加厚的对象就是这 29 章本身，目标是读起来有「经典大典」的密度。

对照 v1.0.7 核对过的事实：

1. **工程深读基本只在附录 A。** 附录 A《工程深读：UART + DMA + IDLE 的两个正确契约》是全书唯一的长篇深读（两份 DMA 契约、ISR 边界、验证矩阵，并在第 5 节顺带写了 H7 上「DMA 完成」不等于「CPU 看见新数据」）。附录 B–F 没有同等深读。附录 A–F 都没有插图。各章仍是教程骨架（学习目标、核心原理、代码、常见坑、实验），数字账集中在附录 D。
2. **教学图大约 40 张 SVG，另有 GIF；书稿不引用 PNG。** `assets/animations/` 25 张原理动画 SVG，`assets/diagrams/` 6 张静态框图，`assets/boards/` 10 张板卡与引脚 SVG，合计 41 张教学 SVG，外加书封 `stm32-book/cover.svg`。`assets/gif/` 有 30 个 GIF，多数是这些 SVG 的动效导出。全仓库 PNG 在 `assets/video/`（讲解封面）和一张公众号二维码，不进书稿。`stm32-book/` 下没有 PNG。中文 29 章的本地图引用以 SVG 为主，另有少量 GIF 和两张 CC0 的 Nucleo 实拍 JPG。中文章内图张数分布是：0 张 1 章、1 张 19 章、2 张 5 章、3 张 2 章、5 张 1 章、8 张 1 章。多数章只有一张程序绘制的示意。
3. **现有许可是「索引，不转载」。** `CREDITS.md` 把中文社区（正点原子、野火、硬汉嵌入式、电子发烧友、B 站课程等）写成索引，不转载内容。附录 E 写明：ST、Arm、FreeRTOS、USB-IF、IETF、OASIS、Wokwi、Renode 与第三方仓库只提供链接、文档号、少量必要事实和独立表述，不再分发其手册、规范或源码。这个禁令继续有效。大典加厚新增的是另一条路：在许可允许时**改写吸收**，并强制署名。见下文「来源与许可」。
4. **系列覆盖偏 F1/F4。** `00`–`22` 与 SPL 章的叙述以 F1（RM0008、F103）和 F4（RM0090 / RM0383、F411 等）为主。G0、L4、H7 的成章材料在第 23、24、25 章；第 27、28 章也写到 H7。附录 D 已有「换系列之前先对的账」，要求换订货号时整行重写。第一对样本不负责把 G0/L4/H7 补到与 F1/F4 同样的厚度。
5. **还没有图目录、表目录。** v1.0.7 的文前是版本与修订，书末是主题索引。目录展开到章，不展开章内二级标题。PDF 书签由构建时的 `outline=True` 按 HTML 标题生成，因此深到二级及以下。章眉当前是 `第 {文件名前两位} 章`，也就是「第 00 章」到「第 28 章」。

有一条独立轨道准备做成 **v1.0.8**：把显示章号改成 1–29，并把 PDF 书签收浅。那条轨道不在本设计里实施，也不放进样本章 PR。文件名保持 `00`–`28`。

## 目标与非目标

### 目标

- 把现有 29 章加厚到「经典大典」的密度：每章都能单独读完原理、看见写实插图、跟上时序或状态，并把坑钉在可点击的出处上。
- 先做**两章样本**，中文和英文一起加厚。用户复审通过后，再用同一模板铺开其余章。
- 样本的材料来自改写吸收，优先 ST 参考手册 / 应用笔记，以及 MIT、BSD、CC BY 的 GitHub 与社区材料。每条被吸收的材料都有出处卡。
- 样本图达到「逼真、翔实、生动」：印刷后不播放动画也能看懂，图上有真实信号名和来自冻结文档的数字。
- 新出处登记进附录 E 的来源卡（由 `manifest.json` / `manifest-en.json` 的 `sources` 生成）。章内出处卡链接到这些锚点。
- 样本合入时做一次 **minor** 版本提升。若当时 `main` 仍是 1.0.7 或并行轨道已先变成 1.0.8，加厚样本都升到 **1.1.0**。中英文整书共用这个版本号。

### 非目标

- 不另起一卷「大典」，不增加第 30 章，不改 `docs/00`–`28` 的文件名。
- 不在本设计 PR，也不在样本 PR 里，实现 v1.0.8 的显示章号 1–29 和浅层 PDF 书签。
- 不把厂商手册、应用笔记、社区文章或第三方仓库的正文、官方插图、PDF 放进仓库。
- 样本复审完成之前，不改其余 27 章的正文。
- 不改附录 D 三套账的既有算术：「会上手的几笔账」「换系列之前先对的账」「通道、描述符与故障寄存器」。加厚可以引用这些数，引用时整格照抄。
- 不把 `assets/video/` 的讲解封面收进书，不为样本章新做讲解视频。
- 不在样本阶段新增图目录或表目录。
- 不打 tag，不创建 GitHub Release。版本页可以在样本 PR 里写下 1.1.0；Release 仍按 `stm32-book/README.md` 的既有规矩，等提交进入 `main` 且 Book CI 产出四份文件之后，由有权限的人另行处理。

## 来源与许可

附录 E 的四层用法不变：

| 层 | 用来做什么 | 加厚时怎么用 |
| --- | --- | --- |
| 规范与芯片手册（RM、DS、PM、协议） | 引脚、电气、寄存器、时序数字的权威 | 写文档号；修订敏感的事实再写 Rev、Figure、Table 或章节。用自己的话重写，不粘贴手册段落，不描官方图 |
| 官方代码与应用笔记（AN、UM、Cube 例程） | 某一个固件包上的做法 | 冻结固件包或 commit。笔记里的步骤改写成本书实验，不随书分发 PDF |
| 官方社区与开源实现 | 发现坑、对照写法 | **新政策见下。** 社区结论仍不是规范；数字要能回到手册或冻结源码 |
| 本项目原创 | 章、例程、图、构建器 | 改写后的正文和图属于这一层，许可仍是正文 CC BY 4.0、代码 MIT |

### 改写吸收

「改写吸收」指：读一份质量够用的材料，用本书口吻重写要点，配自绘图，并在出处卡里写清来源。读者不打开原帖，也应能凭章内边界、时序和出处把结论核对回去。

允许吸收进正文的许可，按这个顺序选：

1. ST 公开的 RM、DS、PM、AN、UM、ES：只吸收事实，独立表述，附文档号与可点击的 ST 文档入口。不吸收原文句子和官方插图。
2. MIT、BSD-2-Clause、BSD-3-Clause、ISC、CC BY 4.0、CC BY 3.0、CC0：可以吸收教学要点。即使许可证不强制署名，本书仍强制署名。
3. 其他许可证（含 GPL、LGPL、CC BY-NC、CC BY-ND、保留所有权利、未写许可的博客和视频）：保持 v1.0.7 的索引政策。可以在「相关资源」放链接，供人自己去读。不把其中的段落、图或成段代码写进书或 `examples/`。

吸收社区材料时，权威数字仍以第 1 层为准。社区帖只支持「这个坑存在、有人这样踩过」。帖子里的寄存器值、电流、波特率误差，要在对应 RM/DS 上重新钉住之后才能写进「原理与边界」或「时序或状态」。钉不住的数留在出处卡的适用范围里，标明「经验线索，未升格为规范」。

GitHub 参考实现继续冻结 tag 或完整 commit，不用「main 现在看起来一样」当证据。社区文章记录访问日期和用途。

### 出处卡字段

附录 E 的卡片继续用现有字段，构建器已经会把 `sources` 里的每一条渲染成带链接的卡片（锚点 `#source-{id}`）：

- `title`
- `authority`
- `url`（正文里的「打开来源」必须可点击）
- `snapshot`（文档 Rev，或 tag / 完整 commit）
- `accessed`（`YYYY-MM-DD`）
- `license`
- `scope`（写明用在哪一章的哪一块、吸收了哪一个要点、没有复制什么）

新 id 追加，不改已有 id。中英两份 manifest 各记一条，`url`、`snapshot`、`license` 相同；`title` / `scope` 用对应语言。章首罗盘的来源锚点要链到新 id。

章内第四块「坑与出处卡」是这一章的索引，不是附录 E 的副本。每一行至少有：现象、原因、处理、`#source-...` 链接、该来源允许支持的主张。一行只钉一个主张。

`CREDITS.md` 在样本 PR 里加一小节，说明大典加厚使用改写吸收，并列出这一对样本新吸收的作品名、许可证和链接。不把社区原文贴进 `CREDITS.md`。

## 样本章方法

第一批固定为 **两章**，在缺口扫描之后锁定。本规格不写死章号。

### 两章分别从哪个池子里选

- **理论偏薄的外设章**：第二至第四部分里，主题是单一外设或总线的章，文件名为 `03`–`14` 与 `16`（GPIO、中断、定时器、UART、I2C、SPI、ADC/DAC、DMA、RTC/看门狗、Flash/IAP、CAN、USB、低功耗）。
- **插图偏少的基础章**：第一部分，文件名 `00`–`02`（怎样学、开发环境、选型与时钟）。

不放入第一对样本的池子：`15`、`17`–`22`、`23`–`25`、`26`–`28`。FreeRTOS、调试、交付、资料、仿真、G0/L4/H7 引脚、SPL、网络和系统架构留到样本复审之后的批次。系列厚薄是后续批次的排序因素。G0/L4/H7 三章不会因为「相对 F1 更薄」就被自动选成第一对样本。

若指定池子里没有「四块模板都缺」的章，扫描记录要写明，并从相邻部分补位，同时说明补位原因。按 v1.0.7 的库存，两个池子都存在明显缺口，预期不需要补位。

### 扫描时记什么

对两个池子里的每一章记一行，中英分开计数：

| 列 | 怎么填 |
| --- | --- |
| 文件名 | `00`–`28`，不改成 1–29 |
| 行数 | 中文、英文各一列。英文行数不到中文一半时标成翻译缺口：加厚时两文都要写满四块；这一列不单独决定入选 |
| 本地图 | 张数与后缀（svg / gif / jpg / png）。外链图不算 |
| 图的角色 | 简化示意、板卡/引脚结构、带数字的时序或状态、实拍。一张图可以占多个角色 |
| 原理边界 | 有没有一节写明：结论在哪颗订货号上成立、换系列时哪一行作废 |
| 时序或状态 | 有没有脱离动画也能读的时序表、状态表或带时间数字的波形说明 |
| 坑的出处 | 坑是否已经链到附录 E 的 `#source-` |
| 系列痕迹 | F1/F4 与 G0/L4/H7 是否出现。只记录，不作为第一对的入选条件 |

v1.0.7 上多数章只有一张图，所以插图缺口不能只比张数，还要看那张图是不是简化示意。理论缺口也不能只比行数：行数多而边界、时序、出处仍缺的章，仍算理论偏薄。

### 锁定规则

1. 外设池按「缺少原理边界、缺少时序或状态、坑没有出处」三项缺失的个数排序，缺得最多的一章作为理论偏薄样本。
2. 基础池按「可印刷的写实图少」排序：没有带数字的时序/状态图的章优先；仍并列时，本地图张数少的优先。
3. 同一池并列时，取文件名前缀较小的一章，并在扫描记录里列出落选的并列章。
4. 两章都必须同时加厚中文和英文。不允许只加厚一种语言。
5. 扫描在样本 PR 开写正文之前做完。锁定结果写在该 PR 说明里，并附上上表。本设计文件不回写章号。

扫描基线是执行当天的 `main`。若 `main` 仍是 v1.0.7，直接用本文件的库存；若中间有过不改章节结构的提交，重新数一遍再锁定。

## 章节加厚模板

样本章在现有 Markdown 里增加四个二级标题。中英文标题固定，验收时按标题检查：

| 块 | 中文标题 | 英文标题 | 这一块要写完的事 |
| --- | --- | --- | --- |
| 1 | `## 原理与边界` | `## Principle and boundary` | 这个外设或概念在解决什么；结论依赖哪颗订货号、哪路时钟、哪一版手册；换系列、换固件包时哪一句作废 |
| 2 | `## 关键插图` | `## Key figures` | 至少一幅符合下文插图标准的主图，带 `figcaption` 能表达的图注（仓库章节里沿用现有 `<img>` + `<sub>`，构建时收成 figure）。图注写出图上的关键数字和文档号 |
| 3 | `## 时序或状态` | `## Timing or state` | 一张时序表或状态表。时间、分频或状态迁移能算回去。外设章优先时序；基础章若没有电气时序，就写工具链、复位或时钟的状态迁移，不留空块 |
| 4 | `## 坑与出处卡` | `## Pitfalls and source cards` | 现象 / 原因 / 处理 / 出处链接。每个坑至少一条 `#source-` |

原有「学习目标、硬件与接线、代码实现、动手实验、相关资源」保留。样本章里若「核心原理」「常见坑与排查」与新块重复，内容并入对应新块，不保留两套说法。代码仍按 `docs/CONTENT_GUIDE.md`：HAL 或锁定版本的 SPL，能编译，参数用宏。自绘图继续标明自绘，不称为实拍。

四块用二级标题，以便和现有章骨架一致。不新开 Markdown 文件，不把四块做成只存在于 `stm32-book/book/` 的附录体裁。构建器加在章首的罗盘保持不动；样本章的「来源锚点」覆盖这四块用到的新来源。

中英文四块的订货号、文档号、寄存器名和算式一致。允许英文句子更短，不允许英文少一块或少一个关键数字。

## 插图标准

用户对样本图的要求是：**逼真、翔实、生动**。简化示意图可以留在章内当辅图，不能充当「关键插图」的主图。

主图同时满足：

- **逼真**：画的是这个外设真实在用的块，而不是三个方框加箭头。总线上写出真实信号名（例如 `SCL`/`SDA`、`TX`/`RX`、通道名、寄存器名）。需要引脚时写出封装和脚位，并注明订货号。
- **翔实**：图上或紧挨的图注里有可以核对的数字：时钟频率、位时间、分频、阈值、状态名。数字来自冻结的 RM/DS/AN 或附录 D 已有的账，图注写出文档号。不发明一个「大约」来代替算式。
- **生动**：同一主题至少让读者看见一次「正常路径」和一次「边界或失败」。失败画在图上或画在紧随的第二张局部图上，例如空窗、绕回、NACK、采样点偏出窗口。读者不用播放 GIF 就能指出失败发生在哪一段。
- **可印刷**：主图是静态 SVG。PDF 关掉动画之后，主图仍然完整。现有 GIF 可以继续当公众号或网页辅图，不代替主图。
- **自绘**：用仓库已有的 `tools/svgkit.py` 或同等可复核脚本生成，登记进 `assets/README.md`。许可 CC BY 4.0。图注写「自绘」，不写「实拍」「手册截图」。不描 ST 官方框图，不放入手册页面扫描。
- **诚实**：不把 F401/F411 的照片或引脚图说成其他型号。新的实拍不在样本范围里；继续只用 `assets/photos/` 里已经登记的两张 CC0，且只在图注型号与照片型号一致时引用。

版式沿用贡献约定：章节用相对路径引用 `../assets/...`；SVG 尽量小于 60 KB，GIF 小于 500 KB。写实主图若一张 SVG 放不下，拆成「主图 + 局部放大」，每张仍争取小于 60 KB。拆开仍超过 60 KB 时，在样本 PR 里写出字节数和原因，不把图改回简笔，也不把 60 KB 改成全仓库的新默认值。

主图要有替代文本。替代文本写出图的结论，不写「示意图」。

样本阶段不为这些图新增图目录或表目录。章内图注已经承担定位作用。

## 工作流与 PR 节奏

### 本 PR（设计）

只新增本文件。不改 `docs/00`–`28`、`docs/en/`、`stm32-book/`、`CREDITS.md`、资产与例程。不升版本，不打 tag，不发 Release。

### 样本 PR（下一轮实现，不在本 PR）

顺序固定：

1. **缺口扫描。** 按上一节的表填两个池子。在 PR 说明里写下锁定的两个文件名和并列取舍。不回写本设计文件的章号。
2. **来源清单。** 动笔之前列出每章要吸收的材料：URL、许可证、冻结点、准备吸收的要点、明确不复制的部分。许可证不在允许列表里的，只留链接。清单可以放在 PR 说明里；最终登记以 manifest 的 `sources` 为准。
3. **中英加厚与作图。** 两章的中文和英文一起提交。主图用脚本生成并提交 SVG 与脚本。
4. **登记。** 新来源写入两份 manifest；附录 E 由构建生成，不手改一本「第二份登记表」。更新章罗盘的来源锚点。`CREDITS.md` 增加样本吸收说明。`revisions.json`、两份 manifest 的 `version`、`stm32-book/README.md` 的当前版本句，一起改为 **1.1.0**，日期用合并准备当天。修订说明只写这两章加厚了什么，不写尚未做的章。
5. **验证后请用户复审。** 复审对象是构建出的中英 HTML（以及有浏览器时的 PDF）里的这两章：四块是否都在、图是否达到标准、链接是否点得开。用户接受之前，不再开「其余 27 章」的加厚 PR。
