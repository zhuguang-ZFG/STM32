# A1 提示词模式：三段式，把决定权从模型手里拿回来

> 🎯 同样一个点灯需求，有人发给模型三行字，拿回能用的代码；有人贴出五十行描述，照样被带进沟里。差距不在字数，也不在模型，在提示词里有多少决定是你亲手做的。模型讨厌留白：你没说的，它替你补；它替你补的每一个决定，都是一颗可能的雷。这一章给你三段式——上下文、约束、验收，把签字的笔一段一段拿回来。

## 本章精髓

1. **弱提示的本质是让渡决定权**。你没指定的总线、极性、顺序、参数，模型不是不知道，是替你做主：它选全网最常见的写法，不选你这块板子的正确写法。被带偏不是模型坏，是该你签的字让它代签了。
2. **三段式各堵一个缺口**。上下文堵事实缺口：给它查得到的锚点（芯片型号、手册章节号、板卡接线）；约束堵边界缺口：封死自由裁量（资源上限、时序纪律、禁用项）；验收堵终裁缺口：定义做完长什么样（可编译、上板现象、对账动作）。
3. **提示词是迭代出来的，不是憋出来的**。每一轮把模型踩的雷翻译成证据三元组（实测、手册出处、板卡事实）回喂，再固化成提示词里的新条款。提示词跟代码一样进版本库，越改越短，越短越准。

- **能理解**：为什么同一个需求，有人三行提示词搞定、有人贴五十行照样被带偏；模型替你做主的决定落在哪几个类别；三段式各自封死哪类风险。
- **能用**：把任意外设需求写成上下文、约束、验收三段式；拿到模型输出先数它替你签了哪些字，再决定信几分；每一轮用证据三元组迭代提示词本身，而不是只改它的回答。

## 先修

- [S3 GPIO](../stm32/03-gpio.md)：点灯全流程与板卡事实，本章提示词的靶子与素材库；
- [S2 RCC 时钟树](../stm32/02-rcc-clock.md)：AHB1 与 APB1 的总线归属，上下文段的常客；
- [A2 手册对账](02-manual-reconciliation.md)：四类幻觉实锤与证据三元组，本章只引用结论，对账细则以它为准。

## 先跑起来（A/B 对照实验，10 分钟）

手边有任意一个代码模型就能做。两组对话，必须开两个独立会话：在同一个会话里连着问，它记得你上一轮说过的话，对照就脏了。

发之前先押个雷数：同一句提示，一份原样发，一份补上那行板卡事实，两边的雷会差多少？差不多、少几颗，还是一颗不剩？押完再发，两份输出摆在一起对答案。

实验 A：原样发送这句弱提示。

> 用寄存器方式初始化 STM32F407 的 GPIOF 引脚 6，推挽输出，点亮 LED。

实验 B：新会话里发同一句提示词，只在末尾补一行板卡事实。

> 用寄存器方式初始化 STM32F407 的 GPIOF 引脚 6，推挽输出，点亮 LED。板子是霸道者 F407，PF6 接红灯，共阳接 3.3V，低电平点亮；GPIOF 基地址 0x40021400，时钟使能位是 RCC_AHB1ENR bit5。

两份回答都先别烧。对照 [A2](02-manual-reconciliation.md) 的四类雷表，各打一遍勾：总线选错没有？电平反了没有？顺序乱没乱？然后填这张便签：

| 对照项 | 实验 A | 实验 B |
|---|---|---|
| 中的雷（颗） | | |
| 它替你做的决定（个） | | |
| 它向你提问（次） | | |

判读时多看一眼实验 B 的提问数：它有没有反问你没给的事实？有，说明「不确定就提问」这类条款值得常驻你的提示词；没有，说明你不能指望它自觉，第三节细说。

多数情况下，实验 B 会少掉总线与极性两类雷；如果你的结果不是这样，带着两份输出读第一节，对得上号。而如果实验 B 还在总线上栽，说明那一行事实里缺了总线锚点，这正是三段式要系统化的东西。一行板卡事实能换掉几颗雷，你自己数。

这张便签留着，读完第二节再回来对照一次：三段式就是把实验 B 的那「一行」，扩写成三段。

## 动画：三段式解剖

一条外设需求从左边进来，剖面分三层：上下文层装事实（芯片、手册章节号、板卡接线），约束层焊边界（资源、时序、禁用项），验收层站终审（编译、上板、对账）。弱提示三层全空，模型在每层替你签字；三段填满，签字笔回到你手里。

## 小节结构

一、弱提示实录：一条回答里，模型替你签了几个字；二、三段式解剖：上下文、约束、验收各管什么；三、强提示实录：同一任务，输出变了什么；四、替你做主决定清单：通用审计入口；五、迭代纪律：证据回喂，提示词进版本库。

## 一、弱提示实录：模型替你签了多少字

先承认，这句提示词不算烂：

> 用寄存器方式初始化 STM32F407 的 GPIOF 引脚 6，推挽输出，点亮 LED。

有芯片型号，有引脚号，有输出类型，比「帮我点个灯」强得多。但它把至少四个决定留白给了模型。

选点灯当靶子不是偶然：它是你在这本书里跑通的第一个外设，每一个位都已经被你自己的手对过账，模型说错什么你手里都有判决书。拿熟透的东西试提示词，才分得清是它的错还是你的不懂。模型的典型回答长这样（注释是它自己加的，雷也是它自己埋的；逐雷拆解在 [A2](02-manual-reconciliation.md) 第一节）：

```c
/* 点亮 PF6 上的 LED */
void led_init(void)
{
    /* 1. 使能 GPIOF 时钟（GPIOF 挂在 APB1 总线上） */
    RCC->APB1ENR |= (1UL << 5);          /* 雷 1：总线归属 */

    /* 2. PF6 推挽输出 */
    GPIOF->MODER   |= (1UL << 12);       /* 模式：输出 */
    GPIOF->OTYPER  |= (1UL << 6);        /* 雷 2：开漏 */
    GPIOF->OSPEEDR |= (3UL << 12);       /* 100MHz */

    /* 3. 拉高 PF6 点亮 LED */
    GPIOF->BSRR = (1UL << 6);            /* 雷 3：位语义 */
}
```

别急着挑雷，这一节先数它替你签的字。读下面这张表时，盯住中间那列：每个决定本来都该是你的。

| # | 模型替你做的决定 | 它的典型选择 | 对应的雷（A2 分类） |
|---|---|---|---|
| 1 | GPIOF 挂哪条总线 | APB1，教程里的高频写法 | 总线归属幻觉：实为 AHB1，RCC_AHB1ENR bit5 |
| 2 | 什么电平算点亮 | 置位输出高，写 BSRR 低 16 位 | 位语义幻觉：共阳要拉低，该写高 16 位 bit22 |
| 3 | 推挽还是开漏 | OTYPER 写 1，开漏 | 硬件语境幻觉：你明说了推挽，它照写开漏 |
| 4 | 先开时钟还是先配寄存器 | 看运气，这次恰好没炸 | 顺序幻觉：时钟先行是铁律 |
| 5 | 输出速度档 | OSPEEDR 拉满 100MHz | 不炸，但点灯用不上：决定权被顺手拿走 |

注意第五行跟前四行不一样：速度档这个决定没炸。决定与雷是两回事，替你做主本身就是问题，哪怕这次结果碰巧能用。因为它下次还会替你做主，而你不一定每次都这么好运。

它的选择逻辑也值得看清：APB1 是教程高频总线，置位点亮是教程高频写法，开漏是 I2C 场景的高频配置。每一个决定都在拟合「最常见」，因为你的提示词里没有放任何能抵消分布的筹码。上下文段的全部意义，就是往天平上放筹码。

三个观察。

观察一：**连明约束都会被吞**。提示词里白纸黑字写了「推挽」，模型照写开漏。弱提示里，你的要求只是它训练分布里的一个弱信号，高频写法一冲就没了。所以光「提要求」不够，要求得变成可检查的条款，这是约束段与验收段存在的理由。

观察二：**它从不为留白提问**。共阳还是共阴、挂哪条总线，这些信息它确实没有，但它选择猜，不选择问。猜的判据是「全网最常见」，不是你的板子。你不给事实，它就还你一个最像答案的答案。

观察三：**留白面积与含雷量几乎成正比**。[A2](02-manual-reconciliation.md) 的四类雷换一个说法，就是四个「你没签、它代签」的决定。提示词每空一处，模型就多一次替你签字的机会。

这个比例关系就是本章的工作假设：想降含雷量，不必换模型，先把留白面积砍下来。三段式，就是砍留白的三刀。

那贴五十行长提示为什么也救不了你？因为它经常是这种（浓缩示意）：

> 我有一块霸道者 F407 开发板，去年买的，上面有个 RGB 灯。我以前学过 51，现在想学寄存器编程，听说要点灯得先配 MODER 寄存器，也有人说直接用库函数方便。我想用寄存器的方式，把 GPIOF 第 6 个脚上的红灯点亮，请给我完整代码，注释写详细点，谢谢。

把这段话按三段式过一遍筛子：

| 三段式要的东西 | 这段五十行里有没有 |
|---|---|
| 芯片型号 | 有：STM32F407 |
| 手册章节号 | 无，它只能凭训练记忆编 |
| 板卡事实（共阳、低电平点亮） | 无，「RGB 灯」三个字撑不起极性 |
| 资源上限 | 无，它顺手多配几个引脚都不犯规 |
| 时序纪律 | 无，时钟先行全凭运气 |
| 禁用项 | 无，「想用寄存器」是愿望不是禁令 |
| 可观察验收 | 无，「点亮」没接任何终裁 |

七项里缺五项。字数花在叙事上，约束一项没落地：没有章节号，它编；没有共阳事实，它猜；没有禁用项，它顺手就上库函数；没有验收，它把过编译当终点。「请」「谢谢」「写详细点」占用的是你的输入预算，不是它的约束力；模型不需要客气，需要条款。

**弱不是短，是缺结构**。三段式治的不是「提示词太短」，是「三段全缺」。反过来，三行字的提示词只要三段齐全，也比五十行叙事强。

把这句弱提示的缺口摆开，正好三个：事实缺位（板卡接线与手册锚点一个没给）、边界缺位（没纪律没禁用项，它想用什么招用什么招）、终裁缺位（没说怎么算对）。三个缺口，正好引出三段式。

这三个缺口还是诊断工具：拿到别人写好的提示词，先看三段齐不齐，比逐字挑毛病快得多。

## 二、三段式解剖：上下文、约束、验收

三段式不是格式癖，一段堵一个缺口：上下文堵事实，约束堵边界，验收堵终裁。

顺序也有讲究：事实在前，锚点先立住；约束居中，在事实圈定的范围里焊边界；验收殿后，终裁标准定义这趟活的终点。

**上下文：给它查得到的锚点**。上下文段只装三样东西。

一是芯片型号：STM32F407，要写到后缀字母（比如 STM32F407ZGT6）：容量与封装由后缀决定，写全了，资源类回答才不会按错档次。光有型号还不够，同型号不同板子的接线天差地别，所以还要后两样。

二是手册章节号：RM0090 §2.3 表 1 管存储器映射（哪个外设挂哪条总线），§7.3 管 RCC 使能位，§8.4 管 GPIO 寄存器位定义。给章节号等于给书签：模型对手册内容有训练记忆，索引却不可靠，你给了锚点它才有地方站稳；你不给，它就编一个自信满满的页码回赠你。

引章节号，不引页码：页码随手册版本与 PDF 排版漂移，章节号稳定可查。模型编页码是最容易穿帮也最常见的一种幻觉（完整类型学在 A4 幻觉防御），这里只留一条：章节号是成本最低的防幻觉件。

三是板卡事实：霸道者 F407，PF6 接红灯，共阳接 3.3V，低电平点亮；GPIOF = 0x40021400，RCC = 0x40023800，AHB1ENR 偏移 0x30、bit5（事实出处 [S3](../stm32/03-gpio.md)）。这类事实最特殊：手册里没有，全网也没有，只活在你的原理图里。它是模型唯一不可能自己补上的上下文，所以必须你亲手给。

板卡事实从哪来？三个来源：原理图（共阳接 3.3V 这种接线事实的唯一权威）、板卡手册与丝印（引脚编号、跳线默认位置）、你自己上板测过的读回值（[S3](../stm32/03-gpio.md) 里读 IDR 的进阶实验就是动手取证）。写进上下文之前，每条事实先问一句：它有出处吗？没出处的事实，跟模型的幻觉是同一物种。

给事实时顺手给推导链，效果比裸事实好：「共阳接 3.3V，所以引脚低电平点亮」，比只说「低电平点亮」多给模型一步推理支点，它自己就能推出该写 BSRR 高 16 位，而不是死记一个结论。给结论也给理由，是上下文段的进阶写法。

**约束：负面清单优先**。约束段封死模型的自由裁量，三类条款。

资源上限：只用哪个引脚、哪个定时器、哪段内存，其余不许动。「只配置 PF6，不动 GPIOF 其他引脚」，少了这句，它可能顺手帮你把 PF7、PF8 也配了。

资源上限还有第二种形态：性能与功耗预算。主频跑多少、电流花多少，点灯任务用不上，换成电机控制或电池供电设备就是硬条款。约束段的原则是：你在乎什么，就封什么；没封的，模型按最省事的来。

时序纪律：时钟先行，初始化顺序显式写死。这条是 [S3](../stm32/03-gpio.md) 的铁律（「时钟永远先于一切」，新手第一大坑），也是顺序幻觉的高发区。写进约束，等于把纪律从「你应该记得」变成「你被要求」。

禁用项：不许用 HAL 与标准库，不许假设电平极性，不许省略对账表。禁用项的逻辑很直接：模型的默认路径是训练分布里的高频路径，嵌入式 C 语料的高频路径是库函数。正面描述（「用寄存器方式」）是给它指路，禁用项（「禁用 HAL」）是把老路堵死；指路会走丢，堵路没得走。第一节被吞的那条明约束，吞的正是指路型条款。

禁用项还能封写法风格：不许用宏魔法藏起寄存器地址，必须用 CMSIS 原名，方便你对账时一眼对上手册。风格条款看着软，审计时最省时间。

约束不是要把模型捆死。三段式封的是「不许碰的」，剩下的空间全是它的：变量怎么命名、注释怎么措辞、先写哪个辅助宏，随它发挥。边界内给自由，比处处微管理好管，也比处处留白安全。

**验收：定义做完长什么样**。验收段回答「这活怎么算干完」，三层缺一不可。

可编译：过 arm-none-eabi-gcc 交叉编译（工具链见 [B0](../build/00-toolchain.md)）。注意是交叉工具链，不是宿主机 gcc：语法哪里都一样，地址映射只有目标平台认。这是最弱的一层，只证明语法合法，但它是门槛，先写上。

上板现象：红灯亮。终裁在硬件，不在编译器，也不在模型的语气。现象必须可观察：「红灯亮」可以，「工作正常」不行。

对账动作：随代码附一张表，逐寄存器列出写入值与依据的手册章节号。这一条把 [A2](02-manual-reconciliation.md) 的对账前置了一半：模型自己先把账对了，你从全手工对账降级成抽查。

对账动作只要求它交表，不等于相信它自查正确；表的意义是让你的抽查有抓手。抽哪几行、按什么风险分级，[A2](02-manual-reconciliation.md) 第五节有现成答案。

三层验收对应三种风险：编译层挡语法错，现象层挡硬件语境错，对账层挡手册幻觉，缺哪层，哪层的风险就裸奔。对账动作写进验收还有个隐藏收益：模型为了交出这张表，写代码时就得先想依据，等于把审计成本前移到了生成时刻。

三条验收的共性只有两个字：可查。编译有退出码，灯有人眼看，表有章节号可翻。验收段的写作练习只有一道题：这条验收，明天交给同事，他能不能不看你的脸色，独立判出通过不通过？

反面教材各来一个，对照着看：

| 段落 | 写了等于没写 | 能用的写法 |
|---|---|---|
| 上下文 | 「参考手册」 | 「位定义查 RM0090 §8.4，使能位查 §7.3」 |
| 约束 | 「代码写规范点」 | 「禁用 HAL；只配置 PF6；时钟使能第一句」 |
| 验收 | 「代码要正确」 | 「过 -Wall 编译；红灯亮；附逐寄存器章节号表」 |

「代码要正确」这类写法对模型不是判据，是愿望：它没法拿「正确」自查，你也没法拿它终审。VS Code 官方文档给 agent 的分工定义就一句：You describe the outcome, review the changes, and verify the result（你描述结果、评审改动、验证结果；能力描述，访问日期 2026-10-27）。验收段，就是「描述结果」的落地处。

**模板：直接抄**。三段拼起来，点灯任务的完整强提示长这样：

> 【上下文】芯片 STM32F407（霸道者开发板），手册 RM0090。目标：GPIOF 引脚 6 接板载红灯，LED 共阳、阳极接 3.3V，引脚输出低电平点亮。已知：GPIOF 基地址 0x40021400，时钟使能位 RCC_AHB1ENR bit5；总线归属查 §2.3 表 1，使能位查 §7.3，位定义查 §8.4。
>
> 【约束】只用 CMSIS 寄存器直写，禁用 HAL 与标准库；只配置 PF6，不动其他引脚；时钟使能必须是第一句（时钟先行）；电平极性按共阳事实推导，不许假设；每行寄存器写操作，注释该行依据的手册章节号。
>
> 【验收】过 arm-none-eabi-gcc -Wall 编译无警告；上板红灯亮；随代码附对账表，逐寄存器列写入值与 RM0090 章节号；你不确定的事实不要猜，列成问题问我。

最后那句是整个模板的保险丝，第三节专门说它。

点灯模板换个外设照样套。通用骨架长这样，占位符换成你任务的：

> 【上下文】芯片与板卡：___。手册与章节号：___。目标外设与引脚：___。板卡事实（接线、极性、默认电平）：___。
>
> 【约束】写法边界（禁用哪些库）：___。资源白名单（只用哪些引脚、定时器、通道）：___。时序纪律（谁先谁后）：___。不许假设的事：___。
>
> 【验收】编译判据：___。上板现象（可观察、可复现）：___。对账动作（列什么表、挂什么出处）：___。不确定就提问。

填空的过程本身就是一次设计评审：哪一格填不出来，哪格就是你还没想清楚的地方。提示词写不下去，往往不是表达问题，是设计没想完。

把这张骨架存进项目仓库（比如 prompt-template.md），新需求先复制再填空。模板的存在感越低越好：最好变成你开新任务时的肌肉记忆。

**一次性对话与项目级上下文**。三段式贴在消息里，管一次对话；同一个项目天天用，就把它固化到工具的项目级机制里。Claude Code 的官方文档写明：CLAUDE.md 是放在项目根的 markdown 文件，每次会话开始时被读取。Cursor 的官方文档把 Agent 拆成 Instructions、Tools、Model 三构件，其中的 Instructions 层（system prompt 与 rules）就是提示词工程的落点（均为官方文档能力描述，访问日期 2026-10-27）。界面与文件名会变，方法论不变：把板卡事实与禁用项放在模型每次都能看见的地方。这些机制怎么配、权限边界在哪，归 A3 工具流，本章只立提示词本身。

判定该贴消息还是该固化，标准也简单：这条上下文，下个任务还用得上吗？用得上就进项目级文件，用不上就留在消息里。项目级文件只装跨任务稳定的东西：板卡事实、编码纪律、验收习惯。

## 三、强提示实录：输出变了什么

把上一节的模板原样发给同一个模型，回答的典型变化有三处。具体措辞每个模型、每天都可能不同，那是天气；你要看的是地形。

**变化一：决定权回到你手里**。弱提示里它替你签的五个字，总线、极性、类型、顺序、速度，这次全在提示词里签好了，它只剩执行。代码从「七行注释埋四颗雷」收敛成三行干净货：

```c
RCC->AHB1ENR   |= (1UL << 5);    /* GPIOFEN：RM0090 §7.3，AHB1ENR bit5 */
GPIOF->MODER   |= (1UL << 12);   /* MODER6=01 通用输出：§8.4 */
GPIOF->BSRR     = (1UL << 22);   /* 高 16 位写 1 拉低，共阳点亮：§8.4 */
```

这三行，每一行都能在你的提示词里找到出处：bit5 来自你给的已知事实，01 来自你指的 §8.4，bit22 来自共阳事实的推导。它没有创造任何决定，这正是你要的状态：模型从决策者降回执笔人。

**变化二：不确定性以提问返还，不再是硬猜**。模板最后那句保险丝起了作用：这轮如果故意把板卡事实从上下文里删掉，它的典型反应是先反问，而不是替你选一个。返还的提问长这样：

> 1. LED 是共阳还是共阴？
> 2. 引脚上有没有限流电阻，阻值多少？
> 3. 初始化需要返回错误码吗，还是上电即配死？

每个问题都对应决定清单里的一类签字。提问的质量也是提示词的镜子：它问得越贴硬件（共阳、限流、返回值），说明上下文给的支点越对；它还在问「要点什么颜色的灯」，说明你的上下文跑偏了。反问不是玄学，是工具链里真实存在的一环：Cursor 官方文档给 Agent 列的工具清单里就有 ask questions，任务进行中向你反问澄清（能力描述，访问日期 2026-10-27）。

但别把反问当默认行为：它不问的时候居多，所以「不确定就提问」要写进提示词，不是写在心里。

如果保险丝失灵了呢？它没反问，直接开猜，输出一份看起来齐活的代码。处理办法有两步：先把「上下文缺事实时必须提问，不许假设」从尾句升级成验收段的明条款；再养成一个阅读习惯，拿到回答先找它提没提问，再读代码。提问数为零而上下文明明有缺口，这本身就是危险信号，跟编译零警告的新代码一样，值得多看一眼。

**变化三：输出自带对账表**。验收段要求了「逐寄存器列章节号」，它就得交：

| 寄存器写操作 | 写入值 | 依据 |
|---|---|---|
| RCC->AHB1ENR bit5 置位 | GPIOFEN = 1 | RM0090 §7.3，RCC 寄存器定义 |
| GPIOF->MODER bits 13:12 | 01，通用输出 | RM0090 §8.4，MODER 位定义 |
| GPIOF->BSRR bit22 写 1 | PF6 输出低 | RM0090 §8.4，BSRR 高 16 位复位；共阳事实来自上下文段 |

你在 [A2](02-manual-reconciliation.md) 练的手工对账，从逐位重查变成抽查：它给的表里抽一行，对得上 §8.4，可信度上一档；对不上，整份退回。注意边界：表是它给的，账还是你审；表一样可能是编的，好在每行都指向手册的具体位置，这正是它可审的原因：查不着的出处，跟没有出处是同义词。对账细则不在这里展开，以 A2 为准。

两份输出摆在一起：

| 对照项 | 弱提示的输出 | 强提示的输出 |
|---|---|---|
| 替你做的决定 | 至少 4 个：总线、极性、顺序、速度 | 0 个，决定全在提示词里 |
| 已知雷数 | 4 颗（A2 第一节实锤） | 0 颗（抽查口径） |
| 向你提问 | 0 次，有缺口就猜 | 漏事实时反问 |
| 手册章节号 | 0 处，注释全是自然语言 | 逐行引用 |
| 你的活 | 全手工对账，加口头 patch | 抽查，加迭代提示词 |

最后一行才是重点：强提示省下的不只是模型的错，更是你的审计成本。

还有一个隐形变化：代码变短了。弱提示下它要替你猜，猜就得铺陈，铺陈就出注释比代码长的「教科书」；上下文给足了，训练分布的引力被锚点抵消，它只写该写的三行。输出的啰嗦程度，反过来也是提示词质量的一枚仪表。

你复现实验时，拿到的具体句子多半跟本节不同：同一模型，不同日期的输出会变。盯结构三指标：它替你做了几个决定、问了几个问题、引了几处章节号。措辞天天变，这三个数是提示词质量的稳定读数。

## 四、替你做主决定清单：通用审计入口

点灯案例里的五个决定不是 GPIO 特产。拿到任何一段模型输出，先别问「对不对」，先问「它替我签了哪些字」。签字高发区一共六类：

| 类别 | 模型常替你签的字 | 收回到哪一段 |
|---|---|---|
| 硬件事实 | 总线归属、电平极性、上下拉、接法 | 上下文：原理图事实加手册章节号 |
| 资源占用 | 用哪个定时器、通道、DMA、引脚 | 约束：白名单，「只用……」 |
| 顺序依赖 | 初始化先后、时钟先行、解锁序列 | 约束：显式时序纪律 |
| 参数取值 | 速度档、波特率、分频系数、超时 | 上下文给数值，或约束给推导口径 |
| 写法风格 | HAL 还是寄存器、阻塞还是中断 | 约束：禁用项负面清单 |
| 范围边界 | 顺手重构、顺手加功能、顺手改风格 | 约束：「只改这个函数」 |

拿第一节那段点灯代码过一遍这张表：硬件事实类，总线归属与电平极性两个字被代签；写法风格类，开漏顶掉你明写的推挽；顺序依赖类，这次恰好没炸；参数取值类，OSPEEDR 100MHz 顺手拉满；范围边界类，这次没越界，换个复杂需求就难说。一段七行的代码，六个类别里中了四类。

这就是审计入口的用法：先归类，再对照右列找到该收紧的段落，把决定写回提示词。

六类里有两类要特别警惕。参数取值类经常「不炸但错」：OSPEEDR 拉满点得亮灯，可你没授权它做这个选择；换到功耗敏感的场景，这就是事故。范围边界类最伤版本库：你让它改一个驱动，它顺手重排了三个文件的缩进，diff 评审成本翻倍，还可能改掉别处的行为。这两类不触发任何编译错误，恰恰只能靠提示词约束提前封死。

反过来，硬件事实与顺序依赖这两类最「响」：错了灯就不亮、板就没反应，反而好抓。评审的力气分配跟响度成反比：越安静的代签，越值得盯。

把这张表用进日常评审，流程只有三步：

- 读输出之前，先默写提示词里你签了哪些字；
- 读输出时对照六类清单，找它代签的部分，逐条归类；
- 把每一类代签翻译成一行提示词条款，写回对应段落。

三步走完，你得到的不只是这份输出的可信度评估，还有提示词的下一个版本。

再换一个任务试这张表：让它初始化串口。它替你签的字立刻变成另一组：波特率取多少、帧格式怎么定、挂哪条总线、阻塞收发还是中断收发、要不要顺带把 printf 重定向也写了。前四项分属参数取值、硬件事实、写法风格，最后一项是范围边界的经典越界。任务换了，六类不变，这就是清单能当通用入口的原因。

这张表本身也是活的：每做完一个项目，把新遇到的代签类别补进去。你的清单比任何通用模板都懂你的项目。

每次评审模型输出，都是在给提示词做增量维护，而不是在给模型挑错。这个心态换过来，评审就从苦役变成了资产积累。

## 五、迭代纪律：提示词进版本库

强提示不是一次憋出来的，是迭代出来的。纪律三条。

**迭代单位是提示词，不是回答**。模型写错总线，你回一句「不对，GPIOF 在 AHB1」，它这轮改对了；然后呢？下个任务、下个会话，它接着替你选 APB1。口头 patch 修好的是这一轮的回答，提示词里的雷一颗没排。

正确的修法是把雷翻译成条款。用点灯任务走一遍完整迭代，看条款是怎么长出来的：

| 轮次 | 这轮炸的雷 | 翻译成的条款 | 落到哪段 |
|---|---|---|---|
| 1 | 代码里混入 HAL 库调用 | 「禁用 HAL 与标准库」 | 约束 |
| 2 | 总线写成 APB1 | 「已知：RCC_AHB1ENR bit5；归属查 §2.3 表 1」 | 上下文 |
| 3 | 按共阴写法点亮，逻辑全反 | 「共阳接 3.3V，低电平点亮」「不许假设极性」 | 上下文加约束 |
| 4 | 收敛：输出自带对账表，抽查通过 | 无新增，验收段原本就有 | 验收 |

每颗雷对应一行条款，提示词就是这样长出来的。注意第 4 轮：没有新条款可长，就是收敛信号。

条款本身也有写法要求：必须可检查。「时钟使能放第一句」查一眼就知，「代码写得健壮点」查无可查。写不出检查办法的条款，跟写不出判据的验收是同一种病，删掉重写。

**回喂用证据三元组**。吐槽对模型是零信息，证据才有校正力：实测现象（灯不亮、引脚读回是高电平）、手册出处（RM0090 §7.3，AHB1ENR bit5 才是 GPIOFEN；APB1ENR bit5 是 TIM7EN，[A2](02-manual-reconciliation.md) 已实锤）、板卡事实（PF6 共阳，低电平点亮）。三元组的写法与案例细则在 A2 第四节，这里只立纪律：每轮迭代必须带证据，不带证据的轮次算浪费。

**提示词跟代码同仓、同评审、同演进**。三段式模板存进项目仓库，或者固化进上节说的项目级上下文文件，跟驱动代码一起进版本控制。三个月后的你、后来的同事，看到的不是「当时好像这么调的」，是 commit 历史里每一行条款的来由。

条款也会过期：换芯片、换板子、换库政策，旧条款就得拿出来重审。从 F407 换到别的板子，霸道者那组事实整段作废，上下文不是一次投资。收敛的标志是提示词越改越短：每收回一个决定，模型要猜的就少一个；最终形态是三张清单，事实清单、负面清单、验收清单，一句寒暄都不剩。

提示词自己也能被评审。不管评审别人的还是三个月前自己的，问四个问题：三段齐不齐？每条验收是不是可观察？禁用项有没有落在明处？章节号随手抽一个能不能查到？四个问题有一个答不上，这条提示词就还没到入库标准。

条款有血统：从别家项目抄来的提示词，堵的是别家的雷。借鉴可以，逐条问一句「这条堵的是我的哪颗雷」，答不上的别入库。

最后划一条边界：提示词再强，压缩的也只是模型的发挥空间，替代不了对账。强提示把雷从四颗压到零颗，是这一章的全部承诺；确认它真是零颗，是 A2 的活。「提示词写好了所以对账免了」这条推论，从来不存在。

## 常见坑

- **验收标准写「正确」二字等于没写**：「代码要正确」对模型不是判据，是愿望。验收必须可观察：编译器过不过、灯亮不亮、对账表里有没有章节号。写不出可观察判据的验收段不如删掉，至少不制造虚假的安全感。
- **约束漏禁用项，模型默认走 HAL**：嵌入式语料的高频路径是库函数，正面描述是指路，禁用项是堵路；指路会走丢，堵路没得走。少了「禁用 HAL」，交上来的「寄存器代码」里很可能藏着库调用。
- **上下文不给手册章节号，模型开始编页码**：「参考手册」四个字给不了锚点，它回赠你自信满满的虚构引用。给 §2.3 表 1、§7.3、§8.4 这种能查证的锚点，成本一行字，省的是整轮对账。
- **口头 patch 两轮就当提示词合格**：「不对，重来」「把 BSRR 改一下」，修的是这一轮的回答，提示词里的留白原样保留，换个任务接着炸。每轮的修法只有一种：把雷翻译成条款写回提示词。
- **板卡事实觉得显而易见就不写**：共阳接法在你脑子里、在原理图上，唯独不在模型的训练数据里。你越觉得「这还用说」的事实，越是必须写进上下文的事实。
- **把三段式当咒语背，不理解各管什么**：照着模板填得满满当当，上下文里抄进半本手册，约束里写满不相干的禁令。三段式不是仪式，是分工：每段只堵自己的缺口，抄来的条款不堵你的雷。
- **把强提示当终点，不烧就合并**：三段式把雷压到零，是概率上的零；烧上板之前，「零颗」只是期望值。验收段里「红灯亮」三个字不是修辞，是终审，终审只能发生在硬件上（[A2](02-manual-reconciliation.md) 闭环的最后一环）。

2. 弱提示「用寄存器方式初始化 STM32F407 的 GPIOF 引脚 6，推挽输出，点亮 LED」里，模型替你做了哪四个以上的决定？各对应 A2 的哪类幻觉？
<details><summary>看答案</summary>至少四个。总线归属（它选 APB1，实为 AHB1）：总线归属幻觉；点亮电平（它写 BSRR 低 16 位置位输出高，共阳其实要拉低）：位语义幻觉；输出类型（你明说推挽，它照写开漏）：硬件语境幻觉，还说明弱提示连明约束都护不住；初始化顺序（先配 MODER 还是先开时钟全凭运气）：顺序幻觉。外加一个不炸但越权的：OSPEEDR 速度档拉满 100MHz，决定权被顺手拿走。</details>

3. 为什么「验收：代码正确」等于没写？合格的验收三件套是什么？
<details><summary>看答案</summary>「正确」不是可执行、可观察的判据：模型拿它无法自查，你拿它无法终审，写与不写对输出质量没有影响。合格三件套：可编译（过 arm-none-eabi-gcc 交叉编译，最弱但是门槛）、上板现象（红灯亮，终裁在硬件）、对账动作（随代码附逐寄存器的 RM0090 章节号引用表，把你的审计从全手工降级成抽查）。三层从弱到强，缺一不可。</details>

4. 为什么约束段里禁用项比正面描述管用？举嵌入式场景最典型的一条。
<details><summary>看答案</summary>模型的默认路径是训练分布里的高频路径，嵌入式 C 语料的高频路径是库函数。正面描述「用寄存器方式」只是指路，高频写法一冲就丢（弱提示里明写的「推挽」照样被吞）；禁用项「禁用 HAL 与标准库」是把老路直接堵死，它没得选只能走新路。最典型的一条就是「禁用 HAL」：少了它，交上来的代码里很可能藏着 GPIO_InitTypeDef 与库函数调用。</details>

5. 每轮迭代的回喂为什么必须是证据三元组？「口头 patch 回答」和「迭代提示词」差在哪？
<details><summary>看答案</summary>证据三元组是实测现象、手册出处、板卡事实（细则在 A2 第四节）。「又错了」只给模型一个布尔值，它下轮只能换个猜法；三元组给的是可验证的更正链，它本轮就能收敛。口头 patch 修好的是这一轮的回答，提示词里的留白原样保留，下个任务同样的雷接着炸；迭代提示词是把雷翻译成条款（总线错了就加「归属查 §2.3 表 1」），雷被排掉而不是被绕开。判断标准看版本库：提示词有没有跟代码一起演进。</details>
