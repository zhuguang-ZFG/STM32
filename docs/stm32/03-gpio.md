# S3 GPIO：七个寄存器位级图解

> 🎯 GPIO 是每个外设的"出发大厅"：不管多高级的功能（串口/SPI/PWM），最后都要从一个引脚进出。而这个大厅的全部管理规章，就写在七个 32 位寄存器里。本章把它们逐位拆开，以后每章的"引脚设置"环节你都能秒过。

## 本章精髓

1. 四个配置寄存器各管一维：**MODER**（输入/输出/复用/模拟，每脚 2 位）、**OTYPER**（推挽/开漏）、**OSPEEDR**（边沿速度）、**PUPDR**（上拉/下拉/浮空）。配置一个引脚 = 按序填这四张表。
2. 三个数据寄存器分工：**IDR** 读真实电平、**ODR** 读写输出（读-改-写有隐患）、**BSRR** 原子置位/复位：BSRR 是"改一位不扰邻居"的正解。
3. 复用（AF）是引脚的第二人生：AFRL/AFRH 每脚 4 位选 AF0~AF15：引脚还是那个引脚，数据源从 ODR 换成外设；datasheet 的复用表是唯一的真值。

- **能理解**：为什么改位要用 BSRR 而不是 ODR，第二节的翻车现场会回答你。
- **能用**：把 [00-blink 的 main.c](https://github.com/zhuguang-ZFG/mcu/blob/main/code/stm32/00-blink/main.c) 每一行讲给同学听，讲不顺的地方回来重读。

## 一、配置四维：四张表，每脚两格

把 GPIO 外设想成一间装配车间，墙上有**四个抽屉柜**：MODER、OTYPER、OSPEEDR、PUPDR。16 个引脚在每个柜子里都占格子：除了 OTYPER 每脚 1 格，其余每脚 **2 格**。配一个引脚，就是按顺序拉开四个柜子填格子：

| 寄存器 | 每脚位宽 | 取值含义（以输出为例） | RM0090 |
|---|---|---|---|
| MODER | 2 位 | 00 输入 / **01 通用输出** / 10 复用 / 11 模拟 | §8.4.1 |
| OTYPER | 1 位 | **0 推挽** / 1 开漏 | §8.4.2 |
| OSPEEDR | 2 位 | **00=2MHz** / 01=25MHz / 10=50MHz / 11=100MHz | §8.4.3 |
| PUPDR | 2 位 | **00 浮空** / 01 上拉 / 10 下拉 | §8.4.4 |

拿 PF6 实拍演算一遍。PF6 在 MODER 里占 bits[13:12]（6×2），目标是 01（输出）：

```c
GPIOF_MODER   &= ~(3UL << (LED_R_PIN * 2));  /* 先清零：~0x3000，两位擦除   */
GPIOF_MODER   |=  (1UL << (LED_R_PIN * 2));  /* 再置位：0x1000，[13:12]=01  */
GPIOF_OTYPER  &= ~(1UL << LED_R_PIN);        /* 0  = 推挽                  */
GPIOF_OSPEEDR &= ~(3UL << (LED_R_PIN * 2));  /* 00 = 低速（复位默认就是）   */
GPIOF_PUPDR   &= ~(3UL << (LED_R_PIN * 2));  /* 00 = 无上下拉               */
```

> **【注】为什么坚持"先清零再置位"？** 不能直接 `|= 01`：万一格子里原来是 11（模拟），或一下变成 11。两位的格子要先擦干净再写。复位后大多数引脚是 00（输入），但 PA13/PA14 这些调试脚默认是复用。所以"先清后置"是永不翻车的写法。

还有一句顺序纪律：**时钟永远先于一切**。`RCC_AHB1ENR |= (1UL << 5);` 不合闸，外设寄存器就是没通电的橱窗：写进去不响，读回全是 0。这是新手第一大坑，没有之一。

## 二、数据三剑客：IDR 看、ODR 写、BSRR 办

- **IDR**（§8.4.5）：只读，引脚上此刻的真实电平。输入的耳朵。
- **ODR**（§8.4.6）：可读写，输出寄存器。看着方便，**但有暗伤**。
- **BSRR**（§8.4.7）：只写，低 16 位置位（BS）、高 16 位复位（BR），写 1 生效、写 0 无影响。

ODR 的暗伤在哪？`GPIOF_ODR |= (1UL << 6);` 这行 C，编译出来是**三条指令**：

```asm
ldr  r0, [r1]        ; ① 把账本读出来
orr  r0, r0, #0x40   ; ② 改自己那位
str  r0, [r1]        ; ③ 整本写回去
```

这就是"读-改-写"：三个人共改一本账。想象 ① 和 ③ 之间插进来一个中断，中断里也改了 ODR 的另一位；中断返回后，main 把 ① 时刻的旧账整本写回——**中断的改动被当场冲掉**。症状是"偶尔丢一次电平"，一周出现一回，查到你怀疑人生。

BSRR 是硬件给的解法：**一条 `str` 完成，没有读、没有改**，中断无从插足；写 0 无影响，所以连掩码都省了。00-blink 里就是这么发令的：

```c
GPIOF_BSRR = (1UL << (LED_R_PIN + 16));  /* BR6 = 0x00400000：拉低 → 红灯亮 */
GPIOF_BSRR = (1UL << LED_R_PIN);         /* BS6 = 0x00000040：拉高 → 红灯灭 */
```

> **【注】共阳反转别和自己过不去。** 霸天虎 RGB 共阳接 3.3V，引脚**低电平灯亮**。所以是"高 16 位亮、低 16 位灭"。写代码时心里默念：BR 亮、BS 灭——反人类一次，记住一辈子。

> **【注】BSRR 两个冷门事实**：读它永远返回 0（只写寄存器）；对它写 0 完全不动作，这就是它能免掩码的原因。

## 三、推挽 vs 开漏：能推能拉，还是只会拉

| | 推挽（PP） | 开漏（OD） |
|---|---|---|
| 输出级 | 上 PMOS + 下 NMOS，两个开关对推 | 只有下 NMOS，**只会拉低** |
| 高电平 | 主动推向 VDD，有力 | "放手"——靠外部上拉电阻抬升 |
| 典型场景 | LED、SPI、USART，绝大多数 | I2C、5V 电平转换、"线与"总线 |

I2C 为什么**必须**开漏+上拉？这是一堂总线外交课：SDA 上挂着主机和好几个从机，**谁都有权拉低**（发 0、应答、 clock stretching）。要是用推挽，一个脚卖力推高、另一个卖力拉低，两个输出级对轰，电流直通，烧脚没商量。开漏的制度是"谁都只能拉，想高就放手"，上拉电阻把线温柔地抬回高电平。多设备共享一根线而不斗殴，这就是"线与"。

> **【注】** F4 大部分引脚标 FT（5V 容忍），开漏加上拉到 5V 就能和 5V 器件对话，但模拟功能脚（标 TTa）不行，接 5V 前先查 datasheet 引脚表。

## 四、复用：引脚的第二人生

引脚默认听 ODR/IDR 的（通用 IO）；写成 MODER=10 后，数据线改接到**片上外设**：USART、TIM、SPI……具体接哪个，由 AFRL/AFRH 决定：每脚 4 位，选 AF0~AF15。**哪个引脚能当什么、是 AF 几，只有 datasheet 的复用功能表说了算**（F407 在 Table 9），别背，查。

以 USART1_TX = PA9 为例，查表得 AF7，配置两行到位：

```c
GPIOA->MODER  &= ~(3UL << 18);
GPIOA->MODER  |=  (2UL << 18);   /* PA9：MODER[19:18] = 10，复用模式 */
GPIOA->AFR[1] &= ~(0xFUL << 4);  /* AFRH 管 pin8~15，PA9 是第 1 个 nibble */
GPIOA->AFR[1] |=  (7UL << 4);    /* AFRH[7:4] = 0x7 = AF7 = USART1_TX */
```

> **【注】复用要成对**：只写 AFRL/H 不改 MODER=10，等于章盖了门没开，外设根本接不进引脚。MODER=10 + AFR 选号，缺一不可。

## 五、SPL 对照：GPIO_Init 没有魔法

标准库（SPL）的 `GPIO_Init` 看着神秘，其实就是把上面这套流程用 for 循环走了一遍。它的形参和我们填的表一一对应：

| GPIO_InitTypeDef 字段 | 落到哪张表 |
|---|---|
| `GPIO_Mode`（IN/OUT/AF/AN） | MODER 两位 |
| `GPIO_OType`（PP/OD） | OTYPER 一位 |
| `GPIO_Speed`（2/25/50/100MHz） | OSPEEDR 两位 |
| `GPIO_PuPd`（NOPULL/UP/DOWN） | PUPDR 两位 |
| `GPIO_Pin`（位掩码） | 决定改哪一格 |
| `GPIO_PinAFConfig()`（复用时另调） | AFRL/AFRH 的 nibble |

剥开 `stm32f4xx_gpio.c` 的 `GPIO_Init`，骨架就这几行（意译，保留原始逻辑）：

```c
for (pinpos = 0; pinpos < 16; pinpos++) {
    if ((GPIO_InitStruct->GPIO_Pin & (1UL << pinpos)) == 0) continue;
    /* MODER：先清零 (3 << pinpos*2)，再或上 mode << pinpos*2 */
    /* 若是 OUT/AF：OTYPER / OSPEEDR / PUPDR 同样先清后或   */
    /* 若是 AF：AFR[pinpos >> 3] 的对应 nibble 写入 AF 号     */
}
```

一个字都没超出本章第一节。读完这一段，库函数在你眼里就是透明的。S15 章会把 SPL 整个掀开细讲。

## 六、输入侧：听外界说话

- **数字输入**：引脚经过**施密特触发器**进 IDR：滞回比较器，边沿再抖也不哆嗦。
- **模拟模式**（MODER=11）：把施密特触发器、上下拉**全部断开**，引脚直通 ADC，漏电流最小，采样最真。
- **按键消抖**两条路：硬件（RC 滤波，一分钱解决）或软件（定时采样，连续 N 次一致才算数）。实验章两条都会走。

## 常见坑

- **忘开 GPIOx 时钟**：寄存器全写不进去（读回全是 0），新手第一大坑，没有之一。
- **用 ODR 翻转单个引脚**：中断插在"读-改-写"中间就丢状态，改位请用 BSRR。
- **OSPEED 盲目拉满**：边沿越快 EMI 越猛；LED/按键用 2MHz 足够，高速信号才需要 50/100MHz。
- **复用功能开了 AF 没换 MODER**：MODER 还在"通用输出"，外设接不进引脚，复用要成对（MODER=10 + AFR 选号）。
- **对 BSRR 用读-改-写**：它读回永远是 0，`|=` 会把你的位全清掉，BSRR 只能纯赋值。

## 短自测

1. 不开 GPIOF 时钟就写 MODER，然后读回 MODER，看到什么？
2. 为什么 BSRR 改一位不怕被中断打断，ODR 怕？
3. I2C 的 SDA 为什么必须开漏 + 上拉？
4. PA9 用作 USART1_TX，MODER 和 AFRH 各写什么值？

<details><summary><b>参考答案（先自己想完再展开）</b></summary>

1. 全是 0。外设没电，写入无效，这就是"忘开时钟"坑的指纹。
2. ODR 是 ldr/orr/str 三条指令的读-改-写，中间可被插队，旧值写回冲掉别人的改动；BSRR 一条 str 原子完成，且写 0 无影响。
3. 多设备共享一根线且谁都可拉低；推挽会一推一拉对轰短路。开漏"只会拉、想高放手"，上拉电阻抬升，这就是"线与"。
4. MODER[19:18] = 10（复用模式）；AFRH[7:4] = 0x7（AF7 = USART1_TX）。
