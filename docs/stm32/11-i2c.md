# S11 I2C：时序与寄存器的逐拍对应

> 🎯 I2C 像一场有规矩的茶话会：两根线上挂着一群设备，谁说话先报名字（地址），说完等对方点头（ACK）。本章把这套礼仪逐拍翻译成 SR1/SR2 的状态流转：I2C 难，难在**每一拍都有一个必须等、必须按顺序清的事件位**。把事件链走通一遍，I2C 从"最容易卡死的协议"变成"最有规律的社交"。

## 本章精髓

1. **时序三要素**：START（SCL 高时 SDA 落）/STOP（SCL 高时 SDA 升）/ACK（第 9 拍拉低）：所有 I2C 波形都是这三块积木；数据跳变只允许发生在 SCL 低区。
2. **开漏+上拉是"线与"**：任何人都能拉低、没人能主动推高，这是 ACK、多主仲裁的物理基础（回 [S3](03-gpio.md) 开漏节）。
3. **寄存器级收发 = 事件驱动状态机**：写 CR1.START→等 SB→写 DR 地址→等 ADDR→读 SR1+SR2 清 ADDR→写数据→等 TXE/BTF，顺序错一拍就卡死，这也是 SPL `I2C_CheckEvent` 存在的全部理由。

- **能理解**：为什么数据只能在 SCL 低区变；为什么清 ADDR 必须"先 SR1 后 SR2"；为什么读完最后一个字节要先 NACK 再 STOP。
- **能用**：寄存器级向 AT24C02 写一页再读回；用逻辑分析仪抓包并对照动画逐拍对表。

## 先跑起来（10 分钟 quick win）

接一块 AT24C02（7 位地址 0x50）到 I2C1（PB6/PB7，AF4，以 datasheet 与板卡规格书为准），写入 0x5A 再读回，串口打印，两线社交一次达成。

写入之前先押个归宿：往同一页多塞一个字节，越过了这一页的边界，它是接着排进后面的页、原地丢掉，还是绕回这一页的开头，把最先写下的那个盖掉？三个去处押一个，再往下读，页边界的三连坑会当庭宣判。

## 板卡事实

- AT24C02：2Kbit = 256 字节，**页大小 8 字节**，写周期 tWR 典型 5ms，这三个数决定第五、六节的全部坑。
- 7 位地址 0x50 = `1010 000`：高 4 位 `1010` 是 EEPROM 的"姓氏"（出厂焊死），低 3 位 A2/A1/A0 由引脚电平决定，全接地 = 0x50。
- 上拉电阻：模块一般自带 10k；速度要上去就换小（1k~4.7k），代价是功耗和下降沿负担，实物实验里亲手看差别。

## 一、礼仪三件套：START、STOP、ACK

总线拓扑先看图：两线开漏、上拉必备、各挂各的地址。

![I2C 总线拓扑：主机、两线总线（各一只上拉）、从机按地址挂载](/arch/i2c-bus.png)

**START**：SCL 保持高，SDA 从高落低（"大家注意，我要说话了"）。**STOP**：SCL 保持高，SDA 从低升高（"我说完了"）。**ACK**：每个字节第 9 拍，接收方把 SDA 拉低（"听到了"）。

推论立刻出来：**数据位只能在 SCL 低电平期间变化**。因为 SCL 高期间的 SDA 跳变被硬件定义为控制信号（START/STOP），你数据线这时候动一下，全场都以为你喊了"注意"或"散会"。动画里 18 拍波形把这条铁律画得很清楚。

电气上这一切成立，靠的是回 [S3](03-gpio.md) 学过的开漏+上拉：SDA/SCL 都是"线与"，任何一个设备都能把线拉低，但谁也无法主动推高（高电平靠上拉电阻"放手"获得）。所以：

- 从机想 ACK，就在第 9 拍把 SDA 拽低，主机读到低电平=点头；
- 主机想 NACK（最后一口不吃了），第 9 拍放手不管，线自己弹高；
- 多主同时讲话时，谁先推高谁"输"（回读发现线被别人拽着），仲裁白送。

> **【注】** 上拉电阻是把双刃剑：越大越省电但上升沿越肉（RC 充电），小到 1k 时沿陡了、速度能冲 400kHz，代价是拉低时电流大。E05 实验让你亲眼对比 10k vs 1k 的上升沿。

![I2C 起止条件与地址字节：SCL 高时 SDA 下降为 START，上升为 STOP；地址后跟 R/W 与 ACK](/figures/stm32-11-i2c.svg)

## 二、地址与方向：一个字节里藏着 8 个 bit 的规矩

7 位地址出厂时只占字节高 7 位，**最低位是 R/W 方向位**：0=主机要写，1=主机要读。AT24C02 地址 0x50，上线时是 `0x50<<1 | 0 = 0xA0`（写）或 `0x50<<1 | 1 = 0xA1`（读），分析仪上你看到的是 A0/A1，不是 50。

SPL 的 `I2C_Send7bitAddress` 就干这件事，逐字原文（stm32f4xx_i2c.c V1.8.0）：

```c
void I2C_Send7bitAddress(I2C_TypeDef* I2Cx, uint8_t Address, uint8_t I2C_Direction)
{
  /* Test on the direction to set/reset the read/write bit */
  if (I2C_Direction != I2C_Direction_Transmitter)
  {
    Address |= I2C_OAR1_ADD0;                 /* 读:bit0 置 1 */
  }
  else
  {
    Address &= (uint8_t)~((uint8_t)I2C_OAR1_ADD0); /* 写:bit0 清 0 */
  }
  I2Cx->DR = Address;                          /* 写 DR = 送上总线 */
}
```

注意调用方传的 `Address` 必须是**已经左移过一位**的地址（0xA0 那种），这个函数只管方向位。而 `I2Cx->DR = Address;` 这一行就是全部"发送"：写 DR 寄存器，硬件自己完成移位输出。**I2C 的发送就是写 DR，剩下的全是等事件。**

## 三、事件链：I2C 的难点不在时序，在"等"

寄存器级一次写事务的法定流程：

1. `CR1 |= START` → 等 **SB**（SR1 bit0：START 已发出）
2. `DR = 地址|W` → 等 **ADDR**（SR1 bit1：从机认了地址）
3. **清 ADDR：先读 SR1，再读 SR2**（硬件规定的顺序，错一步 ADDR 永远挂着，后面全卡）
4. `DR = 数据` → 等 **TXE**（SR1 bit7：DR 空了，可以塞下一个）
5. 最后一个字节发完等 **BTF**（SR1 bit2：移位寄存器也空了，字节真正上了总线）
6. `CR1 |= STOP`

SPL 把"等事件"封装成 `I2C_CheckEvent`，原文只有十行核心（stm32f4xx_i2c.c）：

```c
flag1 = I2Cx->SR1;
flag2 = I2Cx->SR2;
flag2 = flag2 << 16;
lastevent = (flag1 | flag2) & FLAG_MASK;        /* SR1 低16位 | SR2 高16位 */
if ((lastevent & I2C_EVENT) == I2C_EVENT)
  status = SUCCESS;
```

而"事件"就是状态位的组合宏（stm32f4xx_i2c.h）：

```c
#define  I2C_EVENT_MASTER_MODE_SELECT  ((uint32_t)0x00030001)  /* BUSY, MSL and SB flag */
#define  I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED ((uint32_t)0x00070082) /* BUSY, MSL, ADDR, TXE and TRA */
```

看懂这两个数，你就看懂了 SPL 的事件模型：0x00030001 = SR2 的 BUSY|MSL（0x0003 在高 16 位）+ SR1 的 SB（0x0001）："我成了主机且 START 已发"。**等事件 = 等一串状态位同时成立**，比单等一个标志位严谨，也更不容易被"幽灵置位"骗过。

> **【注】** TXE 和 BTF 是新手翻车第一名：TXE 只说"DR 空了"，字节还在移位寄存器里往外蹦；BTF 才说"整个字节发完了"。发完最后一字节只看 TXE 就发 STOP，会把最后一拍拦腰砍断，从机收到半个字节，NACK 伺候。

## 四、SPL 对照：`I2C_Init` 六字段没有魔法

初始化结构体（stm32f4xx_i2c.h）：`I2C_ClockSpeed / I2C_Mode / I2C_DutyCycle / I2C_OwnAddress1 / I2C_Ack / I2C_AcknowledgedAddress` 六个字段。`I2C_Init` 把它们落进三个寄存器，原文关键三段：

```c
freqrange = (uint16_t)(pclk1 / 1000000);   /* CR2.FREQ = PCLK1 的 MHz 数 */
tmpreg |= freqrange;
I2Cx->CR2 = tmpreg;
...
if (I2C_InitStruct->I2C_ClockSpeed <= 100000)            /* 标准模式 */
{
  result = (uint16_t)(pclk1 / (I2C_InitStruct->I2C_ClockSpeed << 1)); /* CCR = PCLK1/(2×目标速率) */
  if (result < 0x04) { result = 0x04; }                  /* 硬件下限 */
  tmpreg |= result;
  I2Cx->TRISE = freqrange + 1;                           /* 标准模式最大上升时间 */
}
else                                                      /* 快速模式 */
{
  result = (uint16_t)(pclk1 / (I2C_InitStruct->I2C_ClockSpeed * 3));   /* Duty 2:1 */
  /* 或 I2C_DutyCycle_16_9 时 ×25 并置 DUTY 位 */
  I2Cx->TRISE = (uint16_t)(((freqrange * (uint16_t)300) / (uint16_t)1000) + (uint16_t)1);
}
```

**拿霸天虎标准时钟树实算**（PCLK1 = 42MHz，见 [S2 RCC](02-rcc-clock.md)）：

| 目标 | 公式 | 结果 |
|---|---|---|
| CR2.FREQ | 42MHz ÷ 1MHz | **42**（告诉外设输入时钟多少 MHz） |
| CCR @100kHz | 42e6 ÷ (100e3 × 2) | **210**（SCL 高低各计 210 个 PCLK1） |
| TRISE @100kHz | 42 + 1 | **43**（1µs 内必须升完，42+1 拍） |

所以"100kHz"不是填进去的，是**分频算出来的**：I2C 外设拿 42MHz，按 CCR=210 数拍子，数出 100kHz 的 SCL。改时钟树不改 CCR？SCL 频率跟着飘，时钟配置和波特率从来是一根绳上的。

## 五、写 EEPROM：三个数引发的连环坑

AT24C02 写一字节的完整事务：`START → 0xA0 → 字地址 → 数据 → STOP`。看起来简单，但板子上躺着三个数：**页 8 字节、tWR 5ms、ACK polling**。

1. **页写回绕**：连写超过 8 字节，超出部分**卷回页首覆盖**：连写 20 字节到地址 0，实际第 9~20 字节盖掉了第 1~12 字节的位置附近（严格按"当前页内回绕"）。对策：按 8 字节对齐分批。
2. **写周期 tWR**：STOP 之后 EEPROM 进入内部擦写（典型 5ms），这期间它**不应答**：你立刻发起下一笔，地址阶段就被 NACK。
3. **ACK polling（应答轮询）**：利用"不应答"特性做等待：循环发 START+写地址，收到 NACK 就再来，直到某次收到 ACK = 擦写完成。比死等 5ms 优雅，也是工业代码的标准写法。

> **【注】** 很多"I2C 偶发丢数据"的玄学 bug，根源就是页边界和 tWR 没伺候好。协议没错，是没按器件的脾气来。

## 六、读回与重复 START：不松手的艺术

读 EEPROM 要先"写"字地址再读数据，但中间**不能发 STOP 松手**：松手期间别的主机（如果有）可能插进来，而且某些器件会把内部地址指针复位。解法是**重复 START**（Repeated START）：

`START → 0xA0 → 字地址 → **重复 START** → 0xA1 → 读数据 → NACK → STOP`

收尾礼仪也有讲究：读最后一个字节前，先 `I2C_AcknowledgeConfig(DISABLE)`（下一拍回 NACK），读完立即 STOP——告诉从机"最后一口，不吃了"。若该 NACK 时回了 ACK，从机会继续往线上怼数据，总线就乱了。

整条链路和第三节的事件链一一对应：每个"→"背后都是一次 `I2C_CheckEvent` 的等待。**时序图是给人看的，事件链是给代码走的，两者逐拍同构**：这就是本章标题的含义。

## 常见坑

- **ADDR 不会清**：先读 SR1 再读 SR2，顺序法定——新手十有八九栽这里；
- **等 TXE 不等 BTF**：STOP 发早，最后一字节没上总线（第三节注）；
- **上拉电阻省掉**：开漏没上拉=永远没有高电平，波形全是 0；
- **页写跨边界**：回绕覆盖页首（第五节）；
- **时钟树改了 CCR 没改**：SCL 频率跟着 PCLK1 飘（第四节实算）。

## 总线卡死恢复：SDA 被从机拉低的急救

I2C 最经典的翻车：主机复位或通信中途崩溃，从机正在发数据（SDA=0），主机重启后 SCL 开始翻转但 SDA 仍被从机锁低，总线"死了"，所有后续事务全部 NACK。

放进茶话会里看：主持人中场晕倒，爬起来重新宣布开场；刚才说到一半的那位客人还占着话头，半个字悬在嘴边，专等下一拍 SCL 把它送出去。

**根因**：从机是纯硬件状态机，不知道主机复位了。它还在等 SCL 时钟把最后一位移完，SDA 保持输出低电平（ACK 或数据 0）。主机 I2C 外设重启后发 START，从机认为"当前事务还没结束"，继续拉低 SDA。

### 恢复方案：GPIO 位带 9 个 SCL 脉冲

```c
void i2c_bus_recovery(void)
{
    /* 1. 关闭 I2C 外设 */
    I2C1->CR1 &= ~I2C_CR1_PE;

    /* 2. 把 SCL/SDA 切到 GPIO 开漏输出 */
    GPIOB->MODER &= ~(0xF << (8 * 2));   // PB6=SCL, PB7=SDA
    GPIOB->MODER |=  (0x5 << (8 * 2));   // 01 = 输出模式
    GPIOB->OTYPER |= (0x3 << (6));       // 开漏
    GPIOB->PUPDR  |= (0x1 << (6 * 2));   // 上拉（辅助）

    /* 3. 手动发 9 个 SCL 脉冲 */
    for (int i = 0; i < 9; i++) {
        GPIOB->BSRR = (1 << (6 + 16));   // SCL 拉低
        delay_us(5);
        GPIOB->BSRR = (1 << 6);          // SCL 释放（上拉拉高）
        delay_us(5);
    }

    /* 4. 检查 SDA 是否释放 */
    if (GPIOB->IDR & (1 << 7)) {
        /* SDA 高了 → 从机已释放总线 */
        GPIOB->BSRR = (1 << (7 + 16));   // 主机发 STOP：SDA 高→低期间 SCL 高
        delay_us(5);
        GPIOB->BSRR = (1 << (6 + 16));   // SCL 拉低
        delay_us(5);
        GPIOB->BSRR = (1 << 7);          // SDA 释放（上拉高）→ STOP
        delay_us(5);
    }

    /* 5. 切回 AF 模式，重新初始化 I2C */
    GPIOB->MODER &= ~(0xF << (8 * 2));
    GPIOB->MODER |=  (0xA << (8 * 2));   // 10 = 复用
    GPIOB->AFR[0] &= ~(0xFF << (6 * 4));
    GPIOB->AFR[0] |=  (0x44 << (6 * 4)); // AF4 = I2C1

    I2C1->CR1 |= I2C_CR1_SWRST;          // 软件复位
    I2C1->CR1 &= ~I2C_CR1_SWRST;
    /* ... 重新 I2C_Init() ... */
}
```

**为什么是 9 个脉冲**：I2C 一字节 8 bit + 1 ACK = 9 个 SCL 周期。从机最多在等 9 个时钟完成当前字节，9 个脉冲保证它走完状态机释放 SDA。这九拍就是主持人补敲的九下杯子：每敲一下，它送出一位；数到九，含在嘴里的必然说完，总线交还。

### DMA + I2C：非阻塞传输

轮询模式等 TXE/RXNE 会阻塞 CPU：主人一个字节一个字节亲自递话，整场就耗在递话上。DMA 让数据搬运脱离 CPU，请个帮手端着整盘字节，按节拍往 DR 里放：

```c
/* DMA 发送：DMA1_Stream6 → I2C1_TX */
DMA1_Stream6->PAR = (uint32_t)&I2C1->DR;
DMA1_Stream6->M0AR = (uint32_t)tx_buf;
DMA1_Stream6->NDTR = len;
DMA1_Stream6->CR = DMA_SxCR_CHSEL_1       // Channel 1
                 | DMA_SxCR_DIR_0          // Memory → Peripheral
                 | DMA_SxCR_MINC           // 内存地址自增
                 | DMA_SxCR_TCIE           // 传输完成中断
                 | DMA_SxCR_EN;            // 使能

I2C1->CR2 |= I2C_CR2_DMAEN;              // I2C DMA 使能
/* DMA 自动把 tx_buf 逐字节写入 DR，I2C 自动发 */
```

DMA 模式的关键：
- **DMA 传输完成 ≠ I2C 传输完成**：DMA TC 中断触发时，最后一字节还在 I2C 移位寄存器里（帮手放空了盘子，不等于最后一个字已经出口）。必须等 BTF=1（移位寄存器也空了）再发 STOP。
- **DMA 接收要用 LAST 位**：`I2C1->CR2 |= I2C_CR2_LAST`，让 DMA 收到最后一字节时自动发 NACK（而不是 ACK），从机知道该停了。

## 短自测

1. 为什么 SDA 的数据跳变必须落在 SCL 低区？
<details><summary>参考答案</summary>SCL 高电平期间的 SDA 跳变被定义为控制信号：下落=START、上升=STOP。数据若在高区变，会被全场误读为"开始/结束"，帧当场报废。所以协议规定数据只在 SCL 低区换脸，高区只负责被采样。</details>

2. 清 ADDR 标志的法定动作是什么？写反会怎样？
<details><summary>参考答案</summary>先读 SR1，再读 SR2。这是硬件约定的清除序列；不读或读反，ADDR 一直挂着，后续事件判断全卡死，I2C 寄存器版最经典的死循环现场。</details>

3. TXE 和 BTF 有何区别？为什么最后一字节必须等 BTF？
<details><summary>参考答案</summary>TXE=数据寄存器 DR 空（可以写下一字节）；BTF=移位寄存器也空了（当前字节完整上了总线）。最后一字节只看 TXE 就 STOP，会把正在移出的字节拦腰砍断，从机收到半帧回 NACK。</details>

4. 向 AT24C02 从地址 0 连写 20 字节会发生什么？正确做法？
<details><summary>参考答案</summary>页大小 8 字节，超出部分页内回绕覆盖页首附近数据；且 STOP 后有约 5ms 擦写期。正确做法：按 8 字节分页写，每页之间用 ACK polling 等擦写完成。</details>
