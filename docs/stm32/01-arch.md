# S1 F407 架构总览：为什么 0x40020000 是 GPIOA

> 🎯 背寄存器地址是最笨的学法。GPIOA 住在 0x40020000 不是天意，是 ST 画"城市地图"时划的门牌：Cortex-M4 统一编址 4GB，外设区从 0x40000000 起，AHB1 从 0x40020000 起，GPIO 每端口隔 0x400——GPIOA 自然就是 0x40020000。

## 本章精髓

1. 统一编址的世界观：Flash/SRAM/外设/内核寄存器全在一张 4GB 地图上，"访问外设"就是"访问某个地址段"，这正是 [C2](../c/02-pointer.md) 点灯公式合法的根源。
2. 总线矩阵决定"谁快谁慢"：内核经 I-Code/D-Code 取指取数，经 System 总线碰外设；AHB1（168MHz）/APB1（42MHz）/APB2（84MHz）三档速度，选错总线时钟源外设直接不干活。
3. 位带（bit-band）别名：把 SRAM/外设区的每一位映射成别名区的一个字：写别名地址=原子改一位，读-改-写隐患的官方解法。

- **能记住**：四句口诀：`0800` Flash、`2000` RAM、`4000` 外设、`E000` 内核；AHB1 上 GPIO、每口隔 `0x400`
- **能理解**：总线矩阵为什么能"边搬边算"；AHB/APB 分频怎么定外设上限；位带公式怎么把 1 位变成 1 个字
- **能用**：拿到任意外设名推出基址与所属总线；会用位带别名做单比特原子翻转，且知道它只覆盖前 1MB

## 先跑起来（10 分钟 quick win）

GDB 里连读三个地址：`x/wx 0x40020000`（GPIOA_MODER）、`x/wx 0x40021400`（GPIOF_MODER）、`x/wx 0xE000ED00`（CPUID），三个街区各看一眼，地图感立刻建立。

连上之前，先押个名字：三位住户里，两位住在同一片外设街区，只有一位不算外设，是内核自家人。是 GPIOA、GPIOF，还是 CPUID？押定再读，地图感从猜的那一刻开始长。

## 动画：一张矩阵上的五次访问

把本章精髓第 2 条播成电影：CPU 的 ICode/DCode/System 三个端口和 DMA 一起挂在 AHB 总线矩阵上，五个阶段各走一条真实路线：**取指**每拍打到 Flash（168 MHz 下 5 个等待周期，靠预取缓冲兜住，见 [S2](02-rcc-clock.md)）；**读 `USART1->SR`** 要穿 AHB→APB2 桥，两个时钟域之间还得同步；**DMA** 是矩阵上的第二台主机，搬得不占指令周期，但要跟 CPU 抢同一块 SRAM；最后一阶段故意走不通——**CCM RAM 只接到 CPU**，DMA 缓冲区放错了地方就是无声失败（[S8](08-dma.md) 有翻车实验）。分区归属依据 RM0090 的存储器映射表；等待周期那条是 S2 已核过的数字，不是估的。

## 动画：位带——一个位搬进一个字

精髓第 3 条的现场版。`GPIOF->ODR` 在 `0x4002_1414`，它的 8 个位在别名区各占一个字：`0x4242_8280`（bit0）到 `0x4242_829C`（bit7）。**地址是算出来的**：`0x4200_0000 + 0x21414×32 + 6×4 = 0x4242_8298`，`sh code/stm32/01-arch/probe.sh` 里三条 `_Static_assert` 替我们验算，编不过就是算错了。同一份 `-O2` 反汇编还把老问题摆了出来：`GPIOF->ODR |= 1u<<6` 编成 `ldr / orr.w / str` 三条，读与写之间有窗口；写别名字只剩 `movs #1` + `str.w [r3,#664]`，`BSRR` 同样一条 `str` 搞定。

## 一、4GB 地图：一块芯片怎么分房

Cortex-M4 是 32 位机，地址空间正好 4GB。ARM 架构把这 4GB 切成固定八段，谁也不能改；ST 只能在自己的段里再划分。

| 区段 | 地址范围 | 放什么 |
|---|---|---|
| Code | `0x0000_0000`–`0x1FFF_FFFF` | Flash 与其别名、系统存储区 |
| SRAM | `0x2000_0000`–`0x3FFF_FFFF` | 片上 SRAM |
| Peripheral | `0x4000_0000`–`0x5FFF_FFFF` | 全部外设寄存器 |
| RAM | `0x6000_0000`–`0x7FFF_FFFF` | 外部 RAM（经 FSMC/FMC） |
| Device | `0x8000_0000`–`0x9FFF_FFFF` | 外部设备 |
| 保留 | `0xA000_0000`–`0xDFFF_FFFF` | — |
| PPB | `0xE000_0000`–`0xFFFF_FFFF` | 内核私有外设（NVIC/SysTick/SCB） |

F407 在其中的实际落位（RM0090 §2.3 表 1）：

- `0x0800_0000`：主 Flash 1MB；同一块 Flash 在 `0x0000_0000` 还有个别名，上电从哪取指由 BOOT 引脚决定（[B4 启动](../build/04-startup.md)）。
- `0x1FFF_0000`：系统存储区，出厂固化的 bootloader 住这。
- `0x2000_0000`：SRAM1 112KB 紧接 SRAM2 16KB，共 128KB 连续。
- `0x1000_0000`：CCM RAM 64KB，只挂在 CPU 的数据总线上，**DMA 够不着**（[S8](08-dma.md) 的翻车实验）。
- `0x4000_0000` 起：外设。
- `0xE000_0000` 起：PPB，`CPUID` 就在 `0xE000_ED00`。

"192KB RAM" 的账就是这么来的：128KB 通用 SRAM + 64KB CCM。

## 二、总线矩阵：谁快谁慢

内核不只有一根总线。Cortex-M4 有三个出口：**I-Code** 取指令、**D-Code** 取数据/常量（两者只覆盖 Code 区）、**System** 管其余一切（外设、SRAM、PPB）。

F407 把这些口和 DMA1、DMA2、以太网 MAC、USB HS 一起接到一张多层 AHB 总线矩阵上，再连向 Flash 接口、SRAM、AHB1/AHB2 外设、FSMC。矩阵是**并发**的：DMA 在搬 SRAM 时，CPU 能同时从 Flash 取指，这正是 [S8 DMA](08-dma.md) 敢说"不占指令周期"的底气。

时钟分三档（[S2 时钟树](02-rcc-clock.md) 算过）：

| 总线 | 频率 | 说明 |
|---|---|---|
| AHB1/AHB2（HCLK） | 168MHz | GPIO、DMA、RCC 等 |
| APB1 | 42MHz | HCLK/4，硬件上限 42MHz |
| APB2 | 84MHz | HCLK/2，硬件上限 84MHz |

APB 分频不为 1 时，挂在 APB 上的定时器拿到的是 `APB×2` 的时钟，[S6](06-tim.md) 会用到。

Flash 取指在 168MHz 下要 5 个等待周期（RM0090 §3.3.1），靠 ART 加速器和预取缓冲把这 5 拍的坑填上。上面那张矩阵动画的"取指"阶段演示的就是这条路径。

## 三、外设门牌推导

外设地址不是背出来的，是推出来的。以 RM0090 存储器映射表为底：

- **AHB1** 段基址 `0x4002_0000`：GPIOA `0x4002_0000`，每端口隔 `0x400`：GPIOB `0x4002_0400`、…、GPIOF `0x4002_1400`。RCC 在 `0x4002_3800`，DMA1 `0x4002_6000`、DMA2 `0x4002_6400`。
- **APB1** 段基址 `0x4000_0000`：USART2 `0x4000_4400`、USART3 `0x4000_4800`、UART4 `0x4000_4C00`、UART5 `0x4000_5000`。
- **APB2** 段基址 `0x4001_0000`：USART1 `0x4001_1000`、USART6 `0x4001_1400`、SPI1 `0x4001_3000`。

记住归属比记住地址更重要：USART1 在 APB2（上限 84MHz）、USART2 在 APB1（上限 42MHz），波特率算错的头号原因就是把总线段记反了（[S7 USART](07-usart.md)）。

## 四、位带：把一位搬进一个字

位带（bit-banding，PM0214 §2.2.5）给两个区各开了一片"影子地址"：

| 位带区 | 地址范围 | 别名区 |
|---|---|---|
| SRAM | `0x2000_0000`–`0x200F_FFFF` | `0x2200_0000`–`0x23FF_FFFF` |
| 外设 | `0x4000_0000`–`0x400F_FFFF` | `0x4200_0000`–`0x43FF_FFFF` |

换算公式：

```
别名地址 = 别名区基址 + (字节地址 − 位带区基址) × 32 + 位号 × 4
```

原位带区一个**位**，在别名区占一个**字**（32 位）；1MB 位带区于是撑出 32MB 别名区。写别名地址=硬件替你完成"读—改—写"，一条 `str` 原子改一位。

实例：`GPIOF->ODR` 的字节地址是 `0x4002_1414`，它的 bit6 别名 =

```
0x4200_0000 + (0x4002_1414 − 0x4000_0000) × 32 + 6 × 4 = 0x4242_8298
```

`probe.sh` 里三条 `_Static_assert` 把 `ODR` 地址、PF6 别名 `0x42428298`、别名区跨度都钉死，算错一个数就编不过。同一份 `-O2` 反汇编还并排摆出两种写法的差别：`GPIOF->ODR |= 1u<<6` 编成 `ldr/orr.w/str` 三条，读与写之间开着窗口；写别名只剩 `movs #1` + `str.w`，`BSRR` 同样一条 `str` 搞定。

## 常见坑

- **APB1 当 APB2 用**：USART2/3 在 APB1（42MHz 上限），波特率算错源头常在总线归属记错。
- **位带去碰多比特字段**：位带一次只能改一位，改两位字段请回 BSRR/掩码。
- **以为所有地址都能读**：未实现的地址段访问直接 HardFault，GDB 乱读也会踩雷（S16 联动）。

## 短自测

**1. GPIOB 的基址是多少？说出你的推导。**

<details><summary>答案</summary>

`0x4002_0400`。AHB1 段基址 `0x4002_0000`，GPIO 每端口隔 `0x400`：GPIOA `0x4002_0000` → GPIOB `0x4002_0400`（GPIOF 就是 `0x4002_1400`，本章 ODR 实验用的那个）。

</details>

**2. 位带别名公式是什么？为什么 1MB 位带区要撑出 32MB 别名区？**

<details><summary>答案</summary>

`别名 = 别名区基址 + (字节地址 − 位带区基址) × 32 + 位号 × 4`。原位带区一个**位**在别名区占一个**字**：1 位换 32 位，所以 1MB × 32 = 32MB。乘 32 的来历就是"位→字"的放大倍数。

</details>

**3. CCM RAM 在哪个地址？为什么 DMA 缓冲区不能放那儿？**

<details><summary>答案</summary>

`0x1000_0000`，64KB。它只挂在 CPU 的 D-bus 上，不在 AHB 总线矩阵上，DMA 控制器根本看不到这段地址，放进去的缓冲区会静默丢数据（[S8](08-dma.md)）。

</details>

**4. USART1 和 USART2 分别在哪个总线段、时钟上限各是多少？**

<details><summary>答案</summary>

USART1 在 APB2（`0x4001_1000`，≤84MHz）；USART2 在 APB1（`0x4000_4400`，≤42MHz）。把 USART2 当成 84MHz 算波特率，误差能大到收不到数据。

</details>
