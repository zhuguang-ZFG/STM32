# 项目实战与交付验收

「做完」不是指灯亮过一次——**别人按你的说明能复现，你能说出还没做的部分**，才算做完。本章把项目实战的推进纪律（一轮只加一个新外设、失败三岔口）与交付验收的方法论（证据链四问、预算先行、四条通用验收纪律、交付包清单）收拢成一张合同：先写输入/输出/失败/恢复，再写业务代码。

证据先说清：本章零板级实测。源章 D19 的十个项目全部没有上板读数，代码段是片段不是工程；五处代码自带「待纠正草图不能直接烧录」声明（本章与代码同页保留）；工时与难度星级是「经验值，仅供规划参考」；WS2812 时序数来自灯珠厂商数据手册（不是 RM0008），带修订版限定。四组资源算术（分区/SRAM/ADC/USB 分包）可复算，与 [v1 各章](../v1-drivers/08-architecture-memory-clock.md) 已冻结口径一致。

> 版本口径：D19《项目实战合集》（`docs/19-项目实战合集.md`，637 行：原理段 + 十个递进项目 + 验收方法论）；ACC《motor 验收框架》（`plans/2026-11-11-motor-control/acceptance.md`）——本章从 ACC 提炼三条通用验收纪律并注明出处，AC/H 编号矩阵本身是 motor 专用，不通用。

## 本章罗盘

- **问题**：选题的「证据链能否闭合」四问是什么？十个递进项目怎么按四问重排验收栏？「一轮只加一个新外设」防的是什么，失败三岔口（贪多/跳步/无证据）怎么识别？预算先行的六项清单是什么，超了怎么办？从 motor 验收框架能提炼哪几条通用纪律（NOT_RUN 不计通过/模拟不填真板/重复全留/阈值先冻结）？交付包要装哪些东西？源代码里的「待纠正草图」怎么处理？
- **交付**：能按四问给任何项目写验收栏；能把六项预算表填出来并执行「超了缩功能或换芯片」；能复述四条通用验收纪律并指出出处；能列交付包五件套（与 ACC §6 取并集）；能识别五类「待纠正草图」并解释为什么声明必须随代码走。
- **边界**：本章讲推进与验收方法论；十个项目的技术细节（每个项目的方案与代码）是源章的正文，本章只收「怎么验收」视角与四组算术；motor 的 PI 调参与指标定义归 [第 39 章](../v5-motion/39-speed-closed-loop-pi.md)；实验仪器方法归 [第 40 章](./40-lab-method-instruments.md)；IAP/OTA 机制归 [v1 第 17 章](../v1-drivers/17-flash-iap-ota.md)。
- **依据锚点**：D19《项目实战合集》（`docs/19-项目实战合集.md`）、ACC（`plans/2026-11-11-motor-control/acceptance.md`）。上游对账：DS5319（C8 SRAM 20 KB）、RM0008/RM0090（分区与外设）、USB 2.0 规范（wMaxPacketSize）——四组算术与 [v1 第 8 章](../v1-drivers/08-architecture-memory-clock.md)、[v1 第 13–14 章](../v1-drivers/13-uart-framed-protocol.md) 已冻结口径互证。

## 先做出来

### 1. 四组资源算术（先算账再动手）

```text
分区账：Bootloader 16 KB(0x08000000) + 参数 2 KB(0x08004000) + APP 46 KB(0x08004800)
        16+2+46 = 64 KB，恰好到 0x08010000
双 APP 不成立：16+2+46+46 = 110 KB → 0x0801B800 越过 C8 的 0x08010000 边界
SRAM 账：C8 SRAM = 20 480 B（20 KB）→ 65 536 字节的缓冲放不下
ADC 名义换算：LSB = Vref/4096；码 2048 @3.3 V → 1.65 V（4095 端点差异近满码约一个 LSB）
USB 分包：应用帧 4+128+1 = 133 B → 全速批量一包 64 B → 拆 64+64+5，wMaxPacketSize 仍写 64
```

「两个 23 KB 只是容量算术，不能认定双槽方案已成立」——这句限定句与算术同页保留。**任何一项超预算都先缩功能或换目标芯片**。

### 2. 四问验收栏

每个项目在动工前先填四问：**输入怎么测**（拿什么仪器、什么判据）？**状态怎么记录**（日志/遥测/指示灯的语义）？**输出怎么验收**（谁来判定、阈值多少、谁冻结）？**失败后怎么恢复**（复位/回滚/降级路径）？填不出来的项目还没到动工的时候——先补设计。

## 机制

### 一、十个递进项目与四问重排

D19 的十个项目（按键/串口/中断/PWM/ADC+DAC/DMA/I2C EEPROM/SPI Flash/CAN/USB/IAP/网络/蓝牙小车/电机/自平衡等，按递进排序）保持原顺序与技术方案；**验收栏按四问重排**——工时与难度星级降为「经验值，仅供规划参考」的注记，不作为承诺。每项目保留七件套里的关键代码片段，五处「待纠正草图」声明随代码同页：

| 草图 | 位置 | 声明 |
| --- | --- | --- |
| WS2812 双 CCR 写法 | D19:382 | 不能直接烧录；时序数（T0H=0.4 µs/T1H=0.8 µs/周期 1.25 µs）来自灯珠数据手册，不能覆盖所有修订版，复位低电平另查 |
| SetMotor 无真值表 | D19:148 | L298N 每路需要 IN1/IN2+ENA，下段未实现 |
| Boot_SelectApp 无边界检查 | D19:329 | 跳转前缺合法性验证（[v1 第 17 章](../v1-drivers/17-flash-iap-ota.md) 的 IAP 跳转向量口径补齐） |
| LA_Upload 不等 BUSY | D19:429 | 上传循环缺忙等待 |
| 逻辑分析仪段实为 TIM 中断 | D19:422 | 注释与实现不符，读代码以实现为准 |

### 二、推进纪律：一轮一个新外设

「一轮只加一个不确定的外设」——两个未知数叠加时，现象无法归因。失败三岔口（出现即回退）：**贪多**（一轮加了两个新东西）、**跳步**（没验证上一轮就推进）、**无证据**（现象没有记录，复现不出来）。推进的每轮结束写两行：这轮证明了什么、还没证明什么。

### 三、四条通用验收纪律（提炼自 motor ACC）

| 纪律 | 出处 | 内容 |
| --- | --- | --- |
| NOT_RUN/BLOCKED 不计通过 | ACC:22 | 状态没跑就是没跑，不能折算成部分通过 |
| 模拟数据不填真板状态 | ACC:17 | 宿主模型的结果只能标「宿主验证」，不填 `hardware_status` |
| 重复全部保留 | ACC:90 | 多次测量全展示，不挑最好的一次 |
| 合同先行，阈值测前冻结 | ACC:20,61 | 指标在测量之前写死；测完改阈值=作弊 |

AC/H 编号矩阵（H01–H10、AC03 等）是 motor 专用——本章取其**语言**，不取其编号。

### 四、交付包清单（D19 四条 + ACC §6 并集）

1. 干净环境重建脚本（第三台机器能一次跑通）；
2. ELF + map（地址与体积的证据）；
3. 配置（版本、hash、与测试记录的关联）；
4. 接线图与验收记录（[第 40 章](./40-lab-method-instruments.md) 的记录表格式）；
5. 已知限制与恢复步骤（「没做的部分」清单——做完的定义里的一半）。

ACC §6 的 SHA256SUMS 与 metadata.json 字段表更严格——取两者并集：原始数据带哈希、metadata 记录版本三元组（[第 40 章](./40-lab-method-instruments.md) 的证据分级标签全程适用）。

### 五、里程碑三岔口与预算清单

项目推进到中期最容易掉进三岔口（贪多/跳步/无证据），解药是**预算先行**的六项清单：Flash、RAM、最坏响应、平均电流、带宽、队列峰值——每项有算式（[第 41 章](./41-dual-board-logger-project.md) 的 64 B/1 KB 账、[第 25 章](../v3-rtos/25-memory-management.md) 的堆预算都是同类）。六项里任何一项超了，先缩功能或换目标芯片，不动阈值。

### 六、SRAM 预算图与缓冲所有权

D19 的 SRAM 账有一句容易漏的话：**heap_4 的 ucHeap 已计入静态占用，动态栈不能再加**（[第 25 章](../v3-rtos/25-memory-management.md) 的 .bss 口径）；DMA 缓冲的所有权交接（半区时间 = 256/采样率秒）与 [v1 第 14 章](../v1-drivers/14-dma.md) 的 DMA 语义一致。自平衡项目的 kp=25.0/kd=0.8 与 5 ms 是**示例参数与调度目标**（需实测、无积分项无速度环）——禁抄成稳定参数。

## 失败分支

| 症状 | 第一条假设 | 区分实验 |
| --- | --- | --- |
| 项目推不下去 | 一轮加了两个新外设（贪多） | 回退到上一轮；一轮一个 |
| 现象复现不出来 | 无证据推进（没记录） | 补记录表；重跑一轮带 [第 40 章](./40-lab-method-instruments.md) 登记 |
| 上电就跑飞 | 跳过了上一轮的验证 | 回到最近一个「两行收尾」完整的轮次 |
| APP 烧不进 / 跳转失败 | 分区账没算或 Boot_SelectApp 无边界检查 | 复算分区账；草图声明逐条对 |
| 缓冲「超 RAM」 | 65 KB 缓冲 vs 20 KB SRAM 的账没做 | 预算六项重填 |
| 验收数字被质疑 | 阈值测后才定 / 只留了最好一次 | 四条通用纪律重读；重复全留 |
| 交付后第三台机器跑不起来 | 缺干净环境重建脚本 | 交付包清单逐项补 |

## 离开检查

- 四问验收栏能给任何项目填出来。
- 四组算术当场复算；「双 APP 不成立」的限定句与算术同在。
- 四条通用验收纪律能背并指出 ACC 出处。
- 交付包五件（并集版）能列全。
- 五处「待纠正草图」的声明与代码同页——禁直接烧录的边界守得住。
- 十项目的验收栏按四问重排，工时星级降为注记。
