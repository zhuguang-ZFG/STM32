# SysTick 与时基（含 RTC）

> 芯片里有两颗心跳。一颗是内核的 SysTick：24 位倒数秒表，LOAD 定周期、VAL 看进度、CTRL 管开关，归零时置一个读过就清的标志。另一颗是备份域的 RTC：主电源断了，只要 VBAT 上还有电，秒计数器照样走。前者回答“过了多久”，后者回答“现在几点”。这一章把 SysTick 的四个寄存器拆成可复算的周期账，把 167999 的来历、忘减一的相位差、24 位上限与回绕安全的超时写法排成一列，再把 RTC 的备份域、LSE 与时间戳边界划清楚。看门狗不在本章，留给[第 19 章](../v2-reliability/19-watchdog-reset-hardfault.md)。

## 本章罗盘

- **问题**：168MHz 下要 1ms，为什么 LOAD 填 167999 而不是 168000？忘减一为什么“次数不变、相位变慢”，5.95ppm 与日漂移 514ms 是怎么算出来的？为什么“先读一次 CTRL 打印、再读一次判断”的查询式延时会死等？`SysTick_Config(168000)` 之后 CTRL 为什么是 `0x00000007`，SHP[11] 为什么是 `0xF0`？168MHz 下 24 位计数器单次最长能撑多久，请求 100ms 为什么被拒、强行截断为什么会 737 倍速？49.7 天回绕时，哪种超时写法仍然正确？主电源拔掉后 RTC 靠什么继续走，F1 与 F4 各保存了什么，时间戳又落在哪一边？
- **交付**：能按“时钟频率 ÷ 每秒 tick 数 − 1”算任意 LOAD，并先判断它是否超过 24 位；能说出 `SysTick_Config` 的三写一设与返回值含义；会把 COUNTFLAG 读一次存进变量再判断；会写 `(uint32_t)(now - then) >= timeout` 的回绕安全超时；能解释 SysTick 优先级为什么落在最低档；能按“电源、复位、写门”三道边界检查 RTC，会选 LSE 或 LSI、写 PRL = 32767、用 BKP 魔数判断首次上电，并分清 F1 的秒计数器与 F4 的 BCD 日历、时间戳。
- **边界**：两平台章。F407 的地址、位段、probe 读数来自 S5《SysTick：内核的心跳》与 `core_cm4.h`、`stm32f407xx.h`；F103 的 72MHz 分母来自根书第 05 章与[第 8 章](./08-architecture-memory-clock.md)，RTC 的备份域、LSE、BKP 与时间戳边界来自根书第 11 章与 RM0008、DS5319。来源没有记录本章的上板读数（PF6 翻转、调试器偷看 CTRL、LSE 起振时间），本章把它们写成实验设计与判据。定时器 TIM 与 PWM 留给[第 12 章](./12-timers-pwm.md)，看门狗留给[第 19 章](../v2-reliability/19-watchdog-reset-hardfault.md)，低功耗唤醒留给[第 18 章](../v2-reliability/18-low-power.md)，RTOS 的 tick 与上下文切换留给[第 21 章](../v3-rtos/21-why-rtos.md)、[第 23 章](../v3-rtos/23-context-switch-porting.md)，NVIC 的优先级分组与 EXTI 留给[第 10 章](./10-interrupts-nvic-exti.md)。
- **依据锚点**：S5《S5 SysTick：内核的心跳》（`mcu/docs/stm32/05-systick.md`）、根书第 05 章《定时器与 PWM》（`docs/05-定时器与PWM.md`）的时基部分、根书第 11 章《RTC 与看门狗》（`docs/11-RTC与看门狗.md`）的 RTC 部分；[第 8 章](./08-architecture-memory-clock.md)的 168MHz 与 72MHz 账、[第 10 章](./10-interrupts-nvic-exti.md)的 SHP 与中断约束、[第 9 章](./09-gpio.md)的 PC13 灌电流规则、[第 2 章](../v0-foundations/02-c-volatile-ub.md)的 volatile 合同、[第 3 章](../v0-foundations/03-struct-abi-registers.md)的寄存器结构体。PM0214、RM0090、RM0008、DS5319 的条文均转引自上述来源。

## 先做出来

开局不烧板，先在宿主机上把 SysTick 的账跑一遍。来源工程把断言、头文件常数与交叉编译证据收在一个脚本里：

```bash
cd mcu/code/stm32/05-systick
sh probe.sh          # 宿主 gcc 跑 42 条断言；PATH 里有交叉工具链时再编一份 Cortex-M4 目标文件
```

输出里先找这两行，它们是本章的骨架：

```text
[宿主] 断言通过 42/42
[6] SysTick_Config(168000)：LOAD=167999 VAL=0 CTRL=0x00000007，SHP[11]=0xF0 → 逻辑优先级 15
```

第二行把四件事排在一起：请求 168000 个时钟的配置，落到 LOAD 里是 167999；CTRL 三位全开是 `0x7`；优先级落在 SHP[11] 的 `0xF0`。交叉编译段还能找到 `movw r2, #16799`、`movw r1, #22783`：16799 是 100µs 的 LOAD（`probe.c:123`），22783 是 100ms 请求被 `& 0xFFFFFF` 截断后的 LOAD（`probe.c:180-181`）；167999（`0x2903F`）超出 16 位 `movw` 立即数的范围，目标文件里不可能靠单条指令认出它。

出个选择题再跑：要 SysTick 每毫秒敲一次钟，LOAD 该填原数、原数减一，还是原数加一？答案就在上面那行 `LOAD=167999` 里；读完“周期 = LOAD + 1”一节，你会知道这不是口诀，是计数器从零起跳的规矩。

有板的人可以先不接仪器：烧一个 1ms tick，主循环里每 500 次翻转一次 PF6，再用逻辑分析仪量翻转周期。来源把这项写成实测对比（500ms±0.1%，软件延时版误差肉眼可见），但没有留下波形或日志；本章把它当作待做的实验，不写成已经量到的读数。

## 机制

SysTick 的机制可以压成一句话：四个寄存器，一条“减到零再重载”的计数规则。RTC 的机制则是三道边界加一条分频。先把内核这颗拆完，再进备份域。

### 四个寄存器，地址固定在 0xE000E010

CMSIS 头文件把四个寄存器排成一个结构体（`core_cm4.h:764-770`）：

```c
typedef struct
{
  __IOM uint32_t CTRL;   /* Offset: 0x000 (R/W) 控制与状态 */
  __IOM uint32_t LOAD;   /* Offset: 0x004 (R/W) 重载值     */
  __IOM uint32_t VAL;    /* Offset: 0x008 (R/W) 当前值     */
  __IM  uint32_t CALIB;  /* Offset: 0x00C (R/ ) 校准       */
} SysTick_Type;
```

基址是拼出来的：`SCS_BASE = 0xE000E000`（`core_cm4.h:1550`），`SysTick_BASE = SCS_BASE + 0x0010`（`:1555`），得 `0xE000E010`。probe 第 1 段用 `offsetof` 实测背书：

```text
[1] 布局：CTRL/LOAD/VAL/CALIB 偏移 = 0x0/0x4/0x8/0xC，SysTick_BASE = 0xE000E010（内核外设，所有 Cortex-M 通用）
```

最后半句是关键：SCS（System Control Space）是 ARM 内核的地盘，不是芯片厂的外设区。STM32、GD32、nRF52 的 SysTick 全在同一个地址，RTOS 的移植层因此只需写一遍 tick 初始化。查手册时也一样：SysTick 的问题翻 PM0214，不翻 RM0090 的外设章节。

| 偏移 | 寄存器 | 读写 | 本章用到的字段 |
| --- | --- | --- | --- |
| `0x000` | `CTRL` | 读写 | ENABLE、TICKINT、CLKSOURCE、COUNTFLAG |
| `0x004` | `LOAD` | 读写 | 重载值，低 24 位有效 |
| `0x008` | `VAL` | 读写 | 当前计数值，`SysTick_Config` 往里写一次清零 |
| `0x00C` | `CALIB` | 只读 | 校准值，本章不展开 |

真正要配的只有前三个。`CALIB` 是只读的，改不动；它的校准值属于另一本账，配 tick 时用不上。

### CTRL：三个开关与一个读过就清的标志

位定义出自 `core_cm4.h:773-783`，`probe.c:36-40` 有同义镜像：

| 位 | 名字 | 作用 |
| --- | --- | --- |
| bit0 | ENABLE | 计数器使能 |
| bit1 | TICKINT | 归零时是否申请 SysTick 中断 |
| bit2 | CLKSOURCE | 1 = 内核时钟（F407 是 168MHz），0 = 参考时钟 |
| bit16 | COUNTFLAG | 归零标志——读 CTRL 即清 0 |

前三位望文生义；bit16 是本章最实用的坑。硬件语义：VAL 归零那一拍把它置 1；软件读 CTRL 这个动作本身把它清 0（read-to-clear，PM0214 的语义，`probe.c:71-77` 的 `sim_read_ctrl` 把它写成了代码）。probe 第 7 段的对照实验：

```text
[7] COUNTFLAG：周期到后第一次读 CTRL=0x00010005（有标志），紧接第二次读=0x00000005（标志已被上一次读清掉）
    对照：5 个周期里单读法数到 5 次；「先偷看再查」双读法数到 0 次——标志被第一次读偷走，延时死等
```

落到代码（`probe.c:244-260`）：

```c
/* 单读法：读一次，结果直接判断 —— 5 中 5 */
if (sim_read_ctrl(&b) & CTRL_COUNTFLAG) got_right++;
/* 双读法：先偷看一眼（调试打印/无意识的首次读），再查 —— 0 中 */
(void)sim_read_ctrl(&b);
if (sim_read_ctrl(&b) & CTRL_COUNTFLAG) got_wrong++;
```

实战规则：读一次、存进变量、再判断。调试器 watch 窗口点一下 `SysTick->CTRL` 都算一次“偷看”；实物上这个坑表现为延时偶发死等。第二种死等来自中断：ISR 里查询 COUNTFLAG，而 tick 中断自己又进不来，计数不前进，见“失败分支”。

### 周期 = LOAD + 1：167999 的来历与忘减一的账

先看这张图：倒数、归零重载，和那个“读一次就清”的 COUNTFLAG。

![SysTick 倒数与 COUNTFLAG 读清：LOAD 减到 0 重载，读 CTRL 清标志](/anim/systick-tick.svg)

硬件语义（`probe.c:45-48` 注释）：使能后每个周期 VAL--；VAL 已经为 0 的那个周期执行重载、置 COUNTFLAG。所以从 LOAD 数到 0 再重载，一个完整周期是 LOAD + 1 个时钟。“减一”不是口诀，是数出来的。

168MHz 要 1ms：168000000 / 1000 = 168000 个时钟 → `LOAD = 168000 - 1 = 167999`。probe 第 2 段一族三例：

```text
[2] 168MHz：1ms → LOAD=167999，100us → LOAD=16799，10ms → LOAD=1679999
```

模型实测（`probe.c:128-135`）：LOAD=167999 跑 1680000 个周期，归零重载恰好 10 次，周期 = 168000 个时钟 = 1.000000ms。

那忘减一（LOAD=168000）会怎样？反直觉的结论：次数一样，相位不对。probe 第 3 段：

```text
[3] 模型：LOAD=167999 跑 1680000 周期 → 归零重载 10 次（周期 = LOAD+1 = 168000 周期 = 1.000000ms）
    忘减一：同跑 1680000 周期两者都重载 10 次——差别不在次数在相位；每个 tick 慢 1/168000（5.95ppm），日漂移 514ms
    相位：第 10 次重载——正确配置在第 1512001 个时钟，忘减一在第 1512010 个，9 个间隔共欠 9 个时钟
```

逐拍对账：正确配置第 10 次重载落在第 1 + 9 × 168000 = 1512001 个时钟；忘减一落在第 1 + 9 × 168001 = 1512010 个。每个 tick 慢 1/168000 ≈ 5.95ppm，一天欠 86400000 × 1000 / 168000 = 514ms。短延时根本看不出，长期计时（数据记录器、日历时基）才暴露，这正是“忘减一”阴险的地方。

<details>
<summary>自己算两笔</summary>

168MHz 下 2ms：168000000 × 2 / 1000 = 336000 个时钟，`LOAD = 335999`，周期 = 336000 个时钟 = 2.000ms。100µs：168000000 / 10000 = 16800 个时钟，`LOAD = 16799`，与 probe 第 2 段同一族。

</details>

### 24 位上限：装不下就是装不下

`core_cm4.h:786-791`：LOAD 与 VAL 的掩码都是 `0x00FFFFFF`，只有低 24 位，`LOAD_MAX = 16777215`。168MHz 下单次最长 (16777215 + 1) / 168 = 99864µs ≈ 99.86ms：1ms tick 无压力，想单次 100ms 就不行。probe 第 4 段给了两级证据：

```text
[4] 24 位上限：LOAD 最大 16777215（0xFFFFFF）→ 最长单次 99864us（≈99.86ms，1ms tick 无压力，100ms 单次不行）
    请求 100ms（ticks=16800000）：SysTick_Config 返回 1 拒配；若强行 &0xFFFFFF → LOAD=22783，tick 变成 135.6us，ISR 狂跳 737 倍速
```

- **正规路径**：`SysTick_Config` 第一行就是 `(ticks - 1UL) > SysTick_LOAD_RELOAD_Msk` 则返回 1（`core_cm4.h:2024-2027`），即拒配，寄存器一个都没动。所以必须查返回值。
- **经典 bug**：不查返回值，强行 `& 0xFFFFFF` 写进去 → `LOAD = 22783`，tick 变成 135.6µs，ISR 以 737 倍速狂跳（16800000 / 22784 = 737），系统直接瘫在中断里（`probe.c:176-186`）。

更长的周期怎么办：要么 CLKSOURCE=0 走参考时钟（F407 上是 HCLK/8，单次上限拉到约 800ms），要么换 32 位的 TIM，那是[第 12 章](./12-timers-pwm.md)的地盘。F103 的参考时钟比例按对应编程手册的 SysTick 一节核对，本章不把 800ms 搬过去。

### 时间换算与回绕：先减再比

![无符号回绕：then 在绕前、now 已绕回时，先减再比仍得 3000ms](/figures/stm32-05-tick-wrap.svg)

1 个时钟 = 1/168MHz = 125/21 ns ≈ 5.952ns。整数公式 `ns = c*1000/168`（向零截断）：c=1 → 5ns，c=168 → 1000ns = 1µs（整 µs 无损），c=1000 → 5952ns = 5.952µs（按整数 µs 取 5µs，丢掉 0.952µs）。probe 第 5 段：

```text
[5] 换算：1 周期 = 125/21 ns ≈ 5.952ns；整数公式 ns=c*1000/168：c=1 → 5ns、c=168 → 1000ns=1us（整 us 无损）、c=1000 → 5952ns=5.952us（按整数 us 取 5us，丢 0.952us）
    回绕：uint32_t ms 计数 49.7 天绕一圈；then=0xFFFFFC18 now=5000 → (now-then)=6000ms（无符号减法跨回绕正确）；而 now>=then+timeout 在 now=2000 时漏报未超时
```

毫秒计数用 `uint32_t`：2^32 / 86400000 ≈ 49.7 天绕一圈。回绕不是“这辈子遇不到”，是“第 50 天前后必爆”——除非写成无符号减法：

```c
uint32_t then = g_tick;                    /* 记录起点 */
if ((uint32_t)(g_tick - then) >= timeout)  /* 先减再比，跨回绕也正确 */
    timeout_handler();
```

反例（`probe.c:205-213`）：`then = 0xFFFFFC18`（绕前 1000ms）、`timeout = 500`，`then + timeout = 4294966796` 没回绕；而 `now = 2000` 已经回绕，朴素写法 `now >= then + timeout` 判出 0（未超时），可真实早已越过 500ms 阈值。这是漏报：本该立刻报超时，它却要一直等到 `now` 也爬到 4294966796 才翻转。无符号减法 `(now - then) = 3000 >= 500` 永远正确。

全站的 delay、采样超时与事件等待，统一用这个写法。probe 第 5 段另一组数 `then = 0xFFFFFC18`、`now = 5000` 得 6000ms，也是同一条减法跨过回绕。

### SysTick_Config：三写寄存器，一次设优先级

`core_cm4.h:2022-2036` 全文就六行有效代码：先查上限，然后写 LOAD、设优先级、写 VAL、写 CTRL。probe 第 6 段实测 `SysTick_Config(168000)` 之后的现场：

```text
[6] SysTick_Config(168000)：LOAD=167999 VAL=0 CTRL=0x00000007，SHP[11]=0xF0 → 逻辑优先级 15（4 位里的最低档，RTOS 就要它在最低）
```

按顺序还原这六个动作：

```c
/* core_cm4.h:2022-2036 的有效动作，按顺序 */
if ((ticks - 1UL) > SysTick_LOAD_RELOAD_Msk) return 1;   /* 查上限：超了拒配，寄存器不动 */

SysTick->LOAD = ticks - 1UL;                              /* 第一写：重载值 */
NVIC_SetPriority(SysTick_IRQn, (1UL << __NVIC_PRIO_BITS) - 1UL); /* 设优先级：最低档 */
SysTick->VAL  = 0UL;                                      /* 第二写：清零 */
SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk |
                SysTick_CTRL_TICKINT_Msk |
                SysTick_CTRL_ENABLE_Msk;                  /* 第三写：0x7，开跑 */
return 0;
```

- `CTRL = 0x00000007`：ENABLE | TICKINT | CLKSOURCE 三位全置：内核时钟、开中断、开跑。
- 优先级怎么算：F407 的 `__NVIC_PRIO_BITS = 4`（`stm32f407xx.h:49`），`SysTick_IRQn = -1`（`:75`）；`__NVIC_SetPriority` 对负数 IRQn 走 `SCB->SHP[((IRQn)&0xF)-4]`（`core_cm4.h:1814-1824`），写入字节 = priority << (8 - 4)。(1 << 4) - 1 = 15，15 << 4 = `0xF0` → SHP[11] = `0xF0`，4 位优先级里的最低档。[第 10 章](./10-interrupts-nvic-exti.md)的七中断表把 SysTick 的 SHP 字节写成 `0xE000ED23`，与下标 11 对得上。

为什么 RTOS 要它最低：tick 中断里跑的是调度器，而调度必须给一切外设中断让路：串口字节不等人的，高优先级 tick 会把 RXNE 中断顶飞。RTOS 的 tick 设计与上下文切换见[第 21 章](../v3-rtos/21-why-rtos.md)、[第 23 章](../v3-rtos/23-context-switch-porting.md)。

### F103：同一个内核秒表，换一个分母

F103 的 SysTick 与 F407 是同一颗内核外设：地址 `0xE000E010`、四个寄存器、`LOAD + 1` 的周期语义都不变。变的只有分母：F103 的 HCLK 是 72MHz（[第 8 章](./08-architecture-memory-clock.md)算过这笔账），1ms 要 72000 个内核时钟，`LOAD = 71999`。

| 目标周期 | F407 @168MHz 的 LOAD | F103 @72MHz 的 LOAD |
| --- | --- | --- |
| 100µs | 16799 | 7199 |
| 1ms | 167999 | 71999 |
| 10ms | 1679999 | 719999 |
| 100ms | 超限：16800000 > 16777216 | 7199999 |
| 1s | 超限 | 超限：72000000 > 16777216 |

按同一公式还能算出两条边界。第一，72MHz 下单次最长 (16777215 + 1) / 72 = 233016µs ≈ 233ms，比 F407 的 99.86ms 宽一倍多。第二，1 秒 tick 需要 72000000 个时钟，远超 24 位，`SysTick_Config(72000000)` 会返回 1 拒配；想要 1 秒，要么用 1ms tick 软件计数，要么换 TIM。

优先级一侧，SHP 的下标公式 `((IRQn)&0xF)-4` 与左移 `8 - __NVIC_PRIO_BITS` 是内核约定；F103 的位宽按 `stm32f103xb.h` 的 `__NVIC_PRIO_BITS` 重算，别把 `0xF0` 当成跨系列的常数。

`HAL_Delay()` 依赖这颗 tick。若在优先级高于 SysTick 的 ISR 里调用它，计数不前进，就会死等；[第 10 章](./10-interrupts-nvic-exti.md)已经拆过这条失败分支。

### RTC：备份域、三道边界与一条分频

RTC 是芯片里的一块电子表，它和备份寄存器、LSE 振荡器一起住在备份域，与主域分开供电、分开复位。主域负责跑程序，备份域负责在主电源断开、复位、甚至待机时守住时间和几十字节的便签。这一节按三道边界看它：电源边界、复位边界、写门。

**电源边界**：RTC 由备份域供电；主电源断开后，只要第 1 脚 VBAT 上还接着纽扣电池，秒计数器和备份寄存器就继续工作。根书以 BluePill 为例：VBAT 接 3V 纽扣电池（CR2032），LSE 晶振焊在 PC14-OSC32_IN（第 3 脚）与 PC15-OSC32_OUT（第 4 脚）。

**复位边界**：NRST、独立看门狗、窗口看门狗与上电复位撞在同一个边界上：主域清零、程序从复位向量重来，备份域不动。所以“重启后表还在走”和“程序重新初始化”是两件事；前者由 VBAT 与备份域保证，后者由复位向量决定。

**写门**：备份域默认不让你随便写。写之前要打开 PWR 与 BKP 时钟，并置位 `PWR_CR` 的 DBP；不解锁就写 PRL 或 BKP_DR，值不会落地。写不进去的时候，多半不是晶振坏了，而是域还锁着，或者写保护没解。

时钟源的选择决定 RTC 能准到什么程度：

| 时钟源 | 频率 | 精度 | 引脚占用 | 适用 |
| --- | --- | --- | --- | --- |
| LSE（外部 32.768 kHz 晶振） | 32.768 kHz | 由晶振决定，常见 ±20 ppm，以晶振手册为准 | PC14/PC15 | 需要准确走时 |
| LSI（内部 RC） | 最小 30 kHz，典型 40 kHz，最大 60 kHz | DS5319 表 25 的范围，不是 ±50% | 无 | 省引脚、仅做唤醒 |
| HSE/128（主晶振分频） | 8 MHz/128 | 取决于 HSE | 占用 HSE | 已有高精度主晶振 |

分频比是 `(PRL + 1)`，不是 PRL。32768 Hz 要 1 Hz，PRL 写 32767；写成 32768 就变成 32769 分频，秒脉冲慢 30.5ppm，一天约 2.6 秒。LSI 典型 40kHz，又会在 30–60kHz 之间漂，用任何整数 PRL 都得不到稳定的 1Hz：RTC 要准就得用 LSE。

F1 与 F4 的 RTC 不是同一套账：

| 功能 | 说明 | 关键寄存器 |
| --- | --- | --- |
| 日历 | F1 需软件换算；F4 硬件 BCD | `RTC_TR`/`RTC_DR`（F4） |
| 闹钟 | F1 比较秒计数器；F4 可按字段掩码匹配 | `RTC_ALR`（F1）/`RTC_ALRMxR`（F4） |
| 周期唤醒 | 按固定周期自动唤醒，配合 STOP 省电 | `RTC_WUTR`（F4） |
| 时间戳 | 引脚上升沿记录当前时间 | `RTC_TSTR`/`RTC_TSDR`（F4） |

时间戳是 F4 才有的硬件功能：引脚上升沿到来时，当前时间被锁进 `RTC_TSTR`/`RTC_TSDR`。F1 的 RTC 只有 32 位秒计数器，没有这组寄存器；要在 F1 上记录“某个边沿发生在第几秒”，只能让 EXTI 中断去读秒数，精度受中断延迟限制。这就是时间戳的边界：不是所有 RTC 都能替你做这件事。

还有一条读一致性：时间与日期分在两个寄存器里，读序列要按锁存规则走。根书例程在读时间后紧接读日期，注释写“读日期会锁存时间寄存器”；把两次读当成同一瞬间，跨秒时就会把前一秒的时间与后一秒的日期拼在一起。日历读取受这条约束；时间戳的 `TSTR`/`TSDR` 是另一对寄存器，读取顺序同样按手册的锁存规则走。

备份寄存器是备份域里的便签纸。C8 上有 10 个 16 位寄存器（`BKP_DR1`~`BKP_DR10`），共 20 字节；资料里的 42 个是大容量型号的数字，不能照抄。最常见的用法是贴一个魔数（如 `0xA5A5`）：上电先读 `BKP_DR1`，匹配就直接读表，不匹配才初始化日历并写回魔数。少了这张条子，每次重启都会把时间重置一遍。F4 换成 20 个 32 位寄存器，宽度与个数都要重查。

LSE 起振慢，初始化超时给得太短会误判失败；真的不起振，再查负载电容与焊接。调试阶段可以暂时改用 LSI，先把日历逻辑跑通，再换回 LSE 校时。LSE 占着 PC14/PC15 时，这两只脚不能再当 GPIO；PC13 若还当心跳灯，规则与[第 9 章](./09-gpio.md)相同：只能灌电流，写 0 才亮。

### 两颗心跳的分工

两颗心跳回答不同的问题。SysTick 回答“过了多久”：它是内核的 tick，分辨率是时钟周期，用于延时、超时、RTOS 节拍；它不记年月日，掉电就重来。RTC 回答“现在几点”：它住在备份域，分辨率是秒（F1）或 BCD 字段（F4），掉电靠 VBAT 续走；它不适合做微秒级延时，读一次也要按锁存规则来。

不要用 SysTick 冒充日历，也不要用 RTC 做毫秒延时：前者的 24 位上限与回绕、后者的 1 秒分辨率，各自划定了能力边界。需要两者配合时（例如数据记录器给每行打时间戳），让 SysTick 管采样间隔、RTC 管墙上时间，两边各自守自己的回绕与锁存规则。

RTOS 的 tick 就建在 SysTick 上：调度器在 tick 中断里决定要不要换任务，所以这颗中断的优先级必须最低。低功耗模式下的时基与 RTC 唤醒见[第 18 章](../v2-reliability/18-low-power.md)。

## 失败分支

| 现象 | 原因 | 区分证据 | 下一动作 |
| --- | --- | --- | --- |
| 延时每个 tick 慢一点，短测看不出 | LOAD 写成 168000，忘减一 | probe 第 3 段：次数相同、相位差 9 个时钟 | LOAD 改成 ticks − 1 |
| 查询式延时偶发死等 | 先读 CTRL 打印或调试器偷看，COUNTFLAG 被读清 | 第二次读 CTRL 的 bit16 恒为 0 | 读一次存变量再判断 |
| 请求 100ms 没反应，寄存器没动 | `SysTick_Config` 返回 1 拒配 | 返回值非 0；LOAD 仍是旧值 | 查返回值，改用 1ms 计数或 TIM |
| tick 变得极快，ISR 打满 CPU | 不查返回值，强行 `& 0xFFFFFF` → LOAD=22783 | 读回 LOAD=22783，周期 135.6µs，737 倍速 | 不要截断；超限换方案 |
| 第 50 天前后超时失灵 | 用 `now >= then + timeout`，回绕时漏报 | 减法 `(now−then)` 正确、朴素写法漏报 | 改成无符号减法 |
| 主循环看不到 `g_tick` 变化 | 共享变量没加 `volatile` | 反汇编里读被优化掉，或值不进循环 | 加 `volatile`，见[第 2 章](../v0-foundations/02-c-volatile-ub.md) |
| ISR 里 `HAL_Delay` 死等 | ISR 优先级高于 SysTick，tick 不前进 | SysTick 计数停住 | ISR 只置标志，延时回主循环 |
| 断电后时间归零 | VBAT 没接，备份域没续电 | 量 VBAT；BKP 魔数也丢了 | 接纽扣电池，检查第 1 脚 |
| 写 PRL/BKP 不生效 | 没开 PWR/BKP 时钟或没置 DBP | 读回 PRL/DR 与写入不符 | 开时钟、置 DBP 再写 |
| RTC 每天慢约 2.6 秒 | PRL 写成 32768 | 读回 PRL=32768 | 改成 32767 |
| RTC 走但不准，漂移超出晶振精度 | 用 LSI 当 RTC 源 | 读 RTC 源选择；LSI 在 30–60kHz 之间 | 改 LSE，按晶振手册选负载电容 |
| LSE 初始化总判失败 | 起振慢，超时给太短；或负载电容过大不起振 | OSC32 引脚无波形；延长超时后成功 | 加长超时、查负载电容与焊接；调试可先 LSI |
| 每次重启时间被重置 | 没写 BKP 魔数，或读错寄存器宽度 | `BKP_DR1` 读回不是 `0xA5A5` | 首次上电写魔数，之后只读 |
| F1 上找不到时间戳寄存器 | 时间戳是 F4 的 RTC 功能 | 手册里没有 `TSTR`/`TSDR` 这组寄存器 | F1 用 EXTI 读秒数，接受中断延迟 |
| 读出的时间与日期差一秒 | 两次读之间跨秒，没按锁存规则 | 时间与日期来自不同瞬间 | 按手册的锁存顺序读，或读后复核 |

## 跨平台边界

F407 一侧，`0xE000E010`、四个寄存器、`LOAD + 1`、COUNTFLAG 读清、SHP 下标与 `0xF0` 都是 Cortex-M4 内核约定或 F407 头文件的具体值。SysTick 的地址跨系列不变，但 `__NVIC_PRIO_BITS`、HCLK 与 Flash 等待必须按芯片重查；168MHz 的 167999 搬到 F103 就不成立。

F103 一侧，内核计数器同名同址，分母换成 72MHz：1ms 是 71999，最长单次约 233ms；1 秒 tick 会被拒配。优先级位宽按 `stm32f103xb.h` 的 `__NVIC_PRIO_BITS` 重算，SHP 下标公式不变；参考时钟比例与 HAL 的 tick 实现按对应手册与库源码核对，不把 F407 的 800ms 上限搬过去。

RTC 一侧，F1 是 32 位秒计数器加 10 个 16 位备份寄存器；F4 是 BCD 日历 `TR`/`DR`、20 个 32 位备份寄存器，还多了周期唤醒与硬件时间戳。LSE 的引脚、VBAT 的脚位、备份寄存器的个数与宽度都随封装与系列变，换芯片先查数据手册的引脚表与备份域章节。LSE 占用的 PC14/PC15 不能再当 GPIO，PC13 的灌电流限制见[第 9 章](./09-gpio.md)。

GD32 的 ARM 型号沿用 Cortex-M 的 SysTick，RISC-V 型号改用 MTIME 一类机器定时器，名字与编程模型都换了；对照见[第 29 章](../v4-platforms/29-gd32-arm-riscv.md)。ESP32 不在本章平台范围，其架构与启动见[第 30 章](../v4-platforms/30-esp32s3-architecture-boot.md)。定时器 TIM 与 PWM 见[第 12 章](./12-timers-pwm.md)，看门狗见[第 19 章](../v2-reliability/19-watchdog-reset-hardfault.md)，低功耗唤醒见[第 18 章](../v2-reliability/18-low-power.md)。

## 离开检查

1. 168MHz 下要 2ms tick，LOAD 写多少？周期是多少个时钟？
2. LOAD 写成 168000 而不是 167999，重载次数为什么不变？相位差多少？一天欠多少？
3. 为什么“先读一次 CTRL 打印、再读一次判断”的查询式延时会死等？正确写法是什么？
4. 请求 100ms tick 会发生什么？不查返回值强行截断会怎样？长周期有哪两条路？
5. `then = 0xFFFFFC18`、`timeout = 500`、`now = 2000`，超时了吗？哪种写法判得对？
6. `SysTick_Config(168000)` 之后 CTRL 是什么值？SHP[11] 为什么是 `0xF0`？为什么 RTOS 要它最低？
7. RTC 在主电源断开后靠什么继续走？写备份域前要做哪两件事？PRL 为什么是 32767？
8. F1 与 F4 的 RTC 各保存什么？时间戳在哪一边？LSE 与 LSI 怎么选？

<details>
<summary>对照答案</summary>

1. 168000000 × 2 / 1000 = 336000 个时钟；`LOAD = 335999`，周期 = LOAD + 1 = 336000 个时钟 = 2.000ms。与 probe 第 2 段同一族：先算时钟数，再减一。
2. 同样跑 1680000 个周期，两者都重载 10 次，差别在相位：每个 tick 慢 1/168000 ≈ 5.95ppm；第 10 次重载正确配置在第 1512001 个时钟，忘减一在第 1512010 个，9 个间隔共欠 9 个时钟；一天欠 514ms。短延时看不出，长期计时才暴露。
3. COUNTFLAG 是 read-to-clear：第一次读（打印那次）已把标志清掉，第二次读永远看到 0。probe 第 7 段对照：单读法 5 个周期数到 5 次，双读法数到 0 次。正确写法是读一次存进变量再判断。
4. ticks=16800000，(ticks−1) > 0xFFFFFF，`SysTick_Config` 返回 1 拒配，寄存器一个都没动。不查返回值强行 `& 0xFFFFFF` → LOAD=22783，tick 变 135.6µs，ISR 737 倍速。长周期两条路：CLKSOURCE=0 走参考时钟（F407 是 HCLK/8，约 800ms），或换 32 位 TIM（[第 12 章](./12-timers-pwm.md)）。
5. 超时了：真实已过 3000ms。`(uint32_t)(2000 − 0xFFFFFC18) = 3000 >= 500` 判对；朴素写法 `then + timeout = 4294966796` 没回绕，而 `now = 2000` 已回绕，`now >= then + timeout` 判成未超时。只有先减再比跨回绕永远正确。
6. `CTRL = 0x00000007`（ENABLE+TICKINT+CLKSOURCE）；优先级 15，因为 `(1 << 4) − 1 = 15`、`15 << 4 = 0xF0`，SHP 下标 `((−1)&0xF)−4 = 11`。RTOS 的 tick 中断里跑调度器，调度必须给外设中断让路，所以 tick 优先级放在最低档。
7. 靠 VBAT 上的纽扣电池给备份域续电，秒计数器与备份寄存器继续工作。写备份域前要打开 PWR 与 BKP 时钟，并置位 `PWR_CR.DBP`。分频比是 `(PRL + 1)`，32768 Hz 要 1 Hz 就得写 32767；写 32768 会变成 32769 分频，慢 30.5ppm、约 2.6s/天。
8. F1 用 32 位秒计数器，年月日软件换算，备份寄存器是 10 个 16 位；F4 用 BCD 的 `TR`/`DR`，备份寄存器 20 个 32 位，还带周期唤醒与硬件时间戳。时间戳只在 F4（`RTC_TSTR`/`RTC_TSDR`）；F1 只能让 EXTI 中断去读秒数，精度受中断延迟限制。要准就用 LSE（32.768kHz，占 PC14/PC15）；LSI 在 30–60kHz 漂，任何整数 PRL 都给不出稳定 1Hz，只适合省引脚或做唤醒。
