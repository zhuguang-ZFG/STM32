# GPIO

> 点灯是仪式，也是体检。一盏灯亮不亮，同时检验四件事：外设时钟有没有合闸、四张配置表有没有配对、数据是写进了 ODR 还是 BSRR、板子的接法到底高有效还是低有效。这一章把 GPIO 拆成“开时钟、配四维、写数据”三步，在 F407 的 PF6 与 F103 的 PC13 上各走一遍，再把复用、输入采样与消抖的边界划清楚。

## 本章罗盘

- **问题**：为什么 PF6 在 `MODER` 里占 bits[13:12]，而 PF6 的灯用 BSRR 的 bit6 与 bit22 控制？为什么不给 `RCC_AHB1ENR` 的 GPIOF 位合闸，写 `MODER` 再读回全是 0？为什么改一个引脚电平要用 `BSRR`，而 `ODR |=` 会偶尔丢一次电平？`MODER=10` 与 `AFR` 为什么必须成对写？输入的施密特触发器修整了什么，而“10~20ms 消抖”为什么查不到手册出处？F103 的 `CRL/CRH`、`AFIO->MAPR` 与 F407 的 `MODER`、`AFR` 哪套账能互相照抄？共阳灯为什么写低电平才亮？
- **交付**：能按“时钟→MODER→OTYPER→OSPEEDR→PUPDR→数据”的顺序手写一个引脚的配置，并说出每一位的取值理由；能用一条 `BSRR` 写入完成原子置位或复位，并说清读改写窗口在哪里；能为一个复用功能查表配好 `MODER` 与 `AFR`；能为按键选定上拉还是下拉，并说清消抖放在硬件还是软件；能把 e01 的接线、步骤、预期现象和记录格式复述给同学。
- **边界**：四平台章。F407 的偏移、位段与 PF6 演算来自 S3《GPIO：七个寄存器位级图解》与 RM0090 §8.4；F103 的 `CRL/CRH`、AFIO 重映射、PC13–PC15 的 3mA/2MHz/30pF 界限来自根书第 03 章与 RM0008、DS5319；GD32 与 ESP32 只在“跨平台边界”指路，不写没有来源的差异。NVIC/EXTI 的按键中断留给[第 10 章](./10-interrupts-nvic-exti.md)，PWM 调光留给[第 12 章](./12-timers-pwm.md)，I2C/SPI 的引脚配对留给[第 16 章](./16-i2c-spi.md)，实验方法与仪器证据留给[第 40 章][ch40]。e01 的来源记录是 `hardware_status: pending`、实测记录表为空，本章不把它的现象写成已跑读数。
- **依据锚点**：S3《GPIO：七个寄存器位级图解》（`mcu/docs/stm32/03-gpio.md`）、根书第 03 章《GPIO 与 LED》（`docs/03-GPIO与LED.md`）、E01《点亮霸天虎的 RGB 红灯（寄存器版）》（`mcu/docs/lab/e01-blink.md`）；[第 8 章](./08-architecture-memory-clock.md)的 AHB1 门牌与位带、[第 3 章](../v0-foundations/03-struct-abi-registers.md)的寄存器结构体、[第 2 章](../v0-foundations/02-c-volatile-ub.md)的 volatile 合同、[第 7 章](../v0-foundations/07-build-systems-legacy.md)的 `GPIO_Init` 解剖。RM0090、RM0008 与 DS5319 的条文均转引自上述来源。

## 先做出来

这一章的开局不烧板，先读代码：打开来源工程的 `mcu/code/stm32/00-blink/main.c`，把 `main()` 里配置段每一行注释成“这是在填哪张表”。填完对着这张底表核一遍：

| main.c 里的一行 | 填的是哪张表 | 动的是哪几位 |
| --- | --- | --- |
| `RCC_AHB1ENR` 或上 `RCC_AHB1ENR_GPIOFEN` | RCC 门控 | `AHB1ENR` bit5 |
| `GPIOF_MODER &= ~(3UL << 12);` | `MODER` 清零 | bits[13:12] 擦成 00 |
| `GPIOF_MODER` 或上 `1UL << 12` | `MODER` 置位 | bits[13:12] = 01 |
| `GPIOF_OTYPER &= ~(1UL << 6);` | `OTYPER` | bit6 = 0，推挽 |
| `GPIOF_OSPEEDR &= ~(3UL << 12);` | `OSPEEDR` | bits[13:12] = 00 |
| `GPIOF_PUPDR &= ~(3UL << 12);` | `PUPDR` | bits[13:12] = 00 |
| `GPIOF_BSRR = (1UL << 22);` | `BSRR` 复位 | bit22 = BR6，拉低 |
| `GPIOF_BSRR = (1UL << 6);` | `BSRR` 置位 | bit6 = BS6，拉高 |

读之前先押两题，答案都在下面的机制里：

1. 霸天虎的 RGB 灯是共阳接法，点亮红灯靠写高电平还是写低电平？
2. 不写 `RCC_AHB1ENR` 的 GPIOF 位，直接写 `GPIOF_MODER`，再读回来会看到什么？

押错了不丢人，改过来就是这一章的收益。来源记录的 e01 状态是 `code_status: ready`、`hardware_status: pending`，实测记录表一行没填；所以下面给的是步骤、预期现象与记录格式，不是已经量到的读数。

## 机制

### 时钟先行：外设没有合闸，寄存器只是橱窗

F407 的 GPIO 挂在 AHB1 上。RCC 的基址是 `0x4002_3800`，`AHB1ENR` 偏移 `0x30`，GPIOF 对应 bit5。这一行必须在任何配置之前：

```c
RCC_AHB1ENR |= RCC_AHB1ENR_GPIOFEN;   /* bit5：给 GPIOF 合闸 */
```

`main.c` 在这行上面的注释只有一句“不先开时钟，下面全白配”。机制是：时钟没到，外设的寄存器读写不生效，写进去不响，读回全是 0。S3 把它列为新手第一大坑，不是修辞。调试器里读回 `GPIOF_MODER` 得到 0，而代码明明写进了 0x1000，这一对矛盾就是“忘开时钟”的指纹。

F103 的账不一样：GPIO 挂在 APB2 上，根书例程用 `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE)` 开的是 GPIOC。寄存器名与总线都不能从 F4 抄过去。

开完时钟还有一个容易漏的动作：等门控真正生效。F4 版 SPL 的 `RCC_AHB1PeriphClockCmd()` 在写完 `AHB1ENR` 后补了一次 `(void)RCC->AHB1ENR;` 读回，手写代码要自己补这次读回或 `__DSB()`；[第 7 章](../v0-foundations/07-build-systems-legacy.md)拆过这段。

### 四维配置：一维一张表，每脚两格

GPIO 的配置被拆成四个寄存器，16 个引脚在每张表里各占格子：

| 寄存器 | 每脚位宽 | 取值（以输出为例） | 手册位置 |
| --- | --- | --- | --- |
| `MODER` | 2 位 | 00 输入 / 01 通用输出 / 10 复用 / 11 模拟 | RM0090 §8.4.1 |
| `OTYPER` | 1 位 | 0 推挽 / 1 开漏 | §8.4.2 |
| `OSPEEDR` | 2 位 | 00 2MHz / 01 25MHz / 10 50MHz / 11 100MHz | §8.4.3 |
| `PUPDR` | 2 位 | 00 浮空 / 01 上拉 / 10 下拉 | §8.4.4 |

配一个引脚就是按顺序填这四张表。PF6 在每张两位的表里占 bits[13:12]（6×2），目标是 `MODER=01`、`OTYPER=0`、`OSPEEDR=00`、`PUPDR=00`：

```c
GPIOF_MODER   &= ~(3UL << (LED_R_PIN * 2));  /* 先清零：擦掉原来的两位 */
GPIOF_MODER   |=  (1UL << (LED_R_PIN * 2));  /* 再置位：[13:12] = 01   */
GPIOF_OTYPER  &= ~(1UL << LED_R_PIN);        /* 0 = 推挽               */
GPIOF_OSPEEDR &= ~(3UL << (LED_R_PIN * 2));  /* 00 = 低速              */
GPIOF_PUPDR   &= ~(3UL << (LED_R_PIN * 2));  /* 00 = 无上下拉          */
```

“先清零再置位”不是洁癖。两位的格子直接 `|= 1`，原来的 10 或 11 会变成 11；先擦后写才能保证落点是 01。复位后多数引脚是 00（输入），但 PA13/PA14 这类调试脚默认是复用，所以这套写法在哪个引脚上都成立。反过来说，把 PA13/PA14 改成普通 GPIO 再烧录，SWD 就再也连不上，后面所有调试都会失去入口；RM0008 表 36 把 SWDIO 钉在 PA13、SWCLK 钉在 PA14。

![GPIO 配置流程动画：合闸、四张表逐格盖章、BSRR 发令](/anim/gpio-config.svg)

速度档是四维里唯一和“电”有关的。档位越高，边沿越陡，EMI 越强；LED 与按键用最低档就够，只有高速信号才需要 50/100MHz。图中四档的斜率差就是代价：

![OSPEEDR 四档：越快上升沿越陡，EMI 越大](/figures/stm32-03-slew.svg)

F103 的速度档是 2/10/50MHz，F407 是 2/25/50/100MHz，数字不能互抄；PC13–PC15 连 50MHz 这一档都不能用，界限见“F1 与 F4”一节。

### 数据寄存器：IDR 看、BSRR 办、ODR 有暗伤

三个数据寄存器分工不同：

- `IDR`（§8.4.5）：只读，引脚上此刻的真实电平。
- `ODR`（§8.4.6）：可读可写，输出寄存器。
- `BSRR`（§8.4.7）：只写。低 16 位置位（BS），高 16 位复位（BR）；写 1 生效，写 0 无影响；读它永远返回 0。

`GPIOF_ODR |= (1UL << 6);` 这行 C 编译出来是三条指令：

```asm
ldr  r0, [r1]        ; ① 读出整本账
orr  r0, r0, #0x40   ; ② 改自己那一位
str  r0, [r1]        ; ③ 整本写回
```

读与写之间有一个窗口。中断若在这时改了 ODR 的另一位，返回后主循环把 ① 时刻的旧值整本写回，中断的改动被冲掉。症状是偶尔丢一次电平，一周出现一回，很难查。`BSRR` 没有读、没有改，一条 `str` 原子完成，写 0 又不影响别的位，连掩码都省了。`main.c` 就是这么发令的：

```c
GPIOF_BSRR = (1UL << (LED_R_PIN + 16));  /* BR6 = 0x00400000：拉低，红灯亮 */
GPIOF_BSRR = (1UL << LED_R_PIN);         /* BS6 = 0x00000040：拉高，红灯灭 */
```

RGB 共阳接 3.3V 时，引脚低电平才灌电流，所以是“高 16 位亮、低 16 位灭”。这套极性记反了，代码会工作得完全相反：写“亮”反而灭。

两个边界要一起记。第一，`BSRR` 只写，不能对它做读改写：`BSRR |= x` 读回 0，或上去等于把 x 的位全清掉，只能纯赋值。第二，位带是另一条原子写位的路：F1 把外设地址的某一位映射到 `0x4200_0000` 起的别名区，写别名等于硬件替你完成读改写。根书给的公式是

```text
别名 = 0x4200_0000 + (地址 − 0x4000_0000) × 32 + 位号 × 4
```

PC13 的 ODR 位按这个式子算；[第 8 章](./08-architecture-memory-clock.md)用 F407 的 PF6 算过一遍，别名地址是 `0x4242_8298`。位带只覆盖两个区的前 1MB，一次只改一位，多比特字段仍要回掩码操作。

HAL 的 `HAL_GPIO_WritePin()` 底层同样落到 BSRR，所以“用库还是手写”在这里不影响原子性结论；根书把 HAL 与直接 BSRR 并排放过，两种写法都原子，ODR 的读改写两种写法都有窗口。

### 推挽与开漏：能推能拉，还是只会拉

| | 推挽（PP） | 开漏（OD） |
| --- | --- | --- |
| 输出级 | 上 PMOS 加下 NMOS | 只有下 NMOS |
| 高电平 | 主动推向 VDD | 放手，靠外部上拉 |
| 低电平 | 主动拉到 GND | 主动拉到 GND |
| 能否线与 | 不能 | 能，多脚并接 |
| 典型场景 | LED、SPI、USART | I2C、电平转换、共享总线 |

I2C 的 SDA 必须开漏加外部上拉：总线上挂着主机和多个从机，谁都有权拉低（发 0、应答、clock stretching）。推挽会让一个脚推高、另一个脚拉低，两个输出级对轰，电流直通。开漏的规则是“只能拉，想高就放手”，上拉电阻把线抬回高电平，多设备共享一根线而不打架。引脚配对与总线电气细节在[第 16 章](./16-i2c-spi.md)。

能否接 5V 只看数据手册那一列的 FT 标记，不是“STM32 都耐 5V”。根书的自测就拿 PA0 举例：数据手册没标 FT 的脚，不能直接接 5V 传感器，来源也不给“大概没事”的电流数。

### 复用：MODER 开门，AFR 选号

引脚默认听 ODR/IDR 的（通用 IO）。`MODER` 写成 10 后，数据线改接片上外设；接哪一个由复用寄存器决定。F407 每个脚 4 位，`AFRL` 管 pin0~7、`AFRH` 管 pin8~15，选 AF0~AF15。哪个脚能当什么、是 AF 几，只有数据手册的复用功能表说了算（F407 在 Table 9），别背，查。

以 USART1_TX = PA9 为例，查表得 AF7，两处寄存器到位：

```c
GPIOA->MODER  &= ~(3UL << 18);
GPIOA->MODER  |=  (2UL << 18);   /* PA9：MODER[19:18] = 10，复用模式 */
GPIOA->AFR[1] &= ~(0xFUL << 4);  /* AFRH 管 pin8~15，PA9 是第 1 个 nibble */
GPIOA->AFR[1] |=  (7UL << 4);    /* AFRH[7:4] = 0x7 = AF7 = USART1_TX */
```

复用要成对：只写 `AFR` 不改 `MODER=10`，等于章盖了门没开；只改 `MODER` 不写 `AFR`，引脚接进的是 AF0，未必是你以为的外设。

F103 没有逐脚 AF 号。它用 AFIO 的 `MAPR` 做整组重映射，例如把 USART1 从 PA9/PA10 挪到 PB6/PB7，而且要先开 AFIO 时钟。这是两代芯片在“换脚”上的结构差异，不是参数差异。

### 输入侧：施密特整形、上下拉与消抖的边界

数字输入经过施密特触发器进 `IDR`：滞回比较器把边沿修整干净，抖动幅度小于回差就不会反复翻转。模拟模式（`MODER=11`）把施密特触发器与上下拉全部断开，引脚直通 ADC，漏电流最小。

![输入侧：施密特整形与 IDR 采样，消抖在器件之外](/figures/stm32-03-gpio-input.svg)

按键的极性由接法决定：上拉加按键接地，空闲高、按下低、下降沿有效；下拉加按键接 VCC，空闲低、按下高、上升沿有效。F1 的内部上拉阻值是 30~50kΩ，只是弱上拉，负责给空闲定电平，不负责给外设供电。

消抖是器件之外的事，两条路：硬件 RC（0.1µF 电容加电阻，或施密特触发器）和软件定时采样（连续 N 次一致才认）。根书把话说得很直：常说的 10~20ms 消抖时间是经验值，RM0008 与 DS5319 都没有给出这个数，别把它当手册规定。软件版骨架：

```c
static uint8_t key_scan(GPIO_TypeDef *port, uint16_t pin)
{
    if (HAL_GPIO_ReadPin(port, pin) == GPIO_PIN_RESET) {  /* 读到低先当毛刺 */
        HAL_Delay(20);                                    /* 等 10~20ms 再确认 */
        if (HAL_GPIO_ReadPin(port, pin) == GPIO_PIN_RESET) return 1;
    }
    return 0;
}
```

轮询还有一条边界：主循环每轮塞进 100ms 阻塞任务，再短按按键，就会漏检或延迟。根书的实验三专门暴露这个现象，删掉阻塞后重测；解法留给[第 10 章](./10-interrupts-nvic-exti.md)的 EXTI 边沿。本章只把边界画出来，不假装轮询能扛住一切。

### F1 与 F4：两套寄存器账

同一件事，两代芯片用了两套账。F407 是本章的主线，F103 的差异集中在这张表：

| 事项 | STM32F407 | STM32F103 |
| --- | --- | --- |
| 配置寄存器 | `MODER`/`OTYPER`/`OSPEEDR`/`PUPDR` | `GPIOx_CRL`/`CRH`，低 8 位与高 8 位引脚分开配置 |
| 数据寄存器 | `IDR`/`ODR`/`BSRR` | 同左，另有独立的 `BRR` |
| 复用 | `AFR[2]`，每脚 4 位选 AF0~AF15 | `AFIO->MAPR` 整组重映射，先开 AFIO 时钟 |
| 速度档 | 2/25/50/100MHz | 2/10/50MHz |
| 时钟总线 | AHB1，`RCC_AHB1ENR`（GPIOF = bit5） | APB2，例程用 `RCC_APB2PeriphClockCmd` |
| 锁寄存器偏移 | `0x1C` | `0x18` |

F103 的引脚还有电气界限，换封装要重查：PA0 是 LQFP48 的第 10 脚，可以做电流源，例程按 `(3.3 − 2.0) / 0.005 = 260` 取 270Ω 给外接红灯限流；2.0V 与 5mA 是例程按普通红灯选的估算值，不是数据手册推荐值。PC13–PC15 走电源开关，灌电流不超过 3mA、速度不超过 2MHz、负载不超过 30pF，而且不能当电流源点灯。BluePill 的板载灯接在 PC13 上还能亮，是因为阳极接 3.3V、引脚只负责灌电流；PA0 那种“写 1 点亮”的接法不能原样搬过去。

锁定配置的序列两代相同：掩码保持不变，写 1、写 0、再写 1，然后连读两次，第二次确认 `LCKK = 1`。中途改了掩码或少一次写读，锁中止，配置仍可改；锁成立后保持到复位。来源把这条序列记在根书第 03 章，RM0008 的出处是第 9.2.7 节。

### 实验 e01：点亮霸天虎的 RGB 红灯

实验只用板载灯，不需要外接元件。霸天虎的 RGB 三色接在 PF6/PF7/PF8，阳极共接 3.3V，阴极经限流电阻到引脚，低电平点亮。绿灯、蓝灯与红灯结构相同：

![霸天虎 RGB 灯原理：共阳接 3.3V，PF6/PF7/PF8 低电平点亮](/images/labs/e01-rgb-led.svg)

步骤来自 E01，本章不改命令：

1. 构建：`cd code/stm32/00-blink && make`，检查 `build/blink.elf` 生成。
2. 烧录：`make flash`，等日志出现 `Verified OK`。
3. 观测：复位后看红灯，用手机秒表粗测 10 次亮灭周期（约 10 秒）。
4. 改参数：把 `main.c` 里两个 `delay(2000000)` 改成 `delay(400000)`，重新 `make flash`，看闪烁明显变快。
5. 换颜色（选做）：`LED_R_PIN` 从 6 改成 7 看绿灯，改成 8 看蓝灯。

预期现象也来自来源：默认固件红灯约 1Hz，软件延时，±30% 属正常，精准时基留给[第 11 章](./11-systick-timebase-rtc.md)；改短延时后明显急促；换引脚后对应颜色闪烁。改参数前先押一个数：延时砍到五分之一，灯会快几倍？答案在秒表上。

三个排障口径也一并带上：`Verified OK` 但灯不亮，先查引脚号是不是 PF6（教程串板常写成 PF9/PA8）；灯常亮不闪，查有没有进 `while`、延时有没有被优化掉，`-O0` 与 `delay` 循环体里的 `__asm__ volatile ("nop")` 是兜底，去掉那一条才真会被删（[第 2 章](../v0-foundations/02-c-volatile-ub.md)）；改完代码现象不变，多半只 `make` 没 `make flash`。

## 测量与证据

## 失败分支

| 现象 | 原因 | 区分证据 | 下一动作 |
| --- | --- | --- | --- |
| 外设寄存器写进去读回 0 | GPIOF 时钟没开 | 读回值与写入无关；使能 `AHB1ENR` bit5 后恢复 | 先合闸再配置，见本章“时钟先行” |
| 灯常亮不闪 | 没进 `while`，或延时循环被优化掉 | 反汇编里 `delay` 被内联或删除；`-O0` 下恢复 | 保留 `__asm__ volatile ("nop")`，用 `volatile` 参数 |
| 偶尔丢一次电平 | `ODR` 读改写被中断插队 | 反汇编是 ldr/orr/str 三条 | 改位一律用 `BSRR` 纯赋值 |
| `BSRR |= x` 后引脚全乱 | 读 `BSRR` 返回 0，或上去把 x 的位清掉 | 写入前后读 `ODR` 对不上 | `BSRR` 只做纯赋值，不做读改写 |
| 复用功能没输出 | 只写了 `AFR` 没把 `MODER` 改成 10，或反之 | `MODER` 仍是 01；`AFR` 仍是 0 | `MODER=10` 与 `AFR` 成对写，并按表选号 |
| 烧完就再也连不上 | PA13/PA14 被配成普通 GPIO | 板上 SWD 无响应；RM0008 表 36 | 保留 PA13/PA14 的调试复用，用复位引脚救回 |
| 按键读数乱跳 | 没有上下拉或没有消抖 | 空闲电平漂浮；按下瞬间多次跳变 | 按接法选上拉/下拉，加 RC 或软件连续采样 |
| 短按被漏掉 | 主循环有长阻塞，轮询错过脉冲 | 删掉阻塞后能读到 | 事件输入改用 EXTI，见[第 10 章](./10-interrupts-nvic-exti.md) |
| F1 的灯写 1 不亮 | PC13 共阳低有效，或 PC13 不能当电流源 | 写 0 亮；外接灯接 PC13 电流不够 | 板载灯写 0；外接灯改 PA0 串 270Ω |
| F1 重映射无效 | 没开 AFIO 时钟，或写错了 `MAPR` 组 | `AFIO->MAPR` 读回不是目标编码 | 先开 AFIO 时钟，再按组写 `MAPR` |
| 锁写了三次仍能改配置 | 序列出错，或第二次读回 `LCKK` 不是 1 | 读 `LCKR` 的 `LCKK` 位 | 掩码不变，重走写 1、写 0、写 1 与两次读 |
| 换到 F103 照抄 `MODER` 编不过 | 两代寄存器结构不同 | 头文件里没有 `MODER` 成员 | 按 `CRL/CRH` 与 `BRR` 重写，见本章对照表 |

## 跨平台边界

F407 这一侧，本章的偏移、位段与 PF6 演算都来自 RM0090 §8.4 与 S3；同系列换型号时，寄存器名与位段仍要按 RM0090 的对应章节重查，不能凭“都是 F4”补一个没读过的位。

F103 这一侧，共用的是“配置 + 数据 + 复用”三分法，不共用寄存器名与编码：配置走 `CRL/CRH`，复位有独立的 `BRR`，换脚走 AFIO 的 `MAPR` 整组重映射，速度档只有 2/10/50MHz，GPIO 时钟在 APB2。电气界限也要按数据手册重查：PC13–PC15 的 3mA/2MHz/30pF 与封装脚位绑定，换封装后第 2 脚、第 10 脚都可能变。

GD32 只划边界。来源 S3 的延伸把对照指向 G2（`mcu/docs/gd32/02-gpio-af.md`）；G2 的记录是“改名不改岗”：GD32F4xx 的同一组偏移上换成了 `CTL`/`OMODE`/`OSPD`/`PUD`/`ISTAT`/`OCTL`/`BOP`，基址与编码不变，另有两个 STM32F4 没有的寄存器 `BC` 与 `TG`。这些差异的来源是 G2 对 `gd32f4xx_gpio.h` 的读数，本章不复述细节；GD32 系列的完整对照与 ARM/RISC-V 两条线见[第 29 章][ch29]。

ESP32 这一侧，本章没有取证来源，不写寄存器差异。ESP32-S3 的架构与启动见[第 30 章][ch30]，外设与驱动框架见[第 31 章][ch31]；不要把这边的 `MODER`、`BSRR`、`AFR` 名字带过去，也不要假设引脚复用是同一套模型。芯片迁移的通用检查表（引脚、时钟、外设能力）在[第 28 章][ch28]。

## 离开检查

1. 为什么必须先开 GPIOF 时钟再写 `MODER`？忘开时读回是什么，指纹为什么是“全 0”？
2. PF6 在 `MODER`、`OSPEEDR`、`PUPDR` 里各占哪两位？配成推挽输出要依次写哪几个值？为什么要先清零再置位？
3. `GPIOF_ODR |= (1 << 6)` 编译成哪三条指令？中断插在哪一步会丢状态？`BSRR` 凭什么免疫？
4. 共阳 RGB 灯为什么写 `BSRR` 的高 16 位才亮？写低 16 位呢？
5. 推挽与开漏的输出级差在哪？I2C 为什么必须开漏加上拉？
6. PA9 用作 USART1_TX 要写哪两处寄存器？F103 换脚为什么是另一套流程？
7. 按键接 GND 时该上拉还是下拉？消抖的 10~20ms 为什么不能写成手册规定？轮询在什么情况下会漏按？
8. F103 的 PC13 为什么不能照搬 PA0 的点灯接法？换封装后要重查哪些项？

<details>
<summary>对照答案</summary>

1. 时钟没到时，外设寄存器读写不生效，写进去不响、读回全是 0；所以“代码写了 0x1000、读回 0”这一对矛盾就是忘开时钟的指纹。F407 的 GPIOF 在 `RCC_AHB1ENR` 的 bit5。
2. 三张两位的表里都占 bits[13:12]（6×2）。先 `&= ~(3 << 12)` 擦成 00，再对 `MODER` 置 `1 << 12` 得 01，`OTYPER` 的 bit6 写 0 得推挽，`OSPEEDR` 与 `PUPDR` 保持 00。先清零是因为两位格子里的旧值可能是 10 或 11，直接或 1 会落成 11；复位后调试脚还是复用，不能假设默认就是 00。
3. `ldr` 读、`orr` 改、`str` 写回三条。中断插在 `ldr` 与 `str` 之间改了另一位，返回后旧值整本写回，改动被冲掉。`BSRR` 一条 `str` 完成，没有读、没有改，且写 0 不影响其它位，所以中断无从插足。
4. 共阳时阳极接 3.3V，引脚拉低才有灌电流；`BSRR` 高 16 位是复位（BR），写 1 把引脚拉低，灯亮。低 16 位是置位（BS），写 1 拉高，灯灭。
5. 推挽有上 PMOS 与下 NMOS，高电平主动推向 VDD、低电平主动拉到 GND；开漏只有下 NMOS，只能拉低，高电平靠外部上拉。I2C 总线上多个设备都可能拉低，推挽会一推一拉对轰短路，开漏加上拉实现线与。
6. `MODER[19:18] = 10` 进复用模式，`AFRH[7:4] = 0x7` 选 AF7；AF 号必须查数据手册复用表。F103 没有逐脚 AF 号，要先开 AFIO 时钟，再写 `AFIO->MAPR` 做整组重映射。
7. 接 GND 时用上拉：空闲高、按下低。10~20ms 是经验值，RM0008 与 DS5319 都没有规定，不能写成手册要求。主循环里有长阻塞时，轮询会错过短脉冲，需要 EXTI 这类边沿触发。
8. PC13–PC15 走电源开关，灌电流不超过 3mA、速度不超过 2MHz、负载不超过 30pF，不能当电流源；PA0 可以推挽输出电流，按例程估算串 270Ω。换封装要重查引脚号、PC13–PC15 注 5 的界限、FT 标记，以及 F1 的 AFIO 重映射与 F4 的 `AFR` 差异。

</details>
