**旁白（与字幕、配音同一份稿）**

1. STM32H743 的 144 脚封装，第 1 脚是 PE2。订购字母 Z 表示 144 脚，I 表示 2 MB 闪存，所以 Nucleo 上常见的 H743ZI 就是这个组合。出处是 DS12110 第 11 版的图 7。
2. 内核供电有两只 VCAP。第 71 脚是第一只，第 106 脚是第二只。外接电容的取值去手册的电气章节，这张引脚图上不标电容值，避免把图注当成规格。
3. USB 有自己的电源脚，第 95 脚名叫 VDD33USB，不要写成普通的 VDD。BOOT0 在第 138 脚。掉电复位控制 PDR_ON 在第 143 脚。这三只在 F1 上没有对应的名字。
4. 这一帧是仓库按手册图 7 画的，不是照片。请核对左上角是 PE2。顶边的脚号从右往左增大，最左上是第 144 脚。数错方向，后面的复用会整圈错位。
5. H7 的 CAN 控制器叫 FDCAN，不是 F1 的 bxCAN。FDCAN1 可以在 PA11 和 PA12，也可以在 PD0 和 PD1，还可以在 PB8 和 PB9。名字抄错，Cube 里你会对不上外设。
6. 芯片分成 D1、D2、D3 三个电源域，可以分别关时钟或断电。这一章不写待机多少微安，因为封面摘录里没有一条可以单独引用的数字。要电流，去电气特性，不要估。
7. 内核最高 480 兆，还有 16 KB 指令和数据缓存。DMA 搬过的缓冲，CPU 可能还看着旧数据，调试器里的数组会和总线上的不一致。
8. SWD 仍是 PA13 和 PA14，脚号 105 和 109，和 BOOT0 分开。高速晶振在 PH0 和 PH1，脚号 23 和 24。
9. 口诀：144 脚从 PE2 数起；VCAP 有两只；USB 电源不叫 VDD。CAN 的名字是 FDCAN。电容值和待机电流，图上没有的就不编。
10. 合上书，三问。第 1 脚叫什么？第二只 VCAP 是第几脚？这里的 CAN 控制器叫 bxCAN 还是 FDCAN？

## 📌 学习目标

- [ ] 能从第 1 脚 PE2 顺着左边数到 NRST，不把顶边的脚号数反。
- [ ] 能指出 FDCAN1、OTG_FS、USART1、I2C1、SWD 至少一组脚。
- [ ] 说清和 F1/F4 的结构差别：三个电源域、FDCAN 而不是 bxCAN、内核要外接 VCAP。
- [ ] 先按 ES0392 识别芯片 revision，再选择 Rev Y/W 的 400 MHz 或 Rev V 的 480 MHz 配置。
- [ ] 能复算 HSE → PLL1P → SYSCLK → HCLK/PCLK，并用 MCO、HAL 频率读回和外设波形交叉验证。

## 🧠 这颗料是谁

图上是 **STM32H743xI 的 LQFP144**。订购信息里 Z = 144 脚，I = 2 MB Flash，所以 Nucleo 上常见的 **STM32H743ZI** 就是这个封装和这个 Flash 档。出处 **DS12110 Rev 11**：

| 事实 | 出处 |
| --- | --- |
| Cortex-M7，最高 480 MHz，带双精度 FPU 和 16 KB I/D Cache | 封面 |
| Flash 最高 2 MB；订购字母 I = 2 MB，Z = 144 脚 | 封面；第 346 页附近的订购信息 |
| 供电 1.62 V 到 3.6 V | 封面 |
| 三个电源域 D1 / D2 / D3，可以分别关时钟或断电 | 封面 |
| 2 个 CAN 控制器，带 CAN FD；目录写的是 FDCAN1、FDCAN2 | 封面特性与目录 |
| 2 个 USB OTG（1 个 FS，1 个 HS/FS） | 封面 |
| 专用 USB 电源，内部 3.3 V 调节器喂 PHY | 封面 |

本章不写 H7 的待机电流。封面摘录里没有一条可以单独引用的微安数字，与其估一个，不如让你自己翻电气特性那一章。

口诀：**144 脚从 PE2 数起；VCAP 有两只，USB 电源不叫 VDD。**

## 🛠️ 和 F1 / F4 比

| 点 | F1 / F4 | H743 LQFP144（Figure 7） |
| --- | --- | --- |
| 第 1 脚 | F103C8 是 VBAT | **PE2** |
| 内核供电 | F1 内部，没有 VCAP 脚 | **脚 71 VCAP1、脚 106 VCAP2**。外接电容的取值以 DS12110 的 VCAP 电气节为准，图上不标电容值 |
| USB 电源 | F1 没有；F4 有 VDDUSB 一类脚 | **脚 95 名称为 VDD33USB** |
| 掉电复位控制 | 无此脚 | **脚 143 PDR_ON** |
| BOOT | F1 专用脚；G0 与 SWCLK 合并 | **脚 138 BOOT0**，和 PA13/PA14 分开 |
| SWD | PA13 / PA14 | **脚 105 PA13、脚 109 PA14** |
| CAN | F1/F4 是 bxCAN | **FDCAN**。PA11/PA12、PD0/PD1、PB8/PB9 都能做 FDCAN1（Table 9） |
| 调试器看变量 | 无 Cache | 有 L1 Cache。DMA 缓冲要按第 10 章处理一致性，否则调试器里的数组和总线不一致 |

顶边的脚号是从右往左增大的：靠近右边的是脚 109，最左上是脚 144（VDD）。左边才是脚 1 往下数。这和 G0、L4 的图是同一套数法。

## ⚡ 先选供电与电压档，再切换 480 MHz

**“H743 最高 480 MHz”是有硅片修订和供电前提的上限，不是所有 H743ZI 上电后都能直接使用的频率。**ES0392 明确指出：Rev Y 和 Rev W 没有 VOS0，CPU 最高 400 MHz；Rev V 才能按 DS12110/RM0433 的 480 MHz 条件使用 VOS0。先核对芯片丝印，必要时读取 `DBGMCU->IDCODE` 的 `REV_ID` 并按 RM0433/ES0392 对照；不要靠开发板商品名猜 revision。

| 项目 | 上电前要确认什么 | 不能怎样理解 |
| --- | --- | --- |
| LDO / SMPS | 原理图、电感与 VCAP 等外部器件必须和 DS12110、AN4938 的选定供电方案一致；启动代码的 `HAL_PWREx_ConfigSupply()` 也必须一致 | 只改一个宏，不能把 LDO 板变成 SMPS 板 |
| VOS1 / VOS0 | Rev Y/W 用 VOS1，上限 400 MHz；Rev V 追求 480 MHz 时用 VOS0，并等待 `VOSRDY` | 在 Rev Y/W 上写 VOS0 不会解锁 480 MHz |
| D1 / D2 / D3 | 是 MCU 内部电源/时钟域，低功耗状态由 PWR/RCC 和模式转换管理 | 不是三条可随意分开的 VDD 电源轨 |
| VCAP1 / VCAP2 | 按数据手册接内核稳压器所需电容 | 不是普通去耦脚，不能直接接 VDD，也不能省电容 |
| VDD33USB | 按 USB PHY 供电要求连接 | 不是内核电源，也不是普通 GPIO |
| PDR_ON | 决定内部电源监测与外部 supervisor 的硬件边界 | 不是普通“芯片使能”或 NRST 替代品 |

供电方案只在启动初期配置一次。下例把 `BOARD_POWER_SUPPLY` 明确定义为 **LDO 板**；如果原理图是 SMPS，必须同时按官方硬件设计改板级参数和软件宏，不能照抄这一行。

## 🕐 HSE 8 MHz 到 480 MHz：一条可复算的时钟链

冻结的 STM32CubeH7 `RCC_ClockConfig` 示例给出 NUCLEO-H743ZI 的 400 MHz 基线：ST-LINK 向 HSE 提供 **8 MHz bypass 时钟**，`PLLM=4`、`PLLN=400`、`PLLP=2`，所以 `8 / 4 × 400 / 2 = 400 MHz`。下面只针对 **Rev V + 8 MHz HSE bypass + LDO 板**改成 480 MHz：电压档改为 VOS0，`PLLN=480`，其余分频保持这条官方拓扑。自焊晶振不是 bypass；不同 HSE 频率必须重算，不能照抄。

```c
/* main.c：仅用于 Rev V、8 MHz HSE bypass、LDO 供电的启动路径。 */
#define BOARD_POWER_SUPPLY        PWR_LDO_SUPPLY
#define CLOCK_STARTUP_TIMEOUT_MS  100U

static HAL_StatusTypeDef SystemClock_Config480(void)
{
    RCC_OscInitTypeDef osc = {0};
    RCC_ClkInitTypeDef clk = {0};
    HAL_StatusTypeDef status;
    uint32_t started;

    status = HAL_PWREx_ConfigSupply(BOARD_POWER_SUPPLY);
    if (status != HAL_OK) {
        return status;                 /* 供电与原理图不一致时不得继续 */
    }

    __HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE0);
    started = HAL_GetTick();
    while (!__HAL_PWR_GET_FLAG(PWR_FLAG_VOSRDY)) {
        if ((HAL_GetTick() - started) > CLOCK_STARTUP_TIMEOUT_MS) {
            return HAL_TIMEOUT;        /* 保留失败证据，不无限卡在启动里 */
        }
    }

    osc.OscillatorType = RCC_OSCILLATORTYPE_HSE;
    osc.HSEState = RCC_HSE_BYPASS;     /* Nucleo ST-LINK MCO；不是晶体模式 */
    osc.PLL.PLLState = RCC_PLL_ON;
    osc.PLL.PLLSource = RCC_PLLSOURCE_HSE;
    osc.PLL.PLLM = 4U;                 /* 8 MHz / 4 = 2 MHz */
    osc.PLL.PLLN = 480U;               /* VCO = 960 MHz */
    osc.PLL.PLLP = 2U;                 /* PLL1P = 480 MHz */
    osc.PLL.PLLQ = 4U;                 /* 本例不分配 PLL1Q 给外设 */
    osc.PLL.PLLR = 2U;
    osc.PLL.PLLFRACN = 0U;
    osc.PLL.PLLVCOSEL = RCC_PLL1VCOWIDE;
    osc.PLL.PLLRGE = RCC_PLL1VCIRANGE_1;
    status = HAL_RCC_OscConfig(&osc);
    if (status != HAL_OK) {
        return status;
    }

    clk.ClockType = RCC_CLOCKTYPE_SYSCLK | RCC_CLOCKTYPE_HCLK |
                    RCC_CLOCKTYPE_D1PCLK1 | RCC_CLOCKTYPE_PCLK1 |
                    RCC_CLOCKTYPE_PCLK2 | RCC_CLOCKTYPE_D3PCLK1;
    clk.SYSCLKSource = RCC_SYSCLKSOURCE_PLLCLK;
    clk.SYSCLKDivider = RCC_SYSCLK_DIV1;
    clk.AHBCLKDivider = RCC_HCLK_DIV2;
    clk.APB3CLKDivider = RCC_APB3_DIV2;
    clk.APB1CLKDivider = RCC_APB1_DIV2;
    clk.APB2CLKDivider = RCC_APB2_DIV2;
    clk.APB4CLKDivider = RCC_APB4_DIV2;
    return HAL_RCC_ClockConfig(&clk, FLASH_LATENCY_4);
}
```

`SystemClock_Config480()` 必须在初始化 UART、定时器、FDCAN、USB 等外设前调用并检查返回值。失败时记录是哪一步、供电宏、芯片 revision 和时钟源；不要带着半配置状态继续初始化外设。Rev Y/W 不走这条 480 MHz 路径：使用官方示例的 VOS1 + `PLLN=400`，并以同样的总线分频得到 400/200/100 MHz。若产品允许自动降频，必须显式报告当前档并重算所有外设，不能静默把 480 MHz 请求当成成功。

| 节点 | Rev V 本例 | Rev Y/W 基线 | 复算关系 |
| --- | ---: | ---: | --- |
| PLL 输入 | 2 MHz | 2 MHz | `HSE / PLLM = 8 / 4` |
| VCO | 960 MHz | 800 MHz | `PLL 输入 × PLLN` |
| CPU / SYSCLK | 480 MHz | 400 MHz | `VCO / PLLP` |
| HCLK（AXI/AHB） | 240 MHz | 200 MHz | `SYSCLK / 2` |
| PCLK1/2/3/4 | 120 MHz | 100 MHz | `HCLK / 2` |
| APB 定时器时钟（APB 分频不为 1） | 240 MHz | 200 MHz | `2 × PCLK` |
| MCO2 = SYSCLK/5 | 96 MHz | 80 MHz | 供示波器/频率计核对 |

这里只分配 **PLL1P 给 SYSCLK**。`PLL1Q = 960 / 4 = 240 MHz`，它不是 USB 所需的 48 MHz；PLL2/PLL3、FDCAN、ADC、SPI、USART 与 USB 的内核时钟要在各自外设章节另选来源和分频。APB 分频为 2 时定时器时钟翻倍，但 PCLK 本身不翻倍，UART  baud rate 不能直接套定时器公式。

### 启动后必须拿到三类证据

1. **软件读回**：确认 `HAL_RCC_GetSysClockFreq()` 为 480000000，`HAL_RCC_GetHCLKFreq()` 为 240000000。此 HAL 的 `HAL_RCC_ClockConfig()` 会更新 `SystemCoreClock` 和 HAL tick；在 H7 上 `SystemCoreClock` 表示 **HCLK=240 MHz**，不是 CPU 的 480 MHz。
2. **独立时钟输出**：确认 PC9 在目标板卡上可用且未与其他功能冲突，再输出 MCO2：

```c
/* PC9 的 GPIO/复用由板级代码确认；预期 MCO2 = 480 / 5 = 96 MHz。 */
HAL_RCC_MCOConfig(RCC_MCO2, RCC_MCO2SOURCE_SYSCLK, RCC_MCODIV_5);
```

96 MHz 是由上述配置得到的**预期值**，不是本仓库实测结果。示波器/频率计读数与读回一致，才同时证明 PLL 选择和分频；若只能看到软件变量，可能只是代码按同一套错误假设算出答案。

3. **外设闭环**：重新核对 SysTick/RTOS tick、UART 波特率、定时器周期、Flash 等待和每个外设内核时钟。用一个已知波特率的 UART 帧或已知周期的 PWM 波形做最后验收；`HAL_Delay(1000)` 约等于 1 秒只是其中一项，不能证明 USB/FDCAN 的独立时钟正确。

PA11/PA12 同时是 FDCAN1 和 OTG_FS。要两样都要，FDCAN1 改到 PD0/PD1 或 PB8/PB9。PB6/PB7 也同时出现在 USART1 和 I2C1 上，同一只脚不要配两个复用。

模拟脚 PC2_C、PC3_C（脚 28、29）名字里的 `_C` 是手册图上的写法，表示可接到模数转换的专用路径。不要在原理图里改成普通的 PC2。

## ⚠️ 从 F4 迁过来

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 内核不起振或随机死 | VCAP1/VCAP2 没按电气节装电容 | 只按 DS12110 的 VCAP 节选值，不凭 F4 的经验 |
| USB 完全无枚举 | 脚 95 VDD33USB 没供电 | 这是 USB 电源，不是任意 VDD |
| 「CAN」初始化失败 | 外设名是 FDCAN，寄存器和 bxCAN 不是同一章 | 打开 RM 里的 FDCAN 章，不要贴 F407 的 bxCAN 代码 |
| DMA 缓冲区在调试器里是旧的 | D1 有 Cache | 按第 10 章做 Cache 维护 |
| 在 Rev Y/W 上请求 480 MHz 后启动失败 | 这些 revision 没有 VOS0，上限是 400 MHz | 按 ES0392 改用 VOS1 + 400 MHz 基线，不重试超规格配置 |
| 改供电宏后仍不启动 | 软件供电方案与 LDO/SMPS 原理图不一致，或 VOS 未就绪 | 同时核对板级供电、供电宏、`VOSRDY` 和启动状态；不要只改 PLL |
| UART/PWM 频率在升频后错误 | 仍沿用旧 HCLK/PCLK 或把 `SystemCoreClock` 当成 480 MHz | 重算外设时钟；本例 `SystemCoreClock` 是 HCLK=240 MHz，再用波形验收 |
