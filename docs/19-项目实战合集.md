10. 合上书，三问。你下一轮只允许新加哪一个外设？怎样算做完？板上的时钟和示例不一致时，你先改哪一部分？

## 学习目标

读这一章之前：每个项目用到的外设，先在第 03–17 章里读过对应的那几章（哪个项目对应哪几章，见下面「先读哪几章」的表）；第 18 章的五步排错法会一直用到。欧姆定律、十六进制、位运算、C 指针和 `volatile` 这些基础，见第 00 章的「零基础预备」。

- [ ] 动手之前，用一句话写下「怎样算做完」和「坏了怎么看出来」。
- [ ] 把一个项目拆成 3~5 个能单独验证的模块，每一轮只加一个新外设。
- [ ] 从仓库里对应的例程起步，先让它在自己的板上原样跑起来，再改成项目要的样子。
- [ ] 用 `arm-none-eabi-size` 算出程序占多少闪存、多少 SRAM，判断 C8 的 64 KB 和 20 KB 放不放得下。
- [ ] 看出一段代码哪里不适合 C8（缓冲太大、引脚不存在、越过闪存地图），改成合适的写法。
- [ ] 做完一个项目写复盘，让别人只看你的说明就能复现。

## 怎样做一个项目

**一句话结论：每一轮只加一个新外设；动手之前，先写下「怎样算做完」和「坏了怎么看出来」。**

### 先打个比方

第一次做一道新菜，没人会把十种调料一起倒进锅里。先把饭煮熟，再一样一样加，每加一样尝一口。咸了，你知道是刚才那勺盐。

做项目也是这样。每加一个外设就完整跑一遍，出了问题，嫌疑只落在刚加的那一个身上。一个周末同时接上蓝牙、显示和存储，坏了以后三样东西互相牵连，你很难说清是谁。

比方到这里为止：菜咸了还能兑水，硬件接错可能直接烧掉芯片或模块。接线和上电这一步没有「尝一口」的机会，通电之前先对照引脚表和供电电压查一遍。

### 1. 从想法到验收：五步

下表按行从上往下填，填完一行再动下一行。右边一列是第 2 个项目（温湿度记录仪）的写法，换成你的项目照着改。

| 步骤 | 写下什么 | 例子：温湿度记录仪 |
| --- | --- | --- |
| 需求 | 一句话的完成标准，加上「坏了怎么看出来」 | 每 5 分钟记一条温湿度，掉电不丢；导出的时间不连续就是坏了 |
| 硬件 | 器件清单和引脚表，每只脚写清用途 | SHT30 和 OLED 共用一路 I2C，W25Q64 用 SPI，纽扣电池接 VBAT |
| 方案 | 数据从哪里来、到哪里去 | RTC 闹钟叫醒 → 读传感器 → 写 Flash → 刷屏 |
| 模块 | 3~5 个能单独测的模块，每个写清接口 | `rtc_now()`、`sht30_read()`、`log_append()`、`oled_show()` |
| 测试 | 每个模块一条单独的测试，最后一条整机测试 | 拔电再上电，导出的记录条数和时间都接得上 |

完成标准要写成能检查的句子。「每 5 分钟记一条，掉电不丢」能拿板子检查；「做一个好用的记录仪」不能。

每做通一轮，留一个回退点：把能编译、能跑的工程整个存一份，用 git 就打一个标签。下一轮改坏了，退回去比从头查快。

「做完」也要写清：别人按你的说明能复现，你能说出还没做的部分。灯亮过一次不算做完。

### 2. 每个项目怎么读

十个项目的写法相同。**需求**说清做成什么样；小表列出硬件清单、关键外设、工时和难度；**技术方案**讲数据怎么流、哪些数要算对；**关键代码片段**给最容易写错的那一段，后面跟着逐段解释；**可扩展方向**留给下一轮。

读小表时先看「关键外设」，它决定你要先会哪几章。「工时」和标题里的星级是经验值，按一个有 C 基础、边查手册边做的人估的，只用来排计划，不是承诺。

代码片段不是完整工程：

- 时钟、引脚和外设的初始化交给 CubeMX 生成（第 01、02 章）。
- 片段里用到的句柄，比如 `htim3`、`huart1`，是 CubeMX 生成在 `main.c` 里的全局变量。片段放进别的文件时，先写一句 `extern TIM_HandleTypeDef htim3;` 这样的声明。
- `Flash_Write()`、`Scope_Draw()` 这类函数是你在前面各章写过的驱动，名字换成你自己的。

代码按 STM32F103C8T6 写：64 KB 闪存、20 KB SRAM、LQFP48 封装的引脚（[DS5319](#source-ds5319-swd)）。换别的型号时，容量和引脚查那颗料自己的数据手册。

### 3. 先读哪几章，从哪个例程起步

按行读：「先读」是这个项目用到的外设所在的章；「起步例程」在仓库的 `examples/` 下，先让它在你的板上原样跑起来；「最小可用版本」是第一轮的完成标准，做到这一格再往下加。

## 1. 蓝牙小车（★★ 入门级）

**需求**：手机通过蓝牙遥控小车前进、后退、左转、右转、停止，能调速。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill + HC-05 蓝牙模块 + L298N 电机驱动 + 2 个直流减速电机（4 个时同侧两个并联）+ 两节 18650 串联 + 车架 |
| 关键外设 | USART1（蓝牙）、TIM3 CH1/CH2（PWM 调速）、GPIO（方向） |
| 工时 | 2~4 天 |
| 难度 | ★★ |

**技术方案**：手机 App 发单字符指令（`F`/`B`/`L`/`R`/`S`）。USART1 每收到一个字节进一次中断，解析后设置两个电机的方向和 PWM 占空比。

L298N 的每个电机有两只方向输入：`IN1`/`IN2` 管电机 A，`IN3`/`IN4` 管电机 B；`ENA`/`ENB` 接 PWM 调速。按 ST 的 L298 数据手册，EN 为高时，两只输入一高一低，电机朝一个方向转，高低反过来就反转；两只输入相同，电机快速制动；EN 为低，电机自由滑行停下。

接线按下表。左两列是 BluePill 这一侧，第三列是模块上的丝印。

| 信号 | BluePill 引脚 | 接到 | 说明 |
| --- | --- | --- | --- |
| PWM A | PA6（TIM3_CH1，第 16 脚） | L298N 的 ENA | 先拔掉 ENA 上的跳线帽 |
| PWM B | PA7（TIM3_CH2，第 17 脚） | L298N 的 ENB | 先拔掉 ENB 上的跳线帽 |
| 方向 A | PB12、PB13 | IN1、IN2 | 例程设定，电机 A 装在左边 |
| 方向 B | PB14、PB15 | IN3、IN4 | 例程设定，电机 B 装在右边 |
| 蓝牙 | PA9（TX）、PA10（RX） | HC-05 的 RXD、TXD | 交叉接 |

PA6、PA7 是 TIM3 两个通道的默认脚（DS5319 Rev 20 表 5；TIM3_REMAP = 00 时 CH1 在 PA6，见 [RM0008 定时器](#source-rm0008-tim)）。常见的 L298N 模块上 ENA、ENB 插着跳线帽，直接接到 5 V，电机只会全速转，接 PWM 之前要拔掉。PB12–PB15 在这个项目里只当普通输出用，换成别的空闲脚也行，只是别用第 10 脚 PA0：第 03 章的外接灯在那里，它还是 WKUP 和 ADC 的输入脚。

供电还有三件事要注意：

- L298 的电机电源要比输入高电平再高 2.5 V 以上（ST L298 数据手册的电气特性表），一节 18650 只有 3.7 V 左右，不够，至少两节串联。
- BluePill 的 GND 和 L298N 的 GND 接在一起，否则方向和 PWM 信号没有共同的参考。
- USART1 的波特率要和 HC-05 的数据波特率一致。很多模块出厂是 9600，以模块说明为准。

**关键代码片段**：

```c
/* 解析蓝牙指令并驱动两个电机（F103，TIM3 CH1/CH2 出 PWM，ARR = 999） */
#include "main.h"

extern TIM_HandleTypeDef  htim3;     /* CubeMX 生成在 main.c 里 */
extern UART_HandleTypeDef huart1;

/* 方向脚是例程设定：电机 A 用 PB12/PB13，电机 B 用 PB14/PB15。不要放在第 10 脚 PA0 */
#define MOTOR_DIR_PORT  GPIOB
static const uint16_t MOTOR_DIR_PIN[2][2] = {
    { GPIO_PIN_12, GPIO_PIN_13 },    /* 电机 A：IN1、IN2 */
    { GPIO_PIN_14, GPIO_PIN_15 },    /* 电机 B：IN3、IN4 */
};
static const uint32_t MOTOR_PWM_CH[2] = { TIM_CHANNEL_1, TIM_CHANNEL_2 };

static uint8_t rx_byte;

/* id：0 = 电机 A（左），1 = 电机 B（右）；duty：-100~100，正负号表示方向 */
static void SetMotor(uint8_t id, int8_t duty)
{
    uint32_t mag = (uint32_t)(duty < 0 ? -duty : duty);
    if (mag > 100U) mag = 100U;
    HAL_GPIO_WritePin(MOTOR_DIR_PORT, MOTOR_DIR_PIN[id][0], duty > 0 ? GPIO_PIN_SET : GPIO_PIN_RESET);
    HAL_GPIO_WritePin(MOTOR_DIR_PORT, MOTOR_DIR_PIN[id][1], duty < 0 ? GPIO_PIN_SET : GPIO_PIN_RESET);
    __HAL_TIM_SET_COMPARE(&htim3, MOTOR_PWM_CH[id], mag * 999U / 100U);   /* 0~999 */
}

static void Car_HandleCmd(char c)
{
    switch (c) {
    case 'F': SetMotor(0, 60);  SetMotor(1, 60);  break;   /* 前进 60% */
    case 'B': SetMotor(0, -60); SetMotor(1, -60); break;   /* 后退 */
    case 'L': SetMotor(0, 0);   SetMotor(1, 60);  break;   /* 左转：左轮停，右轮转 */
    case 'R': SetMotor(0, 60);  SetMotor(1, 0);   break;   /* 右转 */
    case 'S': SetMotor(0, 0);   SetMotor(1, 0);   break;   /* 停止 */
    default: break;
    }
}

void Car_Start(void)                 /* main() 里外设初始化之后调用一次 */
{
    HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
    HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_2);
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart1) {
        Car_HandleCmd((char)rx_byte);
        HAL_UART_Receive_IT(&huart1, &rx_byte, 1);   /* 再挂上，等下一个字节 */
    }
}
```

逐段看：

- `MOTOR_DIR_PIN` 是二维数组，每个电机两只方向脚。L298N 每个电机要两只输入一起给；只接一只，另一只悬空或接死，电机只能朝一个方向转。
- `SetMotor()` 定义在 `Car_HandleCmd()` 前面。C 要求先声明后使用；顺序反过来，GCC 会先报隐式声明，再报「static 声明跟在非 static 声明后面」，编译不过。
- `duty` 为 0 时两只方向脚都是低电平，比较值也是 0，EN 一直为低，电机自由滑行停下。
- 比较值是 `mag * 999 / 100`：ARR = 999（例程设定，第 05 章），占空比 60% 对应 599。PWM 的频率由 PSC 决定，第 05 章的 PSC = 71 在 72 MHz 的定时器时钟下是 1 kHz（[RM0008 定时器](#source-rm0008-tim)）。
- 串口用 `HAL_UART_Receive_IT()` 一次收 1 字节，收完在回调里处理，再挂下一次。回调运行在中断里，这里只写几个寄存器，很快；要做耗时的事，在回调里置标志，交给主循环。

**可扩展方向**：加超声波避障、加编码器做里程或闭环、加 OLED 显示速度、换成 PS2 或 2.4 GHz 遥控。

## 2. 温湿度记录仪（★★ 入门级）

**需求**：定时采集温湿度并显示，存下历史数据，能通过串口导出。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill + DHT11/DHT22 或 SHT30 + SSD1306 OLED + W25Q64 Flash + 32.768 kHz 晶振 + 纽扣电池 |
| 关键外设 | 单线时序或 I2C（传感器）、I2C（OLED）、SPI（Flash）、RTC |
| 工时 | 3~5 天 |
| 难度 | ★★ |

**技术方案**：RTC 闹钟每到点叫醒一次，读一组温湿度，显示到 OLED，再写进 W25Q64 的循环日志区。串口收到命令时把日志导成 CSV。

- F1 的 RTC 拿闹钟寄存器和计数器比较，计数器通常配成每秒加 1（第 11 章）。每次到点，把闹钟设成「当前计数 + 300」，就是每 5 分钟一次（例程设定）。
- 纽扣电池接 VBAT（第 1 脚，[DS5319](#source-ds5319-swd)），主电源断开以后，RTC 照样走。
- DHT11/DHT22 用的是厂家自己的单线时序，不是 DS18B20 那种 1-Wire 协议，要照它的数据手册用 GPIO 和定时器自己解码。SHT30 走 I2C，可以和 OLED 挂在同一路总线上，两者地址不冲突。两种传感器的精度以各自的数据手册为准。
- W25Q64 的最小擦除单位是 4 KB 的扇区，一页 256 字节（Winbond W25Q64 数据手册）。NOR Flash 编程只能把 1 变成 0，要变回 1 只能整扇区擦除。

**关键代码片段**：

```c
/* 每 5 分钟记录一条：RTC 时间戳 + 温度 + 湿度，写进 W25Q64 的循环区 */
#define W25Q_SECTOR_SIZE  4096U          /* W25Q64 最小擦除单位 4 KB */
#define LOG_BASE          0x000000U      /* 日志区起点，必须对齐到 4 KB */
#define LOG_END           0x100000U      /* 例程设定：前 1 MB 存日志 */

typedef struct __attribute__((packed)) {
    uint32_t ts;        /* Unix 时间戳，擦除后读出 0xFFFFFFFF */
    int16_t  temp_x10;  /* 温度 ×10，如 253 = 25.3℃ */
    uint16_t humi_x10;  /* 湿度 ×10 */
} Record_t;             /* 8 字节：4096 / 8 = 512 条正好填满一个扇区 */

static uint32_t wr = LOG_BASE;           /* 下一条要写的位置 */

void Log_Append(const Record_t *r)
{
    if (wr + sizeof(Record_t) > LOG_END) {
        wr = LOG_BASE;                       /* 写满一圈，回到开头覆盖最老的记录 */
    }
    if (wr % W25Q_SECTOR_SIZE == 0U) {
        Flash_EraseSector(wr);               /* 每进入一个新扇区，先擦掉它 */
    }
    Flash_Write(wr, (const uint8_t *)r, sizeof(Record_t));
    wr += sizeof(Record_t);
}

/* 上电调用一次：找到时间戳最大的那一条，下一条写在它后面 */
void Log_Recover(void)
{
    Record_t r;
    uint32_t newest = 0U;
    wr = LOG_BASE;
    for (uint32_t a = LOG_BASE; a < LOG_END; a += sizeof(Record_t)) {
        Flash_Read(a, (uint8_t *)&r, sizeof(r));
        if (r.ts != 0xFFFFFFFFU && r.ts >= newest) {
            newest = r.ts;
            wr = a + sizeof(Record_t);
        }
    }
}
```

逐段看：

- 每进入一个新扇区先擦它。只在回卷时擦第一个扇区是不够的：从第二个扇区起，要写的地方还留着上一圈的数据，NOR Flash 写在没擦的地方，结果是新旧数据按位相与，记录就坏了。
- 一条记录 8 字节，256 和 4096 都是 8 的整数倍，所以一条记录不会跨页，也不会跨扇区。改记录长度时要保住这一点。
- 写指针 `wr` 在 RAM 里，掉电就没了。「掉电不丢」靠 `Log_Recover()`：上电扫一遍日志区，找到时间戳最大的一条。前提是 RTC 时间只往前走，所以纽扣电池不能省。
- 1 MB 能存 1048576 / 8 = 131072 条，5 分钟一条，大约 455 天转一圈。

**可扩展方向**：加 SD 卡存更多数据、加 LoRa 或 NB-IoT 上传云平台、空闲时进 Stop 省电（第 16 章）。

## 3. DMA + ADC 迷你示波器（★★★ 进阶）

**需求**：单通道采集 0~3.3 V 信号，屏幕上画实时波形，显示峰峰值和频率。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill + OLED 或 SPI TFT + 待测信号源（先用另一只定时器输出的 PWM 当信号） |
| 关键外设 | ADC1 + DMA1 通道 1（循环）、TIM3（触发）、I2C 或 SPI（屏幕） |
| 工时 | 1~2 周 |
| 难度 | ★★★ |

**技术方案**：TIM3 的更新事件经 TRGO 触发 ADC1，采样间隔就是 TIM3 的周期。DMA1 通道 1 把转换结果循环搬进一个 512 点的缓冲区。DMA 填满前半区时进「半传输」回调，填满后半区时进「传输完成」回调。回调里只记下哪一半满了，画图放在主循环里做。

- 触发源：ADC1 规则通道的外部触发可以选 TIM3_TRGO（EXTSEL = 100，RM0008 Rev 21 表 67）。CubeMX 里把 TIM3 的 TRGO 选成更新事件，ADC 关掉连续转换，每来一次触发转换一次。ADC1 的 DMA 请求只在 DMA1 通道 1（表 78）。
- 采样率上限：一次转换 = 采样时间 + 12.5 个 ADC 时钟（[RM0008 ADC](#source-rm0008-adc)）。ADC 时钟不能超过 14 MHz（RM0008 Rev 21 第 11.1 节），PCLK2 = 72 MHz 时，不超过 14 MHz 的最快一档是 6 分频，得到 12 MHz（第 7.3.2 节的 ADCPRE）。最短的 1.5 个周期采样加上 12.5 个周期是 14 个周期，约 1.17 µs，TIM3 的触发间隔要比这长。采样时间越短，信号源的内阻要越小（第 09 章）。
- 例程设定：PSC = 0、ARR = 719，72 MHz / 720 = 100 kHz，半个缓冲 256 点是 2.56 ms。
- 输入只能在 0~3.3 V 之间。PA0–PA7 都不是 FT 脚（DS5319 Rev 20 表 5），超出这个范围的信号要先分压或加偏置。例程用 PA4，也就是 ADC12_IN4（[DS5319 ADC](#source-ds5319-adc)）。

**关键代码片段**：

```c
#define ADC_BUF_LEN 512
static uint16_t adc_buf[ADC_BUF_LEN];
static uint16_t *volatile ready_half = NULL;    /* 哪一半已经填满，等主循环去画 */

extern ADC_HandleTypeDef hadc1;
extern TIM_HandleTypeDef htim3;

void Scope_Start(void)
{
    HAL_ADCEx_Calibration_Start(&hadc1);                       /* F1 上电先校准（第 09 章） */
    HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, ADC_BUF_LEN);
    HAL_TIM_Base_Start(&htim3);                                /* 定时器一跑，触发就开始 */
}

void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
{
    (void)hadc;
    ready_half = &adc_buf[0];                    /* 前半区满了，DMA 正在填后半区 */
}

void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    (void)hadc;
    ready_half = &adc_buf[ADC_BUF_LEN / 2];      /* 后半区满了，DMA 回头填前半区 */
}

void Scope_Poll(void)                            /* 主循环里反复调用 */
{
    uint16_t *p = ready_half;
    if (p != NULL) {
        ready_half = NULL;
        Scope_Draw(p, ADC_BUF_LEN / 2);          /* 要在 DMA 转回这一半之前画完 */
    }
}

/* 电压换算：V = code × Vref / 4096（12 位 ADC）。码 2048 在名义 3.3 V 下是 1.65 V。分母 4095 会偏，满量程处偏一个 LSB。 */
static float Code2Volt(uint16_t code)
{
    return (float)code * 3.3f / 4096.0f;
}
```

逐段看：

- 两个回调各管一半：半传输回调说明前半区满了，可以画前半区；传输完成回调说明后半区满了，可以画后半区。
- 回调运行在 DMA 中断里，只记一个指针。画一屏要几毫秒到几十毫秒，放在中断里会把别的中断挡住。`ready_half` 是在中断和主循环之间传递的指针，指针本身要加 `volatile`，所以写成 `uint16_t *volatile`。
- CubeMX 里 DMA 设成 Circular，外设和内存两端都是 Half Word，和 `uint16_t` 的缓冲区对上。
- 主循环要在 DMA 转回这一半之前画完，例程设定下只有 2.56 ms。I2C 的 OLED 一屏 1024 字节，400 kHz 下光传数据就要 1024 × 9 / 400 kHz ≈ 23 ms，画不完。这时改成采满一屏就停（`HAL_ADC_Stop_DMA()`），画完再开，示波器上叫单次触发。
- `Code2Volt()` 的分母是 4096，跟第 09 章同一笔。码 2048 是 1.65 V；分母写成 4095，误差从码 0 处的 0 逐渐增大，到满量程处正好一个 LSB（约 0.8 mV）。

**可扩展方向**：加触发电平和边沿、加 FFT 看频谱、双通道对比、用 DWT 测刷新率（第 17 章）。

## 4. USB 数据采集卡（★★★ 进阶）

**需求**：通过 USB（CDC 或自定义批量端点）把多通道 ADC 数据持续上传到电脑，上位机实时画图。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill（板载 micro-USB 接 PA11/PA12）+ 传感器或信号源 |
| 关键外设 | ADC + DMA + USB Device（CDC，或厂商自定义类） |
| 工时 | 1~2 周 |
| 难度 | ★★★ |

**技术方案**：ADC 配 DMA 采满一帧，加上帧头、序号和校验和打成一包，交给 `CDC_Transmit_FS()` 从 USB 送出去。上位机用 Python（pyserial 或 pyusb）解析并实时画图。USB 的两只脚是第 32 脚 PA11 和第 33 脚 PA12（[DS5319 USB/CAN](#source-ds5319-usbcan)）。

`CDC_Transmit_FS()` 是异步的：它把缓冲区地址交给 USB 栈就返回，数据由 USB 中断一包一包送出去（第 14 章）。所以发送期间，缓冲区既不能在栈上，也不能被改写。上一帧没发完又调用，它返回 `USBD_BUSY`。

下面的代码按 CubeMX 生成的 USB_DEVICE 中间件写，发送函数是 `CDC_Transmit_FS()`（第 14 章）。仓库的 `usb-cdc` 例程没有链接 ST 的中间件，它的 `usb_cdc_write()` 一次最多接 64 字节，先拷进自己的 64 字节缓冲再发。从这个例程起步时，133 字节的一帧要自己分三次交出去：64、64、5，每次等上一包发完。

想提速，先查两件事：每次交给 USB 的数据是不是太短，上位机是不是一次只读几个字节。CDC 的数据本来就走批量端点；换成厂商自定义类，省掉的是主机那边的虚拟串口驱动，线上的批量传输还是同一种。

**关键代码片段**：

```c
/* 一帧：帧头 2 字节 + 序号 2 字节 + 64 个样本（每个 2 字节）+ 校验和 1 字节 */
#include "usbd_cdc_if.h"

#define FRAME_N    64
#define FRAME_LEN  (4 + FRAME_N * 2 + 1)        /* 4 + 128 + 1 = 133 */

static uint8_t frame[2][FRAME_LEN];             /* 两块轮流用：一块在 USB 上，另一块填新数据 */
static uint8_t fill = 0;                        /* 这一帧填哪一块 */

static uint8_t Checksum8(const uint8_t *p, uint32_t n)
{
    uint8_t s = 0;
    while (n--) s += *p++;
    return s;
}

/* 返回 1：这一帧已交给 USB。返回 0：上一帧还在发，稍后用同一组样本再调一次 */
int Upload_Frame(const uint16_t *samples, uint16_t seq)
{
    uint8_t *f = frame[fill];                   /* 另一块可能正在发送，不去碰它 */
    f[0] = 0xAA; f[1] = 0x55;
    f[2] = (uint8_t)(seq >> 8);
    f[3] = (uint8_t)(seq & 0xFF);
    for (int i = 0; i < FRAME_N; i++) {
        f[4 + i * 2]     = (uint8_t)(samples[i] & 0xFF);
        f[4 + i * 2 + 1] = (uint8_t)(samples[i] >> 8);
    }
    f[4 + FRAME_N * 2] = Checksum8(f, 4 + FRAME_N * 2);
    if (CDC_Transmit_FS(f, FRAME_LEN) != USBD_OK) return 0;   /* USBD_BUSY：上一块还没发完 */
    fill ^= 1U;                                 /* 交出去了，下一帧换另一块 */
    return 1;
}
```

逐段看：

- 缓冲区放在函数里当局部数组是错的：局部数组在栈上，函数一返回，那块栈马上会被别的函数用掉，USB 中断却还在从那里读，电脑收到的是乱码。所以用两块静态缓冲轮流用。
- `CDC_Transmit_FS()` 返回 `USBD_OK`，说明上一次发送已经结束，否则它会返回忙。这时换回去填另一块是安全的。
- 返回值不能丢。`USBD_BUSY` 说明这一帧没送出去；不看返回值，帧会悄悄丢掉，上位机只看到序号跳号。
- 133 字节一帧，全速批量端点一包最多 64 字节，USB 栈会把它拆成 64 + 64 + 5 三包。`wMaxPacketSize` 还是 64，不要写成 133（第 14 章）。
- 帧尾是 8 位累加和，查错能力有限；要更可靠，换成 CRC。

**可扩展方向**：加时间戳和触发、上位机存盘、多通道同步、上位机做实时 FFT、把校验和换成 CRC。

## 5. IAP 远程升级（★★★ 进阶）

**需求**：设备出厂后，通过串口、CAN 或网络接收新固件，自己完成升级。升级失败时留在 Bootloader 等下一次下载，不变砖。C8 上做不到退回旧版本，原因见下面。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill（或任意带 Flash 的型号）+ 上位机或网关 |
| 关键外设 | USART 或 CAN + 内部 Flash |
| 工时 | 1~2 周 |
| 难度 | ★★★ |

**技术方案**：C8 上先按第 12 章的一张 APP 做通。Bootloader 从 `0x08000000` 起 16 KB，参数区从 `0x08004000` 起 2 KB，APP 从 `0x08004800` 起、长度 `0xB800`，到 `0x08010000` 之前。第 12 章没有第二张槽。再放一张同样的 `0xB800` 是 110 KB，结束于 `0x0801B800`。把 46 KB 再切成两只 23 KB 是另一份设计，不要写成「见第 12 章」。

参数区记四样东西：有效标记、APP 的长度、APP 的校验和，再加一个「升级请求」。掉电安不安全，取决于写它们的顺序：

1. APP 收到升级命令，把「升级请求」那个字写成 0，然后软件复位。
2. Bootloader 看到请求，先擦参数页，有效标记随之消失；再擦 APP 区、写新 APP。
3. 新 APP 写完，算一遍校验和，对上了，才把长度和校验和写回参数页，有效标记最后一个写。

任何一步掉电，有效标记都不在，下次上电 Bootloader 会留下来等重新下载，不会跳进半截 APP。代价是旧 APP 在第 2 步就被擦掉了。想在失败后退回旧版本，得有第二张槽；46 KB 再来一张就是 110 KB，C8 的 64 KB 放不下。

**关键代码片段**：

```c
/* 两段分别编进 Bootloader 和 APP，宏和结构体放在两边共用的头文件里 */
#include <stddef.h>
#include "stm32f1xx_hal.h"

#define PARAM_ADDR   0x08004000UL     /* 参数区起点，2 KB（第 12 章的地图） */
#define APP_ADDR     0x08004800UL     /* 唯一的一张 APP */
#define APP_MAX      0xB800UL         /* 46 KB：APP_ADDR + APP_MAX = 0x08010000 */
#define PARAM_MAGIC  0x5A5A0001UL     /* 这一章自己约定的有效标记，不是第 12 章的标志值 */

typedef struct {
    uint32_t magic;           /* 等于 PARAM_MAGIC，下面几项才可信 */
    uint32_t app_size;        /* APP 的实际字节数，不超过 APP_MAX */
    uint32_t app_sum;         /* 整张 APP 的 32 位累加和 */
    uint32_t update_request;  /* 擦除值 0xFFFFFFFF = 没有请求；写成 0 = 请求升级 */
} BootParam_t;

/* 和 examples/iap-bootloader 的 checksum32() 一样：逐字节累加 */
static uint32_t checksum32(const uint8_t *data, uint32_t len)
{
    uint32_t sum = 0U;
    while (len--) sum += *data++;
    return sum;
}

/* Bootloader 上电先问这一句：1 = 可以跳到 APP，0 = 留在 Bootloader 等新固件 */
int Boot_AppIsValid(void)
{
    const BootParam_t *p = (const BootParam_t *)PARAM_ADDR;   /* 片内 Flash 可以按地址直接读 */

    if (p->magic != PARAM_MAGIC)                     return 0;   /* 空的，或升级到一半掉了电 */
    if (p->update_request != 0xFFFFFFFFUL)           return 0;   /* APP 要求升级 */
    if (p->app_size == 0U || p->app_size > APP_MAX)  return 0;   /* 长度不可能 */
    return checksum32((const uint8_t *)APP_ADDR, p->app_size) == p->app_sum;
}

/* APP 收到升级命令后调用：只写一个字，不用擦整页 */
void App_RequestUpdate(void)
{
    HAL_FLASH_Unlock();
    HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD,
                      PARAM_ADDR + offsetof(BootParam_t, update_request), 0U);
    HAL_FLASH_Lock();
    NVIC_SystemReset();                      /* 复位后先跑 Bootloader */
}
```

逐段看：

- 参数区和 APP 都在片内 Flash，CPU 可以像读数组一样按地址直接读，不用调用驱动。
- 「升级请求」用擦除值 `0xFFFFFFFF` 表示「没有」，APP 只需把它写成 0。F1 的 Flash 按半字编程，编程前会检查这个位置是不是已经擦除，没擦就跳过并置 PGERR；写 0x0000 是唯一的例外（PM0075 Rev 2 第 2.3.3 节）。所以这一个字不用先擦整页就能写。
- `0x5A5A0001` 只是这一章自己约定的数，Bootloader 和 APP 认同一个值就行。它不是第 12 章的标志值，两章的参数区格式不能混用。
- 跳转的写法（查栈顶、关中断、复位外设、停 SysTick、设 VTOR 和 MSP）照第 12 章做，这里不重复。
- 校验和算法和 `examples/iap-bootloader` 的 `checksum32()` 一样，是逐字节累加；例程的注释也写着量产建议换 CRC32。

**可扩展方向**：加 YMODEM 或自定义分包、加签名校验、加 CAN 多机批量升级、加断点续传。要两张槽和退回旧版本，得换一颗闪存更大的型号。

## 6. WS2812 灯带控制器（★★ 进阶）

**需求**：驱动 WS2812/WS2812B 灯带，做流水、呼吸、彩虹等效果，可调亮度和点亮的颗数。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill + WS2812 灯带 + 5 V 电源（与灯带电流匹配）+ 74HCT 系列电平转换芯片 |
| 关键外设 | TIM2 + DMA（精确 800 kHz 时序），或 SPI |
| 工时 | 3~5 天 |
| 难度 | ★★ |

**技术方案**：WS2812 用**单线归零码**传 24 位 GRB 数据：每一位都是先高后低，高电平短是 0，高电平长是 1。灯珠厂商给的时序是 `T0H=0.4µs`、`T1H=0.8µs`、一位的周期 1.25µs。这些是灯珠厂商的数，不是 RM0008；不同版本的数据手册给的窗口不一样，以你手上那一版为准。

用 **TIM2 + DMA** 输出这种波形：把每一位编码成一个比较值，DMA 每个 PWM 周期往 CCR1 送一个。

- 定时器时钟：TIM2 挂在 APB1 上。APB1 分频不是 1 时，定时器时钟是 APB1 的两倍（RM0008 Rev 21 第 7.2 节），72 MHz 系统时钟下 APB1 = 36 MHz，TIM2 的定时器时钟就是 72 MHz；PSC 设成 0，计数时钟也是 72 MHz。
- 一位 1.25 µs = 90 个计数，ARR = 89。0 的高电平 0.4 µs ≈ 29 个计数，1 的高电平 0.8 µs ≈ 58 个计数。
- DMA：TIM2_CH1 的请求在 DMA1 通道 5（RM0008 Rev 21 表 78）。方向是内存到外设，两端宽度都设成半字，和 `uint16_t` 的缓冲区对上；模式用 Normal，发完一帧就停。
- 引脚：TIM2_CH1 的默认脚是第 10 脚 PA0（DS5319 Rev 20 表 5）。第 03 章的外接灯也在这只脚上，做这个项目先把灯拆掉。
- 电平：5 V 供电的 WS2812B，输入高电平的门槛是 0.7 × VDD = 3.5 V（WS2812B 数据手册），BluePill 输出的 3.3 V 达不到。中间加一片 5 V 供电的 74HCT 电平转换芯片。
- 电流：经验值是一颗全白约 60 mA，60 颗要按 3.6 A 准备电源。灯带的 GND 要和 BluePill 的 GND 接在一起。

**关键代码片段**：

```c
/* TIM2 CH1（PA0）PWM + DMA 产生 WS2812 时序。PSC = 0，计数时钟 72 MHz，ARR = 89 */
extern TIM_HandleTypeDef htim2;

#define LED_NUM      60U
#define WS_T0H       29U          /* 29 / 72 MHz ≈ 0.40 µs：发 0 */
#define WS_T1H       58U          /* 58 / 72 MHz ≈ 0.81 µs：发 1 */
#define RESET_SLOTS  240U         /* 240 × 1.25 µs = 300 µs 的低电平：一帧结束 */

static uint16_t pwm_buf[LED_NUM * 24U + RESET_SLOTS];   /* 一位一个比较值 */
static volatile uint8_t ws_busy = 0;

/* grb：每颗灯 3 字节，顺序是 G、R、B；n：这一帧点亮几颗。返回 0 表示已开始发送 */
int WS2812_Show(const uint8_t *grb, uint16_t n)
{
    uint32_t idx = 0;
    if (ws_busy || n > LED_NUM) return -1;          /* 上一帧还在发，或者超出缓冲 */
    for (uint32_t i = 0; i < n * 3U; i++) {
        for (int b = 7; b >= 0; b--) {              /* 高位先发 */
            pwm_buf[idx++] = ((grb[i] >> b) & 1U) ? WS_T1H : WS_T0H;
        }
    }
    for (uint32_t i = 0; i < RESET_SLOTS; i++) {
        pwm_buf[idx++] = 0;                         /* 比较值 0：整个周期都是低电平 */
    }
    ws_busy = 1;
    if (HAL_TIM_PWM_Start_DMA(&htim2, TIM_CHANNEL_1, (uint32_t *)pwm_buf, (uint16_t)idx) != HAL_OK) {
        ws_busy = 0;
        return -1;
    }
    return 0;
}

/* DMA 送完最后一个比较值，HAL 调这个回调 */
void HAL_TIM_PWM_PulseFinishedCallback(TIM_HandleTypeDef *htim)
{
    if (htim == &htim2) {
        HAL_TIM_PWM_Stop_DMA(&htim2, TIM_CHANNEL_1);
        ws_busy = 0;
    }
}
```

逐段看：

- 一位只要一个比较值：PWM 每个周期自己产生「先高后低」，比较值只决定高电平多长。把一位拆成「高、低」两个比较值，DMA 送出去的就成了两位，灯珠收到的数据全错。缓冲区因此是 `LED_NUM * 24` 个比较值再加复位，60 颗灯一共 1680 个半字，3360 字节。
- 复位留 300 µs：较早的 WS2812B 数据手册写复位低电平大于 50 µs，较新的版本要求大于 280 µs，留 300 µs 两种都满足。复位段还有一个用处：回调停掉 PWM 时，最后几个周期本来就是低电平，切掉也不影响数据。
- `ws_busy` 挡住「上一帧还没发完又改缓冲区」。DMA 发完进回调，停掉 PWM，再清标志。
- 比较值是半字。`HAL_TIM_PWM_Start_DMA()` 的参数类型是 `uint32_t *`，强制转换只是为了对上函数原型；每次搬几个字节，由 DMA 的宽度设置决定。

**可扩展方向**：加音乐律动、加红外或蓝牙控制、多条灯带分别用不同的定时器通道、改用 SPI + DMA 更省 RAM。

## 7. 简易逻辑分析仪（★★★★ 挑战）

**需求**：采样 4~8 路数字信号，通过 USB 上传到电脑，上位机按协议解码（UART、I2C、SPI）。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill + USB，输入串保护电阻；要更深的缓冲和更高的采样率，换 SRAM 更大、主频更高的型号 |
| 关键外设 | TIM2（定时采样）、GPIOA 输入、USB CDC 上传、环形缓冲 |
| 工时 | 2~4 周 |
| 难度 | ★★★★ |

**技术方案**：TIM2 按采样率进更新中断，中断里把 GPIOA 输入数据寄存器 IDR 的低 8 位一次读成 1 字节，存进环形缓冲；触发条件满足后停止采样，再分块经 USB 上传。上位机做协议解码和显示（类似 PulseView 的轻量版）。

- 八路输入是 PA0–PA7（第 10–17 脚）。LQFP48 封装的 C8 没有 PC0–PC7，PC 口只引出 PC13–PC15（DS5319 Rev 20 表 5），照 F4 开发板写的 `GPIOC->IDR` 在这块板上读不到信号。
- PA0–PA7 都不是 FT 脚，被测信号高于 3.3 V 时先分压或用电平转换芯片。每路串一只几百欧的电阻（经验值），接错时限流。
- 缓冲：C8 的 SRAM 一共 20480 字节，例程设定用 8 KB 采样缓冲。
- 采样率上限：每个样本都要进出一次中断，再经过 HAL 的分发。用第 17 章的 DWT 量一下中断里花了多少个周期，就知道上限。要更快，让 TIM2 的更新事件直接触发 DMA：TIM2_UP 在 DMA1 通道 2（RM0008 Rev 21 表 78）；外设端按字读 `GPIOA->IDR`，因为 GPIO 寄存器只能按 32 位访问（第 9.1 节）；内存端按字节写，DMA 只留低 8 位（表 76），正好是 PA0–PA7，CPU 不用参与。

**关键代码片段**：

```c
/* C8 的 SRAM 只有 20480 字节，64 * 1024 = 65536 放不下。先用 8 KB */
#include "usbd_cdc_if.h"

extern TIM_HandleTypeDef htim2;

#define LA_DEPTH  (8U * 1024U)              /* 必须是 2 的幂，下面才能用 & 回卷 */
static uint8_t la_buf[LA_DEPTH];
static volatile uint32_t la_wr = 0;
static volatile uint8_t  la_run = 0;

/* TIM2 更新中断：一次读 PA0–PA7 八路 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim != &htim2 || !la_run) return;
    la_buf[la_wr++ & (LA_DEPTH - 1U)] = (uint8_t)(GPIOA->IDR & 0xFFU);
}

/* 停止采样后分块经 USB CDC 上传（第 14 章） */
void LA_Upload(void)
{
    for (uint32_t off = 0; off < LA_DEPTH; off += 512U) {
        while (CDC_Transmit_FS(&la_buf[off], 512U) == USBD_BUSY) {
            /* 上一块还没发完，等它 */
        }
    }
}
```

逐段看：

- `LA_DEPTH` 必须是 2 的幂。`la_wr & (LA_DEPTH - 1)` 等于对 8192 取余，写指针一直往上加，下标自己回卷。
- 回卷以后，最老的样本在 `la_wr & (LA_DEPTH - 1)` 处，上位机拼波形要从那里开始。
- 所有定时器的更新中断都进这一个回调，所以先判断 `htim`。裸机工程的 HAL 时基是 SysTick，这个回调归你用；CubeMX 把时基换成某个 TIM 时（用 FreeRTOS 时常见，第 15 章），`main.c` 里已经有一份同名回调，把这两行并进去，不要再定义一份。
- 上传时每一块都等 `CDC_Transmit_FS()` 不再返回 `USBD_BUSY`，再交下一块。最后一块交出去以后也要等它发完，再重新开始采样，否则缓冲区会边发边被覆盖。电脑上的串口没打开时，USB 发不出去，这个循环会一直等；正式版要加超时。从仓库的 `usb-cdc` 例程起步时，把 `CDC_Transmit_FS()` 换成 `usb_cdc_write()`，每块改成 64 字节；它返回 -1，说明上一包还没发完或者还没枚举好，等一会儿再交。

**可扩展方向**：加可调采样率和触发、加模拟通道、加协议解码插件、改用 DMA 采样提升速率。

## 8. 多机 CAN 网络（★★★★ 挑战）

**需求**：3 个以上节点用 CAN 组网，主节点轮询，从节点上报传感器数据，带 ID 规划和错误处理。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | 3× BluePill + 3× TJA1050 或 SN65HVD230 + 双绞线 + 2×120Ω 终端电阻 |
| 关键外设 | CAN1（PB8/PB9）、USART（调试） |
| 工时 | 1~2 周 |
| 难度 | ★★★★ |

**技术方案**：沿用第 13 章和 `examples/can-bxcan` 的那一笔：500 kbit/s，也就是 36 MHz 的 APB1 经预分频 9，每位 1 + 5 + 2 = 8 个时间份额，采样点 75%；工作脚 PB8/PB9；总线两端各一只 120 Ω。每个节点用同一组位时序，采样点才一致。

- 引脚：CAN 放到 PB8/PB9，要把 AFIO_MAPR 的 CAN_REMAP 两位设成 10（RM0008 Rev 21 第 9.4.2 节，01 是保留值）。从例程起步时，先用调试器看一眼这两位。
- 收发器：TJA1050 要 5 V 供电，SN65HVD230 用 3.3 V 供电（以各自数据手册为准）。用 TJA1050 时，它 RXD 脚的高电平可能接近 5 V，这只脚接到 PB8；PB8 是 FT 脚（DS5319 Rev 20 表 5），承受得住。
- ID 规划：标准帧 ID 有 11 位，例程设定低 4 位放节点号、高 7 位放功能码；从节点上报用 `0x100` 这一段，主节点命令用 `0x200` 这一段。总线仲裁时 ID 小的帧胜出（RM0008 Rev 21 第 24.7.1 节，第 13 章），所以越急的帧给越小的 ID。
- 过滤器分流：每个节点只收发给自己的命令，主节点只收它关心的上报（第 13 章）。
- 心跳和掉线检测：每个从节点每秒发一帧状态，主节点超过 3 秒（例程设定）没收到就标记掉线。
- 只接一个节点调试时没人回 ACK，帧永远发不出去。例程开着自动重发，发送方会一直重发；发送错误计数涨过 127 进入错误被动以后，按 CAN 规范的故障界定规则，单纯的 ACK 错误不再让它上涨，所以这个节点停在错误被动，不会进入总线关闭（阈值见 RM0008 Rev 21 第 24.7.6 节）。至少接两个节点，或者先用回环模式。

**关键代码片段**：

```c
/* ID 规划（例程设定）：低 4 位 = 节点号，高 7 位 = 功能码 */
#define ID_FUNC_STATUS 0x100u
#define ID_FUNC_CMD    0x200u

#define MAKE_ID(func, node)  ((uint16_t)(((func) & 0x7F0u) | ((node) & 0x0Fu)))
#define GET_NODE(id)         ((id) & 0x0Fu)

void CAN_Send(uint16_t std_id, uint8_t *data, uint8_t len);   /* 第 13 章写过 */

void Node_Report(uint8_t node, int16_t temp_x10, uint16_t humi_x10)
{
    uint8_t data[4];
    data[0] = (uint8_t)(temp_x10 >> 8);
    data[1] = (uint8_t)(temp_x10 & 0xFF);
    data[2] = (uint8_t)(humi_x10 >> 8);
    data[3] = (uint8_t)(humi_x10 & 0xFF);
    CAN_Send(MAKE_ID(ID_FUNC_STATUS, node), data, 4);
}

/* 主节点：收到某个节点的上报就记下时间，超过 3 s 没消息算掉线 */
static uint32_t last_seen[16];

void Master_OnStatus(uint16_t std_id)              /* 在 CAN 接收回调里调用 */
{
    last_seen[GET_NODE(std_id)] = HAL_GetTick();
}

int Master_NodeAlive(uint8_t node)
{
    return (HAL_GetTick() - last_seen[node & 0x0Fu]) < 3000U;
}
```

逐段看：

- `MAKE_ID()` 把功能码和节点号拼成 11 位标准 ID：`0x7F0` 留住第 4–10 位，`0x0F` 留住第 0–3 位。节点 3 的状态帧是 `0x103`。
- 4 位节点号最多 16 个节点；节点更多时，把功能码和节点号的位数重新分。
- `HAL_GetTick() - last_seen[]` 用无符号减法，毫秒计数回绕以后差值照样对。

**可扩展方向**：加 CANopen 协议、经总线给各节点升级固件、加网关转以太网或 4G。

## 9. 自平衡小车（★★★★ 挑战）

**需求**：两轮自平衡小车，能直立，受扰后回正，可由遥控前进和转向。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill + MPU6050（陀螺仪 + 加速度计）+ TB6612 或 L298N + 带编码器的电机 + 车架 + 电池 |
| 关键外设 | I2C（MPU6050）、TIM（编码器 + PWM）、UART（遥控）、固定周期的控制环 |
| 工时 | 3~6 周 |
| 难度 | ★★★★ |

**技术方案**：姿态解算（互补滤波或卡尔曼滤波）用加速度和角速度算出倾角，控制环再由倾角算出 PWM。常见做法是两个环的输出相加：

- 直立环（PD）：P 项按倾角误差纠正，D 项直接用陀螺仪的角速度抑制振荡。下面的代码就是这一环。
- 速度环（PI）：用编码器测出的车速慢慢修正，让车不朝一个方向越跑越快。
- 两个环的输出相加再送电机。也有人把速度环的输出当成直立环的目标角度，那种接法才叫串级。

控制周期固定，例程设定 5 ms。5 ms 定时中断里只置一个标志，读 MPU6050、计算、写 PWM 放在主循环里，或者放进 RTOS 任务用 `vTaskDelayUntil` 定周期（第 15 章）。原因是 HAL 的阻塞式 I2C 读用 `HAL_GetTick()` 算超时：定时器中断的优先级只要不比 SysTick 低，SysTick 就打断不了它，节拍在这个中断里不会走，总线一卡住就永远等下去。

**关键代码片段**：

```c
/* 直立环 PD（倾角误差 → PWM），周期 5 ms。系数是例程设定，要按自己的车重新调 */
static float g_kp = 25.0f, g_kd = 0.8f;
static float target_angle = 0.0f;      /* 目标倾角 0° */
static volatile uint8_t tick_5ms = 0;

static float Clamp(float x, float lo, float hi)
{
    return (x < lo) ? lo : ((x > hi) ? hi : x);
}

float Balance_Update(float angle, float gyro)
{
    float err = target_angle - angle;
    /* P 纠正倾角，D 用陀螺仪的角速度抑制振荡。gyro 的正负要和 angle 对上 */
    return g_kp * err - g_kd * gyro;
}

/* 5 ms 定时中断里只做这一句 */
void Control_Tick_ISR(void)
{
    tick_5ms = 1;
}

/* 主循环里反复调用 */
void Control_Loop(void)
{
    if (!tick_5ms) return;
    tick_5ms = 0;
    float angle = IMU_GetAngle();      /* 互补滤波后的倾角 */
    float gyro  = IMU_GetGyroY();      /* 绕车轮轴的角速度 */
    float pwm   = Balance_Update(angle, gyro);
    Motor_SetBoth((int16_t)Clamp(pwm, -1000.0f, 1000.0f));
}
```

逐段看：

- 代码只有直立环。只有直立环的车能站一会儿，但会朝一个方向越跑越快，要靠速度环拉回来。
- 系数和 5 ms 是例程设定，换了电机、轮子或电池都要重调。常见的调法（经验做法）是先只加 P，加到车开始来回晃，再加 D 把晃压下去。
- 两个正负要先对好。陀螺仪和倾角要同号：车往前倒、倾角变大时，陀螺仪读数也应该是正的，反了就把 `gyro` 取负，否则 D 项会帮倒忙；这由 MPU6050 的安装方向决定。电机转向要和倾角对上：往前倒时轮子要往前追；这由电机接线决定。
- `Clamp()` 把输出限在 ±1000，比 PWM 满量程大的值没有意义。`IMU_GetAngle()`、`IMU_GetGyroY()`、`Motor_SetBoth()` 是你自己的驱动。

**可扩展方向**：加蓝牙遥控、加 OLED 调参、加视觉寻线、用卡尔曼滤波替代互补滤波。

## 10. FreeRTOS 智能网关（★★★★ 挑战）

**需求**：多协议网关：本地传感器采集、OLED 显示、串口或 CAN 转发、低功耗管理，多个任务协同。

| 项 | 内容 |
| --- | --- |
| 硬件清单 | BluePill（F103C8T6，一路 CAN）或 F407（两路 CAN）+ 传感器 + OLED + CAN 收发器 + USB-TTL |
| 关键外设 | I2C、USART、CAN + FreeRTOS（任务、队列、事件组、互斥量） |
| 工时 | 3~6 周 |
| 难度 | ★★★★ |

选型先看 CAN：F103C8 有一个 CAN 接口（DS5319 Rev 20），F407 有两个（DS8626），F411 没有 CAN 控制器（ST DS10314），接了收发器也用不上。用 C8 时还要记住：USB 和 CAN 共用一块 512 字节的专用 SRAM，不能同时工作（RM0008 Rev 21 第 23.2、24.2 节）。所以这里连电脑用 USB-TTL 转串口，不用 C8 自己的 USB。

**技术方案**：任务划分为采集任务、显示任务、通信任务、管理任务。用**队列**传数据，**事件组**等多个条件，**互斥量**保护共享的 I2C 总线（传感器和 OLED 都挂在上面）。管理任务负责喂看门狗和低功耗：

- 喂狗不能无条件地喂。让每个任务每一轮在事件组里置自己的一位，管理任务等到所有位都到齐才喂一次独立看门狗；哪个任务卡住，狗就会咬（第 11 章）。
- 空闲时进 Stop 要多做一步。Stop 模式下 1.8 V 域的时钟全停（RM0008 Rev 21 第 5.3.4 节），SysTick 跟着停，FreeRTOS 的节拍也停了。FreeRTOS 自带的 tickless 实现（`configUSE_TICKLESS_IDLE` 设 1）靠 SysTick 计时，只用 WFI 进睡眠模式（FreeRTOS V11.3.2 的 ARM_CM3 移植）。要进 Stop，得自己写进出 Stop 的那一段：用 RTC 闹钟叫醒；醒来后系统时钟是 HSI（同一节），要重新配 PLL；再把睡掉的节拍补上（第 16 章）。

**关键代码片段**：

```c
/* 采集任务 → 队列 → 通信任务；事件组通知显示任务「有新数据」 */
#include "main.h"
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "event_groups.h"

typedef struct {
    int16_t temp_x10;                 /* 温度 ×10 */
} SensorData_t;

static QueueHandle_t      g_data_q;
static EventGroupHandle_t g_evt;

#define EVT_OLED_READY  (1U << 0)

static void vSampleTask(void *arg)
{
    SensorData_t d;
    TickType_t last = xTaskGetTickCount();
    (void)arg;
    for (;;) {
        d.temp_x10 = Sensor_ReadTemp_x10();
        if (xQueueSend(g_data_q, &d, pdMS_TO_TICKS(100)) != pdPASS) {
            /* 100 ms 还塞不进去：通信任务卡住了，记下来交给管理任务 */
        }
        xEventGroupSetBits(g_evt, EVT_OLED_READY);    /* 通知显示任务 */
        vTaskDelayUntil(&last, pdMS_TO_TICKS(1000));  /* 每 1000 ms 一轮，不被干活的时间拖长 */
    }
}

static void vCommTask(void *arg)
{
    SensorData_t d;
    (void)arg;
    for (;;) {
        if (xQueueReceive(g_data_q, &d, portMAX_DELAY) == pdTRUE) {
            Comm_SendFrame(&d);                       /* 串口或 CAN 转发 */
        }
    }
}

/* main() 里，外设初始化之后调用；正常情况下不返回 */
void Gateway_Start(void)
{
    g_data_q = xQueueCreate(8, sizeof(SensorData_t));
    g_evt    = xEventGroupCreate();
    if (g_data_q == NULL || g_evt == NULL) Error_Handler();        /* 堆不够 */
    if (xTaskCreate(vSampleTask, "sample", 256, NULL, 2, NULL) != pdPASS) Error_Handler();
    if (xTaskCreate(vCommTask,   "comm",   256, NULL, 3, NULL) != pdPASS) Error_Handler();
    vTaskStartScheduler();
}
```

逐段看：

- 队列和事件组在启动调度器之前创建，并检查返回值。它们从 FreeRTOS 的堆里分配，堆不够时返回 `NULL`；拿 `NULL` 去收发，程序会停在断言，或者跑飞（第 15 章）。
- `vTaskDelayUntil()` 让采集固定每 1000 ms 一轮；`vTaskDelay(1000)` 是从这次调用起再等 1000 ms，读传感器花的时间会叠加上去（第 15 章）。
- 栈深度 256 的单位是字，也就是 1024 字节（第 15 章）。队列长度 8、两个优先级都是例程设定。
- 通信任务的优先级比采集任务高，数据一进队列，通信任务马上被唤醒去转发。
- 发送用 100 ms 超时（例程设定），不用 `portMAX_DELAY`。通信任务卡住时，采集任务还能接着跑、接着向管理任务报到，问题能被发现。

**可扩展方向**：加 MQTT 或 Modbus 协议栈、加 OTA 升级、用 `vTaskGetRunTimeStats` 看各任务的 CPU 占用、加掉电数据保护。

## 动手实验（选题与推进）

1. **实验一：先做出最小可用版本。** 任选一个项目，只做「先读哪几章」表里「最小可用版本」那一格。蓝牙小车先只做前进和停止，用 USB-TTL 从电脑发字符，蓝牙模块第二轮再接。
   - 预期现象：半天到一天里（经验值）看到那一格写的现象。
   - 怎么确认：拿动手前写下的那句完成标准，逐字对着板子检查。
   - 没成功先查：起步例程在你的板上能不能原样跑起来；跑不起来，先按第 18 章的五步排查，从复现和最小化开始。
2. **实验二：一次接一个模块。** 把项目拆成 3~5 个模块，每个模块写一条能单独运行的测试。记录仪可以是：串口打印时间，打印读数，写入后读回，OLED 显示固定的字符串。
   - 预期现象：每个模块单独通过测试，然后才和别的模块合在一起。
   - 怎么确认：列一张模块表，每格写「通过」或「没通过」和日期。
   - 没成功先查：这一轮新加的只有一个模块。先退回上一个回退点，确认旧的部分还好，再看新加的这一个。
3. **实验三：在最小可用版本上加一个扩展方向。** 从「可扩展方向」里挑一项，比如加 OLED 显示，加在已经做通的版本上。
   - 预期现象：新功能能用，实验二的每一条测试也都还通过。
   - 怎么确认：把实验二的测试全部重跑一遍。
   - 没成功先查：新旧外设有没有抢同一样东西，比如同一只引脚（WS2812 的 PA0 和第 03 章的灯）、同一个 DMA 通道（RM0008 Rev 21 表 78）或同一个定时器。C8 上 USB 和 CAN 不能同时工作。
4. **实验四：算一算放不放得下。** 编译后对 `.elf` 运行 `arm-none-eabi-size`。
   - 预期现象：得到 `text`、`data`、`bss` 三个数。
   - 怎么确认：`text + data` 是闪存占用，要小于 64 KB，做成 IAP 的 APP 时要小于 `0xB800`；`data + bss` 是 RAM 里的静态变量，加上栈和堆要小于 20480 字节。
   - 没成功先查：链接器报 `FLASH` 或 `RAM` 区域 overflowed，说明已经放不下。先找大数组（逻辑分析仪的缓冲）、FreeRTOS 的堆 `configTOTAL_HEAP_SIZE`，以及为 `printf` 打开的浮点支持（第 18 章）。
5. **实验五：写复盘。** 把踩过的坑按第 18 章的表格写下来：现象、原因、处理、怎么确认。
   - 预期现象：别人只看你的说明和接线表，就能把项目复现出来。
   - 怎么确认：交给同学照着做一遍，或者一周后自己从空工程重做一遍。
   - 没成功先查：说明里有没有写 CubeMX 和 HAL 的版本、时钟配置、每只脚的接法，以及还没做完的部分。

## 自测

1. 你要做温湿度记录仪，手上有 RTC、SHT30、W25Q64、OLED 四样。按「一轮只加一个新外设」排一个顺序，并说出每一轮怎样算做通。
2. 项目 5 的 APP 从 `0x08004800` 开始，长 `0xB800`，它在哪里结束？如果再放一张同样大的 APP，会结束在哪里？C8 放得下吗？
3. 示波器读到码值 2048，名义参考 3.3 V。分母按 4096 和按 4095 各算出多少伏？差多少？
4. 采集卡一帧 133 字节，全速批量端点一包最多 64 字节。USB 线上要几包？最后一包几个字节？
5. WS2812 用计数时钟 72 MHz 的 TIM2，一位 1.25 µs。ARR 填多少？发 1 时比较值大约多少？

参考答案：

1. 一种合理的顺序：RTC → SHT30 → W25Q64 → OLED。RTC 做通：串口打印时间，复位以后时间接着走。SHT30 做通：串口打印读数，用手捂住传感器，温度往上走。W25Q64 做通：写入、断电、上电读回一致，写满一圈能回到开头。OLED 放在最后，显示是最后一层。时间和数据先对，显示才有意义；只要每轮只加一样、显示放在最后，别的顺序也可以。
2. `0x08004800 + 0xB800 = 0x08010000`，正好是 64 KB 闪存的结束地址。第二张接着放是 `0x08010000 + 0xB800 = 0x0801B800`，合计 `16 + 2 + 46 + 46 = 110` KB，超过 64 KB，放不下。
3. 2048 × 3.3 / 4096 = 1.65 V；2048 × 3.3 / 4095 ≈ 1.6504 V，差约 0.4 mV，是半个 LSB。码越大差得越多，到满量程 4095 时正好差一个 LSB（约 0.8 mV）。
4. 133 = 64 + 64 + 5，三包，最后一包 5 字节。拆包由 USB 栈完成，`wMaxPacketSize` 仍然是 64。
5. 1.25 µs × 72 MHz = 90 个计数，ARR = 90 − 1 = 89。1 的高电平 0.8 µs × 72 MHz = 57.6，取 58 个计数，约 0.81 µs；0 的高电平 0.4 µs × 72 MHz = 28.8，取 29。

## 原理与适用范围

> [!NOTE]
> 从这一节到「常见坑与出处」是深入部分，把前面的结论落到具体订货号、手册章节和能复算的数字上。第一次读可以先跳过，做完动手实验再回来对照。

**这一章的范围。** 这一章的代码都按 STM32F103C8T6 写，也就是 BluePill 上那一颗。写在这颗料上的数必须放得进这颗料：闪存地图跟第 12 章是同一张，ADC 的换算跟第 09 章是同一笔。十个项目是十条练习路线，不是十个完整的产品。

**一张 APP。** Bootloader 从 `0x08000000` 起 16 KB，参数区从 `0x08004000` 起 2 KB，APP 从 `0x08004800` 起 46 KB，长度 `0xB800`，到 `0x08010000` 之前结束。`16 + 2 + 46 = 64`。这是第 12 章和 `examples/iap-bootloader` 的地图，见 [本仓库例程](#source-project-examples)。

**第二张放不下。** 再放一张同样的 `0xB800`，合计 `16 + 2 + 46 + 46 = 110` KB。`0x08000000 + 0x1B800 = 0x0801B800`，越过了 `0x08010000`。闪存在 `0x08010000` 结束，见 [DS5319](#source-ds5319-swd)。第 12 章没有第二张槽。把 46 KB 再切成两只 23 KB 是另一份设计，不是这张图的正常路径。

**SRAM 的账。** `64 * 1024 = 65536`。C8 的 SRAM 是 20 KB，也就是 20480 字节，见 [DS5319](#source-ds5319-swd)。65536 大于 20480，这只数组在 STM32F103C8T6 上放不下，项目 7 因此用 8 KB。换别的型号时，SRAM 容量查那颗料自己的数据手册。

**ADC 的分母。** 中密度器件的 ADC 是 12 位，见 [DS5319 ADC](#source-ds5319-adc)，一共 4096 个码。分母是 4096，码 2048 在名义 3.3 V 下是 1.65 V。分母写成 4095，满量程处正好偏一个 LSB，跟第 09 章同一笔。采样时间怎么选、信号源内阻有什么影响，见第 09 章。

**ADC 的转换时间。** 一次转换 = 采样时间 + 12.5 个 ADC 时钟，见 [RM0008 ADC](#source-rm0008-adc)。12 MHz 的 ADC 时钟下，最短的一次是 1.5 + 12.5 = 14 个周期。示波器的触发间隔不能比一次转换短。

**USB 的一包。** 应用帧 `4 + 128 + 1 = 133` 字节。第 14 章全速批量的一包上限是 64 字节，133 要拆成 64 + 64 + 5 三包送；例程 `usb-cdc` 的批量端点就是 64 字节，见 [本仓库例程](#source-project-examples)。不要把 133 写成 `wMaxPacketSize`。USB 要的 48 MHz 时钟和例程的 VID/PID `0x1209/0x0001`，见第 14 章。

**CAN 的一笔。** 项目 8 的两端各 120 Ω、工作脚 PB8/PB9、500 kbit/s、预分频 9，跟第 13 章和 `examples/can-bxcan` 同一笔，见 [本仓库例程](#source-project-examples)。收发器用 5 V 还是 3.3 V，看项目 8 的硬件清单和收发器自己的数据手册。

**PA0 不做方向脚。** 方向脚不要放在第 10 脚 PA0。那只脚是 PA0-WKUP，也是 ADC12_IN0，见 [DS5319 ADC](#source-ds5319-adc)。项目 1 正文里换上的方向脚是例程设定，换成别的空闲脚也行。

**一轮一个外设是方法。** 一轮只加一个新外设，这是做事的方法，不是芯片的电气限制。工时和星级是经验值，只写在各项目的小表里。WS2812 的微秒数是灯珠厂商的数，不是 RM0008，只写在项目 6 里。

## 时序与状态

这一章没有时序图，这一块记的是每个对象的长度、边界和结论。按行读。前三行是闪存的正常路径，从 `0x08000000` 往后排，每一行的结束地址就是下一行的起点；第四行是放不下的第二张。接着三行是 SRAM。最后四行是三个外设各自的一笔账。

| 对象 | 数 | 边界 | 结论 |
| --- | --- | --- | --- |
| Bootloader | 16 KB | 结束于 `0x08004000` | 放得下 |
| 参数区 | 2 KB | 结束于 `0x08004800` | 放得下 |
| 一张 APP | `0xB800` | 结束于 `0x08010000` | 放得下 |
| 两张 `0xB800` | 110 KB | 结束于 `0x0801B800` | 放不下。这不是第 12 章的地图 |
| SRAM 总量 | 20480 字节 | 片内 | 全部变量、栈和堆加起来不能超过它 |
| 65536 字节的数组 | `64 * 1024` | 超出 SRAM | 在 C8 上放不下 |
| 8 KB 的采样缓冲 | `8 * 1024 = 8192` 字节 | 在 SRAM 内 | 放得下，还剩 12288 字节给别的变量、栈和堆 |

| CAN | 500 kbit/s，预分频 9 | PB8/PB9 | 两端各 120 Ω |

## 常见坑与出处

每一行从左往右读：先认现象，再看原因和处理；最后两列写这条结论出自哪里，以及那份出处能证明到哪一步。

| 现象 | 原因 | 处理 | 出处 | 出处能证明的部分 |
| --- | --- | --- | --- | --- |
| 升级方案写成两张 APP，并注明见第 12 章 | 把另一份设计写成了这一章的地图 | C8 上先按一张 `0xB800` 做通 | [本仓库例程](#source-project-examples) | `examples/iap-bootloader` 的 APP 长度是 `0xB800`。第 12 章没有第二张槽 |
| 第二张镜像链接到 `0x08010000` 之后 | 64 KB 已经结束 | 停在 `0x08010000` | [DS5319](#source-ds5319-swd) | STM32F103x8 的闪存是 64 KB。110 KB 是按 `16 + 2 + 46 + 46` 算出来的，不是手册里的数 |
| 逻辑分析仪缓冲在 C8 上链不过 | `64 * 1024` 大于这颗料的 SRAM | 不要把 65536 字节编进 C8，先用 8 KB | [DS5319](#source-ds5319-swd) | SRAM 是 20 KB，即 20480 字节。这一行不给出另一颗料的容量 |
| 示波器电压偏一个 LSB | 分母用了 4095 | 分母用 4096 | [DS5319 ADC](#source-ds5319-adc) | 中密度器件的 ADC 是 12 位，所以有 4096 个码。码 2048 是 1.65 V，是按 4096 和名义 3.3 V 算出来的 |
| 示波器的触发间隔设得比一次转换还短 | 只看了定时器能多快，没算 ADC 一次要多久 | 触发间隔要长于一次转换；12 MHz 的 ADC 时钟下最短 14 个周期 | [RM0008 ADC](#source-rm0008-adc) | 转换时间 = 采样时间 + 12.5 个周期；12 MHz 下 1.5 个周期是 125 ns。14 个周期是两项相加。卡片没有写转换中途来的触发怎样处理，所以不要依赖它 |
| 采集卡把 133 字节写成端点包长 | 把应用帧当成了包上限 | 全速批量一包最多 64 字节，133 拆成 64 + 64 + 5 | [本仓库例程](#source-project-examples) | 例程 `usb-cdc` 的批量端点是 64 字节。133 是 `4 + 128 + 1`，不是第 14 章的包上限 |
| 小车方向写在 PA0 | 和第 10 脚的其他用途撞在一起 | 换离第 10 脚 | [DS5319 ADC](#source-ds5319-adc) | 第 10 脚是 PA0-WKUP，也是 ADC12_IN0。这一行不新分配电机脚 |
| 两个 CAN 节点速率对不上 | 没走第 13 章那一笔 | 用 500 kbit/s，两端各 120 Ω | [本仓库例程](#source-project-examples) | 例程的预分频是 9，工作脚是 PB8/PB9。这一行不规定收发器是 5 V 还是 3.3 V |
| 升级中途掉电，下次上电跳进半截 APP | 只查了栈顶，栈顶已经写好、后面没写完的 APP 挡不住 | 参数页最先擦，有效标记最后写 | [本仓库例程](#source-project-examples) | `examples/iap-bootloader` 跳转前只检查栈顶是否落在 `0x20000000` 那一段；参数区在这个例程里没有用 |
| C8 上 USB 和 CAN 同时打开，其中一个收不到 | 两者共用一块 512 字节的专用 SRAM | 同一时间只开一个；两样都要，换型号 | [DS5319 USB/CAN](#source-ds5319-usbcan) | PA11/PA12 的复用同时有 USB 和 CAN，同一对脚不能同时当两样用。共用 SRAM 那一条在 RM0008 Rev 21 第 23.2、24.2 节，不在这张卡里 |
| 照 F4 开发板的代码在 C8 上读 `GPIOC->IDR` 低 8 位，读不到信号 | LQFP48 的 C8 没有 PC0–PC7 | 改读 `GPIOA->IDR` 低 8 位，也就是 PA0–PA7 | DS5319 Rev 20 表 5（没有出处卡） | 表 5 的 LQFP48 一列里，PC 口只有 PC13、PC14、PC15 |

出处一栏没有链接的那一行，引用的手册章节还没有出处卡。这一章给的是学习路径，不构成安全、EMC、量产测试或法规符合性声明；电池、电机和 5 V 灯带的电流比开发板大得多，接线、保险丝和散热以各自器件的数据手册为准。
