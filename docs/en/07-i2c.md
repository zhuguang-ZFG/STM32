## Principle and scope

Every I2C number in this chapter is for the STM32F103C8T6. I2C1 sits on APB1 with PCLK1 = 36 MHz, as in Appendix D. The working point is one row of DS5319 Table 42: pull-up Rp = 4.7 kΩ, a 400 kHz target, and `I2C_CCR = 0x801E`. The OLED address matches Appendix D: 7-bit `0x3C`, which HAL takes as `0x78`.

After reset, I2C1 is on pin 42 PB6 = I2C1_SCL and pin 43 PB7 = I2C1_SDA. Both pins are alternate-function open-drain, each with a 4.7 kΩ resistor to 3.3 V. Open-drain means the chip can only pull the line low; the high level comes entirely from the pull-up. That differs from the push-pull chip select in the SPI chapter. With the remap, I2C1 moves to pin 45 PB8 and pin 46 PB9. The remap column of DS5319 Table 5 also lets PB6/PB7 serve as USART1_TX / USART1_RX, but only after a remap, not after reset, and the two pins can serve only one peripheral at a time. Pins: [DS5319 Rev 20 Tables 5 and 42](#source-ds5319-i2c).

The 7-bit address `0x3C` is `0111100` in binary. The first I2C byte is the 7-bit address shifted left by one, with the direction in the lowest bit: a write is `0x3C << 1` = `0x78`, a read is `0x79`. HAL's DevAddress expects the shifted value, so you pass `0x78`. Pass the scanner's `0x3C` straight into `HAL_I2C_Master_Transmit` and `0x3C` goes on the wire; that addresses 7-bit `0x1E`, and the OLED never answers. This is the most common mistake in this chapter. The macro in [examples/i2c-oled](#source-project-examples) is already `0x78`. The address byte format is in [RM0008 Rev 21 chapter 26](#source-rm0008-i2c).

The 9th clock is the acknowledge bit. The receiver pulls SDA low for ACK; SDA left high is NACK. With a wrong address no device pulls SDA low, so you see NACK.

`HAL_I2C_Mem_Read` runs START, address plus write, register address, repeated START, address plus read, data, STOP. The middle uses a repeated START, not a STOP. Calling `Master_Transmit` and then `Master_Receive` puts a STOP in between, and some devices then forget the register address you just wrote.

Taking `0x801E` apart: the fast-mode bit is set, DUTY = 0, and the CCR field is 30. At PCLK1 = 36 MHz one SCL period is `3 × 30 / 36e6 = 2.5` µs, which is 400 kHz. For 100 kHz use `0x00B4`: standard mode, CCR field 180, `36e6 / (2 × 180) = 100` kHz. Table 41 says 400 kHz is reached exactly only when PCLK1 is an integer multiple of 10 MHz. 36 MHz is not, so per Table 42 note 2 the actual rate is within ±2%. Neither Table 41 nor Table 42 lists 1 MHz; the F103 I2C has no Fast-mode Plus, so any "up to 1 MHz" claim does not hold for this chip.

This Table 42 row uses an external 4.7 kΩ pull-up. The on-chip pull-up is about 30–50 kΩ (Appendix D and chapter 03). That is too large: the rising edge is too slow for 400 kHz. The rise-time limit is 1000 ns in standard mode and 300 ns in fast mode. The bus capacitance Cb may be at most 400 pF. How to size the pull-up from Cb is in the core ideas below.

In open-drain mode the PMOS to VDD stays off and only the NMOS can pull the line low, which is why the external pull-up is required.

## Timing and state

| Phase | SCL | SDA | Byte on the wire |
| --- | --- | --- | --- |
| START | High | High to low | No address byte yet |
| Correct: write address | 8 clocks | Shifted out | `0x78` |
| Correct: 9th clock | 9th clock | Low | ACK |
| Wrong: write address | 8 clocks | Shifted out | `0x3C`, which addresses `0x1E` |
| Wrong: 9th clock | 9th clock | High | NACK |
| Read direction | After repeated START | Address byte | `0x79`, with no STOP in between |
| Rate | `0x801E` is 400 kHz | `0x00B4` is 100 kHz | Within ±2%. CCR fields 30 and 180 |
| Pull-up | External 4.7 kΩ to 3.3 V | 36 MHz, 3.3 V | On-chip pull-ups alone cannot run 400 kHz |

Rise-time limits: 1000 ns in standard mode, 300 ns in fast mode. The F103 does not support 1 MHz.

## Core ideas

I2C high levels come from the pull-up resistors; devices only drive the bus low. The debug order follows from that: check idle levels and rise time, then address and ACK, and only then inspect the receive buffer.

### 1. Electrical behavior


<p align="center">
  <img src="../../assets/diagrams/sample-07-pullup-cap.svg" width="760" alt="Pull-up resistance versus bus capacitance">
  <br><sub>▲ Drawn for this book. 4.7 k is a starting point; long buses need measurement.</sub>
</p>


Both I2C wires are pulled gently high by resistors, and every device on the bus can do only one thing: pull a wire to ground. If nobody pulls, the wire is high. If anyone pulls, it is low. This is wired-AND, and it is why two I2C devices cannot fight: nobody ever drives a wire high, so the worst case is two devices pulling together. The cost is that after everyone lets go, the wire climbs back slowly through the resistor. A bigger resistor or a longer wire makes it slower.

| Property | Meaning |
| --- | --- |
| Pin type | Open-drain. Both SDA and SCL need pull-ups |
| Wired-AND | If any device pulls low, the line is low. It is high only when everyone releases it |
| Pull-up | 4.7 kΩ is the usual value. Faster, or more capacitance, wants a smaller one |
| Multi-master, multi-slave | Multi-master arbitration and multi-slave addressing are both supported |

Pull-up versus bus capacitance Cb:

| Speed mode | Max rate | Typical pull-up | Notes |
| --- | --- | --- | --- |
| Standard mode | 100 kHz | 4.7 kΩ to 10 kΩ | A long wire or a large capacitance wants a smaller resistor |
| Fast mode | 400 kHz | 2.2 kΩ to 4.7 kΩ | The usual sensors |
| Fast+ | 1 MHz | — | Not supported on STM32F103C8T6 |

> An estimate, not the DS5319 standard-mode limit: `Rp(max) ≈ 300ns / Cb`. More capacitance means a smaller pull-up. The standard-mode rise-time limit is 1000 ns and the fast-mode limit is 300 ns; see the start of this chapter.

### 2. Timing and the protocol


<p align="center">
  <img src="../../assets/diagrams/sample-07-start-ack.svg" width="760" alt="I2C START, 0x78 address, and ACK">
  <br><sub>▲ Drawn for this book. HAL 0x3C<<1=0x78; slave ACK on the 9th clock.</sub>
</p>


The rule is that SDA must not move while SCL is high, and when it does, it means something special. SDA falling while SCL is high is START. SDA rising while SCL is high is STOP. Ordinary data changes only while SCL is low. After every 8 bits, the receiver pulls SDA low on the 9th clock to say "got it", and that is ACK. The master opens with an address. The slave that matches answers ACK, and the rest stay quiet until the next START.

| Signal | Condition | Meaning |
| --- | --- | --- |
| START | While SCL is high, SDA falls | Start of a transfer |
| STOP | While SCL is high, SDA rises | End of a transfer |
| Data bit | SDA is stable while SCL is high | One clock per bit |
| ACK | On the 9th clock, the slave pulls SDA low | Acknowledge |
| NACK | On the 9th clock, SDA stays high | Not acknowledged, or the end of a read |

Address: 7 address bits + 1 R/W bit (0 = write, 1 = read), 8 bits in all. A 10-bit address uses two bytes.

### 3. Clock synchronization and arbitration

Wired-AND makes arbitration natural. Two masters talking at once each listen to the wire as they send. The one that wants a 1 but hears a 0 knows someone is "louder", so it drops out, and the other carries on without ever noticing. Clock stretching works the same way: a slave that is not ready holds SCL low, and the master lets go, sees the wire stay down, and has to wait.

| Mechanism | Meaning |
| --- | --- |
| Clock synchronization | SCL is wired-AND. The device that holds low the longest decides how long the low lasts |
| Arbitration | If several masters transmit at once, the one whose own bit does not match the SDA level drops out |
| Clock stretching | A slave holds SCL low to stretch the clock, and the master has to wait (this is an easy way to get HAL_BUSY) |

### 4. Bit-banged versus hardware I2C

Bit-banging means using two ordinary pins and toggling them bit by bit to the timing yourself. It is slower, but every step is in your hands and any pin will do. Hardware I2C hands the timing to the peripheral and saves the CPU work. The F1 hardware I2C tends to get stuck busy when a slave holds SDA low. The recovery is under "Recover a stuck bus" later in this chapter, so many F1 projects bit-bang instead.

| Dimension | Bit-banged (GPIO toggles) | Hardware I2C |
| --- | --- | --- |
| Pins | Any GPIO | Fixed alternate-function pins |
| Flexibility | High (several buses) | Low |
| CPU use | High | Low (the hardware makes the timing) |
| How solid it is | High (you control it) | On F1 it deadlocks easily |
| Speed | Lower | Fast mode targets 400 kHz. The STM32F103C8T6 does not support 1 MHz |

## Code

```c
/* i2c_oled.c —— hardware I2C1 reads and writes an SSD1306 (HAL) */
#include "stm32f1xx_hal.h"

I2C_HandleTypeDef hi2c1;

#define OLED_ADDR   (0x3C << 1)     /* HAL wants the 8-bit address: shift the 7-bit address left by 1 */
#define OLED_CMD    0x00
#define OLED_DATA   0x40

void SystemClock_Config(void);

static void i2c_init(void)
{
    __HAL_RCC_I2C1_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();

    /* PB6/PB7 alternate open-drain; external pull-ups are required */
    GPIO_InitTypeDef io = {0};
    io.Pin   = GPIO_PIN_6 | GPIO_PIN_7;
    io.Mode  = GPIO_MODE_AF_OD;
    io.Speed = GPIO_SPEED_FREQ_HIGH;
    HAL_GPIO_Init(GPIOB, &io);

    hi2c1.Instance             = I2C1;
    hi2c1.Init.ClockSpeed      = 400000;
    hi2c1.Init.DutyCycle       = I2C_DUTYCYCLE_2;
    hi2c1.Init.OwnAddress1     = 0;
    hi2c1.Init.AddressingMode  = I2C_ADDRESSINGMODE_7BIT;
    hi2c1.Init.DualAddressMode = I2C_DUALADDRESS_DISABLE;
    hi2c1.Init.GeneralCallMode = I2C_GENERALCALL_DISABLE;
    hi2c1.Init.NoStretchMode   = I2C_NOSTRETCH_DISABLE;
    HAL_I2C_Init(&hi2c1);
}

/* write a command or data to the OLED */
static HAL_StatusTypeDef oled_write(uint8_t ctrl, uint8_t *buf, uint16_t len)
{
    uint8_t tmp[129];
    tmp[0] = ctrl;                       /* 0x00 command / 0x40 data */
    for (uint16_t i = 0; i < len; i++) tmp[i + 1] = buf[i];
    return HAL_I2C_Master_Transmit(&hi2c1, OLED_ADDR, tmp, len + 1, 100);
}

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    i2c_init();

    /* probe whether the device is present */
    if (HAL_I2C_IsDeviceReady(&hi2c1, OLED_ADDR, 3, 100) == HAL_OK)
    {
        uint8_t init_cmd[] = {0xAE, 0x20, 0x00, 0xAF};   /* display off → addressing mode → display on */
        oled_write(OLED_CMD, init_cmd, sizeof(init_cmd));
    }

    while (1) { }
}
```

Read an EEPROM (AT24C02) with the Mem API:

```c
/* write one byte to AT24C02 address 0x00 */
uint8_t val = 0x5A;
HAL_I2C_Mem_Write(&hi2c1, 0x50 << 1, 0x00, I2C_MEMADD_SIZE_8BIT, &val, 1, 100);
HAL_Delay(5);   /* the EEPROM needs a write cycle */

/* read it back */
uint8_t rd = 0;
HAL_I2C_Mem_Read(&hi2c1, 0x50 << 1, 0x00, I2C_MEMADD_SIZE_8BIT, &rd, 1, 100);
```

Recover a stuck bus (when a slave is holding SDA, clock it nine times by hand):

```c
/* set SCL to open-drain GPIO, toggle it 9 times to release a stuck slave, then send STOP */
static void i2c_bus_recover(void)
{
    for (int i = 0; i < 9; i++)
    {
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET);   /* SCL low */
        HAL_Delay(1);
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET);     /* SCL high */
        HAL_Delay(1);
    }
    /* then call HAL_I2C_Init again to reset the peripheral */
}
```

## Hands-on labs

1. **Lab 1 (wire waveform):** Scan the bus and capture `START → 0x78 → ACK`. Record SCL frequency, SDA rise time, and the ACK bit. Temporarily pass `0x3C` and save the no-ACK trace for comparison.
2. **Lab 2 (peripheral state):** Write 16 bytes to an AT24C02 and poll until it is ready. Record the HAL result or AF flag, and confirm a repeated start before the read.

### 6. The core of a bit-banged I2C

```c
/* bit-bang I2C with open-drain GPIO (SDA=PB7, SCL=PB6) */
#define SCL_H() HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET)
#define SCL_L() HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET)
#define SDA_H() HAL_GPIO_WritePin(GPIOB, GPIO_PIN_7, GPIO_PIN_SET)
#define SDA_L() HAL_GPIO_WritePin(GPIOB, GPIO_PIN_7, GPIO_PIN_RESET)

static void i2c_start(void)
{
    SDA_H(); SCL_H(); i2c_delay();
    SDA_L(); i2c_delay();          /* SDA falling while SCL is high = START */
    SCL_L(); i2c_delay();
}
```

### 10. Repeated start (Sr)


<p align="center">
  <img src="../../assets/diagrams/sample-07-sr-restart.svg" width="760" alt="Write register, Sr, then read — no STOP in between">
  <br><sub>▲ Drawn for this book. MPU6050/EEPROM pattern: write pointer → Sr → read.</sub>
</p>


When you read a register-style device, the start bit in the middle is a repeated start. It does not send STOP first. `HAL_I2C_Mem_Read` already does it for you: START, device address + write, register address, Sr, device address + read, data, STOP.

If you call `Master_Transmit` and then `Master_Receive` yourself, a STOP lands in between. Many EEPROMs and sensors drop the address, and what you read back is some other register.

The 7-bit address `0x3C` is written in HAL as `0x3C << 1`, which is `0x78`. The bit pattern of `0x3C` is `0111100`. It is not "take `0x3C` as 8 bits and drop the top bit".

Before leaving this chapter, keep one ACK trace, one wrong-address NACK trace, and matching EEPROM buffers from before and after a power cycle.

Self-test:

1. The OLED address is 0x3C. Does HAL's DevAddress get 0x3C or 0x78?
2. Where do a repeated start and an ordinary START differ — which edge, on which wire?
3. Why does I2C send 0xA5 MSB first, while UART sends LSB first?

The next figure collects the three ways this chapter's experiments usually get "stuck": SDA held low, NACK, and SCL pinned low.

<p align="center">
  <img src="../../assets/diagrams/sample-07-i2c-triage.svg" width="760" alt="I2C triage: 9-clock bus clear, 7-bit/8-bit address check, clock stretching">
  <br><sub>▲ Drawn for this book. Branch one: with SDA low and SCL idling high, no START can form and every HAL call returns BUSY — drive SCL as an open-drain GPIO and emit at most 9 pulses (8 data bits plus 1 ACK is exactly what frees the bit the slave holds), sampling SDA between clocks and stopping early, then issue a real STOP (SDA low with SCL low → SCL high → SDA high) and re-init I2C1 before retrying; 9 is a ceiling, not a target. Branch two: the 9th clock stays high, so no device owns that address — the 7-bit address `0x3C = 0111100` puts A6..A0 plus R/W on the wire: write 0x78, read 0x79. The driver macro keeps 0x3C, `HAL_I2C_*` is called with `0x3C << 1`, and CR2 SADD carries those 8 bits; sending 0x3C as-is as 8 bits actually addresses 7-bit 0x1E. Branch three: SCL stays low after the master lets go — the slave is stretching the clock and the bus is not dead. Wait for it to rise; every I2C master, the STM32 peripheral included, must tolerate a stretched low. If it never rises, read SCL as a GPIO, time the high level with a TIM, then run the 9-pulse clear; a stretched low can outlast the HAL timeout — prove the level first, then raise the timeout. Bus clearing and clock stretching: UM10204 Rev 6, chapter 3. Register semantics: [RM0008 Rev 21 chapter 26](#source-rm0008-i2c).</sub>
</p>
