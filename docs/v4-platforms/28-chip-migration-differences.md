# 芯片迁移方法论与引脚/外设差异

换一颗芯片，最贵的不是重新学寄存器，而是把上一颗的记忆带过来：第 1 脚从哪数、BOOT 怎么采样、复位后 GPIO 是什么态、PA11/PA12 归谁。这一章把 F103、G071、L476、H743 与 GD32F4xx 五个家族的差异收进一张迁移检查表——每一条都给「记忆在哪里失效」的案例，先立方法论，再给差异。

证据先说清：本章零板级实测。引脚位号来自各数据手册的转述（DS12232、DS10198、DS12110 的原表在本次调研中未逐页取件，判定多为「来源说法待核」）；GD32 的时钟参数按官方固件库 `@10d02f4` 实取核对；H7 时钟账是算术推导（MCO2=96 MHz 是预期值，不是示波器读数）；保护与启动的边界描述沿用根书引脚三章，写作时凡手册未取件的行都保留「待核」标签。

> 版本口径：STM32 侧引脚与外设差异按 DS12232（G071RB）、DS10198（L476RG）、DS12110（H743ZI）、ES0392（H7 勘误）、RM0444/RM0351/RM0433/RM0090 的既有引用转述；GD32 侧按官方固件库 `@10d02f4`（`system_gd32f4xx.c`）与 UM 既有引用。H7 时钟示例对照 CubeH7 仓库 master 分支（PLLN=400 基线）。F103/F407 的时钟账已在 [v1 第 8 章](../v1-drivers/08-architecture-memory-clock.md) 核过，本章引用不重算。

## 本章罗盘

- **问题**：迁移的第一动作为什么是「从第 1 脚数一圈」而不是查寄存器？F103/G071/L476/H743 四个家族的 BOOT 机制差在哪，G0 的 BOOT_LOCK 真值表怎么读，「拉高 PA14 就进 Bootloader」这句旧印象错在哪？复位后 GPIO 默认态两家族为何不同？PA11/PA12 被两个外设抢时，G0/L4/H7 各自的解法是什么？VDDUSB/VDD33USB/VCAP/PDR_ON 这些电源脚为什么不能漏？H7 的 Rev V 与 Rev Y/W 为什么是 480/400 两条线，官方示例到底背书哪条？时钟链复算后为什么还要软件读回加 MCO 两道证据？L4 低功耗迁移的两条铁律是什么？GD32 从 STM32 迁过去，位宽陷阱藏在哪？
- **交付**：能按「料是谁→引脚对照→复用查表→BOOT/保护→时钟复算→三证据」走完一次迁移检查表；能数对四家族的第 1 脚（PC11/VBAT/PE2）与 H7 顶边的右往左方向；能区分 `nBOOT_SEL` 选的是「用引脚还是用选项位」；能给出 PA11/PA12 冲突的三家族解法表；能把 H7 的 CPU 480/HCLK 240/PCLK 120/定时器 240 四本账和 MCO2=96 MHz 的证据链说清；能守住「官方基线 400 vs 本书改写 480」的界限；能把 L4 醒来分类与快照时序复述对；能把 GD32 的 SDIO 位宽陷阱与 CAN_BT 可搬性写清。
- **边界**：方法论章，不重教任何外设的寄存器细节——GPIO/时钟/中断/UART 各回 [v1 第 8–13 章](../v1-drivers/08-architecture-memory-clock.md)；H7 的 Cache/DMA 一致性与双核契约归第 34 章（B3 卷 4 内），本章只划界；GD32 的 RISC-V 侧（CLIC/mtime/工具链）归[第 29 章](./29-gd32-arm-riscv.md)；FDCAN 的寄存器层归 H7 场，本章只提「它与 bxCAN 不是同一外设」。手册未取件的行一律带「来源说法待核」，不改写成结论。
- **依据锚点**：P23《G0 引脚》（`docs/23-STM32G0引脚.md`）、P24《L4 引脚》（`docs/24-STM32L4引脚.md`）、P25《H7 引脚》（`docs/25-STM32H7引脚.md`）、G4《GD32 外设差异》（`mcu/docs/gd32/04-periph-diff.md`）。上游核对：GD32 官方固件库 [system_gd32f4xx.c](https://github.com/) `@10d02f4`（`:958-996`、`:970-971`）、CubeH7 master（`main.c:189-192,276-279`）。F103/F407 时钟账见 [v1 第 8 章](../v1-drivers/08-architecture-memory-clock.md)（probe 断言 `0x07405408` 等）；保护与选项字节的 RDP 语义见 [v1 第 17 章](../v1-drivers/17-flash-iap-ota.md)。

## 先做出来

不接板，先把三件事在纸上做完——它们决定迁移第一周踩不踩坑。

### 1. 数脚：从第 1 脚起，别用记忆

四个家族的第 1 脚：F103 LQFP48 是 VBAT，G071RB LQFP64 是 **PC11**，L476RG 是 VBAT，H743ZI LQFP144 是 **PE2** 且顶边脚号**从右往左**增大。数法：顶视图 pin 1 在左上标记处，逆时针编号（G0/L4）；H7 的 LQFP144 顶边从右往左——同一个「PA9」，三个封装里物理位置完全不同。迁移第一动作：把新芯片的 DS 封装图打开，从第 1 脚数到你要用的脚，再对原理图网络名。VBAT 在 H743 LQFP144 上是第 1 脚旁边那格——根书 H7 章的自测问过「VBAT 第几脚」没给答案，这里补上：按 DS12110 的 Figure 7 核对（来源说法待核，以你手上的 DS 原图为准）。

### 2. 抢脚：PA11/PA12 三家族三解法

同一个 PA11/PA12，三个家族三种命运：

| 家族 | PA11/PA12 的身份 | 解法 |
| --- | --- | --- |
| G071 | 无 CAN；USB 是 UCPD（供电协商），不是设备控制器 | PA9/PA10 可经 SYSCFG_CFGR1 重映射到 PA11/PA12 位置（RM0444 口径，落表前按原文复核） |
| L476 | CAN1 与 OTG_FS 同时占 | 都要时 CAN 改 PB8/PB9 |
| H743 | FDCAN1 与 OTG_FS 同时占 | FDCAN1 迁 PD0/PD1 或 PB8/PB9；PB6/PB7 在 H7 上还是 USART1 与 I2C1 的双重候选 |

「同一信号名在不同家族上是不同外设的」——UCPD 就不是 USB 设备控制器，别把 G0 的 USB 期望带成 CDC。

### 3. 复算一条时钟链，认清「读回」的必要

H7 的 480 MHz 改写（Rev V + 8 MHz bypass + LDO 板三前提）算术是 8/4×480/2 = 480：CPU 480、HCLK 240、PCLK 120、APB 定时器 240 四本账各自成立。但算完不算完——软件读回 `SystemCoreClock` 是 480（CPU 侧）、`SystemD2Clock`/HCLK 是 240（总线侧），两本账别混；再补一路独立证据 MCO2 = SYSCLK/5 = 96 MHz 输出（预期值，文档推导）。为什么三道：`SCALE0` 宏写的是 `SYSCFG->PWRCR.ODEN`，SYSCFG 时钟没使能时这次写**不生效**——算术对、代码对、时钟没切，只有读回与独立输出能抓到。

## 机制

### 一、迁移检查表：六步

把 P23/P24/P25 的共同骨架与 GD32 外设差异章的「存在性→寄存器映射→引脚」三步收敛成一张表：

| 步 | 动作 | 失效案例 |
| --- | --- | --- |
| 1 料是谁 | DS 封面特性 + 订购字母解码（封装/温度/闪存容量） | 拿同系不同容量型号的引脚表硬套 |
| 2 引脚对照 | 从第 1 脚数一圈，对原理图网络名 | L4 的 HSE 在 PH0/PH1（脚 5/6），F103 的 PD0/PD1 陷阱 |
| 3 复用查表 | 每个 AF 逐条查 DS 表，不背表 | G0 的 PA9/PA10 重映射到 PA11/PA12 位置——没改寄存器前 PA11 不叫 PA9 |
| 4 BOOT/保护 | 四家族 BOOT 对照 + RDP 档位语义 | G0 的 BOOT_LOCK=1 + RDP L1 且未置 `FLASH_ACR.DBG_SWEN`：调试能力停止 |
| 5 时钟复算 | 每条链算术 + 读回 + 独立输出 | 480 MHz 算术对、ODEN 写无效 |
| 6 三证据 | 复算 / 软件读回 / MCO 独立输出（或日志） | 只对算术不读回，切挡失败静默 |

### 二、第 1 脚与复位默认态

第 1 脚的三个反例上一节给了。复位默认态是第二颗雷：**F103 的 GPIO 多为浮空输入，G0 复位后是模拟输入**（DS12232 Table 11 口径）。模拟输入态读不出电平、也不驱动——「复位后先读一次引脚电平判断外部状态」的代码在 G0 上会读到 0。未初始化的脚不能假设可输出；L4/H7 的默认态本章不给（源章未述），按 RM0351/RM0433 各自复核。

### 三、BOOT：四家族对照

| 家族 | BOOT 采样 | 关键差异 |
| --- | --- | --- |
| F103 | 独立 BOOT0 脚（需外部下拉）+ BOOT1/PB2 | 采样在复位释放时刻 |
| G071 | BOOT0=PA14（与 SWCLK 共脚），复位后内部下拉 | 真值表由 `BOOT_LOCK`/`nBOOT1`/`BOOT0`/`nBOOT_SEL`/`nBOOT0` 决定；**启动配置在第四个 SYSCLK 上升沿锁存**，之后 SWCLK 翻转不反向改目标 |
| L476 | BOOT0 独立第 60 脚 | 与 F1 同构，档位走 option 字节 |
| H743 | BOOT0 第 138 脚 | 同 L4 形态，BOOT_ADD 选项字节管地址 |

`nBOOT_SEL` 选的是「用引脚还是用选项位」，不是「Bootloader 开关」——这句是 G0 真值表最容易读错的一格。三条边界同讲：`BOOT_LOCK=1` 强制 Main Flash；`nBOOT_SEL=0` 用 PA14、`=1` 用 `nBOOT0`/`nBOOT1`；空片例外（无有效固件时系统存储器兜底）。「拉高 PA14 就进 Bootloader」这条旧印象在 G0 上不成立——PA14 是 BOOT0 的事实由 `nBOOT_SEL=0` 才成立，且锁存后改引脚无效。

保护侧（G0 素材）：RDP Level 2 **不可逆**；L1→L0 降级触发整片擦除；`BOOT_LOCK=1 + RDP Level 1` 且未置 `FLASH_ACR.DBG_SWEN` 时调试能力停止；选项字节与互补值不匹配会强制 `BOOT_LOCK=1`、RDP 默认进 Level 1。RDP 的完整语义见 [v1 第 17 章](../v1-drivers/17-flash-iap-ota.md)。

### 四、电源边界脚：三家族不同名

| 脚 | L476 | H743ZI LQFP144 | F103 |
| --- | --- | --- | --- |
| USB 电源 | VDDUSB = 脚 48 | VDD33USB = 脚 95 | 无此名 |
| 内核稳压电容 | 无 | VCAP1 = 脚 71、VCAP2 = 脚 106 | 无 |
| 上电使能 | 无 | PDR_ON = 脚 143 | 无 |

VCAP 是内核稳压器的电容——**不能省、不能接 VDD**；PDR_ON 决定上电复位门限的来源。这些脚在 F103 上不存在，「F103 的接线习惯」搬不上 H7。

### 五、H7 的 revision 门禁：480 不是无条件可达

`DBGMCU->IDCODE` 的 REV_ID 对照 ES0392：Rev Y/W 无 VOS0，上限 400 MHz（VOS1）；**Rev V 才有 VOS0 + 480 MHz**。每次换挡等 `VOSRDY`。官方基线要看清：CubeH7 master 的时钟示例仍是 `PLLM=4 / PLLN=400 / PLLP=2` 的 400 MHz——「PLLN=480」是本书带三前提（Rev V + 8 MHz bypass + LDO 板）的改写，不是官方示例原文。转述时保留这层界限：官方仓库背书 400，480 要自己核三个前提。

### 六、GD32：位宽陷阱与可搬性

GD32 从 STM32 迁过去，先分「可搬」与「丢位」两类（G4 的口径）：

- **可搬**：ULPI 12 根信号 GD32F4xx 与 F407 同脚同 AF10（换芯片不改布线只换库——注意源材料把「GD32F4xx」误写成「GD32F407」，芯片名以系列为准）；CAN_BT@0x1C 复位值 0x0123 0000 与 STM32 CAN_BTR 位域全等，位时序寄存器值可原样搬，改编号不改算式（两本手册页码待核）。
- **丢位**：SDIO 分频 STM32 是 CLKDIV[7:0]，GD32 是 DIV[8:0] 九位且第 9 位在 **bit31**，公式同为 /(DIV+2)——GD32→STM32 方向迁移会丢 bit31，卡识别 <400 kHz 先炸。**外设迁移要查位宽不只查偏移**。
- **时钟树**：GD32F450 的 200M 档（PSC=25、N=400、P=2、Q=9；25/25×400/2=200）已按官方库 `@10d02f4` 的 `system_gd32f4xx.c:970-971` 核对，握手顺序是 LDOVS→总线分频→PLL 启动等锁→HDEN 等 HDRF→HDS 等 HDSRF→切 SCS（`:958-996`）——比根书 GD32 章的表更细。**SystemInit 默认 168 MHz，200M 是可选预设档**；PLL1/PLL2 是「配置并使能了、但不在时钟路径」。

### 七、L4 低功耗迁移：两条铁律

- **醒来分两类**：Sleep/Stop 从 WFI 下一条指令继续，Standby/Shutdown 走复位路径——唤醒代码要先判断「这是恢复还是重启」。
- **证据在 HAL 清位之前取**：Stop 2 唤醒证据必须在 IRQ 入口、HAL 清位之前快照（HAL 先清 EXTI 线再清 WUTF 再 callback——清完再看，看到的全是 0）；**时钟恢复先于通信**（醒来先恢复时钟再开串口）；电流账要积分整周期（8 ms@5 mA + 992 ms@2 µA → I_avg=41.984 µA，1000 mAh→≈2.72 年），**封面典型值不是验收上限**——L4 章反复强调的口径，迁移时照样成立。采样率下限 f_s ≥ 10/t_min（8 ms 窗→1.25 kHz），少采样会把 42 µA 读成 2 µA。

## 测量与证据

本章证据口径表：

| 结论 | 身份 | 判据 |
| --- | --- | --- |
| H7 四本账（480/240/120/240） | 文档推导 | 8/4×480/2=480 算术复算 |
| MCO2=96 MHz | 文档推导（预期值） | SYSCLK/5；上板要示波器复核 |
| GD32 200M 档参数 | 手册级（上游已核） | `system_gd32f4xx.c@10d02f4:970-971` |
| GD32 SystemInit 默认 168M | 手册级（上游已核） | 同上 `:56` |
| CubeH7 PLLN=400 基线 | 手册级（上游已核） | `CubeH7@master main.c:189-192` |
| H7 480 三前提 | 来源说法(未复核) | ES0392 未取件；Rev V 实机待验 |
| 各封装脚位号 | 来源说法(未复核) | DS12232/DS10198/DS12110 原表未逐页取件，按你手上的 DS 复核 |
| L4 电流账 41.984 µA | 文档推导 | (5×8+0.002×992)/1000 复算成立 |
| SDIO DIV[8:0] bit31 | 来源说法待核 | UM §24.8.2 未取件，方向自洽 |
| G0 重映射 SYSCFG_CFGR1 | 来源说法待核 | CubeG0 头文件限流未取得，按 RM0444 复核 |

上板复核的最小集：MCO2 输出实测一次（96 MHz 预期）、G0 复位后读一次 GPIO IDR（预期模拟输入态 0）、H7 读回 `SystemCoreClock` 与 `SystemD2Clock` 各一次。三条都能在半小时内做完，做完本章的「待核」就少三条。

## 失败分支

| 症状 | 第一条假设 | 区分实验 |
| --- | --- | --- |
| 换板后 SWD 连不上 | G0 的 PA13/PA14 被改了复用或 RDP 升档 | 读选项字节与 DBGMCU.IDCODE，先取证再动 |
| Bootloader 进不去（G0） | 以为拉高 PA14 就行；`nBOOT_SEL` 用的选项位 | 读 `nBOOT_SEL` 档位；锁存后改引脚无效 |
| USB 枚举不起来（G0） | 把 UCPD 当设备控制器 | G071 无 USB 设备外设，UCPD 是供电协商 |
| 时钟切 480 失败（H7） | Rev Y/W 无 VOS0；或 SYSCFG 时钟未开 | 读 REV_ID；读回 ODEN 是否真写入 |
| SD 卡识别卡在 <400 kHz | GD32→STM32 丢 SDIO bit31 | 对比两边的分频寄存器位宽 |
| 唤醒后串口乱码（L4） | 时钟没恢复就通信 | WFI 后先等 PLLRDY 再开 UART |
| 电流读数「太好」 | 少采样错过活跃段 | 提高采样率到 f_s ≥ 10/t_min |

## 离开检查

- 能默写迁移六步，并给每步一个失效案例。
- 四家族的第 1 脚与 BOOT 采样时刻说得清；G0 真值表的 `nBOOT_SEL` 语义不再读错。
- PA11/PA12 三解法表能白板画出来。
- 480 MHz 的三个前提与「官方基线 400」的界限说得清。
- L4 的两条铁律（快照在清位前、时钟先于通信）能落到代码顺序上。
- GD32 的两个位宽陷阱（SDIO bit31、分频档位）与一条可搬性（CAN_BT）分得清。
