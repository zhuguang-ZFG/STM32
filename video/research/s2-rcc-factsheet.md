# s2-rcc 事实底稿（v2）

本集是「通往单片机之路 S2 · RCC 时钟树」。屏幕上的每个数字只有两个来源：`code/stm32/01-rcc-clock/probe.sh` 的本机实跑输出，或 RM0090 Rev 18 的原文表/约束。没有任何数字来自转述或心算。

## 取证环境与复现

- 复现：`cd code/stm32/01-rcc-clock && sh probe.sh`
- 宿主：gcc 16.1.0（`probe.c` 把 `RCC_PLLCFGR` / `RCC_CFGR` 两个宏改指假寄存器后 `#include "main.c"`，跑的是固件函数本体）
- 交叉：xPack GNU Arm Embedded GCC 15.2.1（`PATH` 里没有则第 3 段整段跳过）
- 产物：`build/probe.exe`、`build/probe-wrongmacro.exe`、`build/main_o2.o`（text 944 / dec 992）
- 本集事实日志：`.temp/v2-facts/s2-probe.log`、`.temp/v2-facts/s2-main-o2.txt`、`.temp/v2-facts/s2-main-o2-nohse.txt`

> 工具链口径：早期一份草稿用了 PATH 里另一套 arm gcc（10.3.1，text 952），字面量池地址整体后移 0x10。屏幕上的反汇编地址一律以 xPack 15.2.1 的 `build/main_o2.o` 为准（text 944，与书稿 `docs/stm32/02-rcc-clock.md` 的「944 字节」一致）。

位段打包：`M=8 N=336 P=/2 SRC=HSE Q=7 → 0x07405408`（M[5:0]、N[14:6]、P[17:16]、SRC[22]、Q[27:24]）。探针按同一布局独立拼一遍，断言与 `-O2` 字面量池里的 `.word 0x07405408` 同字。

约束（RM0090 Rev 18 §7.2.3）：M∈[2,63] 且 VCO 输入 1~2MHz；N∈[50,432] 且 VCO 100~432MHz；P 只有 /2、/4；Q∈[2,15] 且 USB 必须 48MHz。

## 二、等待周期（`latency`）

`probe.sh` 第 1 段第 3 节实跑 `flash_latency_ws_3v3()`，每个边界测两侧：

```
16→0  30→0  31→1  60→1  61→2  90→2
120→3 150→4 151→5 168→5（WS）
```

表本身来自 RM0090 Rev 18 Table 10，按 VDD 分列：2.7~3.6V 为 30/60/90/120/150/168；2.4~2.7V 为 24/48/72/96/120/144/168；2.1~2.4V 为 22/44/66/88/110/132/154/168；1.8~2.1V（预取关）为 20/40/60/80/100/120/140/160。同样 168MHz：3.3V 下 5WS，2.5V 下 6WS。

VOS 只决定天花板，不在 Table 10 里：VOS=0 时 fHCLK 上限 144MHz，VOS=1 才允许 168MHz；F405/407 没有 VOSRDY 就绪位（那是 F42x/43x 的）。

## 三、时钟树回读与总线（`bus-div`、`ppre-bug`、`systick-load`）

喂 `SWS=PLL, PPRE1=0b101, PPRE2=0b100`：

```
{ SYSCLK 168000000, HCLK 168000000, PCLK1 42000000, PCLK2 84000000, TIM2CLK 84000000 }
```

APB 分频 ≠ 1 时定时器时钟 = PCLK × 2；对照组 PPRE1=/1 → PCLK1=TIM2CLK=168000000，规则不触发。

PPRE 只有 3 位（索引 0~7）；旧表照 HPRE 开了 16 格，`0b100/0b101/0b110/0b111` 四档全被静默读成 /1，新表读出 /2 /4 /8 /16。后果：APB1 被算成 168MHz，再乘 ×2 得 336MHz。

SysTick 用回读出来的 HCLK 算 LOAD：`hclk/1000-1`；若仍按 16MHz 算，168/16 = 10.5 倍速。`-O2` 把除以 1000 编成 `umull` + `lsrs #6`，魔数 `0x10624dd3` 在字面量池 28c。

## 四、反汇编对字（`disasm-word`、`const-fold`、`order`、`sw-sws`、`hse-poll`）

xPack 15.2.1 `-O2`，`build/main_o2.o`，text 944：

```
 7a: ldr [r1,#2048] @0x800        ; RCC_CR
 7e: orr #65536     @0x10000      ; HSEON bit16
 82: str [r1,#2048]
 8c: ldr [r1,#2048]               ; 等 HSERDY
 90: lsls #14 / 92 bpl / 88 subs / 8a beq / 94
 a4: bic #16777216  @0x1000000    ; 先关旧 PLL
 ac: lsls #6 / b2 bmi              ; 等它真的停
 b4: ldr [pc,#464] @288
 b6: str [r2,#2052] @0x804        ; PLLCFGR ← 0x07405408
 c0: orr #16777216                 ; PLLON
 c8/cc: lsls #6 / ce bpl           ; 等 PLLRDY bit25
 d8: bic #3 / dc orr #2 / e0 str [r0,#2056] @0x808 ; SW=10b
 ea: ldr [r1,#2056] / ee and #12 / f2 cmp #8 / f4 bne
106 ~ 12e: HPRE /1、PPRE1 /4、PPRE2 /2
```

提频顺序地址（单调）：`50 #16384(VOS) → 5a/66/72 LATENCY+PRFTEN → 7e HSEON → 90 等 HSERDY → a4 关旧 PLL → b6 写 PLLCFGR → c0 PLLON → ce 等 PLLRDY → d8 SW → ee/f2 读 SWS → 106…12e 总线分频`。三处等待自旋（HSERDY / 旧 PLL 停 / SWS）各自留在本步内，没有一步倒回上一阶段。

字面量池：

```
274: 0x40023000   278: 0x40021000   27c: 0x40007000
284: 0x00100001   288: 0x07405408   28c: 0x10624dd3
290: 0x0280de80（= 42000000，MCO1 目标）
```

常量折叠：`g_pll_m/n/p/q` 的四处赋值编成四个立即数 `3a #336 / 3e #8 / 44 #2 / 46 #7`，一条除法都没有。

`USE_HSE_PLL=0` 版（text 536）：字面量池有 `.word 0x00f42400`（16000000）与 `.word 0x007a1200`（8000000），没有 `.word 0x07405408`、没有 `orr #16777216`；唯一一次碰偏移 `#2052` 是 `ldr`（回读函数读 PLLCFGR，但没人写它）。

## 五、MCO1 编码陷阱（`mco-trap`）

`MCO1PRE[2:0]` 真实编码（HAL `RCC_MCODIV_1..5` = 0/4/5/6/7）：最高位 0 → 不除；最高位 1 时 4/5/6/7 分别是 /2 /3 /4 /5。要 /4 应写 `pre=0b110(6)` → PA8=42000000Hz；按「div−1」写 `pre=0b011(3)` → 落进 0xx 区 → div=1 → PA8=168000000Hz；再按 /4 把读数乘 4 → 672000000Hz，凭空多出 504MHz。

## 六、宏填错（`hook-01`、`macro`）

`HSE_VALUE_HZ=25000000` 而板上 8MHz：写入 `0x07405419`（M=25），程序以为 168000000Hz；硅片按 M=25 分，VCO 输入 320000Hz；引脚 53760000Hz，USB 15360000Hz（要 48MHz）；差 114240000Hz，`pll_params_from_hse()` 返回值 = 0。宏填对时差值 = 0Hz，返回值同样 0——唯一的区别在引脚上那个数。

## 七、v2 修订记录（2026-10-29）

- 反汇编地址全部按 xPack 15.2.1 重录：`order` 首条 `4c→50`，总线分频段 `10a…12a→106…12e`；`const-fold` 的 `#8/#336` 行序改为汇编真实顺序 `3a #336 / 3e #8`。
