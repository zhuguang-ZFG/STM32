# 工程深读：从 IDLE 中断到完整帧协议——一条接收链路的五个契约

本书 [S7 USART](/stm32/07-usart.md)、[S8 DMA](/stm32/08-dma.md)、[C5 函数指针、状态机与环形缓冲](/c/05-func-pointer.md)、[C8 串口协议](/c/08-framed-protocol.md) 与 [J1 记录器](/projects/01-f407-logger.md) 各讲了这条链路的一段。这一附录把它们接成**一条完整的字节旅程**：从线路上的一个电平跳变，到业务层手里的一帧数据，中间每一段都签着一份"合同"。违反任何一条，链路都会以一种典型症状死给你看。而症状往往出现在离违约现场很远的地方。

三份配套工程是本附录的证据源：[`code/stm32/03-uart-dma`](https://github.com/zhuguang-ZFG/mcu/tree/main/code/stm32/03-uart-dma)（IDLE+DMA 环形接收的寄存器级最小实现）、[`code/stm32/05-framed-protocol`](https://github.com/zhuguang-ZFG/mcu/tree/main/code/stm32/05-framed-protocol)（帧协议落地）与 [`code/common/reliability`](https://github.com/zhuguang-ZFG/mcu/tree/main/code/common/reliability)（双板共用的 codec 与传输层，测试在 `tests.c`）。

## 0. 全景：一个字节的三段旅程

```
线路 ──USART──▶ DMA 环形缓冲 ──ISR──▶ 字节队列 ──解析器──▶ 帧 ──▶ 业务
       [硬件]      [S8]         [C5]            [C8]        [J1]
```

| 段 | 所有权人 | 这一段的"唯一真相" | 违约的典型症状 |
|---|---|---|---|
| 线路 → DMA 缓冲 | DMA 控制器 | `NDTR`（剩余计数） | 数据撕裂、整段丢失 |
| DMA 缓冲 → 字节队列 | UART/DMA 中断服务 | 环形读写指针 | 重复搬运或漏段 |
| 字节队列 → 帧 → 业务 | 解析器状态机 | `0x00` 分隔符 + CRC | 两段残帧拼成一段"合法"帧 |

发送方向是同一张表的镜像（业务 → TX 队列 → USART），契约相同，只是"消费者"换成了线路。下面逐条展开五个契约。

## 契约一：DMA 只认地址，不认语义

DMA 是一条"给地址就搬"的传送带。它不知道什么是"一帧"，也不知道你的缓冲区有几个逻辑区段。它只知道三件事：从哪搬（`PAR`）、搬到哪（`M0AR`）、还剩多少（`NDTR`）。所以第一份合同签给配置顺序与读数口径：

1. **改配置必须先停流。** `CHSEL`/`DIR`/`CIRC` 这些位只有在 `EN=0` 时才允许改（这是 RM0090 的硬性规定，不是风格建议）。03-uart-dma 的初始化顺序就是"关流 → 配 PAR/M0AR/NDTR → 配控制位 → 最后置 EN"。
2. **写位置是从 NDTR 减出来的。** 环形模式下，DMA 写到了哪里：

   ```c
   uint32_t pos = (RX_BUF_LEN - DMA_S5_NDTR) % RX_BUF_LEN;
   ```

   `NDTR` 是**剩余量**不是已写量；跑满一圈回装原值，所以要取模。读它的时机也有讲究：先读 NDTR、再读 HISR；如果采样间隙恰好跨了一次回绕，事后读到的标志位能提示你"刚才那一下越界了"。
3. **清标志写 HIFCR，不碰 HISR。** Stream5 的标志在高位寄存器（HISR/`HIFCR`），且 HISR 只读，往只读寄存器写 1 什么也清不掉。这是新手"标志永远清不掉、中断一进就是风暴"的第一根因。
4. **"DMA 完成"不等于"CPU 看见"。** 传送完成中断只证明 DMA 把请求做完了；CPU 要读到最新数据，还隔着缓冲区所有权这一层（契约三）。在带 D-Cache 的芯片上（如 H7、S3 的可用 DMA 内存区域限制）这一条还要再拆成"可达性"与"一致性"两个独立问题。

| 违约方式 | 症状 | 在哪一章展开 |
|---|---|---|
| EN=1 时改 CHSEL | 通道根本没换，数据进了别的流 | [S8](/stm32/08-dma.md) |
| 忘掉 `% RX_BUF_LEN` | 一圈后 pos 越界，读走别人的内存 | [S8](/stm32/08-dma.md) |
| 往 HISR 写 1 清标志 | 标志永不清，IRQ 风暴 | [S4 NVIC](/stm32/04-nvic-exti.md) |

## 契约二：IDLE 是"该搬积压了"，不是帧边界

IDLE 标志的含义只有一个：**线路静默了一个帧时间**。它不携带任何"这是一帧"的承诺。03-uart-dma 在源码注释里把这条写死在第一屏：

> IDLE 只提示总线空闲；应用协议必须自行定义帧边界。

所以 `g_frames` 这个观测量的注释也诚实地写着：它是 **IDLE 通知次数**，不是协议帧数。到了 05-framed-protocol，IDLE 的角色进一步降级为"该把积压搬走一趟了"的搬运通知；帧边界完全交给 COBS + `0x00`（契约四）。

错误标志的清除同样有口径：`ORE/FE/NE` 必须按"读 SR 后读 DR"的顺序才会应答清除；IDLE 的清除方式与之相同，但它**不是**协议边界，混在一起处理就会把"线路静默"误当成"收完一帧"。

| 事件 | 硬件语义 | 应用该做什么 | 错误用法 |
|---|---|---|---|
| IDLE | 一个帧时间内无新字节 | 把 DMA 缓冲里的新增区间搬进字节队列 | 当作帧边界直接切帧 |
| ORE | 收到字节时 RX 还没被读走 | 记数、读 DR 清除、考虑加大搬运频率 | 静默丢弃不计数 |
| FE/NE | 帧错误/噪声 | 记数；连续出现时先查波特率与时钟源 | 只清不查根因 |

处理 ORE 的位置值得多说一句：它意味着"数据在 USART 的单字节缓冲里挤丢了"。这时候**计数比恢复更重要**，因为丢的 byte 已经找不回来，能留下的是"链路在什么速率下开始丢"的证据。

## 契约三：环形缓冲的所有权与有序性

ISR 把新增字节从 DMA 缓冲搬进字节队列，这一段是 [C5](/c/05-func-pointer.md) 的主场。免锁的前提是**所有权分离**，四条不变量：

1. 写指针只有生产者（ISR）能改；读指针只有消费者（主循环/任务）能改。
2. 双方各自改**自己那一个**指针，且对它的写对另一方可见即可，单生产者单消费者场景下不需要临界区（[D5] 的结论）。
3. 判空判满必须先声明容量口径：留一格的 A 派（物理 N 格、可用 N−1）或计数 B 派（可用 N，多一个计数变量）。两派混用是"时好时坏"类 bug 的经典来源。
4. `atomic_signal_fence` 只挡**编译器**重排；它不是内存屏障，不解决多核可见性（那是 DMB/DSB 与 Cache 一致性的领地，见 [P4](/esp32/04-irq-dualcore.md)）。

一旦有第二个生产者（比如两个中断往同一个队列塞数据），免锁立即作废：所有权分离被破坏，必须回到关中断或 RTOS 队列（[F4](/rtos/freertos/04-queue.md)）。

```c
/* 队列满时禁止静默覆盖：宁可丢、必须数。 */
if (q->count == Q_SLOTS) { q->dropped = sat_add(q->dropped, 1); return; }
```

上面这行来自 `code/common/logger/logger.c`。注意连**计数本身都用饱和加法**（`sat_add`）：溢出场景下计数器自己先溢出归零，是最讽刺的翻车方式。

## 契约四：帧协议要能从任意字节流再同步

IDLE 不可靠、字节可能丢、线路上可能从帧中间开始听。所以协议层的合同是：**无论从哪个字节开始听，都能在一个帧时间内恢复同步**。`code/common/reliability` 的线上格式：

```
wire = COBS(raw) + 0x00                        # 最长 74 字节
raw  = version:u8=1 | type:u8 | sequence:u16LE | length:u16LE
       | payload[0..64] | crc:u16LE
CRC-16/CCITT-FALSE（poly 0x1021，init 0xffff，不反射）
检查串 "123456789" → 0x29B1
```

三个设计决定各自对应一条纪律：

- **`0x00` 只当帧尾**：COBS 编码保证 raw 里不会出现 `0x00`，于是分隔符可以无歧义；丢失或损坏一段后，**下一个 `0x00` 就是重新同步点**，不用等"恰好对齐"。这是选 COBS 而不是转义或长度前缀的核心理由（[D13]）。
- **CRC-16/CCITT-FALSE 而不是随手挑的多项式**：嵌入式网络环境下这个多项式的检错表现有据可查（[D9]）；`0x29B1` 检查串让你能独立验证自己的 CRC 实现；书里 [C8](/c/08-framed-protocol.md) 手算过一笔 `seq=7 INFO` 请求从 raw 到 wire 的全过程。
- **sequence 回显配对**：响应必须回显请求的 seq。串线、重连、两台主机抢一个设备时，这是防止"旧响应被当成新请求的答案"的最后一道闸。

解析器只有三个状态：`EMPTY → COLLECT → DISCARD`。DMA 错误（TEIF）、UART 错误（ORE/FE/NE）、字节队列溢出，任何一样都把状态机推入 DISCARD：丢掉不确定的残段，在下一个 `0x00` 重新开始。**"可疑就整段丢弃"比"试着抢救"永远便宜。**

## 契约五：慢消费者必须可见地失败

链路的每一层都会遇到"下游来不及"。合同只有一条：**禁止静默覆盖，失败必须变成可读的计数**。传输层（`transport.c`）的实现是一份范本：

| 层 | 满时的行为 | 可观察量 |
|---|---|---|
| TX 响应队列（4 帧） | 新响应直接丢弃，**不覆盖正在发送的帧** | `tx_drop` 计数 |
| TX 发送截止期 | 每帧 100ms 发不出去算失败，补发同步分隔符 | 失败计数 |
| RX 字节队列（512 B） | 溢出即失步：推解析器进 DISCARD | 溢出计数 |
| 记录器槽位（J1 的 16 槽） | 丢新样本，保住未取走的历史 | `dropped`（饱和加法） |
| 配置代次（J1 双槽） | 代次失配的旧读数不进记录 | `dropped`（按代次分账） |

"丢新的还是丢旧的"是每个系统的显式决定：TX 队列选**保旧弃新**（正在发送的帧不能撕），记录器选**保历史弃新样**（故障时刻的数据最值钱）。没有对错，但**必须写下来**。这正是 [S17](/stm32/17-watchdog-reset.md) 与 [P13](/esp32/13-watchdog-health.md) 健康监督的底座：监督的不是"任务活着"，而是"每一层的失败计数没有增长"。

## 六、跨到 ESP32-S3：同一 codec，换一副骨架

这条链路不是 F407 专属。`code/esp32/06-framed-protocol` 与 F407 版**共用同一个 `code/common/reliability` codec**（源文件级复用，不是复制粘贴），只换了搬运骨架：

| 环节 | F407 寄存器版 | ESP-IDF 版 |
|---|---|---|
| 收字节 | IDLE 中断 + DMA 环形，NDTR 轮询位置 | 驱动事件回调 + ring buffer（[P5](/esp32/05-uart-driver.md)） |
| 帧边界 | COBS + `0x00`（同一份 `protocol.c`） | 同左 |
| 溢出语义 | 计数 + DISCARD（同一份 `transport.c`） | 同左 |
| 交叉验证 | `codec-tool.c` encode/decode ↔ Python CLI | 同一份 CLI 对两块板 |

这正是 J1/J2 双板记录器"port 层"的含义：**协议与健康逻辑是公共资产，随硬件变的只有搬运层**。换芯片时重写的代码量被压缩到"怎么把字节搬进来/发出去"这一件事上。

## 七、最小验证矩阵

整链路的验收不是"串口助手里看起来收到了"，而是每一条输入都能用位置、计数与字节比较解释：

| 输入 | 预期 | 证据 |
|---|---|---|
| 1、127、128 字节后停顿 | 字节逐一相同，无越界 | 接收长度、逐字节比较 |
| 恰好半缓冲后停顿 | 不重复、不提前重启 | NDTR 轨迹与标志序列 |
| 超过一圈的连续流 | 跨尾/头连续 | `old_pos → pos` 轨迹 |
| 业务暂停直到队列满 | 溢出计数增长，系统不死锁 | `dropped` 与恢复后的帧序号 |
| 人为制造 ORE / 线路噪声 | 错误可见、DISCARD 后可再同步 | 错误计数、下一个合法帧的 CRC |
| seq 乱序 / 旧响应 | 拒绝配对 | seq 回显核对 |

`code/common/reliability/tests.c` 把这些场景做成了可跑的 C 断言（全切分点、时间回绕、背压、饱和计数、守护式模糊），`sh probe.sh` 一条命令全绿。上板之前，协议层的正确性已经在宿主机上被钉死过一遍。

## 八、一页总图

```
      所有权: DMA          所有权: ISR            所有权: 解析器         所有权: 业务
  ┌────────────────┐   ┌─────────────────┐   ┌──────────────────┐   ┌─────────────┐
  │ 环形缓冲 M0AR   │──▶│ 字节队列(512B)   │──▶│ EMPTY/COLLECT/    │──▶│ 帧分发 +     │
  │ 真相: NDTR      │   │ 真相: 读写指针    │   │ DISCARD          │   │ seq 配对     │
  │ 禁: 改位不停流  │   │ 禁: 双方改同指针  │   │ 真相: 0x00 + CRC  │   │ 禁: 忽略计数  │
  └────────────────┘   └─────────────────┘   └──────────────────┘   └─────────────┘
        契约一                契约三                契约四                契约五
                    ━━━━━━ 契约二：IDLE 只是搬运通知 ━━━━
```

五个契约背下来，你在任何一颗芯片上搭串口接收链路，要做的都只剩同一件事：**给每一段找对所有的主人，把失败变成数字。**
