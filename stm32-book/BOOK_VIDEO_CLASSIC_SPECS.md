# STM32 书籍与视频经典化改造 SPECS

状态：执行基线 v1 · 2026-11-02 · 改造前冻结

适用范围：`docs/00–28`、`docs/en/00–28`、`assets/`、`stm32-book/`、`tools/`、`final-videos/` 及新增的视频可复现源文件。

本 SPECS 扩展而非替换 `stm32-book/BOOK_REDESIGN_SPEC.md`。后者继续约束书籍；本文件新增五个技能的用法、视频质量、书视同源、分轮交付与总完成审计。

## SP-00 目标与不可缩减的完成边界

总目标：把 29 章《STM32 实战》及配套视频改造成准确、趣味、可读、生动、简单易懂、过目不忘、由浅入深的长期学习材料。

“经典级”是质量方向，不靠作者自评证明。完成必须有以下全部证据：

1. 中文与英文各 29 章逐章审计通过，不能只做样章后宣称全书完成。
2. 29 条章配套讲解短片与 29 条章节长课均有可复现脚本、分镜、字幕和实际成片检查。
3. 每个分部形成“先直觉 → 最小结果 → 机制 → 失败分支 → 实验证据 → 回忆检查”的学习闭环。
4. 既有技术事实、公式、型号、revision、电气条件、代码和来源不因美化而丢失。
5. 所有自动检查、实际 HTML/PDF 页面检查、视频媒体检查、联系表目检和 `task_verify` 分别记录；未验证项不能写成通过。
6. 任何剩余外部依赖或人工评审缺口必须明确列出；不能将“经典”当作跳过交付证据的借口。

## SP-03 学习路径与每章教学合同

保留 29 章和七个分部，不重排已公开章号。源文件与视频使用 00–28，书内标题与章首图徽标使用 1–29；这是 `display_chapter_number()` 的既有映射，不在单章改造中混用或反转。若未来统一显示编号，必须另立覆盖全部章节、视频与冻结资产的切片。

每章在学习日志中登记：

- **进入问题**：读者已经遇到什么可观察现象或任务。
- **先备知识**：只引用前面章节已经解释的概念；若必须后用，先给最小定义。
- **最小胜利**：一个可运行、可测量或可查表复算的结果。
- **核心机制**：一个主要认知难点，不用多个比喻争夺注意力。
- **失败分支**：至少一个能区分原因的可观察证据与下一检查动作。
- **迁移边界**：换芯片、库、时钟、封装或软件栈时必须重查的条件。
- **记忆锚点**：一个准确比喻、一张核心关系图、一句可复述口诀；三者必须指向同一机制。
- **离开检查**：不翻书能回答的问题，以及能独立完成的动作。

比喻必须随后用技术对应表或正文说明“哪里相似、在哪里失效”。不得用“芯片像大脑”“DMA 是高速公路”之类泛化比喻替代硬件路径。

## SP-04 正文、视觉与版式质量量规

### 4.1 正文

- 开头 120 字内出现问题、结果或矛盾，删除主题式预告。
- 每节第一句提供结论、判断或操作目标；保留必要的条件和不确定性。
- 同一信息不在标题下、表格后和章末重复三遍。
- 每章至少一个有条件的明确判断，不平均罗列所有方案。
- `humanizer-zh` 只处理真实表达问题；代码、URL、ID、表格数据和引用目标保持原样。
- 英文按英文学习路径重写，不直译中文新增比喻；事实、条件和媒体引用等价。

### 4.2 图像

每张图登记：章节锚点、认知任务、事实来源、视觉类型、Layout/风格/配色（若适用）、生成脚本、图注、证明范围与不能证明的范围。

- stack-diagram：遵守节点 132×100、行距与正交连线规则；明暗两版无文字/箭头碰撞。
- Handraw：知识插图使用 article-illustration-planner；提示词含实际风格与 Layout ID，原文请求存档；图库参考图只约束风格，不污染主题。
- image-prompt-reverse：每个新视觉系列先反推一组本地代表帧，提炼构图、线条、色彩、材质和媒介边界；输出只作视觉规范。
- 技术图与概念图分工明确；装饰性玩偶、咖啡杯、无业务关系的背景不进入知识章节。
- PDF 首帧完整可读；HTML 的动画不是理解唯一途径；`alt` 描述关系而非“示意图”。
- 现有每章视觉锚点数量不得倒退；最大无图区间不得比基线恶化。ch18、ch23、ch28 优先压缩文字墙，最终各章最大无图区间目标不超过 3,500 非空白字符，确有连续推导时记录例外理由。
- 外部实物/测量资产必须有准确型号、许可证、来源、哈希；没有证据就写缺口，不用生成图补假证据。

### 4.3 版式

Unslop 五行方向（在任何 CSS 改造前冻结）：**Product**：给中文 STM32 初学者一条能照着做、量、查的学习路径；**Character**：准确、耐心、略带工程现场感；**World**：开发板、导线、寄存器、波形和实验记录；**Moments**：电流/字节/状态真正发生变化的技术图与测量证据；**Signature**：用同一组“写值 → 电平 → 电流/状态 → 证据”的关系标记贯穿书和视频，不用 mascot 或装饰徽章充当签名。

- 保留现有单文件双语 HTML/PDF 构建器，不建立第二套正文真相源。
- 用 Guizang 设计 token 和组件制作样张，经浏览器验证后再移植到现有 `book.css` 与组件；同时更新哈希合同测试。
- 检查桌面、窄屏和打印：目录、表格、代码、图注、公式、跨页和孤行；不能以桌面截图代替 PDF 检查。
- 深浅主题保持同一信息层级；品牌色不能降低正文对比度。

## SP-05 视频教学与成片合同

### 5.1 单一分镜真相源

每章建立机器可读 storyboard，字段至少包括：

`scene_id / purpose / prerequisite / narration / on_screen / visual_source / fact_source / start / duration / memory_anchor / evidence_type / subtitle_ref`

短片和长课可以从同一章节事实与视觉资产派生，但不能把长课机械加速成短片。短片回答一个核心问题；长课增加推导、失败分支、实验和回忆检查。最终只保留一套分镜源，旧 `narration.py` 的重复事实在迁移后删除。

### 5.2 叙事节拍

1. 0–8 秒：真实问题、错误现象或结果反差；不先念系列口号。
2. 接着给最小可见结果，再解释“为什么会这样”。
3. 主画面优先呈现电流/字节/状态/波形/内存变化；文字卡只承担结论和回忆。
4. 每 8–15 秒检查一次视觉任务是否推进；无信息变化的重复模板页必须合并。
5. 一个场景只承担一个认知动作，复杂场景采用分步显现而非整页塞满。
6. 失败段必须展示证据如何区分两个可能原因，不用“可能坏了”收尾。
7. 章末用一页或一场回忆检查收束核心机制，不复述整章目录。

### 5.3 技术与可访问性

| 项目 | 章配套短片 | 章节长课 |
| --- | --- | --- |
| 目标画幅 | 1920×1080，30 fps；另有竖屏时从同一分镜重构安全区 | 1920×1080，30 fps |
| 时长 | 原则上 90–180 秒，按一个核心问题增减 | 原则上 8–18 分钟，按内容而非模板凑时 |
| 音频 | 目标 -16 LUFS ±1，True Peak ≤ -1 dBTP，无削波 | 同左 |
| 字幕 | 与旁白同源，时间轴连续、不重叠、不丢段 | 同左，并保留章节标记 |
| 首帧/封面 | 静态首帧独立可读；标题在安全区 | 同左 |
| 动效 | 只表达顺序、状态、比较或测量；无装饰性飞入 | 同左 |

每章输出 ffprobe 摘要、音频响度、字幕一致性、分镜覆盖报告和全片联系表。不能只检查 MP4 文件存在。实际播放/抽帧至少覆盖开场、核心机制、失败分支、实验和结尾五类场景。

## SP-06 可复现构建与干净切换

- 复用 `tools/gen_narrated.py`、`tools/narration.py`、SVG/GIF 和书籍构建模式。
- 第一轮为 ch03 长片建立最小生成链：storyboard → 语音/字幕 → 场景帧 → MP4 → 联系表；先证实一条链，再抽象共享实现。
- 若 ch03 证明 schema 合理，后续逐批迁移；全书切换完成后移除重复的旧分镜事实和废弃路径，不保留永久 shim。
- 生成脚本不得依赖作者机器绝对路径、随机数、未记录的网络内容或私有凭据。
- 大型 `final-videos/` 继续保持本地忽略；可追踪的是脚本、分镜、来源、许可、哈希和小型验证报告。
- 不伪造真板测量。没有真实测量时，画面标为“原理演示”或“仿真”，并明确不能证明的范围。
