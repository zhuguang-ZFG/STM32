状态：已发布 · Draft 1（2026-11-02）→ Book 2.0 v1.3.1（2026-11-10）；验收见 `stm32-book/audits/b51-final-acceptance.md`，spec 收口见 `stm32-book/audits/b53-spec-closeout.md`

适用范围：`docs/00–28`、`docs/en/00–28`、`assets/`、`stm32-book/` 及其测试

基线提交：`51b5e1c`

## 1. 为什么要重构

当前书已经具备 29 章中英文正文、可运行示例、离线 HTML/PDF、章节视频、来源快照和回归测试。主要问题不再是“有没有内容”，而是读者能否顺着内容真正学会：

- 一些章节连续数页只有文字、表格和代码，读者需要在脑中自行拼出数据流、状态变化与硬件边界。
- 动画和视频集中在章首。视频不会进入 PDF，因此网页看似有图，纸面仍可能只剩一张章首图。
- 实物照片、测量截图、概念图和连续动画的比例失衡；少量图承担了过多解释任务。
- 固定骨架使用过度后，章节容易出现相同的开头、三段式说明、逐节预告和章末复述，读起来像模板生成。
- 初学者能跟着点灯，但从“能跑”走到“能解释、能测量、能定位、能迁移、能交付”的台阶还不够清楚。
- 中英文内容存在结构漂移。例如第 20 章中文已经加入 SPL 与 CMake 构建合同，英文版尚未同步。
- PDF 已能稳定构建，但图版位置、长表、标题与图注、单双页节奏仍需按整书而不是单篇文章优化。

本次重构不是扩写竞赛。目标是减少无效文字，用更准确的图、例程和证据承担解释工作。

## 2. 最终目标

重构后的书要让读者完成六次能力跃迁：

| 层级 | 读者能做到什么 | 验收证据 |
| --- | --- | --- |
| L0 起步 | 搭好工具链，识别芯片、引脚、电源和时钟边界 | 能独立编译、烧录、复位并记录版本 |
| L1 驱动 | 用 GPIO、中断、定时器和常见总线驱动真实外设 | 波形、寄存器读回和最小可见结果一致 |
| L2 数据 | 解释字节如何经过 UART、SPI、I2C、ADC、DMA 和内存 | 时序图、缓冲区与代码可以逐项对账 |
| L3 可靠性 | 处理掉电、升级、看门狗、低功耗、调度和故障 | 能复现失败，并留下可定位证据 |
| L4 交付 | 组织工程、仿真、测试、板级接线和调试工具 | 项目能重建、能验收、能交给别人继续维护 |
| L5 系统 | 迁移芯片与软件栈，处理 Cache、网络、RTOS 和资源预算 | 能说明边界、最坏情况、恢复路径和取舍条件 |

书名中的“从点亮一颗灯到交付一个系统”必须在正文中成为可验证的学习路径，不只是一句宣传语。

## 3. 不做什么

- 不为了“像人写的”编造故障经历、测试数据、项目背景或个人感受。
- 不用生成图冒充真实开发板、仪器波形、芯片显微图或实验结果。
- 不把某一型号的寄存器、引脚、电气参数和时钟公式泛化到整个 STM32 系列。
- 不用删公式、删阈值、删版本条件的方式换取短文。
- 不给每章机械增加相同数量的标题、列表、插图和实验。
- 不用装饰性插画填空；每张图都必须回答一个正文问题。
- 不因排版方便而牺牲代码可复制性、表格数据或中英文事实一致性。

## 4. 全书信息架构

保留现有 29 章和七个分部，重写分部之间的承接。每章需要明确四件事，但标题名称可以不同，避免所有章节长得一样：

1. 读者带着什么具体问题进来。
2. 这一章先做出什么最小结果。
3. 接着解释哪一个底层机制。
4. 最后用什么证据判断“真的会了”。

章节内部按需要从以下功能块中选择，不要求全都出现，也不固定顺序：

- 现场问题或失败现象；
- 一句话直觉；
- 最小可运行步骤；
- 硬件数据流、状态机或时序；
- 可以复算的公式和参数条件；
- 测量方法与证据；
- 常见误判及其最短排查路径；
- 跨系列迁移边界；
- 由易到难的实验；
- 离开本章前的检查题。

章节可以短，也可以偏科。难点所在的小节应明显更深，安装步骤不必和 Cache 一致性写成同样长度。

## 5. 去 AI 味编辑规范

每批正文采用 Sepia 的技术教程 `refactor` 流程：先列缺陷，再改文字。作者模型按未知处理；执行模型为 GPT 系列、版本未知，相应模型特征只作先验，不作检测结论。

### 5.1 必须清理

- “本章将介绍”“让我们深入了解”“通过以上内容可以看出”等开场和收束残留。
- 定义所有人都知道的主题式开头。优先从真实问题、错误现象、数值矛盾或操作结果切入。
- 每节都“先预告、再解释、后总结”的分形结构。
- 连续出现的“首先/其次/最后”“此外/同时/因此”和整齐的三项排比。
- 没有信息量的强调词，如“至关重要”“显著提升”“全面掌握”“强大而灵活”。
- 为了顺滑而重复上一段结论，或把表格内容重新抄成一段话。
- 无来源的经验口吻、无条件的数字、未运行的通用代码和伪造的失败案例。
- 每个方案都平均介绍、却不给使用条件和推荐结论的对称写法。

### 5.2 必须保留

- 订货号、芯片 revision、手册版本、公式、寄存器位、地址、阈值和单位。
- 能复现失败的前置条件，以及失败时实际可观察的证据。
- 代码的编译边界：目标芯片、库版本、头文件、宏、链接脚本和构建命令。
- 读者真正会问的短句、直白判断和必要的否定。
- 长短不一的段落和句子。技术密度由内容决定，不做统一节拍。

### 5.3 每章至少有一个明确判断

判断必须有条件。例如：

> 新项目优先 HAL/LL；只有在维护锁定版本的 F1 旧工程时才继续用 SPL。

不能只列方案，也不能把个人偏好写成普遍规律。需要说明什么条件会改变该判断。

### 5.4 编辑完成前的两次检查

- 删除检查：删掉新增词句后，意思不变，则新增内容是填充，应删除。
- 回退检查：原句更短、更准确且语气合适，则保留原句，不为“润色”而改写。

## 6. 图文系统

### 6.1 一张图必须完成一种工作

| 图像类型 | 解决的问题 | 典型内容 |
| --- | --- | --- |
| 实物照片 | 读者手里的东西和书中对象是否相同 | 板卡区域、接口、跳线、芯片丝印、探头接法 |
| 测量证据 | 配置是否真的作用在硬件上 | 示波器、逻辑分析仪、调试器寄存器、内存窗口 |
| 概念图 | 哪些对象归谁管、数据往哪里走 | 所有权、层次、内存区、总线、协议封装 |
| 时序/状态动画 | 顺序、并发和状态变化是什么 | 枚举、仲裁、DMA、启动门、调度、超时 |
| 对比图 | 两种做法差在哪里 | 轮询/中断、HAL/SPL、裸机/RTOS、仿真/真机 |
| 决策/排错图 | 下一步应该检查什么 | 启动失败、无波形、网络离线、HardFault |
| 计算图 | 数值从哪里来 | PSC/ARR、BRR、采样时间、位时间、响应预算 |

装饰图、微缩桌面、咖啡杯、玩偶向导和与业务无关的背景不进入知识章节。

### 6.2 HandRaw 视觉约束

知识图解使用 `article-illustration-planner` 的模式 A。每张图登记排版图型、风格和配色，优先使用：

- 流程和排错：`IG-008`；
- 双列比较：`IG-004`、`IG-011`；
- 中心结构标注：`IG-002`；
- 阶段进阶：`IG-010`；
- 漏斗与逐层过滤：`IG-013`；
- 时间轴与状态：`IG-009`、`IG-012`。

全书主基调使用清晰线稿、扁平矢量和工程蓝图类画风。当前已采用的 `FA-002`、`FA-029` 与 `C-03`、`C-10`、`C-27`、`C-31` 可继续使用；新增风格必须先证明不会破坏整书一致性。

### 6.3 数量与分布

“视觉锚点”是 PDF 中仍然存在、能独立读懂的一张图或一组图。章首视频不计入 PDF 视觉锚点；紧邻的封面动画与视频只算一个阅读位置。

| 正文规模 | 目标视觉锚点 | 分布要求 |
| --- | --- | --- |
| 少于 6,000 个非空白字符 | 3–4 | 覆盖开头、核心机制和实验/排错 |
| 6,000–10,000 | 4–6 | 任意连续 1,000–1,200 字不得完全无图 |
| 超过 10,000 | 6–8 | 原理、实现、证据、排错和迁移至少各有一处覆盖 |

相邻插图之间通常保留 400–500 字，并跨过一个完整小节。代码块、长表和公式可以改变间距，但不能用来掩盖整章图片堆在开头的问题。

### 6.4 实物照片和第三方资产

- 硬件选型、板卡、接线和引脚类章节优先加入准确型号的实物照片或测量证据。
- 照片必须本地保存，不热链；记录作者、原图页、许可证、下载日期、裁切/压缩过程、尺寸和 SHA-256。
- 只接受许可证允许仓库再分发的资产。CC0、CC BY 等分别保留原许可，不并入原创图片许可。
- 照片中的型号必须在图注写明；相似板卡不能冒充目标型号。
- AI 生成图可以作为明确标注的概念插画，但不能作为产品、板卡、仪器或实验结果的证据。

### 6.5 图注与无障碍

每张图的正文附近必须回答：

1. 图里应该看哪里；
2. 它证明什么；
3. 它不能证明什么或适用边界是什么；
4. 图从哪里来。

`alt` 描述图中关系，不复述“这是一张示意图”。动画第一帧必须完整可读，保证 PDF 不依赖播放才能理解。

## 7. 当前基线与优先级

2026-11-02 的审计显示，第 20、22、25 章各只有一张静态图和一个章首视频。视频在 PDF 中被移除，因此纸面实际只剩一个视觉锚点：

| 章 | 非空白字符约数 | 当前 PDF 视觉锚点 | 首轮目标 | 主要缺口 |
| --- | ---: | ---: | ---: | --- |
| 20 学习资源与工具链 | 7,500 | 1 | 5 | 手册选择、工具边界、检索流程、构建合同 |
| 22 Wokwi 与 Renode | 5,200 | 1 | 4 | 仿真边界、模型层次、从仿真迁到真板的证据 |
| 25 STM32H7 引脚 | 10,000 | 1 | 7 | 供电域、revision/电压档、480 MHz 时钟链、Cache/引脚迁移 |

第 26–28 章已完成第一轮视觉加厚，不视为最终完成；全书重构时仍要接受同一套文字、分布和排版验收。

## 8. 分阶段实施

每批最多处理 2–3 章，避免大提交无法审查。实施顺序按读者能力递进；严重视觉缺口可以先做桥接批次，但最终仍需从第 00 章顺序复查。

### Phase 0：基础设施与基线

- 固化本 Spec，并在书籍 README 中建立入口。
- 生成全书章节审计：字符数、标题数、表格数、代码块数、视觉锚点数和最大无图区间。
- 区分网页媒体、PDF 静态锚点、实物照片、概念图、动画和证据截图。
- 增加中英文结构差异报告，不只检查文件存在。
- 建立页样抽查脚本：章首页、最长表格页、图文混排页和章末实验页。

### Phase 1：起步与第一条硬件闭环（00–05）

- 先让读者完成一次可重复的编译、烧录、复位和测量。
- 把芯片选型、时钟、GPIO、中断、定时器连成同一个最小项目。
- 增加开发板/调试器实物辨认、工具链产物图、时钟与中断状态动画。
- 删除对初学者无帮助的工具枚举和章末复述。

### Phase 2：字节、波形与内存（06–10）

- UART、I2C、SPI、ADC、DMA 均按“线上波形 → 外设状态 → 内存结果”组织。
- 每章至少有一份可读波形或测量证据。
- 用概念图说明所有权、缓冲区边界和错误发生位置。
- 把 DMA+IDLE、采样时间和 Cache 边界安排成逐级难度，不提前抛出未解释概念。

### Phase 3：可靠性与实时行为（11–17）

- 从 RTC/看门狗走到升级、CAN、USB、RTOS、低功耗和 HardFault。
- 每章加入一个可复现失败和一条最短诊断路径；不编造项目故事。
- 图示突出状态、超时、恢复和最坏情况，不只画正常流程。
- 实验验收从“现象出现”升级为“证据能区分两种失败”。

### Phase 4：项目交付与仿真（18–22）

- FAQ 改为症状驱动的排错入口，项目合集改为能力组合，不做代码清单。
- 第 20 章补齐手册选择决策图、工具链边界图和构建产物流。
- 第 21 章把板卡图鉴与准确型号实拍、接口识别和接线风险对应起来。
- 第 22 章明确 Wokwi、Renode 和真板各自能验证什么；增加仿真到真机的证据阶梯。

### Phase 5：迁移到高性能系统（23–28）

- G0、L4、H7 不是三份引脚表，而是三次迁移：启动、电源、时钟、内存与调试边界逐级增加。
- 第 25 章补齐 H7 供电/revision 决策、时钟链动画、Cache/DMA 所有权和目标板实物辨认。
- SPL、网络、RTOS 继续沿用 26–28 章已建立的图型，但重新检查文字模板、视觉间距和中英文等价。
- 最终以资源预算、启动门、故障恢复和可交付证据收束全书。

### Phase 6：整书编辑与出版验收

- 统一分部开场、章节承接、术语、交叉引用和索引。
- 删除跨章重复解释，把事实放在最合适的一章，其余位置用精确链接。
- 调整 PDF 图版宽度、并排照片、长表、代码换页、孤行寡行和页码目录。
- 中英文分别通读，不把中文句式直译成英文，也不让英文版缺失中文新增内容。
- 输出最终 HTML/PDF、页样联系表和发布说明。

## 9. 每批的固定工作流

1. **冻结事实范围**：列出订货号、库版本、手册 revision、公式和不可改动的数据。
2. **Sepia 诊断**：先输出结构、密度、相关性、立场、具体性、格式、结尾、模板和节奏缺陷，不边看边改。
3. **章节重排**：按问题、最小结果、机制和证据重排；删重复，保留硬核数据。
4. **HandRaw 插图计划**：为每张图登记锚点、认知目的、Layout ID、风格、配色、保真要素和图文关系。
5. **生成与取证**：SVG/GIF 由脚本可复现生成；照片和截图补齐来源、哈希与处理记录。
6. **中英文同步**：同一批次完成，图片引用和事实条件一致，表达按各自语言重写。
7. **自动检查**：运行正文、资产、链接、SVG、视频、中英文结构和构建测试。
8. **本地成书**：串行构建中英文 HTML/PDF，记录页数、文件大小和书签数。
9. **目检页样**：至少看章首页、一个概念图页、一个代码/表格页和章末实验页。
10. **提交与 CI**：一个提交只覆盖一个清晰批次；推送后修到 CI 全绿。

## 10. 每章完成定义

一章只有同时满足以下条件才算完成：

- [ ] 开头在 120 字内给出具体问题或结果，没有主题式空话。
- [ ] 新术语按依赖顺序出现，未使用后文才解释的关键概念。
- [ ] 至少一个可以运行、测量或查表复算的最小结果。
- [ ] 公式、单位、型号、revision 和来源条件完整。
- [ ] 至少一个失败分支，写清可观察证据和下一步检查。
- [ ] 视觉数量与分布达到第 6.3 节目标，没有章首堆图。
- [ ] 图注说明“证明什么”和“不能证明什么”。
- [ ] 实物照片/截图有准确型号、许可、来源和哈希。
- [ ] 动画第一帧在 PDF 中独立可读。
- [ ] 中文完成去 AI 味诊断与删除/回退检查。
- [ ] 英文与中文事实、结构和视觉引用等价。
- [ ] 代码、链接、SVG、资产和书籍构建检查全部通过。
- [ ] 中文与英文 PDF 页样已人工查看。

## 11. 自动化质量门

在现有测试上增加以下契约：

- 统计每章 PDF 视觉锚点和最大无图区间；阈值按正文规模计算。
- 禁止同一小节连续堆放多张无正文承接的插图。
- 检查图片 `alt`、图注、文件存在性和中英文引用对称性。
- 检查 `assets/photos/README.md` 中的文件、尺寸、哈希、来源和许可证是否与实物一致。
- 校验生成脚本能重建新增 SVG，生成结果不依赖随机数和网络。
- 报告中英文二级标题、代码块、表格、公式和媒体数量差异。
- 对常见模板腔做提示性 lint；lint 只报告，不凭单个词自动判定 AI 文本。
- 继续执行全部链接、HTML 契约、视频契约、书签、索引和 PDF 排版测试。
