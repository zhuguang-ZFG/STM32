# 术语表

术语按全书七个分部里读者会反复碰到的主题排列，每条只给本书语境下的一行工作定义。寄存器位、地址、时间和电气参数始终以目标型号的对应修订版手册为准，不能从邻近系列照搬。

## 时钟与复位

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| AHB / APB | 片内总线层级。CPU 和高速外设多挂在 AHB，多数外设挂在 APB，时钟从 SYSCLK 逐级分下来 | APB 分频之后，所有定时器时钟都简单等于 PCLK |
| BOR | 欠压复位。电源低于阈值时让芯片复位，避免在过低电压下继续执行 | 有 BOR 就等于整板电源设计已经合格 |
| CSS | 时钟安全系统。HSE 失效时切到内部高速时钟并报告故障；切到哪一个时钟、走哪一种异常，看该系列手册 | 打开 CSS 之后晶振可以不再焊接 |
| Flash wait state | CPU 读 Flash 时为满足访问时间插入的等待周期，写在 `FLASH_ACR` 的 LATENCY。F103 在 2.7–3.6 V、48–72 MHz 这一档是 2；分档见文末的账 | 主频提高后不需要调整 |
| HCLK | AHB 时钟。CPU 和 AHB 外设常用它，中间可能经过 AHB 预分频，所以不等于 SYSCLK | HCLK、SYSCLK 和定时器时钟是同一个数 |
| HSE / HSI | 外部高速时钟 / 内部高速 RC。HSE 可以是晶体，也可以是外部时钟 | HSE 必然比 HSI 准，且板上一定焊了晶振 |
| HSE bypass | 外部时钟从 OSC_IN 送入，旁路片内晶体振荡电路。用于有源时钟，而不是无源晶振的默认接法 | 焊了晶振就要打开 bypass |
| LSE / LSI | 外部低速晶体 / 内部低速 RC，多供给 RTC 和独立看门狗 | LSI 精度足以直接当高精度 RTC |
| MCO | 主时钟输出。把内部某路时钟分频后送到引脚，便于用仪器核对时钟树 | 任意引脚都能输出任意内部时钟 |
| NRST | 外部复位脚，低电平有效。调试器和复位按键通常都接到这里 | 调试器已连接时，NRST 上的电平可以忽略 |
| PCLK | APB 时钟。STM32 常分成 PCLK1 和 PCLK2，对应 APB1 与 APB2 | 所有外设的内核时钟都等于 PCLK |
| PLL | 对参考时钟倍频、分频的锁相环。USB、特定主频往往还要满足额外的频率约束 | 任意倍频组合都满足芯片和 USB 约束 |
| SYSCLK | 系统时钟，通常在 HSI、HSE 和 PLL 之间选择，再分给 AHB | 复位后的 SYSCLK 已经是手册里的最高主频 |
| TIMCLK | 定时器计数用的输入时钟。F1/F4 一类常见规则是：APB 预分频为 1 时等于 PCLK，否则为 PCLK 的 2 倍；H7 等系列要看各自的时钟树 | 把 PCLK 代进公式就得到所有系列的 PWM 频率 |

## 引脚、GPIO 与复用

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| 5 V tolerant | 部分引脚在数据手册允许的条件下可以承受 5 V 输入。不是所有脚，也不能当成 5 V 推挽输出 | 标成 FT 的脚就可以直接驱动 5 V 器件的电源轨 |
| AF | 复用功能。把引脚交给某个外设，而不是交给 GPIO 的输出数据位。编号以该封装的复用表为准 | 同一个 AF 编号在 F1、G0、H7 上表示同一个外设 |
| Analog mode | GPIO 的模拟模式，供 ADC、DAC 或比较器使用，数字输入缓冲不再表示引脚逻辑电平 | 模拟模式下读 IDR 仍然是可靠的数字采样 |
| BSRR | 置位/复位寄存器。被写 1 的位会置位或清零，写 0 的位保持不变，避免读改写互相踩踏 | 要改一个脚必须先读 ODR 再写回 |
| GPIO | 通用输入输出。模式、上下拉、速度和复用都按具体引脚配置 | 复位后的默认模式在所有系列上都是推挽输出 |
| GPIO speed | 输出驱动斜率的档位，影响边沿和噪声。它不是“把这只脚变成那个频率的时钟” | 选了 50 MHz 档，翻脚频率就会达到 50 MHz |
| Open-drain | 开漏：只能主动拉低，释放后靠上拉变高 | 写 1 会主动输出高电平 |
| Pull-up / Pull-down | 片内弱上拉或弱下拉。能稳定悬空输入，不能代替 I2C 所需的外部上拉电阻 | 打开片内上拉之后，I2C 就可以不焊电阻 |
| Push-pull | 推挽：高电平和低电平都由输出级主动驱动 | 推挽可以接在多主机共用的开漏总线上 |
| Remap | F1 用 AFIO 重映射把外设改到另一组脚。F4 及以后多数字列改为 AF 编号，没有同一套 remap 寄存器 | F1 的重映射代码可以原样写进 G0 或 H7 |

## 中断与内核异常

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| BASEPRI | 只屏蔽优先级数值不低于阈值的可配置异常。写 0 表示不按这个阈值屏蔽 | BASEPRI 会挡住 NMI 和 HardFault |
| EXTI | 把 GPIO 或内部事件接到中断/事件线的控制器。同一条线往往由同一编号的多个端口脚共享 | 每个 GPIO 都有独立的 EXTI 编号 |
| ISR | 中断服务例程。应尽快清源并退出，把耗时工作留给主循环或任务 | ISR 里可以阻塞等待，只要平均时间不长 |
| NVIC | Cortex-M 嵌套向量中断控制器。STM32 上数值越小，逻辑优先级越高 | 数值越大，逻辑优先级越高 |
| PendSV | 可挂起的系统服务异常。RTOS 通常在这里做上下文切换，避免在高优先级中断里直接切换 | 任何中断返回时都会自动切换任务 |
| Preemption | 抢占优先级。更高的抢占优先级可以打断正在执行的低优先级 ISR | 子优先级不同的中断也会互相抢占 |
| PRIMASK | 置 1 后屏蔽可配置优先级的中断。NMI 和 HardFault 仍然可以进入 | 关总中断等于芯片上一切异常都停了 |
| Priority grouping | 把优先级字段拆成抢占位和子优先级位。改变分组会改变已有数值的含义 | 分组只影响新写的优先级，旧值自动保持原意 |
| Subpriority | 子优先级。抢占级相同时，只决定谁先被响应，不能互相打断 | 子优先级可以用来让某个 ISR 打断另一个 |
| SVC | 系统调用异常。常用于从线程进入受控的内核服务，而不是普通 GPIO 中断 | SVC 和普通外设中断的优先级规则不同，所以可以在 ISR 里随便调用 |
| SysTick | 内核系统节拍定时器。HAL 常用它做毫秒时基，RTOS 也常用它或别的定时器做 tick | HAL 时基和 RTOS tick 可以各自把 SysTick 初始化一次而互不影响 |
| Tail-chaining | 异常退出时若已有挂起异常，硬件可省略一部分压栈。它减少开销，不改变谁有权抢占 | 尾链打开后，低优先级中断也能插入高优先级 |
| Vector table | 异常入口表，开头是初始栈顶和复位向量。应用程序若不住在默认地址，入口表也要跟着走 | 跳到应用的 Reset_Handler 之后，向量表仍然留在 bootloader |
| VTOR | 向量表偏移寄存器。重定位时要满足编程手册的对齐要求，不能任意字节偏移 | 只要修改链接脚本里的 Flash 起始地址，VTOR 会自动正确 |

## 定时器与 PWM

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| ARR | 自动重装值，决定计数周期的上界。它和输入时钟、PSC 一起才得到频率 | ARR 就是频率 |
| CCR | 捕获/比较寄存器。比较模式里决定占空比，捕获模式里锁存边沿时刻的计数值 | 只用于 PWM，不能做输入捕获 |
| Dead time | 互补输出之间插入的死区，用来降低桥臂直通的可能。只有带互补输出的定时器才有 | 任意通用定时器都有互补 PWM 和死区 |
| Encoder mode | 用两路正交输入计数位置。两相接反时计数方向相反 | 编码器模式输出的是已换算好的机械角度 |
| Input capture | 在输入边沿把计数器锁进 CCR，用来量脉宽或周期 | 捕获值直接就是微秒，与定时器时钟无关 |
| MOE | 主输出使能。高级定时器的互补输出在 MOE 关闭时不向外输出，刹车可以清掉它 | 置了 CCER 使能位，互补 PWM 就一定出现在引脚上 |
| PSC | 预分频。计数时钟大约是定时器输入时钟除以 (PSC+1)。新的 PSC 通常在更新事件才装载 | PSC 写成目标分频比，而且写完立即生效 |
| PWM | 用周期和占空比表达平均能量或控制量。负载是否线性还要看滤波器和功率级 | 占空比与所有负载的物理输出都成正比 |
| TRGO | 定时器发给 ADC、DAC 或其他定时器的触发输出。连接哪一个外设要看该芯片的触发表 | 任何更新事件都会自动连到任何 ADC |
| Update event | 溢出、下溢或软件触发产生的更新。影子寄存器在这时装载，也可作为 TRGO 的来源 | 更新中断频率永远等于 PWM 引脚上看到的频率 |

## UART、I2C、SPI、CAN 与 USB

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| 7-bit address | I2C 常见的 7 位从机地址。线上的第一个字节是这 7 位加上读/写位。HAL 的 DevAddress 要左移 1 位：SSD1306 的 `0x3C` 写成 `0x78` | 扫描器显示的 7 位地址就是总线上的 8 位帧 |
| ACK / NACK | I2C 第 9 个时钟由接收方决定是否拉低确认。NACK 表示这一字节不被确认 | 收到 ACK 就证明寄存器地址和数据语义都正确 |
| bxCAN | F1 一类芯片上的经典 CAN 控制器 | 与 H7 的 FDCAN 寄存器兼容 |
| Clock stretching | I2C 从机拉住 SCL，让主机等待。主机是否允许、等多久，要单独看控制器和从机手册 | 所有 STM32 主机都会无限等待从机拉钟 |
| CPHA / CPOL | SPI 的采样相位与空闲时钟极性。必须和从机器件时序图一致 | 只要时钟频率一样，四种模式可以随便选 |
| CRC | 检测意外改动的循环冗余校验 | CRC 能证明来源身份或抵抗恶意篡改 |
| FDCAN | 支持 CAN FD 的控制器。帧格式和寄存器都不同于 bxCAN | 只是 bxCAN 改了个名字 |
| FE / NE | UART 帧错误 / 噪声错误。说明线上电平时序异常，不自动等于丢弃了哪一个应用层字段 | 没看到 ORE 就表示每一帧都完整 |
| Full duplex | SPI 在每个时钟沿同时移出和移入一位。主机要读数据，就必须提供时钟 | 读寄存器时可以把 MOSI 悬空，从机仍会吐出数据 |
| IDLE | UART 接收线保持一个帧时间以上的空闲 | IDLE 天然等于协议帧结束 |
| NSS | SPI 片选。许多器件在 NSS 上升沿才执行命令；硬件 NSS 和软件拉脚不是同一件事 | 片选可以一直拉低，事务边界不影响命令 |
| ORE | UART 接收溢出。新字节到来时上一字节还没取走 | 只要开了 DMA 就不可能出现 ORE |
| Repeated START | 不释放总线的再次起始。读寄存器时常是“写指针 + 重复起始 + 读数据” | 两次传输之间必须先 STOP，否则从机不认 |
| TC / TXE | 发送完成 / 发送数据寄存器空。TXE 表示可以写入下一字节，TC 表示移位寄存器里的最后一位也已离开引脚 | TXE=1 表示线上最后一位已经发送完 |
| UART 8N1 | 8 个数据位、无校验、1 个停止位。帧的两端还有起始位和停止位 | 8N1 的“8”已经包含起始位 |
| USARTDIV / BRR | F1 在 16 倍过采样下 `USARTDIV = fPCLK / (16 × 波特率)`。BRR 高位是整数，低 4 位是小数。USART1 挂在 APB2：72 MHz、115200 得到 39.0625，BRR 为 `0x271`，分频误差为 0 | 表上同一行的 0.16% 就是已经写进 BRR 的误差 |
| USB CDC / HID | USB 通信设备类（虚拟串口）/ 人机接口类 | 枚举成功就代表所有主机和所有应用软件都兼容 |

## ADC、DAC 与 DMA

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| ADCCLK | F103 上 ADC 的时钟，从 APB2 再分频，RM0008 规定不得超过 14 MHz。72 MHz 的 APB2 取 ÷6 得到 12 MHz。12 位转换在采样时间之外再加 12.5 个该时钟周期 | ADC 时钟等于 SYSCLK，分频可以随便取 ÷2 或 ÷4 |
| Cache coherency | CPU Cache 与 DMA 看到的内存副本一致。带 D-Cache 的内核上要按缓存行做清洁或无效化。H7 的 D-Cache 行长是 32 字节，区间和缓冲区都按这个长度对齐 | DMA 完成中断会自动刷新 D-Cache |
| Calibration | ADC 校准。许多系列在上电或改变时钟后要求先校准，完成前的码值不能当结果 | 校准是出厂一次完成的，用户代码不用管 |
| Circular mode | DMA 循环模式：传输计数耗尽后自动重装并继续。它不定义业务上的一帧从哪到哪 | 循环 DMA 的每次中断都是一整帧新数据 |
| D-Cache | Cortex-M7 一类内核上的数据缓存。M4 没有同名的 D-Cache 维护问题 | 所有 STM32 都要在每次 DMA 后清洁 D-Cache |
| DMA | 在外设与内存、或内存与内存之间搬运数据的硬件控制器 | DMA 不占 CPU 就等于不会丢数据 |
| DTCM | 与 Cortex-M7 紧耦合的数据内存 | 所有 DMA 控制器都能访问 DTCM |
| HT / TC | DMA 半传输 / 传输完成事件 | HT 和 TC 在所有模式下都代表一帧业务数据 |
| Memory-to-memory | 由软件触发的存储器到存储器搬运，不使用外设请求。不是每个 DMA 控制器都有这种模式 | 打开之后外设请求仍按原通道正常工作 |
| NDTR / CNDTR | DMA 剩余传输项数。单位是数据项，不是字节；宽度为半字或字时更不能当成字节数 | 读到的剩余量永远是字节数 |
| Regular / Injected | 规则组按设定顺序转换。具备注入组的型号可以插入更高优先级的转换；不是每颗 STM32 都有注入组 | 注入通道在所有系列上都存在，而且结果寄存器与规则组相同 |
| Sampling time | 采样开关闭合、向采样电容充电的时间。源阻抗高时要加长 | 采样时间只影响转换速度，不影响码值对不对 |
| SAR ADC | 逐次逼近型模数转换器。有效位数还受参考、源阻抗、噪声和校准影响 | 转换位数越高，实际精度必然等于这个位数 |
| SRAM domain | 不同 SRAM 区域对 DMA 的可达性不同，H7 上尤其明显 | 只要是 RAM，任意 DMA 都能读写 |
| VDDA / VREF | 模拟电源和转换参考。把码值换算成电压时要用实际参考，而不是名义上的 3.3 V | VDDA 一定等于数字 VDD，参考也一定是 3.3 V |

## Flash、启动与低功耗

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| Backup domain | 备份域，通常包含 RTC、备份寄存器和 LSE。写之前一般要打开电源接口时钟并解除写保护 | 主电源在，备份域就可以直接写 |
| BOOT0 | 启动选择脚。它和 BOOT1 或选项字节的组合决定从 Flash、系统存储器还是 SRAM 启动，组合因系列而异 | BOOT0 悬空时启动模式是确定的 |
| Dual bank | 部分型号把 Flash 分成两个 bank，可以一边执行一边擦写另一边。没有双 bank 就不能照搬交换流程 | 所有 STM32 都能做银行交换升级 |
| IAP | 应用内编程：由已经运行的程序接收新镜像并写入 Flash。能跳转不等于升级安全 | 能写 Flash 并跳转就等于安全升级 |
| IWDG / WWDG | 独立看门狗多用 LSI；窗口看门狗用 APB 时钟，喂得太早也会复位 | 两个看门狗都只是“超时就复位”，提前喂总是安全的 |
| Option bytes | 选项字节，存放读保护、写保护、BOR 和启动相关配置。改写通常要解锁，并可能在复位后才生效 | 选项字节和普通 Flash 变量一样，随手写完立即生效 |
| Page / Sector | Flash 的擦除单位。F1 常用页，F4 和 H7 常用扇区，大小都要查该型号 | 擦除粒度在所有系列上都是 1 KB 或 2 KB |
| RDP | 读保护级别。升高后会限制调试器读 Flash；退回级别 0 往往伴随整片擦除，级别 2 在多数型号上不能再退回 | 提高级别不影响 Flash 内容，也总能无损恢复 |
| RTC | 实时时钟，位于备份域。改日历前要进入它要求的初始化模式 | RTC 使用 SYSCLK，主电源一断时间就丢 |
| Sleep / Stop / Standby | 由浅到深的低功耗模式。Sleep 多停 CPU 时钟；Stop 多停高速时钟并保持 SRAM；Standby 更接近掉电复位，SRAM 通常丢失。保持项和唤醒后的时钟以该系列手册为准 | 三种模式只是电流数字不同，唤醒后代码从停下的地方照常运行 |
| System memory | 出厂引导程序所在的系统存储区，不在用户 Flash 里。常用于串口或 USB 下载 | 系统存储器里的 bootloader 就是用户 IAP 工程 |
| VBAT | 备份域供电脚。主电源掉电时由电池或后备电路给 RTC 供电 | VBAT 可以替代整板 3.3 V 电源 |
| Watchdog | 用独立或窗口计数器监督软件是否还在规定时间内表达“健康” | 在固定中断里无条件喂狗就能证明系统健康 |
| WFI / WFE | 等待中断 / 等待事件。能唤醒它们的条件不同，事件不一定进入 ISR | WFI 和一句空循环的功耗相同 |

## RTOS 与并发

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| Binary semaphore | 取值为 0 或 1 的信号量，常用于“事情发生了”的同步。它不带优先级继承 | 二值信号量和互斥量可以互换着保护同一资源 |
| CMSIS | Arm 的内核与设备软件接口标准，包括内核头文件和启动约定 | CMSIS 等于某一家的 HAL |
| CMSIS-RTOS2 | 盖在具体内核上的一套 RTOS API。接口相同不等于底下的 FreeRTOS、RT-Thread 或别的实现行为相同 | 换成 CMSIS-RTOS2 之后就不必再看具体内核的版本和配置 |
| Context switch | 保存一个执行流的寄存器、恢复另一个。RTOS 常把这件事放在 PendSV | 每次中断返回都会切换到另一个任务 |
| Critical section | 短暂关中断或进调度锁的区域。里面不能阻塞，也不能做耗时工作 | 临界区越长，系统越安全 |
| FromISR | 中断里可调用的那一组内核 API。调用者的 NVIC 优先级必须符合该内核的阈值 | ISR 里调用普通的延时或获取互斥量也是安全的 |
| Heap | 这里多指内核自己的堆。任务栈、内核堆、C 库堆和 DMA 缓冲区不是同一块内存 | 一个 malloc 成功就说明四个堆都还有空间 |
| Idle task | 没有其他就绪任务时运行的空闲任务。它的钩子里不能阻塞 | 空闲任务占用率高，说明实时性一定很好 |
| MSP / PSP | 主栈指针 / 进程栈指针。异常常用 MSP，RTOS 任务常用 PSP | 任务和异常始终共用同一个栈 |
| Mutex | 带所有权、通常带优先级继承的互斥量，用来保护共享资源。不能在 ISR 中获取 | 互斥量可以在中断里拿来防止重入 |
| Priority inversion | 低优先级持有资源、高优先级因此等待。优先级继承只缓解互斥量协议覆盖的那一种情形 | 只要用了 RTOS，优先级反转就不会发生 |
| Queue | 任务之间传递有长度上限的数据。队满或队空时线程可以阻塞；ISR 必须用非阻塞的 FromISR 版本 | 队列是无限长的，写失败只会发生在没用 RTOS 的时候 |
| RTOS tick | 内核的时间节拍。它决定延时分辨率，也带来周期开销 | tick 越快，实时性必然越好，而且没有成本 |
| Task | 有独立栈和优先级的执行流。阻塞时让出 CPU | 任务就是一个 while 循环，栈和优先级可以以后再补 |
| WCET | 最坏执行时间。调度预算要按上界，而不是按几次运行的平均值 | 多次平均运行时间可以代替最坏时间 |

## 以太网、lwIP 与 MQTT

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| DHCP | 自动取得 IPv4 地址的协议。地址还没租到时，业务连接不该算作已配置完成 | 网线一插，IP 就已经可用 |
| DNS | 把名字解析成地址。解析失败和随后的 TCP 连接失败不是同一层问题 | ping 的是 IP 地址，所以 DNS 与连通性无关 |
| ICMP | 网络层的控制报文。ping 使用其中的回声请求；ping 通只说明当时这条回声走通了 | ping 通就表示 TCP 端口、MQTT 和 TLS 都可用 |
| lwIP | 面向小型系统的 TCP/IP 实现。raw、netconn 和 socket 的线程模型由移植和 NO_SYS 决定，回调里不能假设可以阻塞等待同一条线程 | lwIP 的 API 和 POSIX socket 在任何配置下都可以混用 |
| MAC | MCU 里的以太网媒体访问控制器。它不含板子上那颗 PHY 的模拟前端 | 芯片手册里的以太网章节已经包含网口变压器和 PHY 寄存器 |
| MDIO | 管理 PHY 寄存器的串行接口。链路是否起来，先看 PHY 状态，而不是只看协议栈的网口标志 | 协议栈显示接口 up，物理链路就一定已经连通 |
| MQTT | 跑在 TCP 上的发布/订阅应用协议。会话、主题和报文标识都在 TCP 已经连通之后才有意义 | MQTT 连上就表示业务数据已经写入非易失存储 |
| MQTT QoS | 协议规定的交接等级。QoS 1 是至少一次，应用层仍可能看到重复消息 | QoS 数字越大，业务就一定只被处理一次 |
| PHY | 网口侧的物理层收发器，多数设计里是片外芯片，经 RMII/MII 和 MDIO 与 MAC 相连 | PHY 地址和寄存器在所有板上都是 0 |
| RMII | MAC 与 PHY 之间的简化媒体接口，100 Mbit/s 时参考时钟是 50 MHz。MII 使用更多并行线 | RMII 和 MII 只是连接器名字不同，时钟可以随便接 |
| TCP | 可靠的字节流。对端的 ACK 只说明 TCP 收到了字节，不说明应用程序已经处理 | 收到 ACK 就可以删除本地的业务记录 |
| TLS | 传输层安全。握手成功说明当时按配置验证了证书链；设备时间不对时，证书有效期判断会错 | 打开 TLS 就等于身份、时间和业务数据都已经可信 |

## 调试

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| BFAR / MMFAR | 总线故障地址 / 存储器管理故障地址。只有对应的“地址有效”标志置位时，这个地址才有意义 | HardFault 一发生，这两个寄存器里就是肇事地址 |
| Breakpoint | 让内核在某条指令停下。外设、DMA 和看门狗是否一起停，取决于调试停机配置 | 断点住了，板上的电机、总线和看门狗也都冻结了 |
| CFSR | 可配置故障状态寄存器，含用法、总线和存储器管理故障的标志 | 只看 HardFault 这个名字就能知道是空指针还是除零 |
| DBGMCU | 调试时的低功耗控制。打开对应位后，Sleep、Stop 或 Standby 期间调试器才容易留住内核 | 进了低功耗仍然能单步，是调试器的默认行为 |
| DWT | 数据观察点与跟踪单元，其中的周期计数器可用来量间隔。使用前通常要打开跟踪使能 | DWT 周期数不打开任何控制位就会自己累加 |
| HardFault | 优先级最高的一类故障异常，或其他故障升级后的落点。原因要结合 HFSR、CFSR 和压栈的 PC | 看到 HardFault 就只需要复位，不必记录寄存器 |
| JTAG | 多线调试接口，通常占 TMS、TCK、TDI、TDO。这些脚要当 GPIO 时，必须先确认调试口已释放 | JTAG 和 SWD 占用的引脚完全相同 |
| SCB | 系统控制块，含故障状态、向量表偏移和部分系统控制寄存器 | HardFault 只看 HFSR 就能找到根因 |
| SWD / SWO | 两线调试接口 / 单线跟踪输出。SWO 是否引到封装上，要看具体型号和封装 | SWO 在所有封装上都默认可用，而且不占复用脚 |
| SWDIO / SWCLK | SWD 的数据脚和时钟脚。部分 G0 上 SWCLK 与 BOOT0 是同一只脚，接调试器会影响启动采样 | 调试器只在下载的那一瞬间占用这两个脚 |

## 工程习惯

| 术语 | 本书中的含义 | 常见误解 |
| --- | --- | --- |
| CubeMX | ST 的图形配置工具，用来生成时钟、引脚和初始化代码。生成结果仍要对照数据手册的复用表 | 图形界面保存之后，引脚冲突和时钟超限都不可能再出现 |
| HAL | ST 的硬件抽象层。它减少直接碰寄存器的次数，但不消除型号、电气和时序差异 | HAL 写完就可以不看参考手册 |
| Linker script | 规定 Flash、RAM 的地址范围和段如何放置。IAP 改变应用起始地址时，链接脚本和向量表要一起改 | 链接脚本只影响变量名，不影响程序跑在哪一段地址 |
| MPU | 内存保护单元，也可配置访问权限和缓存属性。它不是带虚拟内存的 MMU | MPU 能做虚拟地址分页，所以野指针会被自动映射走 |
| Ring buffer | 读写位置绕回的有界队列。容量、满和空的判定要在设计里写明 | 加上 volatile 之后就自动线程安全，而且不会溢出 |
| SPL | F1 常用的标准外设库，对寄存器做薄封装。函数名和 HAL 不是同一套 | SPL 例程可以和 Cube 生成的 HAL 工程无缝混编 |
| `volatile` | 要求编译器按抽象机规则保留对易变对象的访问 | 它同时提供原子性、互斥、内存屏障和队列容量保证 |

## 会上手的几笔账

前面每一行只给工作定义。这张表把 BluePill 上会反复手算的数钉在订货号和手册路径上。换封装、换系列，整行作废，回到那颗料的手册重算。算式都来自第 02、03、06、07、09、11、21 章已经写下的数，这里只把它们收成可以对照实测的一页。

| 账 | 钉在哪 | 数 | 写错时长什么样 |
| --- | --- | --- | --- |
| 这颗料 | 丝印 STM32F103C8T6，LQFP48。第 21 章：micro-USB 5 V 经 RT9193-33 到 3.3 V，PC13 灯低电平亮。容量在 `0x1FFFF7E0` 的低 16 位，单位 KB。中容量 DevID 是 `0x410`。DS5319 | 手册写 Flash 64 KB、SRAM 20 KB。读出来不是 64，就不要按 C8 的手册往下算 | 丝印或卖家写着 128 KB，链接脚本就把 128 KB 都用满 |
| 时钟树 | 板载 HSE 8 MHz，PLL ×9。RM0008 时钟树；第 02 章那张表 | SYSCLK = HCLK = 72 MHz。APB1 ÷2，PCLK1 = 36 MHz；APB2 ÷1，PCLK2 = 72 MHz。APB 预分频不是 1 时，这条总线上的定时器时钟再 ×2，所以 TIM2–TIM7 仍是 72 MHz。TIM1 在 APB2，预分频为 1，不再 ×2 | 用 36 MHz 去除 PSC、ARR，PWM 频率偏一倍 |

| 115200 | 第 06 章的 BRR 公式。USART1 在 APB2，fPCLK = 72 MHz，16 倍过采样 | `72e6 / (16 × 115200) = 39.0625`。小数 `0.0625 × 16 = 1`，BRR = `0x271`。`72e6 / (16 × 39.0625) = 115200`，分频误差是 0。USART2 在 APB1，fPCLK = 36 MHz，同一章给出的 BRR `0x138` 才大约偏 0.16%。把 72 MHz 那一格的小数位丢掉、只用 39，也会得到大约 0.16% | 把表上的 0.16% 当成 USART1 已经偏了，或者把 USART2 的时钟当成 72 MHz |
| 一位和一帧 | 第 06 章：115200 时一位约 8.68 µs。8N1 是起始位 + 8 个数据位 + 停止位，共 10 位。RM0008：RX 空闲满一个帧时间才置 IDLE | 一帧约 86.8 µs。这是线路空闲，不是协议里的长度字段 | 把 IDLE 中断当成对方的一包已经按协议结束 |

| I2C 地址和上拉 | 第 07 章的地址和上拉表。第 03 章：F1 片内上下拉约 30–50 kΩ | SSD1306 的 7 位地址 `0x3C`，HAL 的 DevAddress 填 `0x78`。短总线外接 4.7 kΩ 到 3.3 V | 扫描器看到 `0x3C` 就原样填进 `HAL_I2C_Mem_Read`，或只开片内上拉就跑 400 kHz |
| IWDG 1 秒 | 第 11 章：`T = 预分频 / f_LSI × (Reload + 1)`。LSI 典型 40 kHz，手册范围大约 30–60 kHz | 预分频 64 时，名义计数频率 625 Hz。1 秒要把 Reload 写成 624；写成 625 会多一个计数。同一套预分频和重载，LSI 若是 60 kHz，秒数大约只有 30 kHz 时的一半。名义最长一档大约 26 s | 把 40 kHz 算出来的秒数写成保证值，调试时又不冻住 IWDG |
