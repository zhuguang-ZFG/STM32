# 学习路线收束

这一页只出现在书稿里，用来把七个分部收成一条可以继续走的路。它不增加新的寄存器事实，也不改 `docs/` 里的第 28 章。

## 七段各留下什么证据

| 分部 | 读完时应能拿出 |
| --- | --- |
| 起步 | 可重复的工程：能编译、下载、断点，并写明芯片和时钟假设 |
| 引脚与时间 | 一只脚的真实电平，或一张定时器周期的计算和实测 |
| 搬运 | 一帧 UART、I2C 或 SPI，或一次 ADC/DMA 的缓冲区归属 |
| 可靠性 | 看门狗、低功耗或升级失败时的状态，而不是只在演示路径上通过 |
| 交付 | 一个小项目的复现记录，并分清手册、例程和社区说法 |
| 迁移与联网 | 换系列时重核电源、复用、时钟和内存；网络按链路、地址、传输、应用分层排错 |
| 系统 | 一张有主人、截止时间和恢复证据的系统图，而不是只换了一个 RTOS 的名字 |

## 怎样算这本书读完

三条就够：

1. 工具链能在你自己的板上重做一遍，而不是只在截图里成功。
2. 至少一个结论同时写着期望值、实测值和测量条件。
3. 这个结论能指回文档号或冻结的代码版本。指不回去的数字，先不要写进设计。

## 下一步怎么选

按你真正要交付的约束选一条，做深，而不是把 29 章再扫一遍。

- 还在打通最小闭环：回到第 00–05 章，把点灯、中断和 PWM 做成可测量的记录。
- 数据要进单片机再出去：第 06–10 章加 [附录 A](#appendix-engineering)，把缓冲区和帧边界写清楚。
- 设备要在掉电、升级或低功耗之后还在：第 11、12、16 章，把失败路径和唤醒后的时钟写成表。
- 要上网：第 27 章。链路、地址、TCP、MQTT 和 TLS 分开证明。
- 要选 RTOS：第 15 章和第 28 章。先有栈、队列和中断优先级预算，再比较内核名字。

术语回查用 [附录 D](#appendix-glossary)。什么算数、什么只是线索，用 [附录 E](#appendix-references)。

## 先不要做的事

- 不要把 F1 的寄存器地址抄到 G0、L4 或 H7。
- 不要把仿真通过当成板级电气已经正确。
- 不要把公众号或社区文章里的参数当成手册。
- 英文整书不在这一版里。需要英文时仍用仓库里的 `docs/en/` 章节。

收束之后如果只做一件事：选一个你要交付的行为，写下它的期望、测量和下一次会失败的边界。
