# 14 个例程的验证索引

例程不是“复制后能编译”就结束。每个例程都要留下一个可观察结果，并写清不能由该结果推出什么。默认平台是 STM32F103C8T6（BluePill）；具体时钟、板级接线和固件包版本以各目录 README 为准。

| 顺序 | 例程 | 关联章 | 最小可见结果 | 验收工具 | 不能由此推出 |
| --- | --- | --- | --- | --- | --- |
| 1 | `gpio-blink` | 03 | PC13 约 1 Hz 闪烁，PA0 外接灯按另一周期翻转 | 逻辑分析仪/万用表 | 所有 GPIO 都能承受同一负载 |
| 2 | `exti-key` | 04 | PA0 每次有效按下只翻转一次 PC13 | 逻辑分析仪 + 中断计数 | 消抖参数适合所有按键 |
| 3 | `timer-pwm` | 05 | PA6 为 1 kHz，CCR 改变时占空比连续变化 | 示波器/逻辑分析仪 | LED 亮度与占空比线性 |
| 4 | `uart-dma-idle` | 06、10 | 多种长度命令完整入队，ORE 后可恢复 | USB-TTL + 字节对比/计数器 | IDLE 等同业务帧界；持续流永不溢出 |
| 5 | `i2c-oled` | 07 | OLED 显示并持续刷新，地址扫描只命中目标 | 逻辑分析仪 I2C 解码 | 任意 OLED 都用同一地址/初始化表 |
| 6 | `spi-flash` | 08 | JEDEC ID 符合器件，跨页写入后逐字节一致 | 逻辑分析仪 + `memcmp` | 擦写寿命、掉电原子性已满足产品要求 |
| 7 | `adc-dma` | 09、10 | 3 通道连续采样，输入变化与对应通道一致 | 万用表 + DMA 缓冲观察 | 名义 3.3 V 可当精密参考 |
| 8 | `rtc-alarm` | 11、16 | STOP 后按计划唤醒，VBAT 条件下时间连续 | 电流表 + 串口时间戳 | 整板达到数据手册芯片典型电流 |
| 9 | `iap-bootloader` | 12 | 镜像校验通过后跳转；损坏镜像不跳转 | 串口 + 复位/掉电注入 | 已具备签名、反回滚和安全启动 |
| 10 | `can-bxcan` | 13 | 环回自收；双节点时有 ACK 且过滤器生效 | CAN 分析仪/错误计数 | FDCAN 可直接复用同一寄存器配置 |
| 11 | `usb-cdc` | 14 | 主机枚举出 CDC 端口并完成双向字节传输 | USB 抓包/系统设备信息 | 所有主机、线缆和挂起恢复均兼容 |
| 12 | `usb-hid` | 14 | PA0 边沿产生一次按下和一次全零释放报告 | 文本框 + USB 抓包 | 可作为安全输入设备或通过 USB-IF 认证 |
| 13 | `freertos-task` | 15 | 三任务运行，队列空时阻塞，按键事件唤醒任务 | trace/运行时统计 + 串口 | 最坏响应时间和栈裕量已被证明 |
| 14 | `spl-f1-blink` | 01、26 | ELF/HEX/BIN/MAP 构建闭合；真板上 PC13 约 1 Hz 闪烁 | GNU Arm size/nm + ST-Link + 逻辑分析仪 | 编译链接通过等于真板时钟、接线和运行均已验证 |

## 先和账对上的四行

跑表里的顺序之前，先把这四行和[附录 D](#appendix-glossary)文末的两张账对上。对不上就先不要加下一种总线。

| 例程 | 先对上的数 | 对不上说明什么 |
| --- | --- | --- |
| `gpio-blink` | PC13 低电平点亮。这颗灯的电流不能代表别的脚 | 极性反了，或用 PC13 的亮度去要求一只普通脚 |
| `timer-pwm` | 定时器时钟按 72 MHz 算。PSC 71、ARR 999 得到 1 kHz。同一组数用 36 MHz 去除，算式给出 500 Hz | 示波器上是 500 Hz 或 2 kHz |
| `uart-dma-idle` | USART1、115200、BRR `0x271`。IDLE 约 86.8 µs，不是协议帧界 | 把第 06 章表上的 0.16% 当成这只 USART 已经偏了 |
| `can-bxcan` | APB1 36 MHz，预分频 9、BS1 5、BS2 2，正好 500 kbit/s。预分频 8 且一共 10 个时间份额时是 450 kbit/s | 分析仪停在 450 kbit/s，或把回环收到自己的帧当成两块板已经应答 |

## 推荐跑法

1. **先闭环**：`gpio-blink → exti-key → timer-pwm`。先证明下载、引脚和时基。
2. **再连外设**：`uart-dma-idle → i2c-oled → spi-flash → adc-dma`。一次只引入一种总线或数据路径。
3. **再处理状态**：`rtc-alarm → iap-bootloader → can-bxcan → usb-*`。每一步都保留上一阶段可回退镜像。
4. **最后并发**：`freertos-task`。只有裸机外设行为已经可解释，调度问题才不会和驱动问题混在一起。
5. **最后对照旧库**：`spl-f1-blink` 单独使用 SPL V3.5.0 与 CMake；不要和 HAL 示例在同一外设上双重初始化。先验证 CLI 构建，再分别让 CLion/VS Code 调用同一 preset。

## 每个例程的交付记录

建议在自己的实验目录保留同一张表：

| 字段 | 示例 |
| --- | --- |
| 芯片/板卡 | STM32F103C8T6，BluePill 丝印与来源 |
| 工具版本 | CubeIDE、编译器、Cube 固件包 tag/commit |
| 接线 | 电源、电平、共地、引脚和外部器件型号 |
| 期望 | 可量化的频率、字节、ID、时间或状态 |
| 实际 | 仪器值、串口原始字节、错误寄存器 |
| 边界 | 仿真/真板、温度、电源、尚未覆盖的失败路径 |
| 复现 | 从干净工程到观察结果的最短步骤 |
