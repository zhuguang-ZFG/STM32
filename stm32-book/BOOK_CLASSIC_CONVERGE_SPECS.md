## 1. 问题诊断

### 1.1 三支分叉，尚未合流

| 分支 | 主贡献 | 风险 |
| --- | --- | --- |
| `feat/book-video-classic` | 书视经典化合同、五技能、分镜可复现链、与 `main` 对齐（0 behind） | 底座正确，但教学路径仍偏「七个分部标题」，章内仍易被固定骨架绑架 |
| `feat/strip-spec-voice` | 前四节写给读者；审稿腔硬门（`slop_lint`）；CONTENT_GUIDE 读者规则 | 与 classic 正文偶发措辞冲突；merge-tree 预测约 **20 CONFLICT（可控）** |
| `feat/handraw-sketch-system` | Sepia / plain-voice 文风操作系统；00–19 一批去 AI 味正文节奏实验 | 与 classic **几乎全书中英冲突**；merge-tree 预测约 **76 CONFLICT（高风险）**；价值在规则与技能树，不在覆盖 Book 2.0 已证据化正文 |

三支各自推进导致：同一章可能「有视频合同、有审稿词表、有手绘节奏」，但没有一份文件规定**合并顺序、冲突默认方、哪些文件允许整树拷贝、哪些只抽规则**。

### 1.2 模板疲劳 ≠ 缺内容

仓库已有 29 章中英、示例、HTML/PDF、章视频、来源快照与回归测试。读者卡点不是「有没有字」，而是：

- 章章同一套标题顺序（原理 → 关键插图 → 时序 → 坑 → 学习目标 → …），读三章后产生「下一章也知道长什么样」的疲劳。  
- 分部标题与 L0–L5 能力跃迁不完全同构；读者无法用分部回答「我现在处在哪一级、下一级要交出什么证据」。  
- 手册密度前置：订货号、寄存器墙、全表出现在最小胜利之前，入门读者过早掉队。  
- 视觉任务混用：概念图、技术数据流图、真板照片、示波器截图有时被同一套「示意图」叙事带过。

### 1.3 「AI 味」的真实来源是结构节拍，不是个别套话

抽样显示 `slop_lint` 机械命中已很少。残留的「像生成的」感主要来自：

1. **章骨架同构**：每章标题集合高度重叠。  
2. **旁白/回忆卡同构**：短片与长课重复「问题 → 预告 → 三点 → 总结 → 口诀」的 8–10 拍全章复制。  
3. **对称罗列**：每个方案平均介绍，缺少有条件判断。  
4. **复述三次**：标题下说一遍、表格后再抄、章末再复述。  

因此合流目标是改**操作系统**（路径、合同、门禁、技能树），不是再跑一轮同义润色。

## 2. 合流目标与非目标

### 2.1 目标（可验收）

1. **一份 Overlay**：本文件成为三支合流后的执行合同；旧两份保留为被扩展基线。  
2. **L0–L5 阅读路径**：章号 00–28 不变；分部标题、承接文案、推荐阅读顺序按能力阶梯重写；每分部声明「进入条件 / 本部交付 / 进入下一部条件」。  
3. **每章教学合同**：进入问题、最小胜利、机制、失败分支、迁移、记忆锚点、离开检查七项核心必填，另登记先备知识；章内结构改为功能块可选。  
4. **去 AI 味门禁合流**：strip 的读者规则 + slop_lint；Sepia refactor 流程；plain-voice；人眼节奏检查；禁止全书同构旁白。  
5. **Handraw 统一视觉语言**：技术图与概念图同属 Handraw 规划体系（Layout / 风格 / 配色登记）；真板照片与仪器截图走证据轨，永不 AI 冒充。  
6. **书视同源收紧**：沿用 `BOOK_VIDEO_CLASSIC_SPECS` 分镜与成片合同，叠加本 Overlay 的节拍禁令与样章硬门。  
7. **分支退役**：按「规则优先、正文挑拣」完成 port 后，归档 `feat/strip-spec-voice` 与 `feat/handraw-sketch-system`。  
8. **样章门**：ch03（GPIO 与 LED）先对照 L0–L5 教学合同与本 Overlay 全部门禁验收，通过后再扩批次。

### 2.2 非目标

- 不重排公开章号 00–28，不把显示编号 1–29 与源文件编号混用或反转（既有 `display_chapter_number()` 映射另立切片才可改）。  
- 不整树 merge handraw 的 `docs/` 大改来覆盖 Book 2.0 已证据化正文。  
- 不为「像人写的」编造故障经历、测试数据、项目故事或个人感受。  
- 不用生成图冒充开发板、仪器波形、芯片显微或实验结果。  
- 不删公式、单位、revision、电气条件、来源 id 来换短文或「好读」。  
- 不给每章机械补相同数量的标题、列表、插图、实验。  
- 不建立第二套正文真相源或第二套书籍构建器。  
- 不把「趣味」「网感」写成可以跳过技术证据的借口。

## 4. 每章教学合同

### 4.1 教学合同字段（学习日志 / chapter_guides 登记）

每章在 `manifest` 的 `chapter_guides`（或等价机器可读表）登记以下字段（七项核心 + 先备知识）；中英文各一份事实对齐、表达分写：

| 字段 | 合同含义 | 可检查标准 |
| --- | --- | --- |
| 进入问题 | 读者已遇到的可观察现象或具体任务 | 开头 120 字内出现；禁止主题式预告 |
| 先备知识 | 只引用前文已讲概念；后用概念先给最小定义 | 审计不得发现未定义关键术语依赖后文 |
| 最小胜利 | 可运行、可测量或可查表复算的一个结果 | 出现在手册密度长表之前；步骤可独立复现 |
| 核心机制 | 一个主要认知难点 | 全章只保留一个主比喻/主关系图争夺注意力 |
| 失败分支 | 至少一个能区分原因的证据与下一检查动作 | 禁止以「可能坏了」收尾 |
| 迁移边界 | 换芯片/库/时钟/封装/软件栈时必须重查的条件 | 写成条目，不写「注意移植」空话 |
| 记忆锚点 | 准确比喻 **或** 核心关系图 **或** 可复述口诀（可组合，但必须指向同一机制） | 比喻后必须有「相似点 / 失效点」对照 |
| 离开检查 | 不翻书能答的问题 + 能独立完成的动作 | 与 L0–L5 本部交付对齐；可被测验或实验覆盖 |

「讲透彻」= 核心机制 + 失败分支 + 迁移边界三项同时成立。  
「一点就懂」= 进入问题 + 最小胜利在手册墙之前完成，且记忆锚点可单页复述。  
「从入门到精通」= 读者能指出自己停在 L0–L5 哪一级，并知道下一级缺哪份证据——不是读完 29 章标题。

### 4.2 最小胜利前置、手册密度后置

强制顺序原则（标题名可变）：

1. 进入问题 / 反差现象  
2. 最小胜利（短步骤 + 预期证据）  
3. 核心机制（一个难点）  
4. 按需展开：时序、公式、寄存器、全表、系列差异  
5. 失败分支与排查  
6. 迁移边界  
7. 离开检查  

允许把完整寄存器表、电气极限表、长 API 列表放在机制之后或附录式小节。禁止在最小胜利之前堆「原理与适用范围」式手册墙。

### 4.3 功能块可选清单（取代固定骨架）

章内从下列功能块**按需选取**，不要求全出现，不固定顺序；选用的块必须完成其认知任务，禁止空标题：

| 功能块 | 何时选用 | 完成标准 |
| --- | --- | --- |
| 现场问题 / 失败现象 | 几乎每章 | 可观察、可复述 |
| 一句话直觉 | 概念易混时 | ≤40 字，随后必须被机制校正 |
| 最小可运行步骤 | 每章必有等价物 | 含预期现象或测量 |
| 硬件数据流 / 状态机 / 时序 | L1–L5 机制章 | 能算回去或能逐步对账 |
| 可复算公式与参数条件 | 涉及分频、波特率、采样等 | 变量、单位、适用订货号齐全 |
| 测量方法与证据 | 配置是否作用在硬件上 | 写清探头/窗口/读回位置 |
| 常见误判与最短排查 | 有两种以上易混原因时 | 每行：现象 / 区分证据 / 下一动作 / 出处 |
| 跨系列迁移边界 | 数字会随系列变时 | 列出「什么不变 / 什么必须重查」 |
| 由易到难实验 | 需要动手巩固时 | 1–3 个，难度递进，预期可区分 |
| 离开前检查题 | 每章必有等价物 | 不翻书可答 + 可动作验收 |
| 代码实现（HAL 为主，LL/寄存器/SPL 有边界） | 需要可编译片段时 | 真实可编译边界写清；完整工程链到 `examples/` |
| 硬件与接线表 | 涉及具体引脚时 | 板型 / 外设 / 引脚 / 备注 |
| 相关资源 | 需要手册定位时 | 指向具体手册章节与来源 id，不堆链接墙 |

### 4.4 明确废止的强制结构

`CONTENT_GUIDE.md` §2「每篇文章的固定骨架」代码块中的标题顺序**不再作为合入门禁**。旧标题可在未改造章中暂时残留，但新改章与 ch03 样章必须按 §4.1–4.3 组织。  
保留 strip 已定规则：前四节（若章内仍有 `<!-- video: -->` 区段）写给读者不写给审稿人；「常见坑与出处」合并旧排查节；出处只走 manifest `sources` id。

| plain-voice | 短句、具体动词、少形容词；不把语气档案私人化 | 正文与旁白编辑清单 |
| humanizer-zh（classic 已列） | 只处理真实表达问题；代码/URL/ID/表数据不动 | 与 plain-voice 串联，不互斥 |
| unslop | 页面与视频场景红线：间距、色彩、焦点、文案噪音 | 版式与成片目检，不改技术事实 |
| 人眼节奏检查（本 Overlay） | 章骨架差异、旁白节拍差异、段落长短不齐 | 每批人工清单，不可被 lint 替代 |

### 5.2 必须清理（合并 Book 2.0 §5.1 + strip）

- 「本章将介绍 / 让我们深入了解 / 通过以上可以看出」等开场收束。  
- 定义人所共知主题的开头；改为问题、错误现象、数值矛盾或操作结果。  
- 每节「先预告 → 再解释 → 后总结」的分形结构。  
- 连续「首先/其次/最后」「此外/同时/因此」与整齐三项排比。  
- 「至关重要 / 显著提升 / 全面掌握 / 强大而灵活」等无信息量强调。  
- 把表格再抄成一段；章末复述整章目录。  
- 无来源经验口吻、无条件数字、未运行通用代码、伪造失败案例。  
- 审稿腔泄漏到读者正文（strip 词表 + 同义写法）。  

### 5.3 必须保留

- 订货号、revision、手册版本、公式、寄存器位、地址、频率、单位、来源 id。  
- 失败前置条件与可观察证据。  
- 代码编译边界（芯片、库版本、头文件、宏、链接脚本、构建命令）。  
- 有条件的明确判断（每章至少一个）。  
- 长短不一的段落与句子；技术密度由内容决定。

### 5.4 禁止全书同构旁白 / 回忆卡

短片与长课**不得**共用同一套 8–10 拍模板填词。允许的灵活节拍池（每章选 4–7 拍，顺序可变）：

- 反差开场（0–8 s 内问题或结果）  
- 最小可见结果  
- 机制单步显现  
- 误判对照  
- 测量证据特写  
- 迁移边界一句  
- 离开检查 / 回忆卡  

硬禁：

1. 连续 ≥5 章旁白大纲字段顺序完全一致。  
2. 回忆卡永远「三个要点 + 一句口诀 + 下章预告」三件套。  
3. 长课用短片时间轴线性拉伸充时长。  
4. 文字卡超过必要结论，主画面不推动电流/字节/状态/波形变化。  

检查方法：每批导出旁白大纲 diff；人眼标记「节拍指纹」；相同指纹章 > 本批章数的 40% 则批次失败。

### 5.5 编辑完成前的强制两次检查

1. **删除检查**：删掉新增词句后意思不变 → 删除新增。  
2. **回退检查**：原句更短更准且语气合适 → 保留原句，不为润色而改。  

Sepia 诊断必须先输出缺陷列表再改字；禁止边读边改导致「越改越长」。
